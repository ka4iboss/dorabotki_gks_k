2. C2 — зафиксировать отказ от поиска/замены по Markdown в форме сценария (документ-фиксация в `Описание.md`).

## 3. C1. Картинки в `ИдентификаторыФайловСкриншотов`

### 3.1. Проблема

Типовое поведение ERP предполагает, что в `ИдентификаторыФайловСкриншотов` (ТЧ элемента справочника `ДемонстрационныеСценарии`) собираются идентификаторы всех файлов, относящихся к сценарию. Сейчас расширение вставляет картинки только в HTML и в `ГКСИ_ФайлыИнструкций` (для base64), но не регистрирует их в типовой ТЧ.

### 3.2. Структура типовой ТЧ

Из `AGENTS/описание/Структура.md` §164:
- `ИдентификаторСкриншота` (`String(30)`);
- `ПрисоединенныйФайл` (`CatalogRef.ДемонстрационныеСценарииПрисоединенныеФайлы`).

### 3.3. Что сделать

1. В `ГКСИ_MarkdownФормаСервер.СоздатьПрисоединенныеФайлыИзДопСвойств` (после успешного создания/обновления файла) дополнительно вызывать типовой механизм регистрации в `ИдентификаторыФайловСкриншотов`. Что именно регистрировать — `Файл.Ссылка` или `Файл.УникальныйИдентификатор()` — уточнить по типовой реализации `Catalog.ДемонстрационныеСценарииПрисоединенныеФайлы` (посмотреть, как заполняется `ИдентификаторСкриншота` в основной конфигурации).
2. Если типовой метод отсутствует в открытом виде — прочитать существующий `ДемонстрационныеСценарииПрисоединенныеФайлы` и проверить, какие файлы связаны со сценарием. Добавить недостающие через прямой `НоваяСтрока = СценарийОбъект.ИдентификаторыФайловСкриншотов.Добавить()`.
3. Шаблон поиска: `ИдентификаторыФайловСкриншотов.НайтиСтроки(Новый Структура("ПрисоединенныйФайл", ФайлСсылка))` — если строка уже есть, не добавлять.
4. Сверить с фактическим поведением типовой конфигурации и зафиксировать контракт в `AGENTS/описание/Описание.md` §7.9.

### 3.4. Файлы

- `src/CommonModules/ГКСИ_MarkdownФормаСервер/Module.bsl` — расширить `СоздатьПрисоединенныеФайлыИзДопСвойств`.
- `AGENTS/описание/Описание.md` §7.9 — зафиксировать контракт.

### 3.5. Риски

- **Заимствование объекта.** Чтобы писать в `ИдентификаторыФайловСкриншотов`, нужно либо работать через объектную модель расширения (предпочтительно), либо заимствовать справочник `Catalog.ДемонстрационныеСценарии` в расширение. Поскольку правило «не менять основную конфигурацию» действует, но заимствование не запрещено — нужно решить, какой подход использовать. По умолчанию — без заимствования: писать через `СценарийОбъект.Записать()` после `Разблокировать()`.
- **Типовая логика.** Возможно, ERP ожидает, что в `ИдентификаторСкриншота` пишется не УИД ссылки, а `НомерКартинки` из типовой формы. Перед реализацией — прочитать основную конфигурацию `пустая_для_гкс/src/Catalogs/ДемонстрационныеСценарии/Forms/ФормаЭлемента` (если есть) или `ManagerModule.bsl` обработки загрузки описаний процессов, чтобы сверить.

## 4. C2. Фиксация отказа от поиска/замены по Markdown

### 4.1. Что зафиксировать

Типовая команда «Поиск и замена» работает по HTML-файлу сценария. Добавлять альтернативный поиск по `ГКСИ_ТекстMarkdown` в этой версии нецелесообразно:
1. Пользователь смотрит на HTML-результат, а не на исходник.
2. Поиск по двум представлениям требует удвоенной логики в форме поиска.

Если появятся требования от пользователей — оформим как отдельную задачу в 1.8+.

### 4.2. Что сделать

1. Добавить раздел `§7.10` в `AGENTS/описание/Описание.md` со ссылкой на этот пакет.
2. В разделе указать:
   - статус «отказано»;
   - причины отказа;
   - что делать, если требование всё-таки появится (отдельная задача в 1.8+).

### 4.3. Файлы
