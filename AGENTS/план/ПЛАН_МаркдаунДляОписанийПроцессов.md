# План: редактирование и хранение «Описаний процессов» в Markdown через расширение ГКС_Инструкции

## 1. Цель и контекст

Типовой механизм 1С:ERP «Описания процессов» реализован справочником
`ДемонстрационныеСценарии`:

- текст описания хранится как **HTML в присоединённом файле**
  (`ДемонстрационныеСценарииПрисоединенныеФайлы`, по файлу на язык в табличной части `ОписанияСценария`);
- редактирование в типовом варианте — **голый HTML через внешний редактор**
  (команды «Редактировать» / «Закончить редактирование», `РаботаСФайламиСлужебныйКлиент`);
- вывод (просмотр, Альбом процессов, отчёт «ДемонстрационныеСценарииОбъекта», Поиск и замена)
  читает **HTML из файла** и не зависит от того, как текст был создан.

В расширении уже есть рабочая подсистема Markdown (`ГКСИ_РМ_РедакторMarkdown`), которая
строит панель «Редактирование / Просмотр», умеет превращать markdown в HTML (showdown)
и хранит вставленные файлы в `ГКСИ_ФайлыИнструкций`.

**Цель:** через расширение подменить форму элемента справочника `ДемонстрационныеСценарии`,
давая возможность редактировать текст описания в Markdown и хранить его в Markdown,
при этом **сохранив типовой HTML-вывод** (в типовой HTML-файл по-прежнему пишется HTML).

## 2. Принятые решения

| Вопрос | Решение |
|--------|---------|
| Где хранить markdown | Реквизит-расширение справочника `ТекстMarkdown` (неограниченная строка). Все языки — в одном реквизите с разделителями; в форме показывается только сегмент текущего языка. |
| Мультиязычность | Сохраняется (по `КодЯзыка`, как в типовом). |
| Точка входа | **Заимствование** типовой `ФормаЭлемента` справочника `ДемонстрационныеСценарии` (через `&Перед`/`&После`); типовая разметка и типовые реквизиты формы (`ОписанияСценария`, `ЯзыкСценария` и др.) сохраняются. Своя форма-подмена не создаётся. |
| Миграция старых описаний | Однократная конвертация существующего HTML → Markdown при первом открытии (showdown `htmlToMd`). |
| Роль в проекте | Доработка типового механизма ERP; собственная подсистема `ГКСИ_Инструкции` не дублируется (при желании позже устаревает). |
| Вывод | Остаётся типовым — HTML, который читают Альбом процессов / отчёт / поиск-замена. |

## 3. Формат хранения Markdown (разделители языков)

Один реквизит `ТекстMarkdown` хранит все языки. Пример:

```
<!--md:lang:ru-->
# Заголовок
Текст на русском

- пункт 1
<!--/md:lang:ru-->

<!--md:lang:en-->
# Title
English text
<!--/md:lang:en-->
```

- На форме из реквизита выделяется **только сегмент текущего `КодЯзыка`** (пользователь
  не видит теги), остальные языки скрыты.
- При сохранении сегмент текущего языка перезаписывается, затем реквизит собирается заново.
- Разделители выбраны в виде HTML-комментариев: они валидны в Markdown и не влияют на рендеринг.
- **Запасной вариант** (если набор языков фиксирован и мал): отдельный реквизит
  `ТекстMarkdown_<КодЯзыка>` на язык — проще (без парсинга). Отмечен как альтернатива;
  ниже основной сценарий рассчитан на единый реквизит с разделителями.

## 4. Изменения в расширении

### 4.1 Расширение справочника `ДемонстрационныеСценарии`

- `ТекстMarkdown` — Строка (неограниченная), `Использование: Для элемента`.
- `MarkdownСформирован` — Булево, по умолчанию `Ложь`. Признак того, что markdown уже
  инициализирован (защита от повторной миграции и отличие «ещё не мигрировано» от «пусто»).

### 4.2 Заимствование типовой формы `ФормаЭлемента`

Форма не копируется — расширение принимает (adopt) типовую `ФормаЭлемента` и
перехватывает её обработчики через `&Перед`/`&После`. Типовая разметка, статусы,
режимы «Просмотр / Редактирование / Перевод», переключатель языков, поиск/замена и
отчёт `ДемонстрационныеСценарииОбъекта` остаются как есть. Вместо HTML-редактора
через `&Перед("ПриСозданииНаСервере")` программно подключается подсистема
`ГКСИ_РМ_РедакторMarkdown` (по образцу `ГКСИ_ФункцияДействиеИнструкции`).

**Программно добавляемые реквизиты формы** (через `ИзменитьРеквизиты` в
`&Перед("ПриСозданииНаСервере")`):

- `ТекстMarkdownСтрока` — строка, привязка редактора markdown (текущий язык).
- `ФайлыBase64` — ТЗ: `Код` (Строка 36), `Base64` (Строка, data URI) — подмена `![](Код)`.

> Остальные служебные реквизиты (`ТекстПросмотр`, `РМ_ТаблицаПрисоединенныхФайлов_...`)
> и панель редактора создаёт сам `ГКСИ_MarkdownСерверВызовСервера.ВставитьПолеРедактированияТекстаНаФорму`.

**Заимствуемые из типовой формы реквизиты** (используются как есть):

- `ОписанияСценария` — ТЧ, совместимая с типовыми функциями; колонки:
  `КодЯзыка, Наименование, ТекстHTML, ДатаМодификации, Изменил, Редактируется,
  ДатаЗахвата, Редактирует, ЕстьИзмененияРедактирования, ПрисоединенныйФайл`.
- `ЯзыкСценария` — текущий язык редактирования.
- `ТекстСценария` — HTML текущего языка (нужен для миграции и для типовых обработчиков).

**Перехваты обработчиков:**

- `&Перед("ПриСозданииНаСервере")`:
  - добавить `ТекстMarkdownСтрока` и `ФайлыBase64`;
  - вызвать `ГКСИ_MarkdownСерверВызовСервера.ВставитьПолеРедактированияТекстаНаФорму`;
  - заполнить `ФайлыBase64` из `ГКСИ_ФайлыИнструкций`;
  - выставить текущий язык (язык сеанса, с проверкой по списку языков);
  - выделить сегмент markdown текущего языка из `Объект.ТекстMarkdown`.
- `&После("ПриЧтенииНаСервере")`: повторно установить сегмент markdown текущего языка.
- `&Перед("ТекстСценарияДокументСформирован")`: если `Не Объект.MarkdownСформирован` —
  запустить миграцию HTML → Markdown (§6).
- `&Перед("Подключаемый_ИзменитьЯзыкРедактирования")` и
  `&Перед("Подключаемый_ИзменитьЯзыкПросмотра")` — сохранить сегмент markdown текущего
  языка в `Объект.ТекстMarkdown`.
- `&После("Подключаемый_ИзменитьЯзыкРедактирования")` — установить новый сегмент
  markdown в `ТекстMarkdownСтрока`.
- `&Перед("УправлениеВидимостью")` — скрыть типовые кнопки внешнего HTML-редактирования
  (`ТекстСценарияРедактировать`, `ТекстСценарияЗакончитьРедактирование`,
  `ТекстСценарияОтменитьРедактирование`, `ТекстСценарияНайтиИЗаменить`) и стандартное
  поле `ТекстСценария` в режимах «Редактирование» / «Перевод».
- `ПередЗаписью` (клиент) — сформировать HTML текущего языка:
  - заменить коды файлов на base64 (`ГКСИ_MarkdownКлиент.ЗаменитьКодыФайловНаBase64`);
  - `ТекстHTML = ГКСИ_MarkdownКлиент.ТекстHTMLПоТекстуMarkdown(ПолеПросмотра, ТекстMarkdownСтрока)`;
  - обернуть в полный документ:
    `ДемонстрационныеСценарииКлиентСервер.ДобавитьТегиТелаЕслиНеобходимо(ТекстHTML)`;
  - записать в строку `ОписанияСценария` текущего языка (реквизит `ТекстHTML`)
    и пометить `ЕстьИзмененияРедактирования = Истина`;
  - собрать `Объект.ТекстMarkdown` из `ТекстMarkdownСтрока` текущего языка
    (`<!--md:lang:КОД-->...<!--/md:lang:КОД-->`); `Объект.MarkdownСформирован = Истина`.
- `&Перед("ПередЗаписьюНаСервере")`:
  - сохранить новые присоединённые файлы редактора (`ГКСИ_MarkdownСерверВызовСервера.ЗаписатьНовыеПрисоединенныеФайлы`);
  - сборка `Объект.ТекстMarkdown` уже выполнена на клиенте, дополнительных действий не требуется;
  - финальную запись HTML-файлов выполняет типовая логика после возврата управления.
- `РМ_Подключаемый_*` — делегирование в подсистему (как в `ГКСИ_ФункцияДействиеИнструкции`).

### 4.3 Хранение вставленных файлов (картинок)

Переиспользуется уже адаптированный `ГКСИ_MarkdownПереопределяемый` (сохранение в
`ГКСИ_ФайлыИнструкций`, подмена имени на код `![](Код)`). При генерации HTML для
типового файла коды заменяются на base64 — картинки встраиваются прямо в HTML,
поэтому типовой просмотр работает без доп. прав на справочник файлов.

## 5. Поток данных при сохранении

1. Markdown (сегмент текущего языка из редактора)
2. → подмена `![](Код)` на base64
3. → HTML-фрагмент (`ТекстHTMLПоТекстуMarkdown`, showdown)
4. → обёртка `ДобавитьТегиТелаЕслиНеобходимо` → полный HTML-документ
5. → запись в типовой файл (`ОписанияСценария.ТекстHTML`, стандартный механизм)
6. → сегмент markdown сохраняется в `Объект.ТекстMarkdown`

Типовой вывод (Альбом процессов, отчёт, поиск-замена) продолжает читать HTML из файла —
стандартное поведение сохраняется.

## 6. Миграция существующих описаний HTML → Markdown

При первом открытии элемента, где `ТекстMarkdown` пуст, HTML (из файла) непуст и
`Не MarkdownСформирован`:

- на клиенте через поле просмотра:
  `md = ГКСИ_MarkdownКлиент.ТекстMarkdownПоТекстуHTML(ЭлементПросмотра, ТекстHTML)`
  (showdown `htmlToMd`);
- положить в `ТекстMarkdownСтрока`; при записи — обычный сценарий (§4–§5).

**Ограничение:** `htmlToMd` приблизителен — сложная вёрстка (инлайн-стили, специфичные
HTML-конструкции) может конвертироваться неточно. После миграции рекомендуется выборочно
проверить описания. Для немигрированных объектов форма по-прежнему может открываться:
при пустом markdown показывать исходный HTML как есть (режим «только просмотр») либо
выполнить конвертацию.

## 7. Права и роли

- Заимствованная форма наследует права объекта `ДемонстрационныеСценарии`.
- Роль чтения не меняется: вывод HTML остаётся как в типовом.
- Редакторам выдать использование служебной подсистемы `ГКСИ_РМ_РедакторMarkdown`
  (по аналогии с правами на `ГКСИ_ФункцияДействиеИнструкции`).
- `ГКСИ_ФайлыИнструкций`: права на запись — редакторам; для просмотра не требуется
  (картинки встроены в HTML как base64). Права на чтение оставить по необходимости.

## 8. Этапы работ

1. Расширение справочника: реквизиты `ТекстMarkdown`, `MarkdownСформирован`.
2. Заимствование типовой `ФормаЭлемента` в расширение и подключение markdown-редактора
   через перехватчики `&Перед`/`&После` (по образцу `ГКСИ_ФункцияДействиеИнструкции`).
3. Логика выделения/сборки сегментов языков и переключение языка.
4. Генерация HTML при сохранении и запись типового файла + сохранение markdown.
5. Миграция HTML → markdown при первом открытии.
6. Настройка прав/ролей; тесты в тонком, толстом и веб-клиенте.
7. Обновление README.

## 9. Риски и ограничения

- Заимствование типовой формы срабатывает для всех, у кого есть право открытия элемента —
  меняет типовое поведение.
- `htmlToMd` при миграции может терять сложную вёрстку.
- Картинки из markdown хранятся отдельно (`ГКСИ_ФайлыИнструкций`) и встраиваются в HTML
  как base64 → рост размера HTML-файла.
- Единый реквизит с разделителями требует корректного парсинга; при фиксированном малом
  числе языков проще отдельные реквизиты на язык.
- Статический XML-дамп нельзя скомпилировать — проверка возможна только после загрузки
  расширения в Конфигуратор/EDT.

## 10. Открытые вопросы

- Дублировать ли вставленные картинки ещё и в типовую табличную часть
  `ИдентификаторыФайловСкриншотов` (чтобы они были видны в типовом списке файлов)?
  Пока — нет, используются base64-встраивания.
- Типовой «Поиск и замена» работает по HTML-файлу; поиск по markdown-реквизиту
  не добавляем (оставляем типовое поведение).
