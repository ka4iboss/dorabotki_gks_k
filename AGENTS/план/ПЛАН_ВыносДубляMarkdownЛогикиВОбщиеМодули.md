# ПЛАН: вынос дубля Markdown-логики из ФормаЭлемента/ФормаГруппы в общие модули

## Цель

В формах `ФормаЭлемента` и `ФормаГруппы` справочника `ДемонстрационныеСценарии`
(~250 строк) продублирована служебная логика работы с Markdown-редактором:
сегменты языков, заполнение `ФайлыBase64`, обработчики-делегаты `РМ_Подключаемый_*`,
кнопка-тумблер режима, клиентский `ПередЗаписью` через `УстановитьДействие`,
управление видимостью типовых кнопок внешнего HTML-редактора, миграция
HTML → Markdown, запись HTML-файлов из `ДополнительныеСвойства`.

Цель: вынести общую часть в общие модули
`ГКСИ_MarkdownФормаКлиент` + `ГКСИ_MarkdownФормаСервер`, чтобы
в формах остались только перехватчики `&Перед`/`&После`/`&Вместо` и
параметризация (например, «показывать ли поле `ШиринаКартинок`»).

## Контекст

- Расширение `пустая_для_гкс.ГКС_Инструкции`, версия 1.51.
- Подсистема `ГКСИ_РМ_РедакторMarkdown` остаётся как есть — это низкоуровневый
  программный построитель панели редактора (`ГКСИ_MarkdownСерверВызовСервера.ВставитьПолеРедактированияТекстаНаФорму`,
  `ГКСИ_MarkdownКлиент.ОбработкаКомандыПоляКомментария`, и т.д.).
- Новые модули `ГКСИ_MarkdownФормаКлиент` / `ГКСИ_MarkdownФормаСервер` —
  это слой **над** подсистемой `ГКСИ_РМ_РедакторMarkdown`, специфичный для форм сценариев
  (работа с ТЧ `ОписанияСценария`, присоединёнными HTML-файлами по языкам,
  переключатель режимов формы).
- Существующий модуль `ГКСИ_MarkdownСерверВызовСервера` (в тексте `ФормаЭлемента`) —
  общий модуль подсистемы `ГКСИ_MarkdownСерверВызовСервера` с постфиксом
  `ВызовСервера` (есть в `Configuration.mdo`). Его не путать с новым
  `ГКСИ_MarkdownФормаСервер`.

  `РМ_ПолучитьИсключаемыеГруппыНаСервере`.

## Архитектура

### Новые модули

1. **`ГКСИ_MarkdownФормаКлиент`** (тип: `Клиент`, `ВызовСервера`)
   - Экспортные процедуры/функции:
     - `УстановитьДействиеПередЗаписью(Форма)` — клиентская обёртка
       (на клиенте `УстановитьДействие` недоступен, вызов уходит на сервер).
     - `УстановитьСегментMarkdownВФорму(Форма, КодЯзыка)` (перенос из формы).
     - `СохранитьСегментMarkdownТекущегоЯзыка(Форма)`.
     - `ПолучитьСегментMarkdown(ПолныйТекст, КодЯзыка)`,
       `ЗаменитьСегментMarkdown(ПолныйТекст, КодЯзыка, НовыйСегмент)`,
       `ПолучитьКодыЯзыковИзMarkdown(ПолныйТекст)`.
     - `УправлениеВидимостьюMarkdown(Форма)`.
     - `ОбновитьЗаголовокТумблера(Форма)`.
     - `ВыполнитьМиграциюHTMLВMarkdown(Форма)` — клиентская логика через JS-поле.
     - `ЗаписатьHTMLИзMarkdown(Форма, Отказ, ПараметрыЗаписи)`.
   - Делегаты — **не** переносятся. Они обязаны быть в модуле формы (требование EDT
     и соглашение подсистемы `ГКСИ_РМ_РедакторMarkdown`).
   - Приватная функция `Делегаты()` не нужна.

2. **`ГКСИ_MarkdownФормаСервер`** (тип: `Сервер`, `ВнешнееСоединение`)
   - Экспортные процедуры/функции:
     - `ДобавитьПанельРедактора(Форма, Параметры)` — где `Параметры` это
       `Структура` с полями:
       - `ИмяСтраницыРедактор` (например, `"СтраницаВариантОтображенияРедактирование"`)
       - `ПоказыватьПолеШиринаКартинок` (`Булево`)
       - `ШиринаКартинокПоУмолчанию` (`Строка`)
       - `ПоказыватьПанельГлоссария` (`Булево`)
       - `ДополнительныеОбработчикиПриСозданииНаСервере` (`Массив` из `Структура`,
         опционально — для групповых расширений, например «добавить список шагов»)
     - `ЗаполнитьФайлыBase64(Форма)`.
     - `ДобавитьКнопкуТумблера(Форма)`.
     - `УстановитьДействиеПередЗаписью(Форма)` — серверная часть
       (`УстановитьДействие` на сервере для заимствованных форм работает).
     - `СобратьТекстMarkdown(Форма, ТекущийОбъект)`.
     - `СоздатьПрисоединенныеФайлыИзДопСвойств(Форма, ТекущийОбъект, ПараметрыЗаписи, Отказ)`.
     - `СоздатьПрисоединенныйФайлСценария(ВладелецФайла, Форма, ПолныйКод, КодЯзыка, ТекстHTML)`.
     - `ОбновитьОписанияПослеЗаписиНаСервере(Форма, ДополнительныеДействия)`.

3. **Делегаты `РМ_Подключаемый_*`** остаются в модулях форм
   (требование `ГКСИ_MarkdownСерверВызовСервера` — обработчики должны быть в форме).

### Изменения в формах

`ФормаЭлемента/Module.bsl` (после рефакторинга) — **только перехватчики**:

```1c
&Перед("ПриСозданииНаСервере")
&НаСервере
Процедура РМ_ПередПриСозданииНаСервере(Отказ, СтандартнаяОбработка)

    Если Отказ Тогда Возврат; КонецЕсли;

    ПараметрыПанели = Новый Структура;
    ПараметрыПанели.Вставить("ИмяСтраницыРедактор", "СтраницаВариантОтображенияРедактирование");
    ПараметрыПанели.Вставить("ПоказыватьПолеШиринаКартинок", Истина);
    ПараметрыПанели.Вставить("ПоказыватьПанельГлоссария", Истина);

    ГКСИ_MarkdownФормаСервер.ДобавитьПанельРедактора(ЭтотОбъект, ПараметрыПанели);
    ГКСИ_ГруппыСценариевСервер.ДобавитьПанельГруппСценария(ЭтотОбъект);
    ГКСИ_MarkdownФормаСервер.ЗаполнитьФайлыBase64(ЭтотОбъект);
    ГКСИ_ГруппыСценариевСервер.ЗаполнитьГруппыСценария(ЭтотОбъект);
    ГКСИ_MarkdownФормаКлиент.УстановитьСегментMarkdownВФорму(ЭтотОбъект, ЯзыкСценария);

КонецПроцедуры
```

И аналогично для `&После`, `&ПередЗаписью`, `&ПослеЗаписи`,
`&Перед("ТекстСценарияДокументСформирован")`,
`&Перед("Подключаемый_ИзменитьЯзыкРедактирования")` и т.д.

Глоссарий-специфика (`РМ_ДобавитьПанельГлоссария`,
`РМ_ОбновитьТаблицуГлоссария`, `РМ_ПриЧтенииНаСервереОбновитьГлоссарий`)
переносится в отдельный модуль `ГКСИ_ГлоссарийФормаСервер` —
это **вне** текущего плана, отдельная задача.

Список шагов группы (`РМ_ДобавитьКТекстуСписокШаговГруппыВместо`) остаётся в
`ФормаГруппы` — это узкая групповая логика, которая не переиспользуется.

## Этапы работ

1. Создать `CommonModule.ГКСИ_MarkdownФормаКлиент` (`Клиент`).
2. Создать `CommonModule.ГКСИ_MarkdownФормаСервер` (`Сервер`, `ВнешнееСоединение`).
3. Перенести чистые функции (без зависимости от контекста формы) в клиентский
   модуль: `ПолучитьСегментMarkdown`, `ЗаменитьСегментMarkdown`,
   `ПолучитьКодыЯзыковИзMarkdown`. Проверить `GetMarkers` — 0 ошибок.
4. Перенести серверные процедуры в `ГКСИ_MarkdownФормаСервер`:
   `ЗаполнитьФайлыBase64`, `СобратьТекстMarkdown`,
   `СоздатьПрисоединенныеФайлыИзДопСвойств`,
   `СоздатьПрисоединенныйФайлСценария`. Проверить маркеры.
5. Перенести `ДобавитьПанельРедактора` с параметризацией через `Структура`.
   В `ФормаЭлемента` оставить вызов с `ПоказыватьПолеШиринаКартинок = Истина`,
   в `ФормаГруппы` — без него.
6. Перенести клиентские обёртки (`УстановитьДействиеПередЗаписью`,
   `УстановитьСегментMarkdownВФорму`, `СохранитьСегментMarkdownТекущегоЯзыка`,
   `УправлениеВидимостьюMarkdown`, `ОбновитьЗаголовокТумблера`,
   `ВыполнитьМиграциюHTMLВMarkdown`, `ЗаписатьHTMLИзMarkdown`).
7. Перенести тумблер (`ДобавитьКнопкуТумблера` + `ОбновитьЗаголовокТумблера`).
8. Заменить все вызовы в обеих формах. Оставить делегаты `РМ_Подключаемый_*`
   на месте (требование подсистемы).
9. Удалить старые процедуры из обеих форм.
10. Прогнать `GetMarkers` по обеим формам: должно остаться 0 ошибок,
   количество warning'ов не должно вырасти.
11. Прогнать `mcp__syntax-checker__validate` на новых модулях.
12. Ручная проверка в 1С:Предприятии: открыть элемент сценария, изменить
   описание на русском, переключить язык, пересохранить; то же для группы
   (со списком шагов). Убедиться, что HTML пишется в присоединённый файл
   и отображается в режиме «Просмотр».
13. Обновить `AGENTS/описание/Описание.md` (§7 — Мультиязычность Markdown,
   добавить ссылку на новые модули в структуру перехватчиков).
14. Обновить `AGENTS/описание/Структура.md` (раздел общих модулей + карта файлов).
15. Обновить `AGENTS/состояние/ТODO.md` (закрыть пункт «дубль Markdown-логики»).
16. Поднять версию расширения: `1.51 → 1.6` (большая фича — рефакторинг архитектуры,
   округление вверх до ближайшего 0.1).

## Открытые вопросы

1. **Тумблер в `ФормаГруппы`.** Сейчас есть только в `ФормаЭлемента`.
   В рамках рефакторинга можно либо оставить как параметр `ПоказыватьТумблер`,
   либо добавить и в группу. Решение: оставить параметр, в группу не добавлять
   до явного запроса.
2. **Глоссарий.** Вынести в `ГКСИ_ГлоссарийФормаСервер` отдельной задачей.
3. **Кеш `ReturnValuesReuse`.** Новые общие модули — без кеша.
   Если потребуется — добавим позже (после профилирования).
4. **Имя `ГКСИ_MarkdownФормаКлиент` vs `ГКСИ_MarkdownФормаСервер`.**
   Альтернатива — `ГКСИ_ДемоСценарииФормаКлиент` / `…ФормаСервер`
   (по `ОТЧЁТ_МаркдаунВФормеГруппы.md` упоминался именно этот вариант).
   Решение: оставить `ГКСИ_MarkdownФорма*` — модули привязаны к подсистеме
   Markdown, а не к конкретному справочнику, что упрощает перенос в другие формы
   при необходимости.

## Что НЕ входит

- Перенос глоссария (`ГКСИ_ГлоссарийФормаСервер`).
- Изменение списка шагов группы.
- Переименование `РМ_*` → `ГКСИ_*` (этап 4 `ПЛАН_ИсправленияОшибокEDT.md`).
