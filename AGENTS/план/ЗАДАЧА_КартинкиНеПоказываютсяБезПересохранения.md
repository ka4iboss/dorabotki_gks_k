# ЗАДАЧА: картинки в HTML-описании сценария не показываются до пересохранения элемента

## Статус
**Решена в версии 1.49** (расширение `ГКС_Инструкции`).

## Суть

На форме элемента / формы группы справочника `ДемонстрационныеСценарии`
картинки в HTML-описании сценария не отображались сразу после загрузки
сценария из Markdown. После ручной перезаписи элемента картинки появлялись.

## Корневая причина

В `ГКСИ_ЗагрузкаСценариевИзMarkdown` подмена картинок в исходном тексте
перед конвертацией в HTML обрабатывала только Obsidian-синтаксис
`![[path]]`. Остальные варианты ссылок на картинки оставались «сырыми»:

- `![[path|size|caption]]` — Obsidian с дополнительными полями (текущая
  регулярка `!\[\[([^\]]+)\]\]` их захватывала, но карта подмен содержала
  ключ с `|size`, которого не было в исходном файле);
- `![alt](path)` — стандартный markdown (не обрабатывался вообще).

В результате `MarkdownВHTML` формировал `<img src="path">` с сырым путём
вместо GUID-а файла инструкции. `ЗаменитьКодыИзображенийНаDataURI` в
`ГКСИ_MarkdownПереопределяемый` ищет в `src` только GUID-ы по регулярке
`[0-9a-fA-F]{8}-...`, поэтому сырой путь не матчится — картинка
остаётся битой.

После ручной записи через форму элемента HTML прогоняется по другой
ветке (через `ДемонстрационныеСценарии.РезультатОбновленияПрисоединенногоФайла`
→ `ДемонстрационныеСценарии.ЗаписатьНовыеОписанияСценариевИзФормыОбъекта`),
которая дополнительно обрабатывает картинки — отсюда эффект «появляются
после пересохранения».

## Решение

Расширены три функции в
`src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`:

### 1. `УникальныеПутиКартинокИзТекста` (строка 350)

Собирает уникальные пути картинок из текста Markdown. Добавлен второй
regex для стандартного markdown `![alt](path)` и расширен первый для
Obsidian-варианта с `|...`:

- Obsidian: `!\[\[([^\]|]+)(?:\|[^\]]*)?\]\]` — захватывает чистый путь
  без `|...`;
- Markdown: `!\[[^\]]*\]\(([^)]+)\)` — захватывает URL.

### 2. `СобратьПутиКартинокИзУзла` (строка 901)

Рекурсивный обход дерева узлов и сбор путей картинок. Те же два regex,
что и в `УникальныеПутиКартинокИзТекста`.

### 3. `ПодменитьСсылкиНаКартинкиВТексте` (строка 961)

Подменяет ссылки на картинки по карте «путь → GUID». Полностью переписана:
вместо `СтрЗаменить` по каждому ключу карты — один проход двумя regex
(теми же, что выше), сбор массива замен `{Позиция, Длина, Текст}` и
применение с конца строки (чтобы не сбивать позиции остальных замен).
Если путь не нашёлся в карте — подменяется на `❌ <путь>` (визуальный
маркер, который виден пользователю).

Выделена общая процедура `ДобавитьЗаменыПоРегулярномуВыражению`, чтобы
не дублировать код обхода совпадений.

## Что получили

- Картинки показываются в HTML-описании сценария сразу после загрузки
  из Markdown, без необходимости заходить и перезаписывать элемент.
- Поддерживаются три варианта ссылок: `![[path]]`, `![[path|extra]]`,
  `![alt](path)`.
- Если файл картинки не найден на диске или его хеш не совпадает с
  существующим в справочнике — пользователь видит `❌ <путь>` вместо
  молчаливого broken image.
