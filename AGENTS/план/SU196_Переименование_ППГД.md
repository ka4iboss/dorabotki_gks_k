# SU196 — приведение имён расширения к единому префиксу `ППГД_`

**Решения пользователя (25.09.2026):** единый префикс — `ППГД_`; переименовываем всё
собственное, что должно быть с префиксом; делаем это **до** прогона обмена.
`namePrefix = ППГД_` уже задан в `src/Configuration/Configuration.mdo`.

## Главное про обмен (проверено по коду и `Package.xdto`)

Формат обмена **не содержит** имён собственных объектов расширения. В XML попадают только:
- namespace `http://rules` (`Package.xdto` → `targetNamespace`; строки в коде:
  `ППГД_ВыгрузкаЗагрузкаПрав/Forms/Форма/Module.bsl:252`,
  `ППГД_ВыгрузкаПрав/Forms/Форма/Module.bsl:207`; вызовы `ФабрикаXDTO.Тип("http://rules", …)`
  в `ППГД_ОбменДаннымиXDTOСервер/Module.bsl` — 20 мест);
- имена XDTO-типов и свойств (`Профиль`, `ГруппаДоступа`, `Роли`, `ЗначенияДоступа`, …);
- заголовок `<Message>` + `http://www.1c.ru/SSL/Exchange/Message`.

**Значит:** переименование метаданных (`ппд_*`, `ТБ_*`, `АКС_*`) и даже XDTO-пакета
`ППГД_ПраваДоступа` формат не меняет — код обращается к типам по namespace, а не по имени пакета.
**Не трогать:** `Package.xdto`, вызовы `ФабрикаXDTO.Тип("http://rules", …)`, заголовок сообщения.

## Риски и открытые решения

- **Роли-дубли:** `ППГД_ОсновнаяРоль` и `ППГД_ОсновнаяРоль` — обе собственные, обе без прав.
  Нужно решение: слить в одну или оставить две (`ППГД_ОсновнаяРоль` + `ППГД_ОсновнаяРольТБ`).
- **`ППГД_ПросмотрПрав`** — зарегистрирована как дополнительная обработка; идентификатор команды
  (`РолиДляДоступаКОбъектамМетаданных`) от имени не зависит, но если подключается внешним
  `.epf` — имя файла важно.
- **Реквизиты `Автор`, `ДатаСоздания`, `ДатаПоследнегоИзменения`** (собственные у adopted-объекта)
  — переименование меняет структуру хранимых данных расширения; в план не включены без
  отдельного решения.
- **Обработчики форм** `Расш1_*`, `Расш_ПГД*`, `пд_ПриСозданииНаСервереПосле`,
  `пд_ПередЗаписьюНаСервере` — по ранее зафиксированному решению (SU61) их не переименовывали:
  переименование требует пересоздания команд формы. План этапа 8 предлагает вариант —
  нужно подтверждение.
- **`ППГД_ППГД_ПолучитьТекстСтрокВыбранныхРолей`** (`ПрофилиГруппДоступа/Forms/ФормаЭлемента/Module.bsl:295,301,358`)
  — двойной префикс, чистая опечатка, можно править вне зависимости от остального.
- **Обмен:** обе базы должны обновляться синхронно (расширение одно и то же), иначе обмен между
  разными версиями сломается.

## Уточнения решений (25.09.2026, после инвентаризации)

   реквизиты адресуются путями к данным. `Расш_ПГД…` — штатный стиль EDT для реквизитов,
   добавленных расширением к заимствованному объекту. Переименование = правка всех `data_path`
   в `Form.form`, запросов динамических списков и кода (зона, где уже были потеряны колонки
   в форме `ППГД_ВыгрузкаЗагрузкаПрав`), плюс изменение структуры хранимых данных.
   ТЧ `пд_Объекты` (чужой префикс `пд_`) оставлена по той же причине.
   Реквизиты `Автор`, `ДатаСоздания`, `ДатаПоследнегоИзменения` — тем более не трогаем.

### Пакет 8 (обработчики формы) — отложен, требует отдельного захода

Разбор:
- `Расш1_MaxтекстДобавитьРолиПосле` / `Расш1_MaxтекстИсключитьРолиПосле` зарегистрированы **в модели формы** («Text in 1C model») и объявлены в `Module.bsl:5,12`.
- Аналогично связаны с моделью `Расш_ПГД*` и `пд_ПриСозданииНаСервереПосле` / `пд_ПередЗаписьюНаСервере`.
- **`SU196` на имена процедур модуля формы не срабатывает** — маркер проверяет только имена объектов метаданных. Значит пакет 8 — косметика (единообразие префикса), а не закрытие маркера.
- Порядок работ (безопасный): `inspectForm` (снять текущие привязки) → `addFormEventHandler` с новым именем → только после успеха `removeFormEventHandler` со старым → правка объявлений и вызовов в `Module.bsl`. При ошибке привязки команда формы теряется, поэтому делать только в отдельном заходе и с проверкой формы до/после.
- Безопасный подпункт, который можно сделать сразу: `ППГД_ППГД_ПолучитьТекстСтрокВыбранныхРолей` → `ППГД_ПолучитьТекстСтрокВыбранныхРолей` (`Module.bsl:295,301,358`) — если метод не связан с моделью формы.

**Вывод по инструменту:** `renameObject` в EDT переименовывает не только метаданные, но и все
обращения, включая строковые литералы с именем модуля. Поэтому в пакетах 2–7 достаточно
вызывать `renameObject` и проверять маркеры — отдельная правка строк нужна только там, где имя
попало в текст, не распознанный EDT (например, `ОткрытьФорму("Обработка.…")` — проверить).
