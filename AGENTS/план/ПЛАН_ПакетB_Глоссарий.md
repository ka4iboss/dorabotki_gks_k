# ПЛАН: Пакет B — расширение UX глоссария (версия 1.7)

**Версия расширения:** 1.7.
**Родительский план:** `AGENTS/план/ПЛАН_РазвитиеПодсистемВерсия17.md` §4.
**Статус:** всё к реализации.

## 1. Цель

Сделать работу с глоссарием (`Catalog.Глоссарий` из основной конфигурации, типовой) удобной прямо из контекста расширения: визуально отличать термины с описанием от «пустых», дать CRUD-команды прямо в форме выбора, поддержать синонимы.

## 2. Состав пакета

| Подпакет | Содержимое | Объём |
|----------|------------|-------|
| B1. Подсветка с учётом описания | Разделение CSS-классов `.gksi-term--has-desc` и `.gksi-term--no-desc`; tooltip только у терминов с описанием | средняя |
| B2. CRUD в форме выбора | Кнопки «Создать / Изменить / Удалить» в `ГКСИ_ВыборТерминаГлоссария`, инвалидация кеша `ГКСИ_ТерминыГлоссарияПовтИсп` | средняя |
| B3. Синонимы терминов | Новый регистр `ГКСИ_СинонимыГлоссария` (Измерение: `Термин`, Ресурс: `Синоним`); обогащение HTML и форма выбора учитывают синонимы | большая |

## 3. B1. Подсветка терминов с учётом наличия описания

### 3.1. Проблема

Сейчас в `ГКСИ_Глоссарий.ОбогатитьHTMLТерминами` все термины оборачиваются одинаковым `<span class="gksi-term" ...>`. Пользователь не различает «понятно без подсказки» и «надо посмотреть, что это».

### 3.2. Что сделать

1. Разделить CSS-классы:
   - `.gksi-term--has-desc` — описание есть, `cursor: help`, при наведении tooltip с описанием;
   - `.gksi-term--no-desc` — описания нет, тот же визуальный стиль, но без tooltip и более прозрачный (`opacity: 0.7`).
2. В `ОбогатитьHTMLТерминами` добавить параметр `ОписаниеЗаполнено` в термин (читается из `ТерминыДляАвтоподстановки`) и использовать его при формировании атрибутов `class` и `title`.
3. CSS-блок — в двух местах, где уже добавляется `.gksi-term` (Альбом процессов, скачиваемый файл инструкции) — дополнить новыми классами.

### 3.3. Файлы

- `src/CommonModules/ГКСИ_Глоссарий/Module.bsl` — `ОбогатитьHTMLТерминами`, `ТерминыДляАвтоподстановки`.
- `src/CommonModules/ГКСИ_АльбомПроцессов/Module.bsl` — добавить классы.
- `src/DataProcessors/ГКСИ_ФормированиеИнструкции/Forms/Форма/Module.bsl` — добавить классы.

## 4. B2. CRUD-команды в форме выбора термина

### 4.1. Проблема

В `ГКСИ_ВыборТерминаГлоссария` сейчас только выбор. Если термин нужно создать или изменить — пользователь идёт в типовой справочник `Catalog.Глоссарий` отдельно, потом возвращается.

### 4.2. Что сделать

1. В `Form.form` общей формы добавить командную панель с командами `Создать`, `Изменить`, `Удалить`, `Обновить` (`Видимость = Истина`).
2. В `Module.bsl` обработчики:
   - `Создать` → `ОткрытьФорму("Catalog.Глоссарий.ObjectForm", Новый Структура, ЭтотОбъект)` с `ОписаниеОповещения("ПослеСозданияТермина", ЭтотОбъект)`.
   - `Изменить` → `ОткрытьЗначение(Элементы.СписокТерминов.ТекущаяСтрока)`.
   - `Удалить` → `УдалитьОбъект()` с подтверждением.
3. После любого изменения — `Элементы.СписокТерминов.Обновить()` или перезагрузка через `ГКСИ_Глоссарий.ТерминыДляАвтоподстановки` с инвалидацией кеша `ГКСИ_ТерминыГлоссарияПовтИсп`.
4. В `ГКСИ_Глоссарий` добавить экспортную `ИнвалидироватьКеш()` (через `ПовторноИспользуемыеЗнания.ОчиститьКеш` или `ReturnValuesReuse`-инвалидацию).

### 4.3. Файлы

- `src/CommonForms/ГКСИ_ВыборТерминаГлоссария/Form.form` — командная панель.
- `src/CommonForms/ГКСИ_ВыборТерминаГлоссария/Module.bsl` — обработчики команд.
- `src/CommonModules/ГКСИ_Глоссарий/Module.bsl` — `ИнвалидироватьКеш`.

## 5. B3. Синонимы терминов

### 5.1. Проблема

Термин «НДС» в тексте должен подсвечиваться так же, как «Налог на добавленную стоимость». Сейчас в `ГКСИ_Глоссарий` хранится только наименование.

### 5.2. Что сделать

1. Поскольку `Catalog.Глоссарий` — типовой объект и нельзя менять основную конфигурацию, синонимы хранить **в регистре сведений** `ГКСИ_СинонимыГлоссария`:
   - Измерение: `Термин` (`СправочникСсылка.Глоссарий`);
   - Ресурс: `Синоним` (`Строка(150)`).
2. В `ГКСИ_Глоссарий.ТерминыДляАвтоподстановки` возвращать не только `Наименование`, но и `Синоним` отдельной колонкой. Сортировать по убыванию длины строки, чтобы избежать частичных пересечений.
3. В `ОбогатитьHTMLТерминами` принимать соответствие «синоним → термин» и обрабатывать обе строки одинаково (с приоритетом более длинной).
4. В общей форме выбора термина добавить колонку `Синонимы`.

### 5.3. Файлы

- Новый регистр `InformationRegister.ГКСИ_СинонимыГлоссария` (`src/InformationRegisters/ГКСИ_СинонимыГлоссария/ГКСИ_СинонимыГлоссария.mdo`).
- `src/CommonModules/ГКСИ_Глоссарий/Module.bsl` — `ТерминыДляАвтоподстановки`, `ОбогатитьHTMLТерминами`.
- `src/CommonForms/ГКСИ_ВыборТерминаГлоссария/Form.form` — колонка `Синонимы`.

## 6. Этапы работ

1. B3 (синонимы) — требует нового регистра и самый большой объём правок. Этап 1.
2. B1 (подсветка) — использует данные из B3. Этап 2.
3. B2 (CRUD) — независимо от B1/B3. Этап 3.
4. Документация — обновить `AGENTS/описание/Описание.md` §16 (Глоссарий).
5. Версия расширения — `1.6 → 1.7` (вместе с пакетом A).
