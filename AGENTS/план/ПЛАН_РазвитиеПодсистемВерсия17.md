## 3. Пакет A. Загрузка из Markdown — расширение возможностей

### A1. Обновление существующих сценариев (сейчас SHA-256 блокирует)

**Проблема.** Повторная загрузка того же `.md`-файла в сценарий, у которого в `ГКСИ_ТекстMarkdown` уже сохранён старый текст, не работает: дедупликация по SHA-256 картинок срабатывает и не обновляет сами файлы. В результате картинки новые добавляются, а Markdown — нет.

**Что сделать.**

1. В `ГКСИ_ЗагрузкаСценариевИзMarkdown.ЗаписатьДеревоВСправочник` разрешить действие «Обновить» не только по картинкам, но и по самому сценарию: перезаписать `ГКСИ_ТекстMarkdown`, пересоздать HTML-файлы по всем языкам, пересобрать связи в РС `ГКСИ_ГруппыСценариев`.
2. Добавить хеш-метаданные в сценарий: новый реквизит расширения `ГКСИ_ХешMarkdownЗагруженного` (`Строка(64)`, неогр.) — SHA-256 текста на момент последней успешной загрузки. В обработке загрузки сравнивать с эталоном и подсказывать пользователю: «Текст изменился — обновить?» (использовать как один из вариантов в `ФормаРазрешенияКонфликтов`).
3. Шаблон конфликта «обновление существующего» в форме `ФормаРазрешенияКонфликтов` расширить колонками `СтарыйХеш`, `НовыйХеш`, `ДатаПоследнейЗагрузки` (через `ПолучитьИзВременногоХранилища` + `Прочитать` или прямой запрос — что быстрее).

**Файлы:** `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`, `src/DataProcessors/ГКСИ_ЗагрузкаСценариевИзMarkdown/Forms/ФормаРазрешенияКонфликтов/Form.form`, `src/Catalogs/ДемонстрационныеСценарии/ДемонстрационныеСценарии.mdo` (реквизит), `src/Catalogs/ДемонстрационныеСценарии/ObjectModule.bsl`.

### A2. Валидация MIME при импорте картинок

**Проблема.** Картинки из Obsidian `![[path]]` сейчас записываются в `ГКСИ_ФайлыИнструкций` по расширению файла. Если по факту в файле `evil.exe`, переименованный в `evil.png`, расширение скажет «PNG», а MIME — `application/x-msdownload`. Сейчас эта проверка отсутствует.

**Что сделать.**

1. В `ГКСИ_ЗагрузкаСценариевИзMarkdown.ЗагрузитьФайлыКартинок` (или эквивалентный метод) перед записью прочитать первые 8 байт файла и определить MIME сигнатурно:
   - `89 50 4E 47` → `image/png`;
   - `FF D8 FF` → `image/jpeg`;
   - `47 49 46 38` → `image/gif`;
   - `42 4D` → `image/bmp`;
   - `3C 3F 78 6D 6C` или `3C 73 76 67` → `image/svg+xml`;
   - иное → отказ.
2. При несоответствии расширения и MIME — регистрировать как конфликт «Файл отклонён (MIME/расширение)» с тремя вариантами действий: «Принять как есть (с приведением расширения)», «Отклонить», «Открыть для просмотра». Если ни один конфликт не выбран — файл пропускается.
3. Логика валидации — отдельная экспортная функция `ГКСИ_ЗагрузкаСценариевИзMarkdown.MIMEПоСигнатуре(ДвоичныеДанные)`, чтобы можно было переиспользовать и в других местах.

**Файлы:** `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`.

### A3. Абсолютные пути и URL для картинок

**Проблема.** В `ПодменитьСсылкиНаКартинкиВТексте` обрабатываются только относительные пути. Если в `.md`-файле встретился `C:\Users\…\img.png` или `https://example.com/img.png`, обработка не подставит картинку.

**Что сделать.**

1. Расширить парсер ссылок в `ПодменитьСсылкиНаКартинкиВТексте` тремя дополнительными типами:
   - абсолютный путь Windows (`^[A-Za-z]:\\` или `^\\\\` для UNC);
   - URL (`^https?://`).
2. Для абсолютных путей — копировать файл во временное хранилище через `ПоместитьФайлыНаСерверАсинх` (вариант «диалог выбора каталога не нужен — путь уже известен»), затем `ПолучитьДвоичныеДанныеИзФайла` / `ПолучитьИзВременногоХранилища`.
3. Для URL — `HTTPСоединение.Получить(...)` с таймаутом 30 секунд, размер не более N мегабайт (константа `ГКСИ_ЗагрузкаСценариевИзMarkdown.МАКС_РАЗМЕР_ФАЙЛА_URL = 5 * 1024 * 1024`). При ошибке — конфликт «Не удалось загрузить URL», варианты: «Пропустить», «Открыть в браузере».
4. Поддержка `file://` (отдельно от Windows-пути) — по тому же алгоритму, что и абсолютный путь, только без префикса `file:///`.

**Файлы:** `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`, общий макет с дефолтным таймаутом (опционально).

### A4. Фильтрация по разделам при повторной загрузке

**Проблема.** Сейчас при загрузке берётся весь файл целиком; если нужно обновить только один раздел, приходится редактировать `.md`-файл руками.

**Что сделать.**

1. В форме `Форма` обработки добавить таблицу `ВыбранныеРазделы` (`ИмяРаздела`, `ГУИДУзлаФайла` или просто `ЗаголовокH1`, флажок `Включать`). Изначально таблица заполняется при парсинге всеми заголовками H1/H2 из файла; по умолчанию все флажки включены.
2. Перед записью в `ЗаписатьДеревоВСправочник` отфильтровать узлы по флажкам: если в `ДеревоУзлов` у узла ни один предок не отмечен — узел не пишется.
3. Передача в фон (`ДлительныеОперации.ВыполнитьВФоне`) — сериализованная структура `МассивЗаголовков` с флагами.

**Файлы:** `src/DataProcessors/ГКСИ_ЗагрузкаСценариевИзMarkdown/Forms/Форма/Form.form`, `src/DataProcessors/ГКСИ_ЗагрузкаСценариевИзMarkdown/Forms/Форма/Module.bsl`, `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`, `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdownДлительныеОперации/Module.bsl`.

## 4. Пакет B. Глоссарий — расширение UX

### B1. Подсветка терминов с учётом наличия описания

**Проблема.** Сейчас в `ГКСИ_Глоссарий.ОбогатитьHTMLТерминами` все термины оборачиваются одинаковым `<span class="gksi-term" ...>`. Пользователь не различает «понятно без подсказки» и «надо посмотреть, что это».

**Что сделать.**

1. Разделить CSS-классы:

2. В `ОбогатитьHTMLТерминами` добавить параметр `ОписаниеЗаполнено` в термин (читается из `ТерминыДляАвтоподстановки`) и использовать его при формировании атрибутов `class` и `title`.
3. CSS-блок — в двух местах, где уже добавляется `.gksi-term` (Альбом процессов, скачиваемый файл инструкции) — дополнить новыми классами.

**Файлы:** `src/CommonModules/ГКСИ_Глоссарий/Module.bsl`, `src/CommonModules/ГКСИ_АльбомПроцессов/Module.bsl`, `src/DataProcessors/ГКСИ_ФормированиеИнструкции/Forms/Форма/Module.bsl`.

### B2. CRUD-команды в форме выбора термина

**Проблема.** В `ГКСИ_ВыборТерминаГлоссария` сейчас есть только выбор. Если термин нужно создать или изменить — пользователь идёт в типовой справочник `Catalog.Глоссарий` отдельно, потом возвращается.

**Что сделать.**

1. В `Form.form` общей формы добавить командную панель с командами `Создать`, `Изменить`, `Удалить`, `Обновить` (`Видимость = Истина`).
2. В `Module.bsl` обработчики:

   - `Изменить` → `ОткрытьЗначение(Элементы.СписокТерминов.ТекущаяСтрока)`.

**Файлы:** `src/CommonForms/ГКСИ_ВыборТерминаГлоссария/Form.form`, `src/CommonForms/ГКСИ_ВыборТерминаГлоссария/Module.bsl`.

### B3. Синонимы терминов

**Проблема.** Термин «НДС» в тексте должен подсвечиваться так же, как «Налог на добавленную стоимость». Сейчас в `ГКСИ_Глоссарий` хранится только наименование.

**Что сделать.**

1. Поскольку `Catalog.Глоссарий` — типовой объект и нельзя менять основную конфигурацию, синонимы хранить **в регистре сведений** `ГКСИ_СинонимыГлоссария` (`Измерение: Термин` (`СправочникСсылка.Глоссарий`), `Ресурс: Синоним` (`Строка(150)`)).
2. В `ГКСИ_Глоссарий.ТерминыДляАвтоподстановки` возвращать не только `Наименование`, но и `Синоним` отдельной колонкой. Сортировать по убыванию длины строки (наименование и синонимы суммарно), чтобы избежать частичных пересечений.
3. В `ОбогатитьHTMLТерминами` принимать соответствие «синоним → термин» и обрабатывать обе строки одинаково (с приоритетом более длинной).
4. В общей форме выбора термина добавить колонку `Синонимы`.

**Файлы:** новый регистр `InformationRegister.ГКСИ_СинонимыГлоссария`, `src/CommonModules/ГКСИ_Глоссарий/Module.bsl`, `src/CommonForms/ГКСИ_ВыборТерминаГлоссария/Form.form`.

## 5. Пакет C. Открытые вопросы плана «Markdown для описаний процессов»

### C1. Картинки в `ИдентификаторыФайловСкриншотов`

**Решение — реализовать в версии 1.7.** Типовое поведение ERP предполагает, что в `ИдентификаторыФайловСкриншотов` (ТЧ элемента справочника `ДемонстрационныеСценарии`) собираются идентификаторы всех файлов, относящихся к сценарию. Сейчас расширение вставляет картинки только в HTML и в `ГКСИ_ФайлыИнструкций` (для base64), но не регистрирует их в типовой ТЧ.

**Что сделать.**

1. В `ГКСИ_MarkdownФормаСервер.СоздатьПрисоединенныеФайлыИзДопСвойств` (после успешного создания/обновления файла) дополнительно вызывать типовой механизм `ДемонстрационныеСценарии.ИдентификаторыФайловСкриншотов` — зарегистрировать `Файл.Ссылка` (или `Файл.УникальныйИдентификатор()` в зависимости от типовой реализации ТЧ).
2. Если типовой метод отсутствует в открытом виде — прочитать существующий `ДемонстрационныеСценарииПрисоединенныеФайлы` и проверить, какие файлы связаны со сценарием; добавить недостающие через `ДемонстрационныеСценарии.ЗаписатьФайлВСкриншоты` (если есть такой метод) или через прямой `СтрокаИдентификаторовФайловСкриншотов` (если это `Строка` с перечислением идентификаторов).
3. Сверить с фактическим поведением типовой конфигурации и зафиксировать контракт в `Описание.md` §7.9.

**Файлы:** `src/CommonModules/ГКСИ_MarkdownФормаСервер/Module.bsl`, `AGENTS/описание/Описание.md`.

### C2. Поиск/замена по Markdown

**Решение — зафиксировать ответ «не делаем».** Типовая команда «Поиск и замена» работает по HTML-файлу сценария. Добавлять альтернативный поиск по `ГКСИ_ТекстMarkdown` в этой версии нецелесообразно: (1) пользователь смотрит на HTML-результат, а не на исходник; (2) поиск по двум представлениям требует удвоенной логики в форме поиска. Если появятся требования от пользователей — оформим как отдельную задачу в 1.8+.

**Файлы:** фиксируется в `AGENTS/описание/Описание.md` §7.10.

## 6. Пакет D. Конфликты при загрузке — UX

### D1. Убрать отдельную кнопку «Проверить конфликты»

**Что сделать.**

1. В `Form.form` обработки `ГКСИ_ЗагрузкаСценариевИзMarkdown` команде `ПроверитьКонфликты` (`КнопкаПроверитьКонфликты`) установить `Видимость = Ложь`. Удалять команду нельзя — она нужна для обратной совместимости и для тестовых сценариев; оставляем её как сервисный метод, скрытый от пользователя.
2. Процедуру-обработчик `ПроверитьКонфликты` оставить в модуле формы как сервисную (поставить `@skip-warning module-unused-method`, чтобы EDT не ругался на «неиспользуемый метод» — она вызывается из `Загрузить` через внутреннюю функцию `ПроверитьКонфликтыВнутр()`).
3. Вынести логику проверки в серверную функцию `ПодготовитьДанныеДляФормыКонфликтов()` (она уже есть; оставить публичной, без изменений).

**Файлы:** `src/DataProcessors/ГКСИ_ЗагрузкаСценариевИзMarkdown/Forms/Форма/Form.form`, `src/DataProcessors/ГКСИ_ЗагрузкаСценариевИзMarkdown/Forms/Форма/Module.bsl`.

### D2. Проверка конфликтов вызывается автоматически при «Загрузить»

### D2. Передача данных в форму разрешения конфликтов (реализованный контракт)

**Что сделано.**

1. `ПодготовитьДанныеДляФормыКонфликтов()` возвращает `Структура{МассивКонфликтов, АдресМассиваКонфликтов, КоличествоКонфликтов}`. Массив структур сериализуется через `ПараметрыФормы` напрямую (поля примитивны + `CatalogRef`).
2. `ОткрытьФорму(..., ПараметрыФормы, ..., ОписаниеОповещения("ПослеВыбораДействияПоКонфликтам", ЭтотОбъект, ДопПараметры))`. `ДопПараметры` = `{МассивКонфликтов, АдресМассиваКонфликтов}` — передаётся в `ПоказатьВыборЭлемента`, чтобы обработчик `ПослеВыбораДействияПоКонфликтам` имел массив сразу на клиенте (для массовых действий) и мог передать его в форму разрешения (для индивидуального решения).
3. Для «Обновить все» / «Пропустить все» — `СформироватьРешенияПоВсемКонфликтам(МассивКонфликтов, Действие)` строит соответствие `{ИмяИзФайла -> {Действие, Ссылка}}` без обращения к ВХ. Этот же контракт возвращает форма разрешения и его же ждёт серверный `ОбработатьУзелРекурсивно`.
4. После формирования решений — сразу `ЗапуститьЗагрузкуСейчас()`.

**Почему не ВХ.** Первая попытка с привязкой адреса к `УникальныйИдентификатор` основной формы не сработала: у формы разрешения другой УИД, чтение по нему возвращало `Неопределено`, таблица оставалась пустой. Прямая передача массива структур снимает эту проблему и убирает BSL LS false positive SU254 на двухпараметровом `ПолучитьИзВременногоХранилища(Адрес, УИД)`.

**Адрес ВХ.** Сохранён в возвращаемой структуре и передаётся параметром `АдресМассиваКонфликтов` для обратной совместимости (старый код, открывающий форму разрешения напрямую). Чтение в форме разрешения — фолбэк через `ПолучитьИзВременногоХранилища(Адрес)` без второго параметра.

**Файлы:** `src/DataProcessors/ГКСИ_ЗагрузкаСценариевИзMarkdown/Forms/Форма/Module.bsl`.

### D3. Форма `ФормаРазрешенияКонфликтов` теперь сама заполняется данными (реализовано)

**Что сделано.**

1. `ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)`:
   - Сначала читает прямой параметр `МассивКонфликтов` через `Параметры.Свойство("МассивКонфликтов", ...)`.
   - Если его нет — фолбэк: читает `АдресМассиваКонфликтов` из ВХ.
   - Если оба пусты — пишет предупреждение в ЖР с событием `ГКСИ.ЗагрузкаСценариевИзMarkdown.ПроверкаКонфликтов` и оставляет таблицу пустой.
2. `ЗаполнитьТаблицуКонфликтов(МассивКонфликтов)` — копирует поля структур (`ИмяИзФайла`, `СуществующаяСсылка`, `СуществующееЭтоГруппа`) в таблицу формы `Конфликты` через `ЗаполнитьЗначенияСвойств`.
3. Колонка «Решение» заполняется значением по умолчанию `«Пропустить»`; список выбора — «Пропустить», «Обновить», «Дублировать» (настраивается в `НастроитьКолонкуРешения`).
4. Форма не делает собственных запросов к БД.

**Файлы:** `src/DataProcessors/ГКСИ_ЗагрузкаСценариевИзMarkdown/Forms/ФормаРазрешенияКонфликтов/Module.bsl`.

## 7. Общие архитектурные решения

1. **Кеш глоссария** — расширяется не как `ПовторноИспользуемыеЗнания`, а через инвалидацию ключа в `ГКСИ_ТерминыГлоссарияПовтИсп`. После CRUD-операций из формы выбора термина форма вызывает `ГКСИ_Глоссарий.ИнвалидироватьКеш()` (новая экспортная процедура), которая сбрасывает `ReturnValuesReuse`-кеш.
2. **Хеш Markdown** — `ГКСИ_ХешMarkdownЗагруженного` хранится **только в расширении** (реквизит справочника `objectBelonging: Adopted`), не в основной конфигурации. Это не нарушает правила «не менять основную конфигурацию».
3. **Канал передачи URL** — добавить общий модуль `ГКСИ_HTTPКлиент` (или пополнить существующий) с настройками таймаута и лимита размера. Использовать типовой `HTTPСоединение` платформы, без внешних компонент.
4. **Контракт «ФормаРазрешенияКонфликтов»** — после D3 форма становится «тупым отображением» переданного массива конфликтов и не делает собственных запросов. Это упрощает тестирование и позволяет вызывать её из других мест (например, из обработки группового обновления, если такая появится).
5. **Конфликт-флаги** — в `ПодготовитьДанныеДляФормыКонфликтов` добавить поле `ЭтоОбновление` (`Булево`), чтобы форма могла отображать «обновление существующего» как особый класс конфликта со своим набором вариантов (Обновить/Пропустить/Дублировать).

## 9. Критерии готовности

- [ ] Команда `ПроверитьКонфликты` скрыта; поток «Загрузить» сам вызывает проверку и диалог.
- [ ] Форма `ФормаРазрешенияКонфликтов` принимает массив конфликтов через адрес ВХ и сама строит таблицу.
- [ ] Картинки регистрируются в типовой ТЧ `ИдентификаторыФайловСкриншотов`.
- [ ] MIME-сигнатуры валидируются перед записью картинок; конфликт «Файл отклонён (MIME/расширение)» попадает в общий список.
- [ ] Поддержаны абсолютные пути Windows/UNC и http(s)-URL для картинок; размер URL-картинки ≤ 5 МБ; при ошибке — конфликт «Не удалось загрузить URL».
- [ ] В форме загрузки есть таблица выбора разделов; по умолчанию все разделы включены; загрузка идёт только по выбранным.
- [ ] Термины глоссария с описанием и без визуально различимы в альбоме и инструкции; стили `.gksi-term--has-desc` и `.gksi-term--no-desc` работают.
- [ ] Из формы выбора термина работают команды «Создать / Изменить / Удалить» через `Catalog.Глоссарий`; кеш терминов инвалидируется.
- [ ] Реализован регистр `ГКСИ_СинонимыГлоссария`; обогащение HTML учитывает синонимы; форма выбора термина показывает колонку синонимов.
- [ ] `GetMarkers` по всем изменённым файлам — 0 ошибок `severity: error`.
- [ ] Документация обновлена (Описание.md §7.9, §7.10; новый отчёт).

## 10. Открытые вопросы

1. **Где хранить синонимы глоссария.** План предлагает свой регистр сведений. Альтернативы:
   - Через дополнительные реквизиты (БСП) — медленнее фильтровать, нет типизации.
   - Через табличную часть расширения — проще, но требует заимствования справочника.
   Решение: регистр (принято).
2. **Куда деть старые конфликты при повторной загрузке.** Если в форме уже есть таблица `Конфликты` от прошлой попытки, нужно ли её чистить при новом парсинге? План предлагает чистить (через `Очистить()` перед заполнением).
3. **Объединение с A4 (фильтрация по разделам).** Если выбраны не все разделы, нужно ли обновить уже записанные? По умолчанию — нет (только то, что в файле и выбрано). Раздел, отсутствующий в файле, не трогается.

## 11. Что НЕ входит

- Полная переработка парсера Markdown (см. `ПодменитьСсылкиНаКартинкиВТексте`) — только точечные расширения.
- Изменение типовой конфигурации — всё только в расширении.
- Поддержка глоссария в формах других справочников (только `ДемонстрационныеСценарии`).
- Локализация синонимов (только русский — язык сценариев сейчас только `ru`; расширение для других языков — отдельная задача).
