# Рецепт: нестабильность правки файлов и поиска в текущей сборке

> **Перенесён из расширения `пустая_для_гкс.РасширениеПраваИПрофилиГруппДоступа` в объединённое расширение `Доработки_ГКС_К`. Имена объектов приведены к фактическим (РМ_ → ГКСИ_, ТБ_/ппд_/пд_ → ППГД_).**

## Симптом

Инструмент правки файла отвечает «обновлено» на **каждую** правку, но до файла
доходит примерно **одна правка из пачки**. При пачке из 11 правок применилась 1,
из 3 — тоже 1. Это не откат буфером редактора: вкладка файла может быть закрыта,
поведение сохраняется.

Дополнительно: поиск по тексту отдаёт **устаревший индекс**. Сразу после правок
запрос `ППГД_` по модулю вернул 1 вхождение, хотя их заведомо больше; повторный
запрос по конкретному имени вернул корректные 4 вхождения. Индекс догоняет с
задержкой.

## Как работать

1. **Не полагаться на ответ инструмента.** «Обновлено» не означает, что правка в файле.
2. **Надёжный сигнал — счётчик маркеров.** После каждой правки (или небольшой пачки)
   запрашивать маркеры и смотреть `total_markers`. Если счётчик не сдвинулся —
   правка не дошла, повторить.
3. **Поиск использовать только как вспомогательный сигнал**, с поправкой на задержку
   индекса: при подозрительно малом результате повторить запрос.
4. **Правки, которые нельзя применять повторно, проверять чтением файла**, а не
   повторным применением (см. ниже).

## Ловушка: повторное применение замены не идемпотентно

Если переименование делать заменой по всем вхождениям (`replace_all`), то
**повторное** применение той же замены наслаивает результат:

```
ТекстОставшихсяОтложенныхРолей
  -> ППГД_ТекстОставшихсяОтложенныхРолей        (первое применение)
  -> ППГД_ППГД_ТекстОставшихсяОтложенныхРолей   (повторное применение!)
```

Повторная замена находит исходное имя как **подстроку** уже переименованного и
дописывает префикс ещё раз.

**Правило:** способ «повторить правку, чтобы понять, применилась ли она» — небезопасен.
Проверять состояние нужно **чтением файла** (или маркерами), а повторное применение
делать только после явного подтверждения, что старое имя в файле ещё есть.

## Что безопасно

Переименование «имя + все вызовы» одной операцией `replace_all` **атомарно**: либо
переименованы и определение, и все вызовы, либо ничего. Поэтому при потерянной правке
модуль не ломается — метод остаётся целым. Это подтверждено на практике.

## Рекомендация

При массовых однотипных правках (переименования, обёртывание в области) работать
малыми порциями по 1–3 правки с проверкой счётчика маркеров после каждой порции.
О нестабильности сообщить в поддержку: `ailab@1c.ru`.
