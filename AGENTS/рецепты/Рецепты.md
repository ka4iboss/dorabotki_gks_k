# Рецепты

Переиспользуемые приёмы: что делаем → как делаем. Без привязки к конкретным справочникам/реквизитам — применимо в любом месте.

> **Документ объединяет приёмы двух исходных расширений (`пустая_для_гкс.ГКС_Инструкции` и `пустая_для_гкс.РасширениеПраваИПрофилиГруппДоступа`), перенесённые в объединённое расширение `Доработки_ГКС_К`. Имена объектов приведены к фактическим (РМ_ → ГКСИ_, ТБ_/ппд_/пд_ → ППГД_).**

## Глоссарий

**Индекс картинки в 1С** — целое число (от 0), определяющее, какую именно картинку из общей картинки-коллекции показать в строке таблицы/дерева или в поле `PictureField`. Задаётся в числовом поле строки, привязанном к таблице через свойство `rowPictureDataPath` (или напрямую в свойстве `valuesPicture` колонки).

**Общая картинка-коллекция** — общая картинка (`CommonPicture`) с заполненным `Picture.zip`. Внутри архива — `manifest.xml` и набор png-файлов (по одному на каждый индекс). Каждый png может дополнительно иметь варианты для разных плотностей экрана (`85.png`, `100.png` и т.д.), но индекс привязан к смещению внутри одной картинки. Лента-спрайт с пиксельным расчётом смещения **используется**.

**`rowsPicture`** — свойство таблицы формы (XML-форма: `<rowsPicture>`). Ссылка на общую картинку-коллекцию, которая используется как иконка для всех строк таблицы. Применяется совместно с `rowPictureDataPath`.

**`rowPictureDataPath`** — свойство таблицы формы (XML-форма: `<rowPictureDataPath>`). Путь к числовому реквизиту строки, значение которого = индекс картинки из `rowsPicture`.

**`PictureField`** — колонка таблицы формы (`FormFieldType.PictureField`). Имеет свойство `valuesPicture` (ссылка на общую картинку) и `dataPath` (путь к числовому полю). Альтернатива `rowsPicture`, когда иконка нужна только в одной колонке.

**Перехватчики `&Перед`/`&После`** — аннотации в модуле формы расширения. Позволяют дополнить типовой обработчик формы своим кодом **до** или **после** него, не перекрывая сам обработчик. Сигнатура параметров должна совпадать с типовой.

**Граф в `ПовторноИспользуемыеЗначения`** — кешированная структура (`Соответствие`/`Map`) вида «узел → связанные узлы», сохранённая через `ПовторноИспользуемыеЗнания.Получить/Установить` с уникальным ключом (например, версией данных). Читается многократно без повторных запросов; автоматически сбрасывается при изменении ключа.

**`УстановитьДействие`** — метод управляемой формы, позволяющий программно привязать обработчик к событию, для которого нет стандартной аннотации расширения (например, клиентский `ПередЗаписью`, если его нет в типовой форме и `&Перед` не срабатывает).

**Сирота** — запись справочника, не упомянутая в регистре связей «многие ко многим». В дереве отображается как корневой узел, чтобы не терялась из интерфейса.

**Параметр формы `ВыборГруппИЭлементов`** — значение `ИспользованиеГруппИЭлементов.Группы` / `Элементы` / `ГруппыИЭлементы`. Передаётся в `Параметры` при `ОткрытьФорму("Catalog.Имя.ФормаВыбора", ...)`, чтобы ограничить тип выбираемых объектов только группами (или только элементами).

**`@skip-warning`** — аннотация-комментарий перед процедурой/переменной, подавляющая предупреждения линтера EDT (например, SU44 «неиспользуемый метод» для обработчика-делегата, который вызывается платформой по имени).

**SU73** — код линтера EDT «Более трёх параметров в конструкторе Структура». Обходится через `Кэш = Новый Структура; Кэш.Вставить("К1", …); Кэш.Вставить("К2", …); ...`.

**SU44** — код линтера EDT «Неиспользуемый метод». Для обработчиков-делегатов, привязанных через XML или `УстановитьДействие`, лечится `@skip-warning`. Для реально лишних методов — удалить.

**SU93** — код линтера EDT «Стандартные обработчики формы вне области "ОбработчикиСобытийФормы"». Часто ложное срабатывание после динамических правок.

## Формы и элементы

### Вывести разную картинку в строке таблицы/дерева в зависимости от состояния
У самой таблицы задать свойство **`rowsPicture`** со ссылкой на общую картинку-коллекцию и **`rowPictureDataPath`** с путём к числовому полю строки. В это числовое поле в коде писать индекс нужной иконки. Коллекция должна быть подготовлена как одна PNG-картинка — горизонтальная лента иконок одинакового размера (например, 16×16), с указанными в свойствах картинки шириной и высотой одной иконки. Индекс `N` = `N`-я иконка слева в ленте.

### Отобразить иконку в одной конкретной колонке
Добавить колонку типа **`PictureField`** с `valuesPicture` (ссылка на общую картинку). Числовое значение поля строки = индекс картинки.

### Добавить логику в типовой обработчик формы без его замены
В модуле формы расширения использовать аннотации **`&Перед("ИмяОбработчика")`** или **`&После(...)`** перед процедурой. Платформа вызовет твой код до/после типового обработчика с теми же параметрами. Имя обработчика должно совпадать с типовым.

### Повесить клиентский обработчик на событие, для которого нет аннотации
В серверной части формы вызвать **`УстановитьДействие("ИмяСобытия", "ИмяПроцедуры")`** — например, для клиентского `ПередЗаписью`, которого нет в типовой форме и `&Перед` не срабатывает.

### Создать реквизит и элемент формы программно (без правки Form.form)
1. Добавить реквизит: `МассивРеквизитов.Добавить(Новый РеквизитФормы(...))` → `ИзменитьРеквизиты(МассивРеквизитов)`.
2. Добавить элемент: `Элемент = Элементы.Добавить(Имя, ТипЭлемента, Родитель)`.
3. Привязать к данным: `Элемент.ПутьКДанным = "ИмяРеквизита"`.

### Применить условное оформление из кода
В `ПриСозданииНаСервере`: `ЭлементУсловногоОформления = УсловноеОформление.Элементы.Добавить()` → задать отбор (`ЭлементУсловногоОформления.Отбор.Элементы.Добавить(...)`) и оформление (`УстановитьЗначениеПараметра("ЦветТекста", Значение)`).

### Сделать форму «только для просмотра», не теряя обработчики
1. На форму и таблицу — `<readOnly>true</readOnly>` (запрещает правку ячеек).
2. Кнопки (`Создать`, `СоздатьГруппу`, `Обновить`, `ПометитьНаУдаление`) — добавить в `autoCommandBar` таблицы или формы, привязать к командам формы (`<formCommands>`).
3. Обработчик `Selection` на таблице — даёт открытие по двойному клику.

### Добавить кнопки в командную панель уже декларированной в Form.form таблице
Когда таблица целиком описана в `Form.form` (колонки, поиск, состояние просмотра, автокомандная панель), а кнопки нужно добавить динамически — **родителем кнопки делается родительская группа таблицы, а не сама таблица**: `Элементы.Добавить(Имя, Тип("КнопкаФормы"), ТаблицаФормы.Родитель)` падает с «Недопустимое значение параметров», потому что платформа не разрешает делать дочерним элементом `Table` объект типа `Button` — кнопки в иерархии элементов формы могут лежать только в `FormGroup`. Кнопки появятся **над таблицей**, рядом с ней.

```bsl
ТаблицаФормы = Элементы.Найти("ГКСИ_ГруппыСценария");
Если ТаблицаФормы = Неопределено Тогда Возврат; КонецЕсли;
РодительскаяГруппа = ТаблицаФормы.Родитель;
Если РодительскаяГруппа = Неопределено Тогда
    РодительскаяГруппа = ТаблицаФормы;
КонецЕсли;

Кнопка = Элементы.Добавить("ГКСИ_ДобавитьГруппу", Тип("КнопкаФормы"), РодительскаяГруппа);
Кнопка.ИмяКоманды = "ГКСИ_ДобавитьГруппу";
```

Если же таблица и кнопки создаются **обе программно** внутри одной `ГруппаФормы` — кнопки добавляются прямо в эту группу, а таблица — соседним элементом. Именно так сделано в `ФормаЭлемента` (см. `src/Catalogs/ДемонстрационныеСценарии/Forms/ФормаЭлемента/Module.bsl:747–769`).

### Открыть форму выбора только групп с отбором по иерархии
```bsl
ПараметрыФормы = Новый Структура;
ПараметрыФормы.Вставить("ВыборГруппИЭлементов", ИспользованиеГруппИЭлементов.Группы);
ПараметрыФормы.Вставить("Отбор", Новый Структура("ЭтоГруппа", Истина));
ОткрытьФорму("Catalog.ИмяСправочника.ФормаВыбора",
    ПараметрыФормы, ЭтотОбъект, , , ,
    Новый ОписаниеОповещения("ЗавершениеВыбора", ЭтотОбъект));
```

Чтобы исключить саму редактируемую группу и её потомков — используйте собственную форму выбора (`Catalog.Имя.Form.ГКСИ_ФормаВыбораГруппы`) с динамическим списком и отбором `Ссылка НЕ В (&ИсключаемыеГруппы)`, заполняемым в `ПриСозданииНаСервере`.

### Подавить SU30 «Пропущено определение параметра» на обработчике оповещения
Линтер EDT не разбирает содержимое строкового литерала `ОписаниеОповещения(...)` и ошибочно сообщает, что у параметров `РезультатВыбора`/`ДополнительныеПараметры` нет типа. Это **известная ложь**, лечить не нужно — рабочий код. Маркер исчезает после полного пересчёта проекта в EDT (`Project → Clean → Full Build`).

### Выбрать родителя для программно добавляемой кнопки в форме расширения
Когда добавляешь кнопку программно (`Элементы.Добавить(Имя, Тип("КнопкаФормы"), Родитель)`), **родитель должен быть видим во всех режимах отображения формы** (Просмотр, Редактирование, Перевод). Типовой `УправлениеВидимостью` в формах 1С:ERP может жёстко ставить `Видимость = Ложь` для редакторских групп (`ГруппаРедактирование`, `ГруппаКомментарийРодитель` и т. п.) — и любая программная кнопка внутри такой группы наследует `Видимость = Ложь` и пропадает в режиме просмотра.

**Безопасный родитель для тумблера/команды, видимой в обоих режимах — корень формы:**
```bsl
НоваяКнопка = Форма.Элементы.Добавить(ИмяКнопки, Тип("КнопкаФормы"), Форма);
НоваяКнопка.ИмяКоманды = ИмяКнопки;
НоваяКнопка.Видимость = Истина;
```

Перед выбором кандидата проверить **всю иерархию родителей вверх до корня**: если любой из них переключается в `Видимость = Ложь` в нужном режиме — родитель не подходит. Подробности и корневая причина — в памяти: `form_extension_program_button_visibility`.

### Вызвать неэкспортный типовой метод формы из общего модуля расширения
В расширении нельзя вызвать **неэкспортный типовой метод формы** напрямую из общего модуля (`УстановитьВариантПросмотр(Команда)` и т.п.). Никакие `Выполнить` / `Вычислить` / `ОписаниеОповещения` от имени модуля формы не работают на 8.3.27: компилятор EDT SU226/SU59 + рантайм «Не найден экспортируемый метод».

**Рабочий паттерн** (применим к любому приватному обработчику — `УстановитьВариантПросмотр`, `УстановитьВариантРедактирование`, `УстановитьВариантПеревод`, `Подключаемый_ИзменитьЯзыкРедактирования` и т.д.):

1. В **модуле формы расширения** добавить пустую процедуру с `&После("ИмяТиповогоМетода")` — это закрепляет имя типового метода в области видимости расширения:
   ```bsl
   &После("УстановитьВариантПросмотр")
   &НаКлиенте
   Процедура ГКСИ_ПослеУстановитьВариантПросмотр(Команда)
       // пустое — нужно только для заимствования имени
   КонецПроцедуры
   ```

2. Рядом — **экспортная обёртка**, которая вызывает типовой метод напрямую (он теперь «виден»):
   ```bsl
   &НаКлиенте
   Процедура ГКСИ_УстановитьВариантПросмотр(Команда) Экспорт
       УстановитьВариантПросмотр(Команда);
   КонецПроцедуры
   ```

3. Из **общего модуля** — вызывать экспортную обёртку:
   ```bsl
   Форма.ГКСИ_УстановитьВариантПросмотр(Команда);
   ```

Аннотация `&После` с пустым телом не дублирует типовой вызов (он идёт своим ходом), она лишь закрепляет имя в области видимости. `&Вместо` использовать нельзя — она подменяет типовой метод. Подробности и список неудачных вариантов — в памяти: `form_extension_call_nonexported_typical`.

## Расширения

### Добавить реквизит в заимствованный справочник
В `.mdo` заимствованного объекта добавить `<attributes>` с `objectBelonging: Adopted`, `extendedConfigurationObject: Checked`. Тип — внутри `<typeExtension><types>`. В коде проверять наличие через `Метаданные.Справочники.Имя.Реквизиты.Найти("Имя")`.

### Заимствовать объект в расширение (пометить, не изменяя)
Создать в расширении `.mdo` с тем же именем, `objectBelonging: Adopted`, `extendedConfigurationObject: Checked` (только контроль), `objectModule: Custom`/`Extended` — по факту использования.

### Отредактировать файл `.form`/`Module.bsl`, когда Edit через BM падает
Использовать JShell + `IFile.getContents()` (UTF-8) + `String.indexOf`/`substring` для точечной правки + `IFile.setContents(new ByteArrayInputStream(bytes), IFile.FORCE, null)`.

### Дополнить текст запроса по условию (для отсутствующего реквизита)
1. Перед текстом запроса проверить метаданные: `Метаданные.Справочники.Имя.Реквизиты.Найти("Имя") <> Неопределено`.
2. Собрать строку полей запроса через конкатенацию (не использовать `Структура(>3 ключей)` — лимитер SU73).
3. В цикле выборки защититься через `Если Кэш.Свойство("ИмяПоля") Тогда ...`.

## Запросы и кеши

### Защитить текст запроса от висячей запятой при условной сборке полей
Собирать поля порциями с переносами строк внутри многострочной строки, добавлять запятую **перед** следующим блоком, а не **после** предыдущего. Иначе при пустом блоке в запросе остаётся `,...` → синтаксическая ошибка `ИЗ`.

### Получить быстрый доступ к иерархии без повторных запросов
Один раз построить граф в `Соответствие` (`Узел → Дочерние`, `Узел → Родители`) и сохранить в `ПовторноИспользуемыеЗначения`. Ключ — версия данных. Инвалидировать при любой записи в источник (например, `ПовторноИспользуемыеЗначения.Установить(...)` сбрасывается автоматически по ключу).

### Безопасно читать поле структуры, которое может отсутствовать
`Если Структура.Свойство("ИмяКлюча") Тогда Значение = Структура.ИмяКлюча; КонецЕсли;` — иначе будет `Поле объекта не обнаружено`.

### Избежать лимитера SU73 на количество ключей в `Новый Структура(…)`
Не использовать конструктор с >3 ключами. Вместо этого — собирать структуру через `Кэш = Новый Структура; Кэш.Вставить("Ключ1", …); Кэш.Вставить("Ключ2", …)`.

## Длительные операции (БСП)

### Контракт параметров `ДлительныеОперации.ВыполнитьВФоне`

Переданное значение `ПараметрыВызова` приходит **первым фактическим аргументом** в фоновый метод, не в массиве. Никакой промежуточный массив на клиенте делать не нужно.

Серверная сторона (общий модуль длительных операций):

```bsl
Процедура МояФоноваяПроцедура(ПараметрыЗадания, АдресРезультата) Экспорт
    // ПараметрыЗадания - то, что передал клиент.
    // АдресРезультата - служебный адрес от БСП, обязателен по контракту.
КонецПроцедуры
```

Клиентская сторона — передавать напрямую:

```bsl
ДанныеФоновогоЗадания = ДлительныеОперации.ВыполнитьВФоне(
    "ОбщийМодуль.МояФоноваяПроцедура",
    СтруктураПараметров,
    ПараметрыВыполнения);
```

**Почему именно так.** БСП внутри `ДлительныеОперации.Модуль` делает `ПараметрыЭкспортнойПроцедуры.Добавить(ПараметрыПроцедуры)` и далее рендерит вызов как `ИмяМетода(Параметры[0], Параметры[1])` через `Выполнить(...)`. Поэтому:

- если передать `Новый Структура(...)` — фон получит `Структура` как первый аргумент, `ПолучитьИзВременногоХранилища(Структура)` упадёт с «Неправильный путь к файлу Структура»;
- если передать `Новый Массив(...)` — упадёт с «Неправильный путь к файлу Массив» (та же ошибка).

**Что передавать.** Если нужно передать несколько значений — пакуйте их в одну `Структуру`, не делайте массив. Диагностический стек с упоминанием `Метод(Параметры[0],Параметры[1])` означает, что БСП разворачивает массив и подставляет поэлементно — это нормальное поведение, но тогда `ПараметрыВызова` и должен быть одиночным значением, а не массивом.

### Передать в фон ссылку или простой объект

Любой сериализуемый тип — `Структура`, `Соответствие`, примитив, `СправочникСсылка`, `ДокументСсылка`. Ссылочные типы передаются **по ссылке** (без сериализации в строку), но фон получит их как обычные значения — повторное обращение к БД делать не нужно.

### Прогресс и опрос результата из клиента

Для длительных операций (>5 секунд) — показывать прогресс через `ДлительныеОперацииКлиент.ОжидатьЗавершение` с `ОповещениеОЗавершении`, в обработчике оповещения прочитать результат из `ДанныеФоновогоЗадания.АдресРезультата` через `ПолучитьИзВременногоХранилища`. На сервере — писать прогресс через `ДлительныеОперации.СообщитьПрогресс(Процент, Текст)`, на клиенте — `ПодключитьОбработчикОжидания(...)` с интервалом >= 1 секунда (платформа запрещает меньший интервал для периодических обработчиков).

## Общие модули форм (вынос дублирующейся логики)

### Признак того, что пора выносить в общий модуль

Две и более формы одного объекта (например, `ФормаЭлемента` и `ФормаГруппы` справочника) содержат практически идентичные процедуры работы с реквизитами формы, программным построением элементов, конвертацией данных, миграциями. Типовые признаки:

- одинаковые имена `РМ_*`-обработчиков в обоих модулях формы с совпадающей логикой;
- дублирование серверных функций-обёрток над `РаботаСФайлами`, `Справочники.Имя.ПолучитьСсылку(...)` и т.п.;
- параллельные изменения в обеих формах каждый раз, когда поправлен баг в одной из них.

### Паттерн «тонкие делегаты» в форме + три общих модуля

Не переименовывать обработчики в формах (это потребует перенастраивать `УстановитьДействие`, `&Перед`/`&После`/`&Вместо`, привязки кнопок). Вместо этого оставить в форме процедуры-обёртки с историческими именами, а реальную логику перенести в общие модули.

Структура трёх общих модулей по контекстам:

- `<Префикс>_МодульФормыКлиентСервер` — чистые функции, доступные в обоих контекстах (парсинг строк, разбор сегментов, константы вроде ключа `ПараметрыЗаписи`). Директивы `&НаКлиентеНаСервереБезКонтекста` (или настройка модуля «КлиентСервер»).
- `<Префикс>_МодульФормыСервер` — серверная логика: запросы, `РаботаСФайлами`, программное построение элементов формы через `Элементы.Добавить`, `ИзменитьРеквизиты`, делегация к типовым методам формы. Директивы `&НаСервере` или настройка «Сервер».
- `<Префикс>_МодульФормыКлиент` — клиентская логика: работа с полями формы, тумблеры, оповещения, миграции HTML↔Markdown. Директивы `&НаКлиенте` или настройка «Клиент».

Каждый модуль настраивается в `.mdo` явно (см. SU193): `server=true`, `clientManagedApplication=true` и т.д. — `createObject` создаёт модуль с неполными настройками, и без `setObjectProperty` линтер EDT будет сыпать ошибки SU193.

В форме оставляются обёртки с прежней сигнатурой:

```bsl
&НаСервере
Процедура РМ_СоздатьПрисоединенныеФайлыИзДопСвойств(Форма, ТекущийОбъект, ПараметрыЗаписи, Отказ)
    ГКСИ_MarkdownФормаСервер.СоздатьПрисоединенныеФайлыИзДопСвойств(
        Форма, ТекущийОбъект, ПараметрыЗаписи, Отказ);
КонецПроцедуры

&НаКлиенте
Процедура ГКСИ_ПереключитьРежим(Команда)
    ГКСИ_MarkdownФормаКлиент.ПереключитьРежим(ЭтотОбъект, Команда);
КонецПроцедуры
```

### Соглашение о ключах в `ПараметрыЗаписи`

Когда клиент передаёт на сервер нетривиальные данные (адрес ВХ с `Соответствие`, сериализованный массив, набор флагов), **имя ключа в `ПараметрыЗаписи` централизуется в одном месте** — функция `<Префикс>_МодульФормыКлиентСервер.КлючАдресаЧегоТоТам()` возвращает строковую константу. И клиент (`ПараметрыЗаписи.Вставить(КлючАдресаHTMLПоЯзыкам(), АдресВХ)`), и сервер (`Если ПараметрыЗаписи.Свойство(КлючАдресаHTMLПоЯзыкам())`) используют её через вызов. Без этого клиент и сервер расходятся при переименовании и ловят трудноуловимые баги «значение не пришло».

### Безопасная миграция

Этапы, чтобы ничего не сломать:

1. **Создать модули** через `1C_EditMetadata createObject CommonModule.<Имя>` → сразу `setObjectProperty` для всех флагов контекста (без этого SU193 блокирует компиляцию).
2. **Перенести чистые функции** в `<Префикс>_МодульФормыКлиентСервер` — это самый безопасный шаг, нет контекстных проблем.
3. **Перенести серверные процедуры** в `<Префикс>_МодульФормыСервер`. Каждая процедура должна получать `Форма` явным параметром (не `ЭтотОбъект`), если она раньше была в модуле формы.
4. **Заменить вызовы в формах** на делегаты — текстовой заменой `РМ_` → `ГКСИ_MarkdownФорма*.`.
5. **Удалить старые тела процедур** из форм, оставив только делегаты. Проверить `GetMarkers` на предмет «хвостов» старых тел функций.
6. **Сборка и проверка маркеров**. Остаются только `SU61` (имя метода не начинается с префикса — для делегатов `РМ_*` оставить как есть, поставить `@skip-warning`) и `SU44` (неиспользуемый метод — для делегатов тоже `@skip-warning`).

### Свойства общих модулей форм в `.mdo`

Для `ГКСИ_MarkdownФормаСервер` нужны: `server=true`, `externalConnection=true`, `clientOrdinaryApplication=true`. Для `ГКСИ_MarkdownФормаКлиент`: `clientManagedApplication=true`. Для `ГКСИ_MarkdownФормаКлиентСервер`: все четыре `true`. EDT не выставит их сам, требуется явный `setObjectProperty`.

## Данные и деревья

### Построить иерархию «многие ко многим» через регистр сведений
Связи «элемент ↔ группа» хранить в регистре сведений с измерениями `Сценарий`, `Группа`. Стандартное поле `Родитель` справочника обнулить в `ПередЗаписью` модуля объекта.

### Отобразить один объект под несколькими родителями в ValueTree
В коде построения дерева для каждого родителя из регистра создавать свой узел, ссылающийся на тот же объект. Сирот (не упомянутых в регистре) добавлять корневыми узлами.

### Переключить пометку удаления программно
`Объект = Ссылка.ПолучитьОбъект(); Объект.УстановитьПометкуУдаления(НЕ Объект.ПометкаУдаления, Истина);` — второй параметр разрешает удаление подчинённых.

### Заполнить «Полный код» для сирот
Для записей, не упомянутых в регистре связей, в качестве полного кода использовать собственный код объекта (из кеша/выборки), а не пустую строку.

### Открыть форму выбора с фильтром только по группам
`ПараметрыФормы = Новый Структура("ВыборГруппИЭлементов", ИспользованиеГруппИЭлементов.Группы); ОткрытьФорму("Catalog.Имя.ФормаВыбора", ПараметрыФормы, …);` — параметр `ВыборГруппИЭлементов` принуждает форму выбора к нужному режиму.

## Markdown / присоединённые файлы

### Хранить многоязычные тексты в одном строковом реквизите
В одной строке разделять сегменты маркерами: `<!--md:lang:ru-->…<!--/md:lang:ru--><!--md:lang:en-->…<!--/md:lang:en-->`. Читать/писать сегменты отдельными процедурами (`ПолучитьСегмент`, `УстановитьСегмент`).

### Подключить Native-компоненту
1. Хранить `.dll/.addin` в общем макете с типом `AddIn`.
2. `ПодключитьВнешнююКомпоненту(Макет.Адрес, ИмяКомпоненты, ТипКомпоненты)`.
3. `Объект = Новый("AddIn." + Имя + "." + Класс);` (синхронно — для управляемых форм оборачивать в обработчик-обещание).

### Сохранить файл как присоединённый
Использовать типовой справочник присоединённых файлов (есть в типовых конфигурациях): заполнить `ДвоичныеДанные`, `Расширение`, `ИмяФайла`, вызвать `Записать()`. Для своей логики — общий модуль-переопределяемый.

### `НСтр` с многострочным текстом

**Нельзя.** Символ `|` интерпретируется как перевод строки **только** в обычных строковых литералах `"..."`. Внутри аргумента `НСтр(...)` текст берётся между одинарными кавычками после `=`, и весь этот текст — **одна строка**. Любые `|` внутри — обычные символы. Платформа возвращает обрезанную или мусорную строку; пользователь видит пустое окно или обрубок.

```1c
// ❌ ПЛОХО: | внутри НСтр не работает
ТекстВопроса = НСтр("ru = 'Выполнить загрузку сценариев в справочник?
    |Для существующих элементов будут применены выбранные решения
    |(если проверка конфликтов не выполнялась — все совпадения будут пропущены).");
```

**Можно.** Несколько `НСтр`, склеенных через `Символы.ПС`:

```1c
// ✅ ХОРОШО: три отдельных НСтр + переводы строк
ТекстВопроса = НСтр("ru = 'Выполнить загрузку сценариев в справочник?'")
    + Символы.ПС
    + НСтр("ru = 'Для существующих элементов будут применены выбранные решения.'")
    + Символы.ПС
    + НСтр("ru = '(Если проверка конфликтов не выполнялась - все совпадения будут пропущены.)'");
```

**Можно.** Многострочный литерал с `|` (где он работает) — **снаружи** `НСтр`:

```1c
Шаблон = "Выполнить загрузку сценариев в справочник?
    |Для существующих элементов будут применены выбранные решения.
    |(Если проверка конфликтов не выполнялась - все совпадения будут пропущены.)";
ТекстВопроса = НСтр("ru = '" + Шаблон + "'");
```

Также: вызов `НСтр("Пропустить'")` без кода языка и без `=` — синтаксически некорректен. Правильно — `НСтр("ru = 'Пропустить'")`. Иначе платформа возвращает пустую строку (например, выпадающий список будет пустым).

## Отладка и диагностика

### Понять, почему «не работает индекс» в коллекции картинок
Добавить временный `СообщениеПользователю` в код, выводящий возвращаемый индекс и входные параметры. Открыть форму → посмотреть в окно сообщений. После отладки — убрать.

### Проверить, что в коллекции картинок есть нужные индексы
Открыть общую картинку в EDT двойным кликом → редактор коллекции показывает все позиции с превью. Пустые позиции = не заданы png.

### Проверить маркеры EDT после правки формы
`GetMarkers` по абсолютному пути к `Form.form` — должно быть 0 errors. Warnings SU93/SU44/SU72 на стандартных обработчиках часто ложные (артефакты кеша линтера).

### Игнорировать предупреждение линтера при нестандартном имени обработчика
Поставить `@skip-warning` в строке перед процедурой — линтер не будет ругаться на «неиспользуемый метод» / «нестандартную область».

### Ошибка «Поле объекта недоступно для записи (ИмяПоля)» при присваивании параметру
Если функция/процедура **переприсваивает свой параметр** (`Расширение = СокрЛП(Расширение);`), а фактическим аргументом вызова передано **свойство выборки из запроса** (`Выборка.Расширение`), платформа пытается записать в это поле выборки и падает с «Поле объекта недоступно для записи (Расширение)».

Диагностический признак: в тексте ошибки стоит имя **фактического** поля выборки, а не формального параметра, поэтому переименование параметра (`Расширение` → `РасширениеФайла`) ничего не меняет — сообщение и строка падения те же. Лечится не переименованием, а устранением присваивания:

- нормализовать значение прямо в выражении: `Суффикс = ?(ЗначениеЗаполнено(РасширениеФайла), "." + СокрЛП(РасширениеФайла), "");`
- либо сначала сохранить свойство выборки в локальную переменную и передавать её: `РасширениеКартинки = Выборка.Расширение; УникальноеИмяФайла(..., РасширениеКартинки, ...);`

### Убедиться, что в базе исполняется актуальная сборка модуля
При работе с серверной базой (в т. ч. запуск через Run из EDT) удобно поставить в начало проверяемой процедуры `ВызватьИсключение "MARKER_vN";` и посмотреть стек в журнале регистрации. Если маркер появился — код до базы дошёл; если стек указывает на старую строку — исполняется кэш/прежняя сборка, и дело в способе обновления, а не в правке. Перед проверкой очищать журнал регистрации, чтобы не читать старые записи.

## Добавление кнопок, команд и обработчиков на форму в EDT через JShell

Контекст: EDT 2026+, платформа 8.3.27+, заимствованная форма в расширении. Правим `Forms/<FormName>/Form.form` (НЕ `BaseForm/Form.form`). API пакета: `com._1c.g5.v8.dt.form.model.*`. Фабрика: `com._1c.g5.v8.dt.form.model.FormFactory` (в JShell — `formFactory`).

### Структура объекта `Form`

| EMF-метод | XML-секция | Что внутри |
|---|---|---|
| `form.getItems()` | `<items>` верхнего уровня | `FormGroup`, `FormField`, `Table`, `Button`, `Decoration` |
| `form.getFormCommands()` | `<formCommands>` | `FormCommand` |
| `form.getAttributes()` | `<attributes>` | `FormAttribute` (реквизиты формы) |
| `form.getHandlers()` | `<handlers>` | `EventHandler` (обработчики событий формы) |

### 1. Получить объект `Form`

Через `globalContext.execute(...)` и `transaction.getTopObjectByFqn(...)` форму не достать — она лежит в EMF-ресурсе, а не в BM-транзакции. Читаем напрямую через `ResourceSet`:

```java
IBmModel bmModel = modelManager.getModel(project);
ResourceSet rs = bmModel.getResourceSet();
IFile formFile = project.getFile(
    new Path("src/Catalogs/ДемонстрационныеСценарии/Forms/ФормаГруппы/Form.form"));
Resource res = rs.getResource(
    URI.createURI(formFile.getLocationURI().toString()), true);
Form form = (Form) res.getContents().get(0);
```

### 2. Добавить реквизит формы (FormAttribute)

```java
FormAttribute attr = formFactory.createFormAttribute();
attr.setName("ГКСИ_ГруппыСценария");

IEObjectProvider typeProvider = IEObjectProvider.Registry.INSTANCE
    .get(McorePackage.Literals.TYPE_ITEM, v8project.getVersion());

TypeItem vtType = (TypeItem) typeProvider.getProxy(IEObjectTypeNames.VALUE_TABLE);
attr.setValueType(new TypeDescriptionBuilder().addType(vtType).build());
form.getAttributes().add(attr);

FormAttributeColumn col1 = formFactory.createFormAttributeColumn();
col1.setName("Группа");
TypeItem catalogRef = (TypeItem) typeProvider.getProxy(
    "CatalogRef.ДемонстрационныеСценарии");
col1.setValueType(new TypeDescriptionBuilder().addType(catalogRef).build());
attr.getColumns().add(col1);

FormAttributeColumn col2 = formFactory.createFormAttributeColumn();
col2.setName("ПолныйКодКонтекстный");
TypeItem stringType = (TypeItem) typeProvider.getProxy(IEObjectTypeNames.STRING);
col2.setValueType(new TypeDescriptionBuilder()
    .addType(stringType)
    .setStringQualifiers(250, false)  // длина 250
    .build());
attr.getColumns().add(col2);
```

**Почему `TypeDescriptionBuilder`:** квалификаторы типов в `mcore` — абстрактные, инстанцировать напрямую нельзя. Альтернатива — `EcoreUtil.copy(existingType)` с имеющегося атрибута.

### 3. Создать команды формы (FormCommand)

```java
FormCommand cmdAdd = formFactory.createFormCommand();
cmdAdd.setName("ГКСИ_ДобавитьГруппу");
cmdAdd.setAction("ГКСИ_ДобавитьГруппу"); // ← имя процедуры в модуле формы
form.getFormCommands().add(cmdAdd);

FormCommand cmdDel = formFactory.createFormCommand();
cmdDel.setName("ГКСИ_УдалитьГруппу");
cmdDel.setAction("ГКСИ_УдалитьГруппу");
form.getFormCommands().add(cmdDel);
```

- `setName(...)` — имя команды (в дереве метаданных).
- `setAction(...)` — **имя обработчика в модуле формы**. EDT использует его как имя процедуры/функции в `Module.bsl`. Если имя расходится — будет ошибка при компиляции модуля.

### 4. Создать кнопки (Button) и привязать к команде

```java
Button btnAdd = formFactory.createButton();
btnAdd.setName("ГКСИ_ДобавитьГруппуКнопка");
btnAdd.setCommandName(cmdAdd);   // ← ссылка на FormCommand, НЕ строка
btnAdd.setType(ButtonType.USUAL_BUTTON);
btnAdd.setRepresentation(ButtonRepresentation.AUTO);

Button btnDel = formFactory.createButton();
btnDel.setName("ГКСИ_УдалитьГруппуКнопка");
btnDel.setCommandName(cmdDel);
btnDel.setType(ButtonType.USUAL_BUTTON);
```

**`commandName` — это `EReference` на объект `FormCommand`.** Именно так EDT связывает кнопку с командой. Если поставить строку — будет SU45 / «неразрешимая ссылка».

### 5. Добавить кнопки и таблицу в группу на форме

```java
FormGroup group = formFactory.createFormGroup();
group.setName("ГКСИ_ГруппаВходитВГруппы");
group.setType(FormGroupType.USUAL_GROUP);
UsualGroupExtInfo info = formFactory.createUsualGroupExtInfo();
info.setGroup(FormChildrenGroup.ALWAYS_HORIZONTAL);
group.setExtInfo(info);
group.getTitle().put("ru", "Входит в группы");

group.getItems().add(btnAdd);
group.getItems().add(btnDel);

Table tbl = formFactory.createTable();
tbl.setName("ГКСИ_ГруппыСценарияТаблица");
DataPath dp = formFactory.createDataPath();
dp.setSegments(java.util.Arrays.asList("ГКСИ_ГруппыСценария"));
tbl.setDataPath(dp);

FormField colG = formFactory.createFormField();
colG.setName("ГКСИ_ГруппыСценарияКолонкаГруппа");

dpG.setSegments(java.util.Arrays.asList("ГКСИ_ГруппыСценария", "Группа"));
colG.setDataPath(dpG);
colG.getTitle().put("ru", "Группа");
tbl.getItems().add(colG);

FormField colC = formFactory.createFormField();
```

События формы — `EReference` на конкретные объекты `Event` в `FormPackage`:

|---|---|

В `Module.bsl` после этого должны появиться процедуры с **точно такими же именами**, что и `setName(...)` у `EventHandler`, иначе модуль не скомпилируется.


После — `GetMarkers` по `marker_type:"1c"` и `marker_type:"problem"`.

### Частые ошибки

| Ошибка | Причина | Решение |
|---|---|---|
| SU45 / «UUID required» | Не назначен UUID | В JShell с `mdFactory` обязательно `setUuid(UUID.randomUUID())`. Для объектов внутри `Form` UUID обычно не требуется |
| Кнопка не реагирует | `commandName` указано строкой | Это `EReference` — передавай сам объект `FormCommand` |
| Обработчик не вызывается | `setAction` отличается от имени процедуры в `Module.bsl` | Имя должно совпадать побуквенно |
| «Не найдено событие OnCreateAtServer» | Строка вместо ссылки | Получай `EReference` из `FormPackage.Literals.FORM` или копируй из BaseForm |
| Форма не меняется в EDT после сохранения | Кэш/ресурс не обновлён | `project.refreshLocal(DEPTH_INFINITE, monitor)` + проверить, что `res.save()` прошёл без исключений |
| `BmObject`-ошибка при ручной правке XML | Это заимствованный объект BM | Только через JShell/EDT API, никаких `Edit`/`Write` на `.form`-файлах |

3. В `Module.bsl` есть процедуры с именами из `setName(...)` у `EventHandler`

## Диагностика: BSL-валидатор EDT не видит контекст управляемой формы

### Симптомы

В `Module.bsl` управляемой формы массово появляются ошибки линтера:

- «Переменная `Параметры` не определена» (сервер)
- «Переменная `Элементы` не определена» (клиент)
- «Переменная `Список` не определена» (сервер)
- «Процедура `Закрыть` не определена»
- «Процедура `ОповеститьОВыборе` не определена»

+ предупреждения SU90 «Неиспользуемый метод `<ИмяПривязанногоОбработчика>`» и SU71 «Обращение к несуществующему параметру формы».

При этом `GetMarkers` по `Form.form` показывает **0 ошибок** — сама XML-форма валидна. Standalone-валидатор `mcp__syntax-checker__validate` по коду модуля тоже возвращает 0 ошибок.

### Корень проблемы №1 (самая частая): переводы строк LF вместо CRLF

**Признак:** проект требует CRLF (Windows), но файлы записаны с LF (Unix). Проверить через JShell:

```java
import org.eclipse.core.resources.ResourcesPlugin;
import org.eclipse.core.runtime.Path;
IFile f = ResourcesPlugin.getWorkspace().getRoot()
    .getProject("<ИмяПроекта>")
    .getFile(new Path("<путь-к-Module.bsl>"));
byte[] all = f.getContents().readAllBytes();
int lfOnly = 0, crlf = 0;
for (int i = 0; i < all.length; i++) {
    if (all[i] == '\n') {
        if (i > 0 && all[i-1] == '\r') crlf++;
        else lfOnly++;
    }
}
// Если lfOnly > 0 — это и есть причина
```

Сравнить с соседней **рабочей** формой: у неё `lfOnly == 0`, `crlf > 0`.

**Как исправить:** через JShell перезаписать файл с заменой LF → CRLF (безопасный алгоритм, не превращающий существующие CRLF в `\r\r\n`):

```java
byte[] current = f.getContents().readAllBytes();
String text = new String(current, "UTF-8");
StringBuilder sb = new StringBuilder();
for (int i = 0; i < text.length(); i++) {
    char c = text.charAt(i);
    if (c == '\n') {
        if (i == 0 || text.charAt(i-1) != '\r') sb.append('\r');
        sb.append('\n');
    } else {
        sb.append(c);
    }
}
f.setContents(
    new java.io.ByteArrayInputStream(sb.toString().getBytes("UTF-8")),
    IFile.FORCE,
    new NullProgressMonitor());
```

После — обязательно Reload проекта в EDT (правый клик → Reload), чтобы BSL-валидатор пересобрал AST с новым EOL.

**Превентивно:** при записи `Form.form`/`Module.bsl` через JShell (`IFile.setContents`) всегда использовать разделитель `\r\n`, не `\n` — иначе проектные `.mdo`-правила требуют перезаписи.

### Корень проблемы №2 (если №1 не помог): порядок элементов `Form.form` не соответствует XSD

Эталонный порядок корневых элементов `<form:Form>`:

```
items → handlers → (windowOpeningMode) → saveWindowSettings →
autoTitle → autoUrl → group → autoFillCheck → allowFormCustomize →
enabled → showTitle → showCloseButton → attributes → formCommands (×N) →
parameters → commandInterface → extInfo
```

Признаки нарушения: `<attributes>` стоит в самом конце, нет корневого `<handlers>`, `<commandInterface>` стоит до `<formCommands>`. Подробности — в разделе «Приведение `Form.form` в соответствие XSD через JShell + `IFile.setContents`» ниже.

### Сброс кеша BSL-валидатора EDT через JShell

Когда форма исправлена, но `GetMarkers` упорно показывает старые ошибки (валидатор держит устаревший AST), помогает связка:

## Приведение `Form.form` в соответствие XSD через JShell + `IFile.setContents`

### Когда применять

Когда в `Module.bsl` управляемой формы появляется «куча» однотипных ошибок BSL-валидатора EDT:

- «Переменная `Параметры` не определена» / «`Элементы` не определена» / «`Список` не определена»;
- «Процедура `Закрыть` не определена» / «`ОповеститьОВыборе` не определена»;
- маркеры SU90/SU85/SU93/SU71 на стандартных обработчиках формы.

А сам `Form.form` формально валиден по схеме (нет маркеров на `.form`), но при детальном сравнении с эталонной рабочей формой видно, что **нарушен порядок корневых элементов** и/или **неправильная структура `<formCommands>`**.

Корень проблемы: BSL-компилятор не считает файл полноценным модулем управляемой формы → контекстные идентификаторы (`Параметры`, `Элементы`, `ЭтотОбъект`, `Закрыть`, `ОповеститьОВыборе`) и реквизиты формы (`Список`) числятся «не определены».

### Эталонный порядок корневых элементов `<form:Form>`

XSD-схема формы **требует** строго такой порядок корневых элементов:

```
items → handlers → (windowOpeningMode) → saveWindowSettings →
autoTitle → autoUrl → group → autoFillCheck → allowFormCustomize →
enabled → showTitle → showCloseButton → attributes → formCommands (×N) →
parameters → commandInterface → extInfo
```

Признаки нарушения:
- `<attributes>` стоит в самом конце (после `</parameters>`) — неверно;
- `<commandInterface>` и `<extInfo>` стоят **до** `<formCommands>` — неверно;
- нет корневого `<handlers>` с привязкой `OnCreateAtServer` → `ПриСозданииНаСервере` сразу после `</items>` — неверно.

### Эталонная структура `<formCommands>` (для локальной команды формы)

```xml
<formCommands>
  <name>ИмяКоманды</name>
  <title>
    <key>ru</key>
    <value>ИмяКоманды</value>
  </title>
  <id>22</id>
  <use>
    <common>true</common>
  </use>
  <action xsi:type="form:FormCommandHandlerContainer">
    <handler>
      <name>ИмяКоманды</name>
    </handler>
  </action>
</formCommands>
```

Признаки нарушения:
- Присутствует `<commandKind>FormItemCommand</commandKind>` — лишний, в эталонных формах его нет;
- Порядок дочерних элементов отличается от `name → title → id → use → action`;
- Нет блока `<use><common>true</common></use>` — без него BSL-валидатор не считает команду «подключённой» и помечает соответствующий обработчик в `Module.bsl` как неиспользуемый.

### Способ правки

`Edit` и `Write` напрямую на `.form`-файле падают: первый — с `BmObject`-ошибкой (заимствованный объект), второй — `edit_form не поддерживает создание новых файлов`. Через **JShell** с manual_id `edit_form` доступен `IFile.setContents` — это Eclipse IFile API, не инструмент `Edit`/`Write`. Допустимо **только для собственных форм расширения** (не для заимствованных из основной конфигурации — там переписывание `Form.form` ломает BM-связи).

Алгоритм:

1. Открыть сессию через `JShellSession` для проекта расширения.
2. Получить manual через `JShellManual` со сценарием `edit_form` (статус `exact`).
3. Выполнить `JShell` с этим `manual_ids`. Код (с разбиением XML на части через `StringBuilder`, чтобы JShell-компилятор не подавился многострочным литералом):

```java
StringBuilder sb = new StringBuilder();
sb.append("<?xml version=\"1.0\" encoding=\"UTF-8\"?>\n");
sb.append("<form:Form xmlns:xsi=\"...\" xmlns:core=\"...\" xmlns:form=\"...\">\n");
// ... все блоки XML в целевом порядке ...
sb.append("</form:Form>\n");

IProject project = workspaceRoot.getProject("Доработки_ГКС_К");
IFile formFile = project.getFile(new Path(
    "src/Catalogs/ДемонстрационныеСценарии/Forms/ГКСИ_ФормаВыбораГруппы/Form.form"));

formFile.setContents(
    new java.io.ByteArrayInputStream(sb.toString().getBytes("UTF-8")),
    IFile.FORCE, null);
project.refreshLocal(IProject.DEPTH_INFINITE, null);
```

4. После правки вызвать `GetMarkers` по `Form.form` и `Module.bsl` — ошибки должны исчезнуть. Если ошибки BSL-валидатора в `Module.bsl` остались сразу после правки — нужно сделать Reload проекта (правый клик → Reload), потому что BSL-валидатор кеширует модель формы.

### Образцы для сравнения

В проекте `Доработки_ГКС_К` эталонные формы:

- `src/Catalogs/ДемонстрационныеСценарии/Forms/ФормаЭлемента/Form.form` — простая форма элемента, чистый эталон порядка.
- `src/Catalogs/ДемонстрационныеСценарии/Forms/ГКСИ_ФормаСпискаДеревоГрупп/Form.form` — форма списка с динамическим списком, образец для форм выбора.

### Контрольный чек-лист после правки

1. `GetMarkers` по `Form.form` = 0 ошибок.
2. `GetMarkers` по `Module.bsl` = 0 ошибок BSL-валидатора (`Параметры`/`Элементы`/`Список`/`Закрыть`/`ОповеститьОВыборе`).
3. Если в `Module.bsl` остались только SU71/SU85/SU90/SU93 — это нормально (ложные срабатывания линтера, см. глоссарий).

## Приёмы подсистемы ППГД

### 1. Расширение типового справочника собственными реквизитами и табличными частями

В расширении типовой справочник (`ПрофилиГруппДоступа`, `ГруппыДоступа`) заимствуется
(`Adopted`), после чего к нему добавляются собственные реквизиты и ТЧ. Имена собственных
объектов снабжаются префиксом (`Расш_ПГД…`, `ППГД_…`), чтобы не конфликтовать с типовыми.

В этом проекте так добавлены:
- реквизиты `Автор`, `ДатаСоздания`, `ДатаПоследнегоИзменения`,
  `Расш_ПГДОтложенныеРолиДобавление`, `Расш_ПГДТекстовыеРолиКРодительским`,
  `Расш_ПГДОтложенныеРолиУдаление`;
- ТЧ `ППГД_Объекты`, `Расш_ПГДРодительскиеПрофили`.

> Реквизиты/ТЧ менять только через EDT-инструменты работы с метаданными, не вручную
> в `.mdo`.

### 2. Дополнение модуля объекта заимствованного справочника через `&Перед`

Вместо переписывания типового обработчика используется аннотация расширения:

```1c
&Перед("ПередЗаписью")
Процедура ППГД_ПередЗаписью(Отказ)
	// ... собственная логика, типовая запись выполняется после
КонецПроцедуры
```

Применено в `src/Catalogs/ПрофилиГруппДоступа/ObjectModule.bsl`. Имя процедуры снабжается
префиксом расширения. Такой приём не ломает типовую логику и не требует `&Вместо`.

### 3. Обмен правами через XDTO

Формат обмена описан XDTO-пакетом `ППГД_ПраваДоступа` (namespace `http://rules`).
Последовательность:

- **Выгрузка:** `ИнициализироватьКомпонентыОбмена` → `ОткрытьФайлВыгрузки` →
  `Выгрузка*` (создание XDTO-объектов) → `ФабрикаXDTO.ЗаписатьXML`.
- **Загрузка:** `ЗагрузкаСообщения` → `ПрочитатьСообщениеОбмена` →
  `ОбъектXDTOВСтруктуру` → `СтруктураОбъектаXDTOВДанныеИБ` →
  `КонвертацияСвойствСтруктурыОбъектаXDTO` → запись в ИБ.

Все методы — в общем модуле `ППГД_ОбменДаннымиXDTOСервер` (см. `AGENTS/описание/ППГД/Описание.md` §5.3, §7).

### 4. Обновление ролей профиля из родительских профилей

В форме списка `ПрофилиГруппДоступа` роли родительских профилей (ТЧ
`Расш_ПГДРодительскиеПрофили`) добавляются в текущий профиль:
`ППГД_ОбновитьИзРодителейПослеНаСервере` собирает роли запросом и добавляет их в
`РольОбъект.Роли` через `ОбщегоНазначения.ИдентификаторОбъектаМетаданных("Роль." + …)`.

### 5. Просмотр прав как внешняя обработка

Обработка `ПросмотрПрав` регистрируется как дополнительная обработка через
`СведенияОВнешнейОбработке()` (команда `РолиДляДоступаКОбъектамМетаданных`, использование
«ОткрытиеФормы»). Это позволяет вызывать её из интерфейса «Дополнительные обработки».

### Общие правила работы с проектом

- Менять можно **только файлы расширения** и служебные md-файлы; файлы основной
  конфигурации `пустая_для_гкс` — read-only.
- Если нужно изменить типовой объект — заимствовать его в расширение.
- Файлы не удалять окончательно, а переименовывать в `.bak`.
- После правок проверять маркеры: `GetMarkers` (по изменённым объектам) и/или
  `mcp__syntax-checker__validate` (новый код).
- Сигнатуры платформенных методов проверять по документации, а не по памяти.
