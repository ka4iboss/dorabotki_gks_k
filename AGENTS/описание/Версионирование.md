# Версионирование расширения «Доработки_ГКС_К»

Канонический источник правды по версионированию объединённого расширения.
Схема введена 2026-10-08 (см. `ИсторияВерсий.md`, раздел 0).

## 1. Версия расширения

Ведётся в `src/Configuration/Configuration.mdo`, атрибут `<version>`, и состоит из
**четырёх чисел**:

```
major расширения . major подсистем . minor подсистем . patch подсистем
```

Стартовое значение — `1.0.0.0`.

- **X — major расширения.** Уровень релиза всего расширения. Поднимается **только по
  явному запросу пользователя** при фундаментальных изменениях логики или пересборке
  архитектуры. Самостоятельно не поднимать.
- **Y.Z.W — накопительные счётчики изменений подсистем** (общие для всех подсистем,
  отсчёт от старта `1.0.0.0`):
  - `W` (patch подсистем) — +1 при patch-изменении любой подсистемы;
  - `Z` (minor подсистем) — +1 при minor-изменении, `W` сбрасывается в 0;
  - `Y` (major подсистем) — +1 при major-изменении, `Z` и `W` сбрасываются в 0.
- Холостые правки (без реальных изменений) версию не двигают.

**Примеры:**

| Изменение | Версия подсистемы | Версия расширения |
|---|---|---|
| patch в ГКСИ | `2.35.1 → 2.35.2` | `1.0.0.0 → 1.0.0.1` |
| patch в ППГД | `1.20.3 → 1.20.4` | `1.0.0.1 → 1.0.0.2` |
| minor в ППГД | `1.20.4 → 1.21.0` | `1.0.0.2 → 1.0.1.0` |

## 2. Версии подсистем

Независимые `major.minor.patch` для каждой подсистемы, ведутся в общем модуле
`ГКСК_Версии` (`src/CommonModules/ГКСК_Версии/Module.bsl`, контекст: Сервер +
Внешнее соединение + Клиент обычного приложения):

| Функция | Что возвращает |
|---|---|
| `ВерсияГКСИ()` | версия подсистемы ГКСИ (старт `2.35.1`, унаследована от `ГКС_Инструкции`) |
| `ВерсияППГД()` | версия подсистемы ППГД (старт `1.20.3`, унаследована от `РасширениеПраваИПрофилиГруппДоступа`) |
| `ВерсияВерсииОбъектов()` | версия подсистемы ВерсииОбъектов (старт `1.0.0`) |
| `ВерсияРасширения()` | версия расширения из метаданных (`РасширенияКонфигурации.Получить(...)`) |
| `Версии()` | структура со всеми версиями |
| `ПоказатьВерсии()` | процедура: выводит версию расширения и версии подсистем в окно сообщений |

Схема версии подсистемы — `Major.Minor.Patch`, **всегда три компонента**
(`2.35.1`, а не `2.35`):

- `Major` — только по явному запросу пользователя;
- `Minor` — новая функциональность или изменение бизнес-логики;
- `Patch` — багфиксы, hotfix-ы.

## 3. Порядок при выпуске изменения

1. Поднять версию изменившейся подсистемы в `ГКСК_Версии` (`ВерсияГКСИ()` /
   `ВерсияППГД()` / `ВерсияВерсииОбъектов()`).
2. Поднять версию расширения в `Configuration.mdo` по схеме из §1.
3. Дописать короткую запись в `ИсторияВерсий.md`:
   версия → что изменено (1–3 предложения) → тип (фича / багфикс / рефакторинг).

Версия расширения фиксируется **в самом конце задачи** — после обновления документации
и проверки маркеров.

## 4. Почему так

- **Общая версия** — это «версия поставки»; её видно в свойствах расширения.
- **Версии подсистем** нужны, чтобы понимать, что именно изменилось в этой поставке
  (подсистемы развиваются независимо и с разной интенсивностью).
- **Константы для хранения версий подсистем не используются.** У объекта метаданных
  «Константа» нет свойства предзаполнения (`fillValue` — только у реквизитов), поэтому
  значение пришлось бы синхронизировать кодом (обработчиком обновления/старта сеанса).
  Версии в модуле `ГКСК_Версии` всегда синхронны с кодом и попадают в поставку
  автоматически. Отвергнутый вариант: константы `ГКСК_ВерсияГКСИ` / `ГКСК_ВерсияППГД`.
- Версия в `Configuration.mdo` меняется **только через модель конфигурации**
  (инструмент правки метаданных, `object_name = Configuration`); файловые инструменты
  этот файл не редактируют.
