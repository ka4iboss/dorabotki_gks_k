# Подсистема «ВерсииОбъектов» — просмотр версий объектов

Канонический источник правды по подсистеме **ВерсииОбъектов** расширения `Доработки_ГКС_К`.
Подсистема не относится к ГКСИ и ППГД — это самостоятельный утилитарный инструмент.

## 1. Назначение

Инструмент администратора/аналитика для работы с историей изменений данных:

- просмотр трёх ключевых версий данных: текущей, прошлой и первой;
- сравнение реквизитов между этими тремя версиями одной таблицей;
- открытие печатной формы данных по конкретной версии;
- переход (восстановление) на выбранную версию — поштучно и пакетно.

Поддерживаются **два** механизма версионирования (подробно — §4):

1. **Версионирование объектов** — штатная подсистема БСП, хранилище `РегистрСведений.ВерсииОбъектов`.
   Ссылочные типы: справочник, документ, бизнес-процесс, задача, план видов характеристик,
   план счетов, план видов расчёта. Типы основной конфигурации и расширений конфигурации.
2. **Платформенная история данных** — глобальный контекст `ИсторияДанных`, включается свойством
   метаданных «История данных» (`ИспользованиеИсторииДанных.Использовать`). Те же ссылочные типы,
   планы обмена и **регистры сведений**; у регистра сведений единица истории — запись (по ключу
   записи), поэтому список слева показывает записи регистра, а не объекты.

Собственного хранилища версий нет — используются оба штатных механизма; выбор делается по данным
(сначала проверяется `ВерсииОбъектов`, затем история данных).

## 2. Состав объектов

| Объект | Назначение |
|---|---|
| Подсистема `ГКСК_ВерсииОбъектов` | Размещение объектов подсистемы в командном интерфейсе. |
| Обработка `ГКСК_ПросмотрВерсийОбъектов` | Обработка с формой просмотра версий (форма `Форма`, тип `GENERIC`). |
| Общий модуль `ГКСК_ВерсииОбъектовСервер` | Серверная логика: список версионируемых справочников, список объектов, сведения о версиях, таблица различий, переход на версию, фоновая процедура пакетного перехода. |

Общий модуль — **чисто серверный** (`server = true`, `clientManagedApplication = false`,
`externalConnection = false`, `clientOrdinaryApplication = false`).

## 3. Интерфейс формы

```
┌─ ГруппаПакет (видна только при праве перехода) ──────────────────────────┐
│  [Перейти для отмеченных]   Целевая версия: [Текущая/Прошлая/Первая ▼]   │
└──────────────────────────────────────────────────────────────────────────┘
┌─ ГруппаЛевая ─────────────────┐ ┌─ ГруппаПравая ────────────────────────┐
│  [Найти][Отметить][Снять]     │ │  ГруппаТекущая:  [Перейти][Отчёт]     │
│  Тип объекта: [..............]│ │     <подпись текущей версии>          │
│  Поиск:       [..............]│ │  ГруппаПрошлая:  [Перейти][Отчёт]     │
│  Вид номенкл.:[..............]│ │     <подпись прошлой версии>          │
│  ┌──────────────────────────┐ │ │  ГруппаПервая:   [Перейти][Отчёт]     │
│  │ ✔ | Наименование         │ │ │     <подпись первой версии>           │
│  │   |                      │ │ │  ТаблицаРазличий:                     │
│  └──────────────────────────┘ │ │   Реквизит | Текущая | Прошлая | Перв.│
│   ТаблицаОбъектов             │ │                                       │
│   (для регистра сведений —    │ │                                       │
│    ТаблицаЗаписей)            │ │                                       │
└───────────────────────────────┘ └───────────────────────────────────────┘
```

- **Слева** — таблица данных выбранного типа. Для ссылочных типов это динамический список
  объектов (`ТаблицаОбъектов`), для регистров сведений — таблица значений записей регистра
  (`ТаблицаЗаписей`, колонки «Отметка» и «Запись регистра»); видимость таблиц переключается
  по виду списка типа (`ВидСпискаТипаОбъекта`). Колонка-флажок «Отметка» показывает отмеченные
  данные (для пакетной обработки); строки выделяются (режим множественного выделения) — кнопки
  «Отметить»/«Снять» меняют отметку у выделенных строк. Кнопки отметки есть в командных панелях
  обеих таблиц.
- Поле **«Вид номенклатуры»** отбирает список объектов по реквизиту `ВидНоменклатуры` и видно
  только для типов, у которых такой реквизит есть (проверка `ЕстьРеквизитВидНоменклатуры`).
  Отбор применяется при нажатии «Найти» (как и поиск по строке) и при смене типа объекта.
- **Справа** — три ключевых версии выбранного объекта (кнопки перехода и открытия печатной формы
  версии) и сводная таблица различий реквизитов.
- Группы `ГруппаОсновная` → `ГруппаЛевая` / `ГруппаПравая` размещены горизонтально
  (`group = HorizontalIfPossible`).

### Реквизиты формы

| Реквизит | Тип | Назначение |
|---|---|---|
| `СписокОбъектов` | `ДинамическийСписок` | Источник данных левой таблицы (`ТаблицаОбъектов`). Произвольный запрос с полями `Ссылка`, `Наименование` и вычисляемым `Отметка`; основная таблица и текст запроса переустанавливаются на сервере по выбранному типу объекта. |
| `ОтмеченныеОбъекты` | `Строка` | Отмеченные данные, упакованные `ЗначениеВСтрокуВнутр`: массив ссылок (для ссылочных типов) или массив строк — ключей записей регистра (`Запись` из `ТаблицаЗаписей`). Для динамического списка передаётся в параметр `Отмеченные` запроса. |
| `ТипОбъекта` | составной: `СправочникСсылка.ИдентификаторыОбъектовМетаданных`, `СправочникСсылка.ИдентификаторыОбъектовРасширений` | Выбранный тип объекта (основной конфигурации или расширения). |
| `СтрокаПоиска` | `Строка(20)` | Подстрока поиска по наименованию/коду (для регистров — по представлению записи). |
| `ВидНоменклатуры` | `СправочникСсылка.ВидыНоменклатуры` | Отбор списка объектов по виду номенклатуры (для типов с реквизитом `ВидНоменклатуры`). |
| `ТаблицаЗаписей` | `ТаблицаЗначений` | Колонки: `Отметка`, `Запись`, `Наименование`. Список записей регистра сведений, заполняется на сервере (`СписокЗаписейРегистра`); колонка `Запись` (упакованный ключ записи) на форме скрыта. Колонки `Запись` и `Наименование` — строки без ограничения длины и 200 символов соответственно: упакованный ключ длиннее 100 символов, при коротком квалификаторе он обрезается и ключ не восстанавливается. |
| `ТаблицаРазличий` | `ТаблицаЗначений` | Колонки: `Реквизит`, `Текущая`, `Прошлая`, `Первая`, `ЕстьРазличие`. |
| `ВыбранныйОбъект` | составной: `СправочникСсылка`, `ДокументСсылка`, `БизнесПроцессСсылка`, `ЗадачаСсылка`, `ПланВидовХарактеристикСсылка`, `ПланСчетовСсылка`, `ПланВидовРасчетаСсылка` | Текущий объект правой панели (для ссылочных типов). |
| `ВыбраннаяЗапись` | `Строка` | Ключ выбранной записи регистра сведений (упакованный `ЗначениеВСтрокуВнутр`); используется вместо `ВыбранныйОбъект` для регистров. Длина не ограничена — как и у колонки `Запись`. |
| `ПодписьТекущая` / `ПодписьПрошлая` / `ПодписьПервая` | `Строка(200)` | Представления версий. |
| `ЦелеваяВерсия` | `Строка(20)` | Вид версии для пакетного перехода. |
| `ЕстьПравоПерехода` | `Булево` | Признак права перехода на версию. |
| `ТолькоРазличия` | `Булево` | Показывать в таблице различий только изменённые реквизиты. |

> **Выбор данных правой панели** определяется видом списка: для ссылочных типов — `ВыбранныйОбъект`,
> для регистров — `ВыбраннаяЗапись`. Единая точка получения — серверная функция
> `ДанныеВыбраннойСтроки()` (для регистра она восстанавливает ключ записи функцией
> `ДанныеПоЗаписиСтрокой`).

> **Проверка «данные выбраны».** Используется серверная функция
> `ЕстьДанныеДляПросмотраВерсий(Данные)`, а не `ЗначениеЗаполнено`: для ключа записи регистра
> сведений `ЗначениеЗаполнено` зависит от заполненности измерений и может вернуть `Ложь`
> у существующей записи (например, если измерение-строка пустая). Тогда правая панель
> молча оставалась пустой — без версий и без таблицы различий. Заполненность проверяется
> только для ссылочных данных.

### Команды формы

`НайтиОбъекты`, `ПерейтиНаТекущую`, `ПерейтиНаПрошлую`, `ПерейтиНаПервую`,
`ОткрытьОтчетТекущая`, `ОткрытьОтчетПрошлая`, `ОткрытьОтчетПервая`, `ПерейтиДляОтмеченных`,
`ПоказатьТолькоРазличия`, `ОтметитьВыделенные`, `СнятьОтметкуВыделенных`.

> **Кнопка «Только изменённые реквизиты»** расположена в командной панели таблицы различий.
> Поле-флажок в командную панель положить нельзя (панель принимает только кнопки), поэтому
> это кнопка-переключатель с пометкой (`КнопкаТолькоРазличия`, свойство `Пометка`): нажатое
> состояние означает включённый фильтр.

> **Отметки объектов.** Динамический список не поддерживает штатные отметки, поэтому они
> сымитированы: в запрос добавлено вычисляемое поле `Отметка`
> (`ВЫБОР КОГДА Объекты.Ссылка В (&Отмеченные) ТОГДА ИСТИНА ИНАЧЕ ЛОЖЬ КОНЕЦ`), которое
> выводится колонкой-флажком. Массив отметок хранится в реквизите формы `ОтмеченныеОбъекты`;
> кнопки «Отметить выделенные» / «Снять отметку с выделенных» (`КнопкаОтметитьВыделенные`,
> `КнопкаСнятьОтметкуВыделенных` в левой группе) меняют массив и перечитывают список.
> Кликнуть по самому флажку нельзя — данные динамического списка доступны только для чтения.

> **Важно:** команда «Найти» названа `НайтиОбъекты`, а не `Найти`: `Найти` — зарезервированное
> слово языка, и процедура-обработчик `Процедура Найти(Команда)` даёт ошибку разбора модуля.

## 4. Логика определения версий

Версии ищутся **последовательно в двух механизмах**; функция `СведенияОВерсиях(Данные)` возвращает
ещё и ключ `Источник` (`"ВерсионированиеОбъектов"`, `"ИсторияДанных"` или `""` — версии не найдены),
который далее используется при чтении реквизитов версии и при переходе.

### 4.1. Версионирование объектов (регистр `ВерсииОбъектов`)

Регистр `РегистрСведений.ВерсииОбъектов` (непериодический, подчинён регистратору).
Учитываются только версии с `ТипВерсииОбъекта = Перечисление.ТипыВерсийОбъекта.ИзмененоПользователем`
(служебные версии синхронизации игнорируются).

| Вид версии | Правило |
|---|---|
| **Текущая** | Версия с максимальным номером среди изменённых пользователем. |
| **Прошлая** | Предыдущая (вторая с конца) версия среди изменённых пользователем; `Неопределено`, если её нет. |
| **Первая** | Версия с минимальным номером среди изменённых пользователем. |

Номера версий для списка объектов считаются **одним запросом** (`НомераВерсийПользователя`)
с последующим разбором в коде — обращения к базе в цикле отсутствуют.

### 4.2. Платформенная история данных

Если в `ВерсииОбъектов` версий нет, версии запрашиваются у платформы:
`ИсторияДанных.ВыбратьВерсии(Отбор, Колонки, Порядок, МаксимальноеКоличество)`
(отбор по `Данные` — ссылка или ключ записи регистра; порядок `НомерВерсии` по возрастанию).
Правила те же: текущая — последняя версия, прошлая — предпоследняя, первая — самая ранняя.
Важно: параметр «максимальное количество» принимает `Неопределено` для «без ограничения»,
поэтому `0` в API модуля преобразуется в `Неопределено` (иначе выборка будет пустой).

Реквизиты версии читаются `ИсторияДанных.ПолучитьДанныеВерсии(Данные, НомерВерсии)` (структура
«имя поля — значение»; ссылки приходят структурой `{Ссылка, Представление}` — берётся представление;
табличные части пропускаются; для версии удаления метод возвращает `Неопределено`).

### 4.3. Список записей регистра сведений

Для типа-регистра (вид списка `ЗаписиРегистра`) список слева — не объекты, а **записи регистра**:
`ИсторияДанных.ВыбратьВерсии` с отбором по объекту метаданных, порядок «дата/номер версии по убыванию»;
по каждой записи берётся последняя версия (первое вхождение ключа записи в выборке), из неё —
`ПредставлениеДанных` (представление записи) и сам ключ записи. Ключ упаковывается
`ЗначениеВСтрокуВнутр` от структуры значений измерений (плюс `Период` для периодических регистров
и `Регистратор` для регистров, подчинённых регистратору) — так он хранится в таблице формы
и восстанавливается функцией `ДанныеПоЗаписиСтрокой` через `СоздатьКлючЗаписи(Структура)`.

### 4.4. Состав типов объектов

Состав типов — объединение двух источников (`ВерсионируемыеОбъекты`):

- типы из `РегистрСведений.НастройкиВерсионированияОбъектов` (отбор `Использовать = Истина`),
  поддерживаемые измерением `Объект` регистра `ВерсииОбъектов`;
- объекты метаданных с включённой историей данных (`ИсторияДанных = ИспользованиеИсторииДанных.Использовать`)
  по коллекциям: справочники, документы, регистры сведений, бизнес-процессы, задачи,
  планы видов характеристик, планы счетов, планы видов расчёта, планы обмена.

Идентификатор типа (`ТипОбъекта`) разрешается в объект метаданных штатными методами БСП
(`ОбщегоНазначения.ОбъектМетаданныхПоИдентификатору`, `ОбщегоНазначения.ОбъектыМетаданныхПоИдентификаторам`),
а для обратного преобразования используется `ОбщегоНазначения.ИдентификаторОбъектаМетаданных` —
поэтому поддерживаются идентификаторы как основной конфигурации
(`Справочник.ИдентификаторыОбъектовМетаданных`), так и расширений
(`Справочник.ИдентификаторыОбъектовРасширений`). Представление типа — синоним объекта метаданных.
При открытии формы по умолчанию выбирается `Справочник.Номенклатура`, если он версионируется.

Вид списка типа определяется функцией `ВидСпискаТипаОбъекта`: `"ЗаписиРегистра"` для регистров
сведений, `"Ссылки"` для остальных поддерживаемых типов, `""` — тип не распознан.

### Таблица различий

Для каждой из трёх версий читается таблица реквизитов тем механизмом, в котором найдены версии
(`РеквизитыВерсииПоИсточнику`): для версионирования объектов —
`ВерсионированиеОбъектов.РазборВерсии(Ссылка, НомерВерсии)` (таблица `Реквизиты`), для истории
данных — `ИсторияДанных.ПолучитьДанныеВерсии`. Строится объединение имён реквизитов по трём версиям,
для каждого реквизита выводится представление значения в каждой версии и признак `ЕстьРазличие`.

**Фильтр «только изменённые».** Кнопка-переключатель в командной панели таблицы различий
(реквизит формы `ТолькоРазличия`) оставляет в таблице только строки с `ЕстьРазличие = Истина`.
Заполнение выполняет серверная процедура `ЗаполнитьТаблицуРазличий`: полный набор строк
получается из `ТаблицаРазличийВерсий` и фильтруется в коде.

**Ограничение текущей версии:** сравниваются только плоские реквизиты (и дополнительные
реквизиты, попадающие в разбор версии). Табличные части не сравниваются.

## 5. Переход на версию

Поштучный переход: клиент запрашивает подтверждение (`ПоказатьВопрос`), затем вызывает
`ГКСК_ВерсииОбъектовСервер.ПерейтиНаВерсию(Данные, НомерВерсии, ТекстОшибки, Источник)`:

- `Источник = "ВерсионированиеОбъектов"` → `ВерсионированиеОбъектов.ПерейтиНаВерсиюСервер(...)`
  (результат `"ВосстановлениеВыполнено"`, `"ОшибкаВосстановления"` или `"ОшибкаПроведения"`);
- `Источник = "ИсторияДанных"` → `ИсторияДанных.СформироватьПоВерсии(Данные, НомерВерсии)` и
  `Записать()` полученного объекта (для записи регистра — набора записей).

Источник передаётся явно (берётся из `СведенияОВерсиях(...).Источник`), чтобы не выполнять
запрос к `ВерсииОбъектов` в цикле пакетной обработки. После успеха обновляются сведения о версиях.

### Пакетный переход

Пользователь отмечает данные в левой таблице, выбирает в поле `ЦелеваяВерсия` вид версии
(`Текущая` / `Прошлая` / `Первая`) и нажимает «Перейти для отмеченных».
Каждая позиция переходит **на свою** версию выбранного вида.

Выполняется асинхронно, через механизм длительных операций БСП:

1. клиент вызывает `ДлительныеОперации.ВыполнитьВФоне("ГКСК_ВерсииОбъектовСервер.ВыполнитьПереходНаВерсииДляОтмеченных", Параметры, ПараметрыВыполнения)`.
   В параметрах передаются `СписокОбъектов` (ссылки), `СписокЗаписей` (упакованные ключи записей),
   `ТипОбъекта` (только для перехода по записям) и `ТипВерсии`;
2. фоновая процедура считает номера версий **без обращений к базе в цикле** (для ссылок — один запрос
   по `ВерсииОбъектов` плюс один запрос истории данных на каждый тип; для записей — один запрос
   истории данных по объекту метаданных), выполняет переходы и помещает во временное хранилище
   структуру `{Выполнено, Ошибки}`;
3. клиент ожидает завершение (`ДлительныеОперацииКлиент.ОжидатьЗавершение`) и выводит итог.

Так форма не блокируется на время массовой обработки.


## 6. Права

| Действие | Условие |
|---|---|
| Просмотр списка объектов и различий | Право просмотра данных версий (проверка не блокирует, при отсутствии данных `РазборВерсии` перехватывается). |
| Переход на версию | `Пользователи.ЭтоПолноправныйПользователь()` **и** `ВерсионированиеОбъектов.ЕстьПравоЧтенияИнформацииОВерсияхОбъектов()`. |

При отсутствии права перехода кнопки «Перейти…» и группа «Пакетный переход» скрываются
(функция `ЕстьПравоПереходаНаВерсию` в общем модуле; повторно проверяется в
`ПерейтиНаВерсиюСервер`).

## 7. Известные ограничения

- Сравниваются только плоские реквизиты (табличные части — нет).
- Поле `ЦелеваяВерсия` — поле ввода со списком выбора, заполняемым на сервере
  в `ПриСозданииНаСервере` (`Элементы.ЦелеваяВерсия.СписокВыбора`).
- Левый список — динамический список. **Каркас** динамического списка (основная таблица,
  признак «Произвольный запрос») задаётся только в редакторе форм EDT; текст запроса,
  значения параметров и основная таблица переустанавливаются на сервере при смене типа
  объекта (`НастроитьДинамическийСписок` + `НастройкиДинамическогоСпискаОбъектов`).
- Ограничения запроса динамического списка: не допускаются соединения с подзапросами,
  поэтому количество версий в списке не выводится (считается отдельно, если понадобится).
- Пакетный переход выполняется по **отмеченным** данным. Отметки — имитация (штатных отметок
  динамический список не имеет): вычисляемое поле `Отметка` в запросе по параметру `Отмеченные`
  (ссылочные типы) либо колонка `Отметка` таблицы записей регистра. Массив отметок — в реквизите
  формы `ОтмеченныеОбъекты`. Ставятся/снимаются кнопками по выделенным строкам; для динамического
  списка каждое изменение перечитывает список, для таблицы записей — только пересчитываются флажки.
  Кликнуть по самому флажку нельзя.
- Отбор по виду номенклатуры доступен только для справочников с реквизитом `ВидНоменклатуры`
  (в частности, `Справочник.Номенклатура`); для остальных типов поле скрыто. Справочник
  `ВидыНоменклатуры` заимствован в расширение.
- Статус `"ОшибкаПроведения"` (возможен для документов) не поддерживает повторный переход
  с отменой проведения — при необходимости доработать по образцу типовой формы
  `РегистрСведений.ВерсииОбъектов.Форма.ВыборХранимыхВерсий`.
- Право перехода проверяется одной функцией `ЕстьПравоПереходаНаВерсию`
  (`Пользователи.ЭтоПолноправныйПользователь()` **и**
  `ВерсионированиеОбъектов.ЕстьПравоЧтенияИнформацииОВерсияхОбъектов()`). Для объектов, у которых
  версии есть только в истории данных (например, регистров сведений), вторая проверка формально
  не требуется — если понадобится разделить права, функцию следует расширить.
- Константы в списке типов не предлагаются: единицей истории у константы является ключ значения
  (`КонстантаКлючЗначения`), а список слева для них не реализован.
- Платформенная история данных должна быть **включена в метаданных** объекта (свойство
  «История данных»); если история включена недавно, ранее созданные версии отсутствуют.
- Типы, для которых не поддерживается ни один механизм, в списке типов не предлагаются.
  Если такой тип всё же выбрать в поле «Тип объекта» вручную (через форму выбора), список
  очищается и выводится сообщение «Для типа объекта … просмотр версий не поддерживается».
- Ключ записи регистра хранится в таблице формы как упакованная структура значений измерений
  (`Период` — для периодических регистров, `Регистратор` — для подчинённых регистратору);
  при изменении состава измерений регистра ранее сохранённые в открытой форме отметки
  восстановить не удастся (ключ просто не распознается).
