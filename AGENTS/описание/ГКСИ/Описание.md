## 1. Общее назначение

Подсистема ГКСИ добавляет к типовой конфигурации `1С:ERP Управление предприятием 2`
две функциональные области:

1. **Инструкции и описания демонстраций (рабочая документация).** Ведение
   демонстрационных сценариев процессов: справочник `ДемонстрационныеСценарии`
   (заимствован и расширен), множество групп для одного сценария (регистр сведений
   `ГКСИ_ГруппыСценариев`), хранилище изображений (`ГКСИ_ФайлыИнструкций`),
   импорт/экспорт сценариев в Markdown (`ГКСИ_ЗагрузкаСценариевИзMarkdown`,
   `ГКСИ_ВыгрузкаСценариевВMarkdown`), построение «Альбома процессов»
   (`ГКСИ_АльбомПроцессов`), интеграция с типовым «Глоссарием» (`ГКСИ_Глоссарий`).
2. **Редактор Markdown (подсистема `ГКСИ_РМ_РедакторMarkdown`).** Переиспользуемая
   подсистема, встраивающая WYSIWYG-редактор Markdown в произвольные управляемые формы
   1С на базе библиотек `showdown.js` и `highlight.js` (исходный код хранится в общих
   макетах). Интегрирована в форму элемента типового справочника
   `ДемонстрационныеСценарии`, форму группы и в общую форму справки.

- Длина кода 36 символов, переменная — позволяет записывать GUID, сгенерированный

- Идентификация файла в Markdown — по коду (GUID). При рендеринге HTML код подменяется
  на data URI в формате `data:<mime>;base64,<base64>`.
- Создание и поиск элементов выполняется через общий модуль

## 4. Регистр сведений `ГКСИ_ГруппыСценариев`

### 4.1 Назначение

Справочник `ДемонстрационныеСценарии` (заимствован из `1С:ERP 2`) исторически позволял
одному элементу входить только в одну группу через стандартный реквизит `Родитель`.
Цель подсистемы — дать возможность одному сценарию состоять в нескольких группах,
сохранив вложенность групп.

### 4.2 Принцип

Платформенный реквизит `Родитель` справочника **больше не используется**. Иерархия групп
и связь «элемент ↔ группа» хранятся в собственном регистре сведений `ГКСИ_ГруппыСценариев`.
Группы могут быть вложены друг в друга (через ту же запись регистра:
`Группа1 → Группа2` = «Группа2 входит в Группу1»).

### 4.3 Структура регистра

Файл: `src/InformationRegisters/ГКСИ_ГруппыСценариев/ГКСИ_ГруппыСценариев.mdo`.
Режим записи — независимый (без регистратора).

| Поле | Тип | Назначение |
|------|-----|------------|
| `Сценарий` (измерение) | `CatalogRef.ДемонстрационныеСценарии` | Член группы — элемент или подгруппа. Индексировано, запрет незаполненных |
| `Группа` (измерение) | `CatalogRef.ДемонстрационныеСценарии` | Родительская группа. Индексировано, запрет незаполненных |
| `КореньИнструкции` (измерение) | `CatalogRef.ДемонстрационныеСценарии` | Корневая инструкция, в которой создана связь |
| `ПолныйКодКонтекстный` (ресурс) | `String(250)` | Кеш пути от корня к сценарию через группу |
| `КодВКонтексте` (ресурс) | `String` | Полный код сценария в контексте конкретного корня |

Составной ключ регистра — `(Сценарий, Группа, КореньИнструкции)`, что позволяет хранить
несколько связей «Сценарий — Группа» для одного узла, если он живёт в нескольких корневых
инструкциях (см. §14).

### 4.4 Общий модуль `ГКСИ_ГруппыСценариевСервер`

Файл: `src/CommonModules/ГКСИ_ГруппыСценариевСервер/Module.bsl`.
Настройки модуля: `Server = true`, `ExternalConnection = true`, `ClientOrdinaryApplication = true`.

#### Управление связями

| Метод | Описание |
|-------|----------|
| `ДобавитьСценарийВГруппу(Сценарий, Группа, КореньИнструкции)` | Идемпотентно добавляет сценарий в группу. Проверяет отсутствие цикла (выбрасывает исключение) |
| `УдалитьСценарийИзГруппы(Сценарий, Группа)` | Удаляет связь. Без ошибок, если связи нет |
| `УдалитьСвязиОбъекта(Ссылка)` | Удаляет все осиротевшие записи по обоим измерениям (используется из `ПередУдалением`) |
| `ЗарегистрироватьКорневуюГруппуИнструкции(Сценарий)` | Пишет самоссылочную запись регистра для корневой `#`-группы инструкции (`Сценарий = Группа = КореньИнструкции = Сценарий`). Идемпотентна. Используется при первичной загрузке MD-файла, чтобы форма списка находила корневую группу в РС и отображала её с настоящим именем из справочника |

#### Чтение структуры

| Метод | Описание |
|-------|----------|
| `ПолучитьГруппыСценария(Сценарий)` | Массив непосредственных родительских групп |
| `ПолучитьСценарииГруппы(Группа)` | Массив элементов группы (только не-группы) |
| `ПолучитьЧленовГруппы(Группа)` | Массив всех членов группы — элементы и подгруппы |
| `ПолучитьПотомковГруппы(Группа)` | Транзитивное поддерево групп (включая корень) |
| `ПолучитьРодительскуюГруппу(Группа)` | Непосредственный родитель группы или пустая ссылка |

#### Валидация

| Метод | Описание |
|-------|----------|
| `ЕстьЦиклВГруппах(Сценарий, Группа)` | Проверяет, что Сценарий не входит в цепочку предков Группы |

#### Полный код

| Метод | Описание |
|-------|----------|
| `ПолныйКодВКонтексте(Сценарий, Группа)` | Возвращает строку вида `Корень.Промежуточная.Группа.Сценарий` (до 50 уровней). Позиция среди сиблингов родителя: для корневой группы — её собственный системный `Код`, для вложенных групп и самого сценария — позиция (`ЧЦ=3; ЧВН=`) среди прямых сиблингов родителя, отсортированных по системному `Код`. Подгруппы и обычные элементы делят общий счётчик внутри родителя |
| `ПолныйКодВКонтекстеГрафа(Сценарий, Группа, Граф)` | Локальная. Полный код сценария в контексте конкретной группы по графу |
| `ПолныйКодГруппыГрафа(Группа, Граф)` | Локальная. Рекурсивно вычисляет полный код группы по графу |
| `ПересчитатьПолныйКодКонтекстныйДляСценария(Сценарий)` | Перезаписывает кеш для всех групп сценария |
| `ПересчитатьПолныйКодДляПоддерева(Группа)` | Перезаписывает кеш для всей подветки группы |
| `ГКСИ_ПолучитьСледующийКодКорневойОбертки()` | Возвращает следующий по порядку строковый код для новой корневой группы-обёртки инструкции в формате `ЧЦ=3; ЧВН=` (например, `"001"`, `"002"`). Если корневых обёрток ещё нет — `"001"` |
| `ГКСИ_ИсправитьИнструкцииИсточников()` | Разовая сервисная функция приведения реквизита `ГКСИ_ИнструкцияИсточник` в соответствие с реальной структурой РС (устарела, см. §14) |

Лимит обхода — `МаксимальнаяГлубинаИерархииГрупп = 50`.

**Пример формата кода:**

```
Корневая группа 001           →  "001"
├─ Элемент A (системный 002)  →  "001.001"
├─ Элемент B (системный 003)  →  "001.002"
└─ Подгруппа X (системный 010)→  "001.003"
   └─ Элемент C (системный 011) → "001.003.001"
```

#### Сервисные методы

- `ИмяФайлаОписанияСценария(Сценарий, КодЯзыка)` — формирует имя файла описания как
  `<GUID_сценария>_<КодЯзыка>` (без расширения), что обеспечивает стабильность имени
  при перемещении сценария между группами.

#### Граф в `ПовторноИспользуемыеЗначения`

Граф предзагружается в `ПовторноИспользуемыеЗначения` (метод `ГКСИ_ГрафГрупп`) пакетным
запросом из двух наборов (связи `РС.ГКСИ_ГруппыСценариев` + справочник целиком) и строит
четыре `Соответствия`:

- `ЧленыГрупп` — `{Группа -> {Член -> Истина}}`;
- `РодителиГрупп` — `{Сценарий -> {Группа -> Истина}}`;
- `ЭтоГруппа` — `{Ссылка -> Булево}`;
- `КодыПоСсылкам` — `{Ссылка -> Код}` (для построения полного кода).

Все публичные методы работают с этим графом в памяти — **O(1) на запрос к иерархии, без
обращений к БД в циклах**. Кеш сбрасывается автоматически при изменении ключа в
`ПовторноИспользуемыеЗначения`.

### 4.5 Изменения в справочнике `ДемонстрационныеСценарии`

Файл модуля: `src/Catalogs/ДемонстрационныеСценарии/ObjectModule.bsl`.
В `.mdo` справочника включён режим `<objectModule>Extended</objectModule>`.
В модуле объекта добавлены перехватчики:

- `&Перед("ПередЗаписью")` → `ГКСИ_ПередЗаписью(Отказ)`:
  - пропускает обмен данными (`ОбменДанными.Загрузка`);
  - сохраняет старое значение `Родитель` в `ДополнительныеСвойства["ГКСИ_ПрежнийРодитель"]`;
  - принудительно обнуляет `Родитель` (платформенная иерархия отключена).
- `&После("ПриЗаписи")` → `ГКСИ_ПриЗаписи(Отказ)`:
  - пропускает обмен данными;
  - для группы — вызывает `ПересчитатьПолныйКодДляПоддерева(Ссылка)`;
  - для элемента — вызывает `ПересчитатьПолныйКодКонтекстныйДляСценария(Ссылка)`;
  - при непустом канале `ДополнительныеСвойства["ГКСИ_АдресHTMLПоЯзыкам"]` создаёт/обновляет
    присоединённые HTML-файлы (см. §7.4).
- `&Перед("ПередУдалением")` → `ГКСИ_ПередУдалением(Отказ)`:
  - очищает из регистра `ГКСИ_ГруппыСценариев` все осиротевшие записи, в которых удаляемый
    объект фигурирует как `Сценарий` или как `Группа`
    (через `ГКСИ_ГруппыСценариевСервер.УдалитьСвязиОбъекта(Ссылка)`).

### 4.6 Ограничения

1. **Нет миграции данных** — справочник наполняется загрузкой из Markdown.
2. **Транзакция записи группы** удерживается дольше из-за рекурсивного пересчёта кеша.
   На малых объёмах приемлемо, при росте — выносить в фон.
3. **Платформенная иерархия остаётся в БД**, но не используется. Запросы, использующие
   `В ИЕРАРХИИ` к этому справочнику, вернут пусто.

## 5. Подсистема `ГКСИ_РМ_РедакторMarkdown` (ядро)

### 5.1 Общий сценарий встраивания

Подсистема реализует паттерн «встраивание через программное построение элементов формы»:

1. На сервере вызывается `ГКСИ_MarkdownСерверВызовСервера.ВставитьПолеРедактированияТекстаНаФорму(Форма, Родитель, ПутьКДанным, ВариантПодсветки, ТолькоПросмотр)`.
2. Модуль программно создаёт реквизит-дублёр (по имени, производному от `ПутьКДанным`),
   страницы формы «Редактирование / Просмотр», кнопочную панель редактирования, поле
   просмотра HTML, таблицу присоединённых файлов.
3. На форму программно устанавливаются обработчики с именами `РМ_Подключаемый_*`, которые
   делегируют вызовы в `ГКСИ_MarkdownКлиент`.
4. `ГКСИ_MarkdownКлиент` отвечает за работу с `showdown.js` / `highlight.js` на клиенте
   (через HTML-поле просмотра), за вставку изображений из буфера, открытие и сохранение
   присоединённых файлов.
5. `ГКСИ_MarkdownПереопределяемый` (серверный) реализует фактическое сохранение файла в
   конкретное хранилище. В расширении это справочник `ГКСИ_ФайлыИнструкций`. В других
   проектах подсистему можно перенести на стандартный механизм присоединённых файлов,
   переопределив этот модуль.

### 5.2 Алгоритм `ВставитьПолеРедактированияТекстаНаФорму`

Файл: `src/CommonModules/ГКСИ_MarkdownСерверВызовСервера/Module.bsl`.

Сигнатура:

```1c
Процедура ВставитьПолеРедактированияТекстаНаФорму(
	Форма, ГруппаЭлементовТекста, ПутьКДанным,
	ВариантПодсветкиСинтаксиса = "ones",
	ТолькоПросмотр = Ложь) Экспорт
```

Параметры:

- `Форма` — управляемая форма, в которую встраивается редактор.
- `ГруппаЭлементовТекста` — элемент-родитель (обычно `ЭтотОбъект`).
- `ПутьКДанным` — путь к реквизиту формы, содержащему текст Markdown.
- `ВариантПодсветкиСинтаксиса` — имя CSS-стиля подсветки кода (по умолчанию `"ones"`).
- `ТолькоПросмотр` — если Истина, страница «Редактирование» не создаётся, остаётся только
  страница «Просмотр» (используется в общей форме справки).

Этапы алгоритма:

1. Получить «чистый» путь к данным (без префиксов) через
   `ГКСИ_MarkdownКлиентСервер.ПолучитьПутьКДаннымБезЛишнего`.
2. Создать `Страницы` (`ВидГруппыФормы.Страницы`) с именем из
   `ГКСИ_MarkdownКлиентСервер.ПолучитьИмяЭлементаПанелиСтраницРедактированияКомментария(ПутьКДанным)`.
   Установить отображение «Закладки снизу», обработчик `ПриСменеСтраницы` →
   `РМ_Подключаемый_ПриСменеСтраницыПоляКомментария`.
3. Если `Не ТолькоПросмотр` — создать страницу «Редактирование».
4. Создать страницу «Просмотр».
5. Если `Не ТолькоПросмотр`:
   - `ДобавитьКнопкиВКоманднуюПанельРедактированияПоляMarkdown(...)` — командная панель
     с кнопками: «Синтаксис», «Жирный», «Курсив», «Зачёркнутый», «Заголовок 1/2/3»,
     «Список (марк./нумер./задач)», «Цитата», «Ссылка», «Код», «Таблица», «Скрепка»
     (прикрепить файл), «Вставить изображение из буфера», «Глоссарий»;
   - создать `ПолеВвода` (TextBox) с путём к данным и многострочным режимом.
6. Создать поле HTML-документа для просмотра (на странице «Просмотр»).
7. Создать таблицу присоединённых файлов с типизированной структурой
   (Ссылка, ПутьКФайлу, ИмяФайла, Адрес, ЭтоНовый).

Все программные элементы и обработчики именуются по правилам модуля
`ГКСИ_MarkdownКлиентСервер` (см. §5.7).

### 5.3 Сборка HTML для просмотра

`ГКСИ_MarkdownСерверВызовСервера.СформироватьТекстHTMLДляТекстаMarkdown(ВариантПодсветкиСинтаксиса)`

Собирает HTML-страницу с подключёнными `showdown.js` и `highlight.js`, стилями
wiki-разметки и выбранным CSS-вариантом подсветки. Возвращает текст HTML, который далее
присваивается полю просмотра. В HTML определены JS-функции:

- `clearTexts()`, `addText(key, text)`, `deleteText(key)` — управление словарём текстов;
- `convertOneText(key, text)` — рендеринг одного сегмента;
- `mdToHtml(text)`, `htmlToMd(text)` — конвертация в обе стороны;
- `markdownConvert()` — рендер всех сегментов + подсветка `hljs.highlightBlock` для всех `<code>`.

**Версия showdown**: `showdown v1.9.1` (общий макет `ГКСИ_showdown`, лицензия MIT). Выбор
ветки 1.x обусловлен тем, что в showdown 2.x удалён метод `converter.makeMarkdown()`,
используемый в JS-функции `htmlToMd` (для обратной миграции HTML→Markdown через
`ГКСИ_ВыполнитьМиграциюHTMLВMarkdown` — см. §7.3). Обновление до 2.x потребует замены
`htmlToMd` на отдельный HTML→MD-конвертер (например, Turndown.js).

**Поддержка GitHub Alerts**: реализована собственным JS-расширением `gksi-alerts`,
регистрируемым через `showdown.extension()`. Поддерживаемые типы блоков: `[!NOTE]`,
`[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]` — рендерятся в
`<div class="markdown-alert markdown-alert-{type}">…</div>` со стилями GitHub-default
и иконкой Octicon. Допустимо переопределение заголовка через `|`:
`> [!NOTE|Свой заголовок]`.

### 5.8 Видеоплеер в инструкциях (разметка `!video(...)`)

Модуль: `src/CommonModules/ГКСИ_Видео/` (серверный, `Server = true`,
`ExternalConnection = true`, `ClientOrdinaryApplication = true`).

Назначение — вставить в текст инструкции видео с внешнего/сетевого диска и
воспроизвести его встроенным HTML5-плеером. Разметка Markdown:

```
!video(D:\Video\Демонстрация.mp4)
!video(\\server\share\video\demo.mp4)
!video(https://example.com/videos/demo.mp4)
```

- Цель — до первого `)`. Пути со скобкой `)` в имени не поддерживаются.
- Обрамляющие кавычки снимаются: `!video("D:\загрузки\a.mp4")` и
  `!video(D:\загрузки\a.mp4)` обрабатываются одинаково (путь к файлу часто
  копируют из проводника Windows или мессенджера вместе с кавычками; кавычки в
  URL дают `file:///%22D:/…` и видео не воспроизводится). Поддерживаются
  парные `"`, `'`, `«»`, `“”` — функция `ГКСИ_Видео.УбратьОбрамляющиеКавычки`
  на сервере и `gksiUnquoteVideo` в JS.
- `ГКСИ_Видео.НормализоватьПутьКВидео(Путь)` приводит путь к URL для атрибута
  `src`: `http(s)://` и `file://` — как есть; `\\server\share\…` → `file://server/share/…`;
  `D:\…` → `file:///D:/…`; абсолютный `/…` → `file:///…`.
- `ГКСИ_Видео.РазметкуВидеоВHTML(Текст)` заменяет все вхождения `!video(...)`
  на фрагмент плеера (идемпотентно — при отсутствии маркера текст не меняется)
  и добавляет в конец скрипт изменения размера, если в тексте есть плеер:

```html
<div class="gksi-video">
  <div class="gksi-video-frame" style="position:relative;display:inline-block;width:100%;max-width:100%;line-height:0;">
    <video controls="controls" preload="metadata" style="display:block;width:100%;height:auto;max-width:100%;">
      <source src="НОРМАЛИЗОВАННЫЙ_URL" />
    </video>
  </div>
  <div class="gksi-video-caption">
    <a class="gksi-video-open" href="#" data-gksi-video="ИСХОДНЫЙ_ПУТЬ">Открыть во внешнем плеере</a>
  </div>
</div>
```

Стили заданы инлайново, потому что в сохранённом HTML описания CSS проекта
нет (в файл добавляется только `<style>img { vertical-align: middle; }</style>`).
Плеер по умолчанию занимает всю ширину описания.

**Изменение размера.** Ширина плеера регулируется **тем же значением, что и ширина
картинок** — реквизитом формы «Ширина картинок и видео» (`ШиринаКартинок`,
CSS-значение: `100%`, `600px`, `40em`) и слайдером «Размер картинок и видео» в
альбоме процессов:

- предпросмотр — `СтильИзображений` добавляет в блок `rm-img-style` правило
  `.gksi-video-frame { max-width: X; min-width: X; }`, а `setImageMaxWidth`
  переписывает его при изменении поля;
- альбом процессов — то же правило уходит в `<style id="album-imgs-style">`
  (с `!important`) при сборке документа, а `ГКСИ_ОбновитьСтильКартинок`
  переписывает блок при движении слайдера — без серверного вызова.

`max-width` уменьшает плеер, `min-width` позволяет растянуть его шире описания
(у фрейма в разметке задан `width:100%`, а `min-width` перебивает `width`).
Инлайнового `max-width` у фрейма нет намеренно — иначе он перебил бы правило из
стилей.

**Сохранённый HTML описания (типовые поля «Текст сценария» / «Текст сценария
(чтение)») ширину не регулирует** — там статический HTML без скриптов и без CSS
проекта, плеер занимает всю ширину описания. Это то же поведение, что у картинок:
их ширина в сохранённый файл из формы тоже не пишется.

Плеер работает в трёх местах:

1. **Предпросмотр в форме** — JS-функция `gksiPreprocessVideo` в
   `ГКСИ_MarkdownСерверВызовСервера.СформироватьТекстHTMLДляТекстаMarkdown`
   (вызывается в `convertOneText` и `mdToHtml` после `gksiPreprocessLinks`,
   до алертов); CSS классов `gksi-video*` — в блоке `СтильCSS`.
2. **Сохранённый HTML описания** (присоединённый `.html`) — тот же JS-конвейер:
   HTML формируется в браузере из Markdown и сохраняется вместе со стилями.
3. **Альбом процессов** — HTML собирается из сохранённого описания, разметка уже
   в виде плеера.

**Импорт `.md`** (обработка `ГКСИ_ЗагрузкаСценариевИзMarkdown`): в
`MarkdownВHTML` добавлен вызов `ГКСИ_Видео.РазметкуВидеоВHTML(Текст)` сразу
после замены картинок (до разбора абзацев), а строка с `<div class="gksi-video"`
распознаётся как готовый тег, чтобы не попасть внутрь `<p>`.

**Сохранённый HTML описания.** Типовые поля «Текст сценария» / «Текст сценария
(чтение)» и альбом процессов показывают HTML, записанный в присоединённый файл,
и он формируется **на сервере**. Поэтому, как и ссылки `[[…]]`, разметка видео
разбирается на сервере — `ГКСИ_Видео.РазметкуВидеоВHTML(...)` вызывается рядом с
`ГКСИ_СсылкиСценариев.ПодставитьСсылкиВТекст(…, "Навигация")` в:

- `ГКСИ_MarkdownФормаСервер.СоздатьПрисоединенныеФайлыИзДопСвойств` (перезапись
  существующего файла);
- `ГКСИ_MarkdownФормаСервер.СоздатьПрисоединенныйФайлСценария` (первая запись);
- `Catalog.ДемонстрационныеСценарии.ObjectModule` (запись объекта);
- `ГКСИ_АльбомПроцессов` (защита для описаний, сохранённых до появления
  поддержки видео).

Подстановка идемпотентна: если JS-предпросмотр уже заменил разметку, повторный
вызов ничего не меняет. После правок, влияющих на сохранённый HTML, сценарий
нужно **перезаписать**, чтобы файл перегенерировался.

**Кнопка на панели редактора.** `КомандаMDВидео` («Видео», картинка
`БиблиотекаКартинок.ГКСИ_Ссылка`) добавляется в
`ДобавитьКнопкиВКоманднуюПанельРедактированияПоляMarkdown`. Обработка — в
`ГКСИ_MarkdownКлиент.ОбработкаКомандыПоляКомментария`: на тонком клиенте
(`#Если Не ВебКлиент`) открывается `ДиалогВыбораФайла` с фильтром видеофайлов и
вставляется `!video(<ПолноеИмяФайла>)`; в веб-клиенте диалог недоступен —
вставляется пустой шаблон `!video()`, путь вводится вручную.

**Фоллбэк «Открыть во внешнем плеере».** Браузерное поле HTML-документа 1С
(WebKit) может блокировать загрузку `file://`-ресурсов. Поэтому под плеером
всегда выводится ссылка с атрибутом `data-gksi-video`; клик по ней открывает
файл системным проигрывателем через `НачатьЗапускПриложения`. Путь из данных
события достаёт `ГКСИ_MarkdownКлиент.ПутьВидеоИзДанныхСобытия(ДанныеСобытия)`
(читает `ДанныеСобытия.Anchor.getAttribute("data-gksi-video")`). Обработчики:

- `ГКСИ_MarkdownКлиент.ПриНажатииПоляПросмотраКомментария` — предпросмотр;
- `ГКСИ_ТекстHTMLПриНажатии` (`&Вместо`) формы `АльбомПроцессов` — альбом;
- `РМ_ПередТекстСценарияПриНажатии` / `РМ_ПередТекстСценарияЧтениеПриНажатии`
  форм `ФормаЭлемента` и `ФормаГруппы` (`&Перед`, гасит `СтандартнаяОбработка`
  только для клика по видео) — типовые HTML-поля `ТекстСценария` /
  `ТекстСценарияЧтение`.

Ограничения: путь с `)` в имени файла не поддерживается; URL не кодируется
(пробелы и кириллица в пути — на усмотрение браузера); разметка дублируется в
JS и BSL и должна поддерживаться синхронно.

## 6. Хранение файлов изображений

Файл: `src/CommonModules/ГКСИ_MarkdownПереопределяемый/Module.bsl`.
Настройки: `Server = true`, `ExternalConnection = true`, `ClientOrdinaryApplication = true`.

Реализует абстракцию «присоединённый файл» поверх справочника `ГКСИ_ФайлыИнструкций`.

### 6.1 `ЗаписатьПрисоединенныйФайлВБазу(ПараметрыФайла, АдресФайлаВоВременномХранилище, Форма, ПутьКДанным, Предмет = Неопределено)`

Шаги:

1. Создаёт новый элемент справочника `ГКСИ_ФайлыИнструкций`.
2. Присваивает `Наименование = ИмяБезРасширения`, `Расширение = РасширениеБезТочки`,
   `Файл = Новый ХранилищеЗначения(ПолучитьИзВременногоХранилища(...))`,
   `Описание = НСтр("ru = 'Вставлен из редактора Markdown'")`.
3. Явно присваивает `Код = Строка(Новый УникальныйИдентификатор())` (длина кода = 36).
4. Вычисляет и записывает `ХешSHA256`.
5. Вызывает `Записать()`.
6. В тексте Markdown (`Форма[ПутьКДанным]`) заменяет:
   - `"![](" + ИмяФайла + ")"` → `"![](" + НовыйФайл.Код + ")"`;
   - `"(" + ИмяФайла + ")"` → `"(" + НовыйФайл.Код + ")"`.

### 6.2 `ОбработкаИзображенияВТексте(КодФайла)`

1. Если `КодФайла` пустой — возвращает `""`.
2. Запросом `ВЫБРАТЬ Файл, Расширение ИЗ Справочник.ГКСИ_ФайлыИнструкций ГДЕ Код = &Код`
   находит файл.
3. Возвращает строку вида `data:<mime>;base64,<base64>` (MIME определяется `ПолучитьMimeТип()`).

Поддерживаемые расширения и MIME-типы:

| Расширение | MIME |
|------------|------|
| `png` | `image/png` |
| `jpg`, `jpeg` | `image/jpeg` |
| `gif` | `image/gif` |
| `bmp` | `image/bmp` |
| `svg` | `image/svg+xml` |
| иное | `application/octet-stream` |

### 6.3 Заглушки

`ЗаполнитьПрисоединенныеФайлыКОбъекту(...)` и `ПриПолученииДанныхФайла(...)` объявлены,
но не реализованы (заглушки для совместимости с подсистемой). В текущей реализации
расширения не используются.

### 6.4 Клиентский переопределяемый модуль

`src/CommonModules/ГКСИ_MarkdownКлиентПереопределяемый/Module.bsl` содержит процедуру-заглушку
`ОткрытьПрисоединенныйФайлПоСсылке(СсылкаНаПрисоединенныйФайл, УникальныйИдентификатор)`
(тело закомментировано). Метод предназначен для открытия файла по ссылке (в стандартной
интеграции — `УправлениеЗадачамиКлиент.ОткрытьПрисоединенныйФайлПоСсылке`).

## 7. Мультиязычность Markdown в `ДемонстрационныеСценарии`

Расширение заменяет в форме элемента типовой HTML-редактор на Markdown-редактор, но
сохраняет совместимость с типовым механизмом HTML-файлов по языкам: для каждого языка
по-прежнему существует присоединённый HTML-файл в справочнике
`ДемонстрационныеСценарииПрисоединенныеФайлы`. Между Markdown-текстами разных языков и
HTML-файлами поддерживается двусторонняя миграция.

### 7.1 Хранение Markdown по языкам

Все сегменты Markdown хранятся в одном реквизите `ГКСИ_ТекстMarkdown`, разделённые
текстовыми маркерами:

```text
<!--md:lang:ru-->
… текст на русском …
<!--/md:lang:ru-->
<!--md:lang:en-->
… text in English …
<!--/md:lang:en-->
```

Сегмент конкретного языка читается/пишется функциями модуля
`ГКСИ_MarkdownФормаКлиентСервер`:

- `ПолучитьСегментMarkdown(ТекстMarkdown, КодЯзыка)`;
- `ЗаменитьСегментMarkdown(ТекстMarkdown, КодЯзыка, Текст)`;
- `ПолучитьКодыЯзыковИзMarkdown(ТекстMarkdown)`;
- `КлючАдресаHTMLПоЯзыкам()` — возвращает `"ГКСИ_АдресHTMLПоЯзыкам"`.

### 7.2 Перехватчики (`&Перед` / `&После`)

Расширение не перекрывает типовые обработчики, а дополняет их через аннотации:

- `&Перед("ПриСозданииНаСервере")` → `ГКСИ_ПередПриСозданииНаСервере`:
  1. устанавливает действие клиентского `ПередЗаписью` (через `УстановитьДействие`);
  2. `ГКСИ_ДобавитьПанельРедактора()` — программно добавляет реквизиты, страницы редактора,
     командную панель, таблицу присоединённых файлов, обработчики `РМ_Подключаемый_*`;
  3. `ГКСИ_ЗаполнитьФайлыBase64()` — читает все файлы и формирует строки
     `data:<mime>;base64,...`;
  4. `ГКСИ_УстановитьСегментMarkdownВФорму(ЭтотОбъект, ЯзыкСценария)`.
- `&После("ПриСозданииНаСервере")` → `ГКСИ_ПослеПриСозданииНаСервере` — управляет видимостью
  панели Markdown.
- `&После("ПриЧтенииНаСервере")` → `ГКСИ_ПослеПриЧтенииНаСервере` — повторно извлекает
  сегмент текущего языка.
- `&Перед("ПередЗаписьюНаСервере")` → `ГКСИ_ПередПередЗаписьюНаСервере`:
  1. `ГКСИ_СоздатьПрисоединенныеФайлыИзДопСвойств(...)` — для каждого языка создаёт/обновляет
     присоединённый HTML-файл;
  2. `ГКСИ_СобратьТекстMarkdown(ТекущийОбъект)`.
- Клиентский `ГКСИ_КлиентскийПередЗаписью(Отказ, ПараметрыЗаписи)` (через `УстановитьДействие`)
  → `ГКСИ_ЗаписатьHTMLИзMarkdown(Отказ, ПараметрыЗаписи)` — получает HTML из поля просмотра
  и помещает его в `ПараметрыЗаписи` по ключу `ГКСИ_АдресHTMLПоЯзыкам`.
- `&После("ПослеЗаписиНаСервере")` → `ГКСИ_ПослеПослеЗаписиНаСервере` — обновляет `ФайлыBase64`
  и переустанавливает сегмент Markdown.
- `&После("ОбработкаОповещения")` → `ГКСИ_ПослеОбработкаОповещения` — реагирует на событие
  `"ГКСИ_ОбновитьФайлыBase64"`.
- `&Перед("ТекстСценарияДокументСформирован")` → `ГКСИ_ПередТекстСценарияДокументСформирован` —
  миграция HTML → Markdown при первом формировании поля просмотра.
- `&Перед("ТекстСценарияПриНажатии")`, `&Перед("ТекстСценарияЧтениеПриНажатии")` — сохраняют
  текущий сегмент Markdown перед обработкой клика в типовом HTML-поле.
- `&Перед("Подключаемый_Открытие")` → `ГКСИ_ПередПодключаемыйОткрытие`.
- `&Перед("Подключаемый_ИзменитьЯзыкРедактирования")`, `&Перед("Подключаемый_ИзменитьЯзыкПросмотра")`
  — сохраняют сегмент текущего языка перед переключением.
- `&После("Подключаемый_ИзменитьЯзыкРедактирования")`, `&После("Подключаемый_ИзменитьЯзыкПросмотра")`
  — после переключения устанавливают сегмент нового языка и обновляют видимость панели.

### 7.3 Миграция HTML → Markdown

`ГКСИ_ВыполнитьМиграциюHTMLВMarkdown()` вызывается на клиенте при первом формировании
HTML-просмотра типовой формы (когда объект уже сохранён и есть HTML-файлы по языкам, но
Markdown ещё не сформирован). Если `ГКСИ_MarkdownСформирован = Ложь`:

1. Читает ТЧ `ОписанияСценария` текущего объекта.
2. Для каждой строки с непустым присоединённым файлом извлекает HTML, конвертирует в
   Markdown (через `showdown`'s `converter.makeMarkdown()` — JS-функция `htmlToMd`).
3. Записывает результат в `ГКСИ_ТекстMarkdown` с маркерами `<!--md:lang:...-->`.
4. Устанавливает `ГКСИ_MarkdownСформирован = Истина`.

### 7.4 Сборка Markdown и обратная миграция

При записи:

1. `ГКСИ_СобратьТекстMarkdown(ТекущийОбъект)` — собирает сегменты для всех языков.
2. `ГКСИ_MarkdownФормаСервер.СоздатьПрисоединенныеФайлыИзДопСвойств(...)` — для каждого языка,
   чей HTML лежит в `ПараметрыЗаписи`/`ДополнительныеСвойства` по ключу `ГКСИ_АдресHTMLПоЯзыкам`:
   - находит существующий или создаёт новый элемент справочника
     `ДемонстрационныеСценарииПрисоединенныеФайлы` (имя — `ИмяФайлаОписанияСценария(ПолныйКод, КодЯзыка)`);
   - записывает HTML в двоичные данные;
   - приводит строку ТЧ `ОписанияСценария` в состояние «не изменена типом».

Типовая функция `ДемонстрационныеСценарии.ЗаписатьНовыеОписанияСценариевИзФормыОбъекта`
после этого работает как обычно и подхватывает подготовленные данные.

### 7.4а Обновление содержимого присоединённого HTML-файла

В ветке «файл уже есть» `ГКСИ_MarkdownФормаСервер.СоздатьПрисоединенныеФайлыИзДопСвойств`
вызывает экспортную `ОбновитьФайлХранилищеСценария(ПрисоединенныйФайл, ДанныеHTML)`
(а не типовую `РезультатОбновленияПрисоединенногоФайла` и не «создать новый + удалить старый»).
Реализация:

```1c
ФайлОбъект = ПрисоединенныйФайл.ПолучитьОбъект();
ФайлОбъект.ФайлХранилище = Новый ХранилищеЗначения(
	ДвоичныеДанныеHTML,
	Новый СжатиеДанных(9));
ФайлОбъект.Размер = ДвоичныеДанныеHTML.Размер();
ФайлОбъект.Записать();
```

**Почему только так:** `РезультатОбновленияПрисоединенногоФайла` мутирует
`СведенияОФайла.АдресВременногоХранилищаФайла`, из-за чего падает с «Некорректный тип
хранилища файлов». Вариант «создать новый + удалить старый + обновить ссылку» даёт рассинхрон
с `Форма.Объект`. Прямое обновление `ФайлХранилище` существующего элемента ссылку не меняет.

### 7.5 Дополнительные программные элементы

- `ГКСИ_УстановитьДействиеКлиентскогоПередЗаписью` — привязывает обработчик `ПередЗаписью`
  управляемой формы к `ГКСИ_КлиентскийПередЗаписью` через `УстановитьДействие`.
- `ГКСИ_УправлениеВидимостьюMarkdown(Форма)` — управляет видимостью/доступностью панели
  Markdown в зависимости от режима формы.

### 7.6 Перекрытие типовых обработчиков внешнего HTML-редактора

Типовые клиентские обработчики команд `Редактировать`, `ЗакончитьРедактирование`,
`ОтменитьРедактирование` открывают и закрывают присоединённый HTML-файл сценария во внешнем
приложении. Поскольку сценарий редактируется прямо в форме через Markdown-редактор, внешний
HTML-редактор не нужен. В `Module.bsl` формы `ФормаЭлемента` определены три пустых перекрытия
с аннотацией `&Вместо`:

- `&Вместо("Редактировать")` → `ГКСИ_РедактироватьВместо(Команда)`;
- `&Вместо("ЗакончитьРедактирование")` → `ГКСИ_ЗакончитьРедактированиеВместо(Команда)`;
- `&Вместо("ОтменитьРедактирование")` → `ГКСИ_ОтменитьРедактированиеВместо(Команда)`.

Видимость кнопок управляется отдельно через `ГКСИ_УправлениеВидимостьюMarkdown(Форма)`.

## 8. Общие модули формы Markdown (`ГКСИ_MarkdownФорма*`)

Дублирующаяся логика из форм `ФормаЭлемента` и `ФормаГруппы` справочника
`ДемонстрационныеСценарии` вынесена в три общих модуля:

- `ГКСИ_MarkdownФормаКлиент` (`src/CommonModules/ГКСИ_MarkdownФормаКлиент/`) — клиентский
  контекст: тумблер режима формы, миграция HTML → Markdown, добавление кнопки тумблера.
- `ГКСИ_MarkdownФормаСервер` (`src/CommonModules/ГКСИ_MarkdownФормаСервер/`) — серверный
  контекст: заполнение `ФайлыBase64`, сборка `ГКСИ_ТекстMarkdown` из сегмента текущего языка,
  создание/обновление присоединённых HTML-файлов по языкам, добавление программной панели
  редактора и панели глоссария, обновление ТЧ `ОписанияСценария` после записи.
- `ГКСИ_MarkdownФормаКлиентСервер` (`src/CommonModules/ГКСИ_MarkdownФормаКлиентСервер/`) —
  клиент-серверный контекст: чистые функции парсинга Markdown-сегментов
  (`ПолучитьСегментMarkdown`, `ЗаменитьСегментMarkdown`, `ПолучитьКодыЯзыковИзMarkdown`),
  единая константа `КлючАдресаHTMLПоЯзыкам()` (= `"ГКСИ_АдресHTMLПоЯзыкам"`).

В формах оставлены тонкие процедуры-обёртки с префиксом `РМ_`
(`РМ_УправлениеВидимостьюMarkdown`, `РМ_ДобавитьКнопкуТумблера`,
`РМ_СоздатьПрисоединенныеФайлыИзДопСвойств`, `РМ_СоздатьПрисоединенныйФайлСценария`,
`РМ_ВыполнитьМиграциюHTMLВMarkdown` и др.), которые немедленно делегируют в общий модуль.
Исторические имена `РМ_*` сохранены, чтобы не менять точки вызова из обработчиков событий
формы. Реальная логика — в общем модуле.

**Контракт по ключу `ГКСИ_АдресHTMLПоЯзыкам`:** клиент помещает в `ПараметрыЗаписи` по этому
ключу адрес временного хранилища, в котором лежит `Соответствие<КодЯзыка → HTML>`. Серверный
`ГКСИ_MarkdownФормаСервер.СоздатьПрисоединенныеФайлыИзДопСвойств` читает этот ключ, для каждого
языка находит/создаёт строку `ОписанияСценария` и создаёт/обновляет присоединённый HTML-файл.
Имя ключа централизовано в `ГКСИ_MarkdownФормаКлиентСервер.КлючАдресаHTMLПоЯзыкам()`.

**Выравнивание картинок в сохранённом HTML.** Сохранённый HTML-файл сценария собирается без
CSS, поэтому при картинке и тексте в одной строке текст прижимается к низу картинки. В
`ГКСИ_MarkdownФормаКлиент.ЗаписатьHTMLИзMarkdown` в `<body>` вставляется
`<style>img { vertical-align: middle; }</style>`, чтобы сохранённый файл совпадал с
предпросмотром формы.

## 9. Общая форма `ГКСИ_MarkdownСинтаксис`

Файл: `src/CommonForms/ГКСИ_MarkdownСинтаксис/`.

Используется для отображения справки по синтаксису Markdown. Содержит единственный реквизит
`ТекстСинтаксиса` (Строка). Программно при создании на форме вызывается
`ГКСИ_MarkdownСерверВызовСервера.ВставитьПолеРедактированияТекстаНаФорму` с параметром
`ТолькоПросмотр = Истина`.

Содержимое справки — длинная строка в `Module.bsl`, разделённая символом `|` (заголовки
H1–H3, жирный/курсив/зачёркнутый, списки, цитаты, ссылки, изображения, блоки кода, таблицы
и т.д.). Текст разбивается на массив строк (`СтрРазделить`), формируется HTML и помещается
в `ТекстСинтаксиса`.

Корневой элемент формы — `ГруппаКраткийСинтаксис` (UsualGroup, HorizontalIfPossible).
Командная панель и навигация отключены.

## 10. Альбом процессов

### 10.1 Назначение

Форма «Альбом процессов» (заимствованная форма `ДемонстрационныеСценарии.АльбомПроцессов`)
собирает из выбранных групп иерархию сценариев и формирует единый HTML-документ с
многоязычными разделами, чтобы пользователь мог распечатать или экспортировать процесс
целиком.

### 10.2 Файлы

| Файл | Назначение |
|------|------------|
| `src/Catalogs/ДемонстрационныеСценарии/Forms/АльбомПроцессов/Module.bsl` | Модуль формы. Обрабатывает параметры, формирует `ТекстHTML`, управляет слайдером ширины картинок, очищает DOM перед закрытием |
| `src/Catalogs/ДемонстрационныеСценарии/Forms/АльбомПроцессов/Form.form` | Состав формы: `ТекстHTML` (HTMLDocumentField, занимает всё окно) и полоса `ГруппаРазмера` (`HorizontalIfPossible`) внизу — ползунок `ШиринаКартинокЧисло` и выбор `ШиринаКартинокЕдиница` (см. §10.11) |
| `src/CommonModules/ГКСИ_АльбомПроцессов/Module.bsl` | Серверный построитель альбома |
| `src/CommonModules/ГКСИ_MarkdownПереопределяемый/Module.bsl` | Подстановка изображений в HTML (`ЗаменитьКодыИзображенийНаDataURI`) |
| `src/CommonModules/ГКСИ_ДанныеИзображенийMarkdown/Module.bsl` | Серверное чтение двоичных данных изображений (пакетный запрос, опциональный ресайз) |
| `src/CommonModules/ГКСИ_ДанныеИзображенийMarkdownПовтИсп/Module.bsl` | Тонкая кеш-обёртка над предыдущим с `ReturnValuesReuse = DuringSession` |

Настройки модуля `ГКСИ_АльбомПроцессов`: `Server = true`, `ExternalConnection = true`,
`ClientOrdinaryApplication = true`.

### 10.3 Конвейер построения альбома

1. Клиент формы вызывает `ГКСИ_АльбомПроцессов.СобратьДокументАльбома(...)` на сервере.
2. **Фаза 1. Граф.** Получает дерево через `ГКСИ_ГруппыСценариевСервер` (кеш
   `ПовторноИспользуемыеЗначения`).
3. **Фаза 2. Сбор листьев.** Рекурсивно обходит выбранные группы и накапливает список сценариев.
4. **Фаза 3. Пакетное чтение.** Одним запросом читает для всех листьев: имена файлов описаний,
   двоичные данные через `РаботаСФайлами.ДвоичныеДанныеФайлов`, мультиязычные HTML-фрагменты.
5. **Фаза 4. Обход и сборка.** Обходит дерево, накапливает фрагменты HTML, после сборки —
   `СтрСоединить`.
   - Корневые группы и подгруппы сортируются по возрастанию `ПолныйКод`; элементы внутри
     группы — так же (см. §10.8).
6. **Подстановка картинок.** `ГКСИ_MarkdownПереопределяемый.ЗаменитьКодыИзображенийНаDataURI`
   находит `<img src="КОД">` и `![alt](КОД)`, читает данные через
   `ГКСИ_ДанныеИзображенийMarkdownПовтИсп.СоответствиеКодДанные` (кеш сеанса), кодирует в
   `data:image/...;base64,...`.
7. **CSS.** Стиль ограничения ширины картинок вынесен в `<style id="album-imgs-style">…</style>`,
   содержимое формируется с учётом ширины картинок.
8. **Глоссарий.** После сборки HTML прогоняется через `ГКСИ_Глоссарий.ОбогатитьHTMLТерминами`.
9. Клиент получает готовый HTML и устанавливает в `ТекстHTML`.

### 10.4 Кеш изображений и серверное сжатие

Кеш `ГКСИ_ДанныеИзображенийMarkdownПовтИсп` (`ReturnValuesReuse = DuringSession`) кеширует
результат экспортной функции `СоответствиеКодДанные(КлючКеша)` в разрезе параметров на время
сеанса. Экспортная функция принимает **строку-ключ** вида `"<Код1>|<Код2>|...#<Ширина>"` —
это обходит ограничение платформы на типы параметров кешируемой функции (допустимы только
примитивы/ссылки/Структура; Массив не подходит). Парсинг ключа и реальное чтение выполняет
`ГКСИ_ДанныеИзображенийMarkdown.СоответствиеКодДанныеПоКлючу`.

Если максимальная ширина пикселей > 0, при первом чтении выполняется пропорциональный ресайз
через `ОбрабатываемаяКартинка`:

| Исходник | Целевой формат | Почему |
|----------|----------------|--------|
| JPEG/JPG | JPEG | Меньше base64 без потерь смысла |
| BMP | JPEG | Большой выигрыш (~10x) |
| PNG | PNG | Сохраняем прозрачность |
| GIF | PNG | Теряется анимация (некритично для инструкций) |
| SVG | (пропускаем) | Вектор, сжимать нечего |

### 10.5 Слайдер ширины картинок (без сервера)

Слайдер на клиенте вызывает `ГКСИ_ОбновитьСтильКартинок`: находит узел стиля
`album-imgs-style` в DOM и меняет `textContent`. Обращения к серверу нет, картинки не
перезагружаются, стиль применяется мгновенно.

### 10.6 Кнопка «Альбом процессов» в форме списка

В `ФормаСпискаДеревоГрупп` добавлена команда `АльбомПоВыделенным`, открывающая
`АльбомПроцессов` с параметром `ГруппыДляАльбома` (массив выбранных групп). Форма списка
также отвечает за древовидное отображение справочника (`ГКСИ_ПостроитьДерево`).

Из формы списка поддерево выделенных групп собирается серверно
(`ГКСИ_СобратьПоддеревоАльбомаНаСервере`) и передаётся в альбом через параметр
`ПоддеревоАльбомаАдрес`; модуль альбома перекладывает поддерево из ВХ с УИД формы списка
в ВХ с УИД текущей формы. Приоритет источников в `ГКСИ_СобратьАльбомНаСервере`:
`ПоддеревоАльбомаАдрес` → `ГруппыДляАльбома` → весь каталог.

### 10.7 Очистка памяти при закрытии формы

В обработчике `ГКСИ_ПередЗакрытием`:

```1c
Картинки = Элементы.ТекстHTML.Документ.images;
Для Индекс = 0 По Картинки.length - 1 Цикл
	Картинки[Индекс].src = "";
КонецЦикла;
Элементы.ТекстHTML.Документ.head.innerHTML = "";
Элементы.ТекстHTML.Документ.body.innerHTML = "";
ТекстHTML = "";
```

Порядок важен: сначала `src = ""`, потом `head.innerHTML = ""`, потом `body.innerHTML = ""`,
потом `ТекстHTML = ""`. Без этой последовательности WebKit удерживает декодированные
картинки в памяти до принудительного GC.

### 10.8 Сортировка по `ПолныйКод`

Действует единое правило «сначала группа с меньшим кодом, потом её элементы от меньшего к
большему, потом группа с большим кодом». Внутри каждой группы сценарии и подгруппы идут
**вперемешку** в порядке возрастания `ПолныйКод`. Сортировка строковая; коды имеют вид
`XXX.YY` с числовыми префиксами и ведущими нулями, поэтому лексикографический порядок
совпадает с числовым.

### 10.9 Сворачивание групп в альбоме

Каждая группа выводится сворачиваемым блоком `<details class="album-group-details">`:
заголовок группы помещён в `<summary class="album-group-summary">`, всё содержимое — после
`<summary>`. Все группы выводятся с атрибутом `open`. Сворачивание/разворачивание по клику —
нативное поведение WebKit, JS не используется.

Массовые команды «Развернуть всё» / «Свернуть всё» **удалены** (вместе с процедурами
`ГКСИ_ДобавитьКомандыСворачивания`, `ГКСИ_ДобавитьКомандуИКнопку`, `ГКСИ_РазвернутьВсеГруппы`,
`ГКСИ_СвернутьВсеГруппы`, `ГКСИ_УстановитьОткрытиеВсехГрупп`): сворачивание отдельных групп
остаётся нативным — по клику на `<summary>`, а командная панель формы теперь пуста и не
отображается, что дополнительно увеличивает место под тело альбома.

### 10.11 Компактная компоновка формы

Тело альбома должно занимать максимум места, поэтому форма собрана «сверху вниз»:

- корневая группа формы — `Vertical`: элементы идут друг под другом, а не колонками;
- `ТекстHTML` (HTMLDocumentField) растягивается и по горизонтали, и по вертикали, занимая
  всё окно;
- заголовок формы скрыт (`showTitle = false`) — экономит строку, название остаётся
  в заголовке окна;
- управление размером собрано в одну строку внизу: группа `ГруппаРазмера` с направлением
  `HorizontalIfPossible` содержит только ползунок `ШиринаКартинокЧисло` и поле выбора
  `ШиринаКартинокЕдиница`;
- никаких подписей на полосе нет: у обоих полей скрыты заголовки (`titleLocation = None`,
  `showInHeader = false`), назначение поясняют только всплывающие подсказки (`toolTip`):
  «Размер картинок и видео в описаниях альбома» и «Единица измерения размера:
  px, %, em, rem, vw, vh»;
- надпись-декорация «Размер 1 ⟵⟶ 200» (создавалась в `ГКСИ_ИнициализироватьПоляШирины`
  вместе с атрибутом формы `ШиринаКартинокДиапазон`) удалена;
- командная панель формы пуста (кнопки массового сворачивания удалены) и не отображается.

До этого группа управления стояла **справа** колонкой (корневая группа `AlwaysHorizontal`)
и постоянно отнимала у тела ширину, а над ней выводился заголовок «Группа управления».

### 10.10 Публичный API модуля `ГКСИ_АльбомПроцессов`

| Функция | Описание |

| `СобратьДокументАльбома()` | Полный альбом по всем корневым группам подсистемы множественной принадлежности |
| `СобратьДокументАльбомаПоГруппам(ГруппыДляАльбома)` | Альбом по выбранным группам. Если массив пуст — по всему каталогу |

## 11. Обработка `ГКСИ_ЗагрузкаСценариевИзMarkdown`

### 11.1 Назначение

Импорт иерархии групп и элементов в `ДемонстрационныеСценарии` из Markdown-файла. На входе —
`.md` (или `.txt`), на выходе — группы/элементы в справочнике, заполненный `ГКСИ_ТекстMarkdown`
у листов, присоединённые HTML-файлы в `ДемонстрационныеСценарииПрисоединенныеФайлы` и записи
в ТЧ `ОписанияСценария`.

Формат входа:

```text
# Группа 1
Текст группы (Markdown, опционально).
## Подгруппа 1.1
### Элемент 1.1.1
Текст элемента (Markdown).
```

Правила:

- заголовок `#` → уровень 2 в дереве, `##` → уровень 3, `###` → уровень 4;
- текст под заголовком до следующего заголовка того же или большего уровня становится
  Markdown-описанием узла;
- узел без дочерних → элемент, узел с дочерними → группа;
- повторный заголовок уровня с тем же именем переиспользует существующего ребёнка.

### 11.2 Состав

- `src/DataProcessors/ГКСИ_ЗагрузкаСценариевИзMarkdown/` — метаданные
  (`defaultForm = Форма`, `useStandardCommands = true`);
- `Forms/Форма/` — основная форма (`Form.form` + `Module.bsl`);
- `Forms/ФормаРазрешенияКонфликтов/` — форма разрешения конфликтов;
- `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/` — общий модуль серверной логики;
- `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdownДлительныеОперации/` — точка входа
  фонового задания.

### 11.3 Серверная логика (общий модуль)

Файл: `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`.
Настройки: `Server = true`, `ExternalConnection = true`, `ClientOrdinaryApplication = true`.

#### Экспортные функции

| Функция | Описание |
|---------|----------|
| `РазобратьMarkdownВДерево(АдресФайлаВоВременномХранилище, ИмяФайла = "")` | Читает двоичные данные, читает как UTF-8, возвращает `ДеревоЗначений` (колонки `Уровень`, `Наименование`, `ТекстMarkdown`, `Порядок`). Корневой узел (уровень 1) — служебная обёртка с именем файла без расширения |

|---------|-----|-------|

#### Парсер: алгоритм

`РазобратьMarkdownВДерево` использует **массив-стек**:

1. Корневая обёртка кладётся в стек (индекс 0).
2. Текст разбивается на строки через `СтрРазделить(ТекстФайла, Символы.ПС, Истина)`; `\r`
   отбрасывается.
3. Заголовки распознаются по ведущим `#` (`Уровень = Кол-воРешёток + 1`). После `#` должен
   идти пробел.
4. При появлении заголовка уровня N стек усекается до позиции `N − 2`; если у родителя уже
   есть ребёнок с тем же именем — он переиспользуется.
5. Обычная строка текста добавляется в `ТекстMarkdown` верхушки стека с `\n`.

#### Запись: алгоритм

`ЗаписатьДеревоВСправочник` для каждого узла:

1. Определяет `ЭтоГруппа = Узел.Строки.Количество() > 0`.
2. Достаёт решение по конфликту из `РешенияПоКонфликтам`:
   - `Пропустить` → запись не выполняется;
   - `Обновить` → перезапись существующего;
   - `Прикрепить к нашей группе` → использовать существующий узел; текст в БД не перезаписывается;
   - иначе → авто-резолв по предзагруженному кешу существующих узлов (см. §11.11).
3. `ЗаполнитьРеквизитыУзла` — проставляет `Наименование`, `ГКСИ_ТекстMarkdown` (через
   обёртку в маркеры языка), `ГКСИ_MarkdownСформирован = Истина`, `Статус = НаПроверке`.
   `Родитель` не заполняется (обнуляется в `ObjectModule`).
4. Для корневой обёртки инструкции явно задаётся
   `Код = ГКСИ_ГруппыСценариевСервер.ГКСИ_ПолучитьСледующийКодКорневойОбертки()`.
5. Если `Узел.ТекстMarkdown` заполнен — конвертирует в HTML и накапливает структуру
   `{Сценарий, КодЯзыка, ТекстHTML}` во внешнем накопителе `МассивHTMLПоУзлам` (см. §11.10).
6. `ОбъектУзла.Записать()`.
7. Регистрация в `ГКСИ_ГруппыСценариев`:
   - если есть родитель — `ДобавитьСценарийВГруппу(Ссылка, Родитель, КореньИнструкции)`;
   - иначе, если узел — корневая обёртка инструкции — `ЗарегистрироватьКорневуюГруппуИнструкции`.
8. Рекурсия по `Узел.Строки`.
9. После рекурсии для корневой обёртки — однократный
   `ПересчитатьПолныйКодДляПоддерева(Ссылка)`.
10. На исключение — `ОтменитьТранзакцию()`, строка результата с `Действие = "Ошибка"`.

### 11.4 Форма `Форма`

Файл: `src/DataProcessors/ГКСИ_ЗагрузкаСценариевИзMarkdown/Forms/Форма/Module.bsl`.

Реквизиты формы:

| Реквизит | Тип | Назначение |
|----------|-----|------------|
| `АдресФайлаВоВременномХранилище` | `Строка` | Адрес двоичных данных выбранного `.md`-файла |
| `ИмяФайла` | `Строка` | Полное имя выбранного файла |
| `ТекстПревью` | `Строка` (неогр.) | Содержимое файла для предпросмотра |
| `АдресДереваУзлов` | `Строка` | Адрес дерева узлов во временном хранилище |
| `АдресРешенийВоВременномХранилище` | `Строка` | Адрес соответствия решений по конфликтам |
| `АдресРезультатаЗагрузки` | `Строка` | Адрес таблицы результата загрузки |
| `КаталогРесурсов` | `Строка` | Путь к каталогу с ресурсами |
| `КаталогПоиска` | `Строка` | Дублирует `КаталогРесурсов` на момент записи |
| `ГКСИ_ИнструкцияИсточник` | `CatalogRef.ДемонстрационныеСценарии` | Явно выбранный корень-инструкция для импорта (см. §14) |

Сценарий работы (4 шага):

1. **Выбрать каталог** — клиентская команда `ВыбратьКаталог` (диалог выбора каталога,
   затем выбор конкретного `.md` из найденных).
2. **Загрузить файл** — `ЗагрузитьФайл` → серверная `ЗагрузитьФайлНаСервере`:
   читает файл в `ТекстПревью`, вызывает `РазобратьMarkdownВДерево`, при заполненном
   `КаталогПоиска` попутно подготавливает картинки.
3. **Проверить конфликты** — `ПроверитьКонфликты` → сбор имён, `НайтиСуществующихПоИмени`,
   при наличии конфликтов открывается `ФормаРазрешенияКонфликтов`.
4. **Выполнить загрузку** — `ВыполнитьЗагрузку` → вопрос Да/Нет → серверная
   `ВыполнитьЗагрузкуНаСервере`: восстанавливает дерево и решения, `КодЯзыка = "ru"`,
   `ЗаписатьДеревоВСправочник(...)`, `ОповеститьОбИзменении(...)`.

Загрузка выполняется **в фоновом задании** (`ДлительныеОперации.ВыполнитьВФоне` →
`ГКСИ_ЗагрузкаСценариевИзMarkdownДлительныеОперации.ЗаписатьДеревоФоново`), прогресс читается
из ВХ.

### 11.5 Форма `ФормаРазрешенияКонфликтов`

Принимает параметр `МассивКонфликтов` (массив структур `{ИмяИзФайла, СуществующаяСсылка,
СуществующееНаименование, СуществующееЭтоГруппа, ТекстИзФайла, СуществующийТекст}`). Показывает
таблицу с вариантами `Пропустить` / `Обновить` / `Дублировать` / `Прикрепить к нашей группе`.
По закрытию возвращает соответствие через `ОповеститьОВыборе`:

```text
Имя → {Действие, Ссылка, ТекстИзФайла}
```

При выборе «Прикрепить» для узлов, у которых текст из файла и существующий текст различаются,
открывается цепочка диалогов `ПоказатьВыборИзМеню` («Оставить из файла» / «Оставить наш» /
«Пропустить узел»).

### 11.6 Канал передачи HTML между обработками и `ObjectModule`

Любая серверная логика, записывающая элемент/группу `ДемонстрационныеСценарии` с
HTML-описанием, передаёт HTML через `ПараметрыЗаписи`/`ДополнительныеСвойства` по ключу
`"ГКСИ_АдресHTMLПоЯзыкам"` (адрес во временном хранилище, по адресу — `Соответствие`
КодЯзыка → HTML). Этот канал используют `ФормаЭлемента` и `ФормаГруппы`.

`ObjectModule.ГКСИ_ПриЗаписи`:

1. Пропускает `ОбменДанными.Загрузка`.
2. Пересчитывает `ПолныйКод`.
3. При непустом канале вызывает `ГКСИ_СоздатьПрисоединенныеФайлыИзДопСвойств(Ссылка)`:
   читает адрес, перечитывает объект для свежего `ПолныйКод`, для каждого языка находит/создаёт
   строку ТЧ `ОписанияСценария`, создаёт/обновляет присоединённый файл, записывает объект.

Создание файлов идёт **после** пересчёта `ПолныйКод` — имя файла строится из актуального кода.

### 11.7 Что НЕ делает обработка

- Не изменяет `ObjectModule.ДемонстрационныеСценарииПрисоединенныеФайлы` — присоединённые
  файлы создаются только через `ObjectModule.ДемонстрационныеСценарии`.
- Не использует типовое поле `Родитель` — иерархия строится через РС `ГКСИ_ГруппыСценариев`.
- Не парсит изображения при формировании HTML — вставки `![[...]]` / `![alt](path)`
  подменяются **до** конвертации в HTML на коды файлов инструкций через карту подмен.

### 11.8 Известные ложные срабатывания EDT

- `SU83` на `НСтр("ru = ...")` — EDT не подхватывает коды локализации из расширения.
- `SU29` на `Соответствие` без указания типа элемента коллекции.
- `SU18` на `Возвращаемое значение:` без конкретного типа.
- `SU72` на `&Перед`/`&После` в `ObjectModule`.

Все предупреждения — не блокирующие, на логику не влияют.

### 11.9 Загрузка картинок из Markdown (Obsidian `![[...]]` и `![alt](url)`)

Если при запуске обработки указан каталог ресурсов, вместе с текстом сценария загружаются и
встраиваются картинки. Поддерживаются варианты ссылок:

- `![[path]]` — Obsidian-синтаксис;
- `![[path|extra]]` — Obsidian с дополнительными полями (после `|` отбрасываются);
- `![alt](path)` — стандартный markdown.

Поиск идёт рекурсивно относительно каталога ресурсов; путь в `![[...]]` нормализуется
(обрезаются `#anchor` и `|alt`).

**Дедупликация (SHA-256).** Если файл с тем же содержимым уже загружался и существует в
`ГКСИ_ФайлыИнструкций` (по реквизиту `ХешSHA256`, индексирован), переиспользуется его `Код`.

**Алгоритм (без запросов в цикле).** Подготовка карты подмен вынесена в отдельную функцию
`ПодготовитьФайлыИнструкций(...)` (вызывается синхронно до старта фонового задания) либо
`ПодготовитьКартинкиДляДерева(...)` (внутри фона, для сценария «каталог на диске сервера»):

1. Собирает уникальные пути картинок из дерева.
2. Для каждого пути ищет файл и считает хеш (без обращения к БД).
3. Один пакетный запрос `ХешиСуществующихФайлов` собирает коды уже существующих элементов.
4. Для картинок без существующего кода вызывает `СоздатьЭлементФайлаИнструкции`.
5. Возвращает готовую карту `Соответствие("ОригинальныйПуть" → "КодФайла")`.

**Битые ссылки.** Если файл не найден: в журнал регистрации пишется предупреждение; в тексте
узла `![[path]]` заменяется на `❌ path`; запись узла продолжается.

### 11.10 Пакетное создание присоединённых HTML-файлов

HTML-файлы создаются одним проходом после записи всего дерева, а не на каждом узле.
Внешний массив структур `МассивHTMLПоУзлам` (`{Сценарий, КодЯзыка, ТекстHTML}`) накапливается
в `ОбработатьУзелРекурсивно` и передаётся через параметр.

`СоздатьПрисоединенныеHTMLФайлыПакетно(МассивСценариевИHTML, РазмерЧанка = 1)`:

1. Группирует элементы по `Сценарий`.
2. Разбивает на чанки; для каждого: `НачатьТранзакцию()` / `Попытка`; для каждого сценария —
   внутренний `Попытка`/`Исключение`; находит/создаёт строку ТЧ, создаёт/обновляет файл,
   при модифицированности ТЧ — `Записать()`.
3. Итог в ЖР: сколько сценариев, сколько файлов создано/обновлено, сколько ошибок.

**`РазмерЧанка = 1` по умолчанию** — атомарность на уровне одного сценария. Основной выигрыш —
от устранения повторной `ОбъектСценария.Записать()` после создания файла.

### 11.11 Авто-добавление родителя существующим узлам

При импорте нового MD-файла для каждого узла, который уже существует в `ДемонстрационныеСценарии`
с подходящим типом (группа/элемент), автоматически добавляется связь с родителем из текущего
MD в `ГКСИ_ГруппыСценариев` — даже если форма разрешения конфликтов не запускалась. Это
позволяет описывать одни и те же шаги в нескольких сценариях без дублей.

Алгоритм:

1. `ГКСИ_СобратьУникальныеИменаИзДерева(ДеревоУзлов)` — итеративный обход в глубину (без рекурсии).
2. Одним вызовом `НайтиСуществующихПоИмени(...)` получается кеш `Имя → Массив {Ссылка, ЭтоГруппа}`.

В `ОбработатьУзелРекурсивно`, если `РешениеПоУзлу = Неопределено`, вызывается
`ГКСИ_АвтоРезолвУзлаПоКешу(...)`: достаёт из кеша ссылки с тем же именем, фильтрует по признаку
«группа/элемент», при наличии одного подходящего возвращает решение «Обновить». При нескольких
подходящих берётся первый, в ЖР пишется предупреждение.

Дальнейшая ветка «Обновить» корректно добавляет связь с родителем через
`ДобавитьСценарийВГруппу` (идемпотентно).

## 12. Обработка `ГКСИ_ВыгрузкаСценариевВMarkdown`

Обратная операция к `ГКСИ_ЗагрузкаСценариевИзMarkdown`: выгружает инструкции (сценарии) из
базы в файлы Markdown.

### 12.1 Назначение и источник данных

- Источник текста — реквизит `ДемонстрационныеСценарии.ГКСИ_ТекстMarkdown` (мультиязычный
  формат с маркерами `<!--md:lang:КОД-->`). Конвертация HTML→Markdown не используется.
- Гранулярность: одна инструкция (корневая обёртка) → один `.md`-файл. Имя файла — наименование
  корневой обёртки.
- Языки: выгружается один выбранный язык (по умолчанию `ru`) через
  `ГКСИ_MarkdownФормаКлиентСервер.ПолучитьСегментMarkdown`.
- Картинки: сохраняются рядом с `.md`; ссылки `![](КОД)` разворачиваются обратно в `![[имя файла]]`.

### 12.2 Состав

| Объект | Расположение | Назначение |
|--------|--------------|------------|
| Обработка `ГКСИ_ВыгрузкаСценариевВMarkdown` | `src/DataProcessors/ГКСИ_ВыгрузкаСценариевВMarkdown/` | Точка входа, форма |
| Общий модуль `ГКСИ_ВыгрузкаСценариевВMarkdown` | `src/CommonModules/…/Module.bsl` | Серверная логика выгрузки |
| Общий модуль `ГКСИ_ВыгрузкаСценариевВMarkdownДлительныеОперации` | `src/CommonModules/…/Module.bsl` | Точка входа фонового задания |

### 12.3 Серверный программный интерфейс

- `ПолучитьКорневыеОберткиИнструкций()` — массив корневых обёрток (самоссылки РС:
  `Сценарий = Группа = КореньИнструкции`), упорядочен по коду.
- `ПолучитьКорневуюОберткуИнструкции(Ссылка)` — корневая обёртка для произвольного узла.
- `ПодготовитьФайлыКВыгрузке(МассивКорней, КодЯзыка, АдресПрогресса = "")` — главная функция.
  Возвращает структуру `{Файлы, Ошибки, ОбработаноИнструкций}`, где `Файлы` — массив структур
  `{ИмяФайла, ДвоичныеДанные, ЭтоКартинка}`.

### 12.4 Алгоритм `ПодготовитьФайлыКВыгрузке`

1. **Этап 1 (0–10%).** Сбор узлов всех инструкций: `СвязиГруппПоКорням()` строит связи по каждому
   корню (измерение `КореньИнструкции`) одним запросом; `СобратьУзлыРекурсивно` обходит поддерево.
   Затем один запрос `ТекстыИНаименованияПоСсылкам` читает наименования и тексты всех узлов.
2. **Этап 2 (10–30%).** Для каждой инструкции формируется текст: `СобратьТекстИнструкции` выводит
   заголовки (`Уровень 2 → #`, `3 → ##`, …, корневая обёртка уровня 1 — только имя файла) и
   сегмент языка узла. Из текстов собираются коды картинок; `ПодготовитьКартинки` одним запросом
   читает `ГКСИ_ФайлыИнструкций` и присваивает файлам уникальные имена.
3. **Этап 3 (30–100%).** `РазвернутьСсылкиНаКартинки` заменяет `![](КОД)` на `![[имя]]`;
   формируются `.md`-файлы (UTF-8 без BOM), затем добавляются файлы картинок.

### 12.5 Форма и сохранение на диск

- Реквизиты: `ГКСИ_ИнструкцияИсточник` (корень), `КодЯзыка`, `КаталогВыгрузки`,
  `ПроцентГотовности`, `ТекстПрогресса`, `АдресПрогресса`, `АдресРезультата`,
  `ИдентификаторЗадания`.
- Команды: `Выгрузить`, `ВыгрузитьВсе`, `ВыбратьКаталог`.
- Выгрузка выполняется **в фоновом задании** (`ДлительныеОперации.ВыполнитьВФоне` →
  `ГКСИ_ВыгрузкаСценариевВMarkdownДлительныеОперации.ПодготовитьФайлыФоново`), прогресс читается
  из ВХ. По завершении форма помещает каждый файл в ВХ с УИД формы и сохраняет их в выбранный
  каталог через `НачатьПолучениеФайловССервера`. Существующие файлы перезаписываются.

### 12.6 Ограничения

- Полноценной серверной конвертации HTML→Markdown в расширении нет (она клиентская, через
  HTMLDocumentField + `showdown.makeMarkdown`) — выгрузка опирается только на `ГКСИ_ТекстMarkdown`.
- Текст хранится нормализованным (строки соединены `\n`, пустые строки потеряны при загрузке) —
  round-trip не гарантирует байтовое совпадение с исходным `.md`.

## 13. Глоссарий (интеграция с типовым справочником `Catalog.Глоссарий`)

Используется типовой справочник `Catalog.Глоссарий` основной конфигурации ERP **без
заимствования в расширение**. Реквизиты: `НаименованиеЯзык1`, `НаименованиеЯзык2`,
`ХэшДанныхПоставщика`. Табличная часть `ОбъектыКонфигурации` связывает термин с объектами
метаданных через `CatalogRef.ИдентификаторыОбъектовМетаданных` (или `…Расширений`).
Табличная часть `ОписанияГлоссария` хранит описания по языкам в реквизите `Описание`
(тип `ХранилищеЗначения`).

### 13.1 Серверные модули глоссария

| Модуль | Назначение |
|--------|------------|
| `ГКСИ_Глоссарий` | Чтение терминов (фильтр по объектам метаданных и без), выбор наименования по языку, извлечение описания из `ХранилищеЗначения`, идентификация объекта метаданных по ссылке, обогащение HTML терминами |
| `ГКСИ_ТерминыГлоссарияПовтИсп` | Кеш терминов с `ReturnValuesReuse = DuringSession`. Возвращает массив структур `{Ссылка, Наименование, Описание}` для активного языка |

### 13.2 Форма выбора термина

`CommonForm.ГКСИ_ВыборТерминаГлоссария` — общая форма с таблицей терминов (`Ссылка`,
`Наименование`, `Описание`) и полем поиска по подстроке наименования. Список заполняется
`ГКСИ_Глоссарий.ТерминыПоОбъектамМетаданных`: при отборе по объектам метаданных источник —
табличная часть `Справочник.Глоссарий.ОбъектыКонфигурации`, без отбора — все неудалённые
элементы `Справочник.Глоссарий` (термины без привязки к объектам тоже попадают в список).
Результат выбора — XML-представление ссылки на термин (`Закрыть(ВыбраннаяСсылка)`).
Открывается из подсистемы Markdown (кнопка «Глоссарий»); после выбора термин вставляется в
текст Markdown как Markdown-ссылка на карточку термина —
`ГКСИ_MarkdownСерверВызовСервера.ФрагментСсылкиНаТерминГлоссария` формирует
`[Наименование](e1cib/data/Справочник.Глоссарий?ref=…)`, где наименование локализовано
(`ГКСИ_Глоссарий.НаименованиеТерминаПоЯзыку`).

### 13.3 Панель глоссария на формах сценариев

В `Form.form` заимствованных форм `ДемонстрационныеСценарии.ФормаЭлемента` и `ФормаГруппы`
декларативно объявлена таблица `ГКСИ_ТерминыГлоссария` (`ValueTable`) с колонками `Ссылка`
(String(36)), `Наименование` (String(150)), `Описание` (String, неогр.). В `Module.bsl`
программно добавляется группа `РМ_СтраницаГлоссарий` с таблицей формы, привязанной к этому
реквизиту; группа встраивается в страницу `СтраницаСвязи`. Таблица заполняется через
`ГКСИ_Глоссарий.ТерминыПоОбъектамМетаданных`, отфильтрованным по идентификатору метаданных
текущего сценария/группы.

### 13.4 Обогащение HTML

`ГКСИ_Глоссарий.ОбогатитьHTMLТерминами(HTML, КодЯзыка)`:

1. Загружает термины через кеш `ГКСИ_ТерминыГлоссарияПовтИсп`.
2. Сортирует термины по убыванию длины наименования (чтобы избежать частичных пересечений).
3. Исключает из обработки содержимое `<code>`, `<pre>`, `<a>` (через
   `СтрНайтиВсеПоРегулярномуВыражению` + плейсхолдеры).
4. Для каждого термина экранирует спецсимволы и ищет целое слово через
   `СтрЗаменитьПоРегулярномуВыражению` с lookbehind/lookahead. Термин оборачивается в
   `<span class="gksi-term" data-term-guid="<GUID>" title="<описание>">…</span>`.
5. Восстанавливает исключённые фрагменты.

Точки вызова: `ГКСИ_АльбомПроцессов.СобратьДокументАльбома...` (обогащение после сборки всего
документа).

### 13.5 Локализация

Подбор термина под язык:

- `КодЯзыка = "ru"` → `НаименованиеЯзык1` (с фолбэком на `Наименование`).
- Любой другой → `НаименованиеЯзык2` (с фолбэком на `Наименование`, затем `НаименованиеЯзык1`).
- Описание берётся из ТЧ `ОписанияГлоссария` по `КодЯзыка`.

Текущий код языка получается через `ГКСИ_Глоссарий.ТекущийКодЯзыка()`.

### 13.6 Страничная структура форм сценария

Формы `ФормаЭлемента` и `ФормаГруппы` разложены по страницам (конструктор форм):

- `ГруппаШапка` (вне страниц): переключаемые страницы шапки
  `СтраницыШапкаВариантыОтображения` (наименование, код, тип группы) и поле `ПолеСтатус`
  (`Объект.Статус`);
- `СтраницыОсновные`:
  - `СтраницаОписание` — первая и основная: Markdown-редактор и просмотр;
  - `СтраницаСвязи` — связанные объекты, профили групп доступа, панель «Входит в группы»
    и глоссарий (обе панели создаются программно и встраиваются в эту страницу);
  - `СтраницаСогласование` — таблица `Подписанты`;
  - `СтраницаДополнительно` — комментарий.

Поле `Родитель` и поле «Ширина картинок и видео» с форм убраны (реквизит `ШиринаКартинок`
остался — значение по умолчанию используется при сборке HTML). Колонки таблицы подписантов
имеют осмысленные имена: `ПолеПодписант`, `ПолеЭтап`, `ПолеРезультат`, `ПолеКомментарий`,
`ПолеДатаСогласования`, `ПолеВерсия`, `ПолеУзел` (только в форме группы).

### 13.7 Markdown-редактор в конструкторе формы

Статическая часть редактора объявлена декларативно в `Form.form` обеих форм, а не создаётся
в рантайме:

- `РМ_Страницы_ТекстMarkdownСтрока` — переключатель страниц;
- `РМ_Страница_Редактирование_ТекстMarkdownСтрока` — панель `РМ_КомманднаяПанель_Редактирование_ТекстMarkdownСтрока`
  (подменю `РМ_ПодменюВставитьЗагруженноеИзображение_ТекстMarkdownСтрока` и 19 команд/кнопок
  форматирования: жирный, курсив, зачёркнутый, заголовки 1–3, цитата, ссылка, код, списки,
  таблица, изображение из буфера, файл, справка по синтаксису, глоссарий, ссылка на узел, видео),
  поле ввода `РМ_ТекстMarkdownСтрока`, группа `РМ_НовыеПрисоединенныеФайлы_ТекстMarkdownСтрока`;
- `РМ_Страница_Просмотр_ТекстMarkdownСтрока` — HTML-просмотр `РМ_ПолеПросмотра_ТекстMarkdownСтрока`;
- реквизиты формы `РМ_ПолеПросмотра_ТекстMarkdownСтрока` и `РМ_ТаблицаПрисоединенныхФайлов_ТекстMarkdownСтрока`
  (колонки `Ссылка`, `ПутьКФайлу`, `ИмяФайла`, `Адрес`, `ЭтоНовый`);
- панель глоссария `РМ_СтраницаГлоссарий` с таблицей `РМ_ТаблицаГлоссария`;
- кнопка-тумблер `ГКСИ_ПереключитьРежим` в шапке.

Программным остаётся только то, что зависит от данных: группы и кнопки присоединённых файлов
(`ВывестиЭлементыПрисоединенногоФайлаНаФорму`) и панель «Входит в группы»
(`ГКСИ_ГруппыСценариевСервер.ДобавитьПанельГруппСценария`). Все процедуры создания элементов
в `ГКСИ_MarkdownСерверВызовСервера.ВставитьПолеРедактированияТекстаНаФорму` и в панелях форм
сначала проверяют наличие элемента по имени, поэтому код совместим и с декларативной формой,
и со старой конфигурацией формы. Каждая команда форматирования имеет в модуле формы
собственный обработчик-обёртку (требование проверки SU116), делегирующий в
`РМ_Подключаемый_ОбработкаКомандыПоляКомментария`.

## 14. Изоляция узлов по корню инструкции (`КореньИнструкции`)

### 14.1 Бизнес-правило

В форме `ФормаСпискаДеревоГрупп` различаются **группы** и **элементы**:

- **Группа** (подпроцесс) — общий контейнер, может входить в несколько инструкций (например,
  ГИП и ДМТО). Отображается во всех ветках, где есть связь в РС `ГКСИ_ГруппыСценариев`.
- **Элемент** (конкретный шаг роли) — отображается только в ветке той инструкции, в которой
  он был создан.

### 14.2 Хранение

Точный механизм — измерение `КореньИнструкции` в РС `ГКСИ_ГруппыСценариев` (см. §4.3): каждая
связь `(Сценарий, Группа)` несёт корневую инструкцию, в которой была создана при загрузке MD.
Дополнительный ресурс `КодВКонтексте` хранит полный код сценария в контексте этого корня.

Реквизит справочника `ГКСИ_ИнструкцияИсточник` — **устаревший** (Deprecate), оставлен для
обратной совместимости. Ранее (версии 1.78) изоляция строилась на нём; в 1.85+ замещён
измерением `КореньИнструкции`.

### 14.3 Запись при загрузке MD

В `ОбработатьУзелРекурсивно` при создании связи `(Сценарий, Группа)` передаётся третий параметр
`КореньИнструкции`. `ДобавитьСценарийВГруппу` и внутренняя `ГКСИ_ЗаписатьПолныйКодКонтекстный`
записывают значение в измерение и ресурс. Если для пары `(Сценарий, Группа)` уже есть запись с
этим корнем — обновляется ресурс; иначе создаётся новая запись.

### 14.4 Явная передача корня через форму загрузки

В форме загрузки есть поле `ГКСИ_ИнструкцияИсточник` (тип `CatalogRef.ДемонстрационныеСценарии`),
позволяющее выбрать корневую группу-инструкцию для импорта. Параметр передаётся по цепочке:

```text
Форма (поле ГКСИ_ИнструкцияИсточник)
  → ЗапуститьЗаписьДереваВФоне (структура параметров фонового задания)
    → ЗаписатьДеревоФоново (модуль ДлительныеОперации)
      → ЗаписатьДеревоВСправочник
        → ОбработатьУзелРекурсивно
```

Приоритет в `ОбработатьУзелРекурсивно`: явно переданный `ИнструкцияИсточник` → иначе первый
`#`-заголовок (уровень 2) → иначе наследование от родителя. Без заполнения поля работает
fallback на первый `#`-заголовок.

### 14.5 Фильтр Альбома по корню

`ГКСИ_АльбомПроцессов.ГКСИ_ОтфильтроватьУзлыПоИнструкции(...)` строит фильтрацию запросом к
РС по измерению `КореньИнструкции`:

```text
ВЫБРАТЬ Сценарий ИЗ РС.ГКСИ_ГруппыСценариев
ГДЕ КореньИнструкции В (&КорневыеИнструкцииАльбома)
```

Узел показывается в альбоме, если существует хотя бы одна связь в РС с корнем, входящим в
корневые инструкции альбома. Это решает оба ограничения: уникальные шаги одной роли не попадают
в чужой альбом, а общий шаг попадает в оба альбома.

### 14.6 Пересчёты с учётом корня

Все процедуры пересчёта сохраняют/восстанавливают `КореньИнструкции` из существующих записей РС:

- `ПересчитатьПолныйКодДляПоддереваГрафа` — для каждой группы поддерева запросом получает список
  корней и для каждого корня пересчитывает коды;
- `ПересчитатьПолныйКодКонтекстныйДляСценария` — собирает все пары `(Группа, КореньИнструкции)`
  и для каждой пересчитывает код в контексте её корня;
- `ГКСИ_ПересчитатьВсеКодыВРегистре` — глобальный пересчёт итерирует по записям, сохраняя каждую
  тройку `(Сценарий, Группа, КореньИнструкции)` в её корне.

`ГКСИ_ЗаписатьПолныйКодКонтекстный(Сценарий, Группа, ПолныйКод, КореньИнструкции)` формирует
набор записей регистра с тремя элементами отбора.

## 15. Роли и безопасность

- В файлах ролей `ГКСИ_РедактированиеИнструкций` и `ГКСИ_ЧтениеИнструкций` (`.mdo`) условия RLS
  (`<rlsCondition>` / `<restrictionTemplate>`) не определены — права на уровне записей не задаются.
- Роль `ГКСИ_ЧтениеИнструкций` дополнена правами, достаточными для просмотра описаний процессов
  и формирования альбома процессов:
  - `Read` на `InformationRegister.ГКСИ_ГруппыСценариев`;
  - `Read` на `Catalog.ДемонстрационныеСценарии`, `View` на формы `ФормаЭлемента`, `ФормаГруппы`,
    `ФормаСпискаДеревоГрупп`;
  - `View` и `Use` на форму `АльбомПроцессов`;
  - `Read` на `Catalog.ДемонстрационныеСценарииПрисоединенныеФайлы`;
  - на уровне атрибутов и стандартных реквизитов `Catalog.ГКСИ_ФайлыИнструкций` заданы
    `View=false, Edit=false`; `Read=true` наследуется от родительского объекта.
- Права на уровне шагов (в старой модели) реализовывались программно; в новом составе объекты
  шагов/инструкций удалены (см. §17).

## 16. Особенности, ограничения, ложные срабатывания EDT

### 16.1 Особенности хранения данных

- **Файлы инструкций хранятся в справочнике `ГКСИ_ФайлыИнструкций`.** Код = GUID (строка 36).
  Файл хранится в реквизите `Файл` типа `ХранилищеЗначения`. Имя в Markdown заменяется на код
  при сохранении.
- **Изображения в Markdown вставляются как `![](Код)`.** При рендеринге HTML коды подменяются
  на data URI.
- **Мультиязычный Markdown** хранится в одном реквизите `ГКСИ_ТекстMarkdown` с разделителями
  `<!--md:lang:...-->`. Параллельно поддерживается совместимость с типовым механизмом HTML-файлов
  по языкам.
- **Множественная принадлежность к группам** — через РС `ГКСИ_ГруппыСценариев`, с изоляцией по
  корню инструкции (`КореньИнструкции`).

### 16.2 Особенности кода

- **Директивы компиляции** в общих модулях подсистемы (`ГКСИ_Markdown*`) не используются — модули
  помечены в `.mdo` как «Клиент» / «Сервер» / «КлиентСервер».
- **Аннотации `@skip-warning`** используются на процедурах-делегатах `РМ_Подключаемый_*` и на
  программно создаваемых обработчиках команд.
- **Программное построение форм.** Подсистема редактора добавляет реквизиты, элементы, команды
  и обработчики к управляемой форме через `ИзменитьРеквизиты()` и `Элементы.Добавить()`, не
  модифицируя `.form`-файлы.
- **Использование HTMLDocumentField.** Поле просмотра — `HTMLDocumentField`; содержимое
  формируется из общих макетов `ГКСИ_showdown` + `ГКСИ_highligthjs` + пользовательских стилей,
  обновляется через функцию `markdownConvert()`.
- **Использование Native-компоненты `ClipboardControl`** для вставки изображений из буфера
  (общий макет `ГКСИ_КомпонентаДляРаботыСБуферомОбмена`).
- **Расширение не меняет типовые обработчики** формы `ДемонстрационныеСценарии`, а дополняет их
  через `&Перед` / `&После` (кроме трёх команд внешнего HTML-редактора — см. §7.6).

### 16.3 Ограничения текущей реализации

- `ГКСИ_MarkdownКлиентПереопределяемый.ОткрытьПрисоединенныйФайлПоСсылке` — заглушка.
- `ГКСИ_MarkdownПереопределяемый.ЗаполнитьПрисоединенныеФайлыКОбъекту` и `ПриПолученииДанныхФайла`
  — заглушки.
- Добавление/удаление файлов в Markdown вызывает событие `"ГКСИ_ОбновитьФайлыBase64"`,
  обрабатываемое в `ГКСИ_ПослеОбработкаОповещения`.
- Модули `ДемонстрационныеСценарииВызовСервера`, `ДемонстрационныеСценарииКлиент`,
  `ДемонстрационныеСценарииКлиентСервер` — заимствованные (Adopted); код расширяется
  механизмом расширений.
- Миграция старых записей регистра в формат с `КореньИнструкции` не автоматизирована: после
  обновления нужно заново загрузить MD-файлы.

### 16.4 Известные ложные срабатывания EDT

- `SU83` на `НСтр(...)` — локализация расширения.
- `SU29`, `SU18`, `SU58`, `SU78` — на документирующих комментариях к гетерогенным коллекциям.
- `SU72` — на `&Перед`/`&После` в `ObjectModule`.
- `SU95` (запрос в цикле) — подавляется `@skip-warning SU95` там, где цикл является логическим
  обходом зависимостей графа (не «горячий» цикл).
- `SU220` на присваивании `Код` справочника `ДемонстрационныеСценарии` — ложное срабатывание
  (тип заимствованного реквизита не разрешается статически).

## 18. Вики-ссылки на группы и шаги (`[[…]]`)

Ссылки в Markdown-текстах описаний сценариев на другие группы/шаги — аналог ссылок на
документы в Obsidian. Полное описание — `AGENTS/отчёт/ОТЧЁТ_ВикиСсылкиНаГруппыИШаги.md`.

### 18.1 Синтаксис

```text
[[Имя группы или шага]]
[[Имя группы или шага|Отображаемый текст]]
[[КодВКонтексте|Отображаемый текст]]
```

`![[…]]` — картинка, ссылкой не считается (обрабатывается механизмом картинок, см. §11.9).

### 18.2 Разрешение цели

Общий модуль `ГКСИ_СсылкиСценариев` (сервер) строит карту узлов двумя пакетными запросами
(связи РС `ГКСИ_ГруппыСценариев` + реквизиты узлов). Порядок разрешения:

1. по `КодВКонтексте` — однозначный идентификатор;
2. по наименованию — **только если оно уникально** в пределах карты.

Неразрешённая цель превращается в `<span class="gksi-link-broken" title="Ссылка не найдена: …">`.
Карта строится по корню инструкции (`КореньИнструкции`) текущего узла, для альбома — по всем
корням, представленным в альбоме.

### 18.3 Точки отображения

| Место | Как работает |
|---|---|
| Предпросмотр Markdown | JS-предобработка в `ГКСИ_MarkdownСерверВызовСервера` до конвертации showdown; карта передаётся как `window.__gksiLinks` |
| Сохранённый HTML описания (присоединённый файл) | HTML пишется при записи объекта (`ГКСИ_MarkdownФормаСервер.СоздатьПрисоединенныеФайлыИзДопСвойств`, `СоздатьПрисоединенныйФайлСценария`, `Catalog.ДемонстрационныеСценарии.ObjectModule`) и перед сохранением прогоняется через `ПодставитьСсылкиВТекст(…, "Навигация")` — ссылки разбираются на сервере, поэтому типовые поля «Текст сценария» / «Текст сценария (чтение)» показывают готовые `<a>` независимо от JS-предпросмотра. Подстановка идемпотентна |
| Формы элемента и группы | `href` = навигационная ссылка 1С; клик обрабатывает `ГКСИ_MarkdownКлиент.ПриНажатииПоляПросмотраКомментария` через `ПерейтиПоНавигационнойСсылке` |
| Альбом процессов | Описания обрабатываются `ПодставитьСсылкиВТекст(…, "Навигация")`, затем ссылки на узлы альбома переписываются на `#gksi-node-<uuid>` |

Разметка ссылки (порядок атрибутов обязателен — на него опирается переписывание на якоря):

```html
<a class="gksi-link" href="<адрес>" data-gksi-anchor="<якорь>">текст</a>
```

### 18.4 Якоря альбома и перехват нажатия

- Разделы альбома получают `id="gksi-node-<uuid>"`: у групп — на `<details>`, у шагов — на `<tr>`.
- Клик по внутреннему якорю обрабатывает перехватчик `&Вместо("ТекстHTMLПриНажатии")` в модуле
  формы `АльбомПроцессов`: раскрывает свёрнутые `<details>` по пути к цели и выполняет
  `scrollIntoView`. Прочие адреса делегируются типовому
  `ДемонстрационныеСценарииКлиент.ПриНажатииВПолеHTMLДокумента`.
- Перехват нужен потому, что типовой обработчик подавляет стандартную обработку для любой
  непустой ссылки и пытается открыть `#gksi-node-…` как навигационную ссылку.

### 18.5 Вставка ссылки в текст

Кнопка **«Ссылка на группу или шаг»** на панели Markdown-редактора открывает форму выбора
`Catalog.ДемонстрационныеСценарии.Form.ГКСИ_ФормаВыбораГруппы` — таблицу всех узлов всех
инструкций (колонки «Группа / шаг», «Код», «Группа», «Инструкция»). Форма закрывается методом
`Закрыть(Результат)` и возвращает структуру `{Ссылка, ЭтоГруппа, Фрагмент}`, где `Фрагмент` —
готовый `[[Код|Наименование]]` (`ГКСИ_СсылкиСценариев.ФрагментСсылкиДляУзла`); он подставляется
в позицию курсора. Ссылку можно и просто набрать руками.

**Параметров открытия у формы нет** — объявлять их в редакторе формы не требуется (ранее форма
принимала `РежимВыбора`/`СсылкаУзла`/`ИсключаемыеГруппы`, но они не были объявлены и молча
отбрасывались платформой). Контекст проверяет вызывающая сторона:

| Вызывающий | Использует | Что проверяет сам |
|---|---|---|
| `ГКСИ_MarkdownКлиент` (вставка ссылки) | `Фрагмент` | фрагмент не пуст |
| `ФормаЭлемента`, `ФормаГруппы` («Добавить группу») | `Ссылка` | нужна группа, не сама себя, без дублей; в форме группы — ещё и без потомков (защита от цикла) |
| Обработки выгрузки и загрузки (выбор инструкции-источника) | `Ссылка` | нужна группа |

### 18.6 Что не меняется

Загрузка/выгрузка Markdown: `[[…]]` хранятся в `ГКСИ_ТекстMarkdown` как есть, преобразование
выполняется только при отображении — round-trip тождественный.

## 19. Согласование инструкций (бизнес-процесс `ГКСИ_СогласованиеИнструкции`)

Инструкцию целиком или её отдельный узел (группу/шаг) можно отправить на согласование:
сначала согласуют начальники отделов, затем — подчинённые этих начальников.
Участники выбираются в первой задаче процесса.

### 19.1 Состав объектов

| Объект | Назначение |
|---|---|
| `BusinessProcess.ГКСИ_СогласованиеИнструкции` | процесс согласования. Реквизиты: `Предмет`, `ВидСогласования`, `КорневаяИнструкция`, `Автор`, `Наименование`, `Комментарий`, `РезультатСогласования`, `ДатаНачала`, `ДатаЗавершения` |
| ТЧ `Начальники`, ТЧ `Подчинённые` | участники этапов: `Сотрудник`, `РезультатСогласования`, `Комментарий`, `ДатаСогласования`, `НомерВерсии` |
| `Enum.ГКСИ_ВидыСогласованияИнструкций` | `ВсяИнструкция` / `ЭлементИнструкции` |
| `Enum.ГКСИ_РезультатыСогласованияИнструкций` | `Согласовано` / `НеСогласовано` |
| `Task.ЗадачаИсполнителя` (заимствована) | тип задачи процесса; собственные формы задач `ГКСИ_ФормаЗадачиНазначенияУчастников` и `ГКСИ_ФормаЗадачиСогласования` |
| `CommonModule.ГКСИ_СогласованиеИнструкцийСервер` | `ОпределитьКорневуюИнструкцию`, `ЗапуститьСогласование`, `ПараметрыОткрытияПервойЗадачи`, `УстановитьСтатусСогласования`, `ОбеспечитьВерсионированиеИнструкций`, `НомерВерсииСогласуемогоУзла`, `ПодписантыПоПредмету` |

### 19.2 Маршрут

`НазначитьУчастников` → `СогласованиеНачальниками` → `СогласованиеПодчинёнными` →
`ОбработкаРезультата` → `Завершение`.

- На точке `НазначитьУчастников` исполнитель (автор) заполняет табличные части `Начальники`
  и `Подчинённые` в форме `ГКСИ_ФормаЗадачиНазначенияУчастников`. Участники записываются
  в бизнес-процесс обработчиком формы `ПередВыполнением` — так они попадают в процесс
  независимо от того, чем завершают задачу (кнопкой «Назначить участников» или стандартной
  командой формы задачи «Выполнена»); при незаполненных начальниках выполнение отменяется
  (`Отказ = Истина`). Без такой записи следующая точка создаёт нуль задач и процесс остаётся
  незавершённым.
- На каждом этапе согласования задача создаётся **каждому** участнику соответствующей
  табличной части (`СоздатьЗадачиПоУчастникам`): исполнитель, точка маршрута и срок
  проставляются при создании задачи.
- Согласующий фиксирует результат в форме `ГКСИ_ФормаЗадачиСогласования`
  («Согласовать» / «Отклонить» с обязательным комментарием): результат, комментарий, дата
  и номер текущей версии узла пишутся в строку участника, затем задача выполняется.

### 19.3 Запуск

Кнопка «Отправить на согласование» размещена:

- в форме группы — согласование всей инструкции (`ВидСогласования = ВсяИнструкция`);
- в форме элемента — согласование отдельного узла (`ЭлементИнструкции`);
- в форме списка-дерева групп — по выделенным узлам (вид определяется сравнением узла
  с его корневой инструкцией).

Формы вызывают `ГКСИ_СогласованиеИнструкцийСервер.ЗапуститьСогласование(Предмет, ВидСогласования)`,
который создаёт процесс, заполняет `Предмет`, `ВидСогласования`, `КорневаяИнструкция`,
`Автор` и стартует его. Повторный запуск по предмету с незавершённым процессом запрещён
(`СтартПередСтартом` → `ЕстьАктивныйПроцессПоПредмету`).

Сразу после запуска открывается форма первой задачи процесса (назначение участников):
`ГКСИ_СогласованиеИнструкцийСервер.ПараметрыОткрытияПервойЗадачи(Процесс)` находит первую
невыполненную задачу бизнес-процесса и возвращает имя формы и параметры её открытия
(форма выбирается штатно через `БизнесПроцессы.ГКСИ_СогласованиеИнструкции.ФормаВыполненияЗадачи`).
Серверные обработчики запуска в формах группы, элемента и списка-дерева групп возвращают
эти параметры, а клиентские команды «Отправить на согласование» открывают форму задачи
методом `ОткрытьФорму`.

### 19.4 Статусы

Статус согласования (`Статус`, перечисление `СтатусыДемонстрационныхСценариев`: `ВРаботе`,
`НаПроверке`, `ЕстьЗамечания`, `Проверено`) меняет `УстановитьСтатусСогласования`:

- при старте процесса затрагиваемым узлам ставится `НаПроверке`, по итогу согласования —
  `Проверено` или `ЕстьЗамечания`;
- если согласуется вся инструкция (согласуемый объект совпадает с корневой группой), статус
  получают **все группы и элементы** инструкции — состав берётся одним запросом из регистра
  `ГКСИ_ГруппыСценариев` по измерению `КореньИнструкции`; если согласуется некорневая группа
  или элемент — статус получает только этот узел;
- запись статуса выполняется с `ОбменДанными.Загрузка`, чтобы не запускать пересчёт кодов
  и пересборку присоединённых HTML на каждом узле.

При изменении текста сценария (реквизит `ГКСИ_ТекстMarkdown`, из которого при записи
формируется присоединённый HTML описания) статус изменённого элемента или группы сбрасывается
в `НаПроверке` — в `ГКСИ_ПередЗаписью` объектного модуля справочника.

Статус выводится колонкой «Статус» в форме списка `ФормаСпискаДеревоГрупп` (основная форма
списка справочника).

### 19.5 Роли

Права на бизнес-процесс выданы ролям `ГКСИ_ЧтениеИнструкций` (просмотр),
`ГКСИ_РедактированиеИнструкций` и `ГКСКОсновнаяРоль` (полный набор).

### 19.6 Прослеживаемость согласования и версии

**Форма бизнес-процесса** (`ФормаБизнесПроцесса`) показывает ход согласования:

- страница «Ход согласования» — единый динамический список `ХодСогласования` (произвольный
  запрос, только просмотр), объединяющий участников процесса и его задачи: колонка
  «Тип записи» показывает «Процесс» (строки табличных частей `Начальники`/`Подчинённые`)
  или «Задача» (строки `Задача.ЗадачаИсполнителя`), далее — этап (точка маршрута), участник,
  задача, результат, комментарий, дата, номер версии, отметка выполнения. Запрос сводит
  табличные части процесса и таблицу задач по текущему процессу
  (`УстановитьПараметрыДинамическихСписков`). Настоящая иерархия «этап → задачи» динамическим
  списком не строится (родитель и дети — разнородные сущности), поэтому выбран плоский
  список с признаком типа записи;
- страница «Задачи процесса» — динамический список `ЗадачиПроцесса` (произвольный запрос,
  только просмотр): задача, этап (точка маршрута), отметка выполнения, дата; отбор по
  бизнес-процессу. Собственные реквизиты заимствованной задачи (срок, результат,
  исполнитель) модель расширения не видит — доступны только стандартные поля задачи;
- списки участников на страницах «Начальники»/«Подчинённые» — только для чтения
  (состав участников задаётся в первой задаче процесса);
- двойной клик по строке открывает то, на что указывает пользователь: в «Ходе согласования»
  по строке задачи (колонка «Тип записи» = «Задача») — задачу бизнес-процесса, по колонке
  участника — карточку (`Справочник.Пользователи.Форма.ФормаЭлемента`), по остальным
  колонкам строки процесса — карточку самого бизнес-процесса в новом окне; в
  «Задачах процесса» — задачу бизнес-процесса (`ФормаВыполненияЗадачи`);
- поле `Состояние` — «Не начато» / «В процессе согласования» / «Согласовано» /
  «Не согласовано»; условным оформлением просроченное состояние выделяется цветом
  (`СостояниеПросрочено` — плановая дата завершения раньше текущей).

**Версионирование инструкций** — штатное БСП-версионирование объектов:

- `ГКСИ_СогласованиеИнструкцийСервер.ОбеспечитьВерсионированиеИнструкций` включает
  версионирование справочника `ДемонстрационныеСценарии` (вариант «Версионировать при записи»),
  если оно ещё не включено, и возвращает признак доступности;
- версия узла пишется процедурой `ЗаписатьВерсиюИнструкции` из `ГКСИ_ПередЗаписью`
  объектного модуля справочника: подписка БСП на запись версии для объектного типа
  сценария в расширении не срабатывает, поэтому `ВерсионированиеОбъектов.ЗаписатьВерсиюОбъекта`
  вызывается явно. Записи с `ОбменДанными.Загрузка` (массовая установка статусов по
  поддереву инструкции) версий не создают;
- `НомерВерсииСогласуемогоУзла(Предмет)` возвращает последнюю версию узла
  (`ВерсионированиеОбъектов.НомерПоследнейВерсии`); при подписании номер пишется
  в строку участника (`НомерВерсии`);
- просмотр версий — обработка `ГКСК_ПросмотрВерсийОбъектов` (различия версий и переход
  на версию) и штатная команда «История изменений» на формах элемента и группы
  (справочник включён в определённый тип `ВерсионируемыеДанные`).

**Подписанты на формах справочника** — таблица `Подписанты` (реквизит-`ТаблицаЗначений`)
в группе «Подписанты»:

- форма элемента — подписанты самого узла (`ПодписантыПоПредмету(Объект.Ссылка, Ложь)`);
- форма группы — подписанты всей инструкции вместе с вложенными узлами
  (`ПодписантыПоПредмету(Объект.Ссылка, Истина)`, есть колонка «Узел инструкции»).

По каждому сотруднику выводится его **последний** результат согласования (выбирается
по дате процесса): этап, результат, комментарий, дата и версия инструкции, которую он подписал.

### 19.7 Текст согласуемого объекта в задаче согласования

Форма задачи согласования (`Task.ЗадачаИсполнителя.Форма.ГКСИ_ФормаЗадачиСогласования`)
показывает согласующему то, что он подписывает:

- **вся инструкция** (`ВидСогласования = ВсяИнструкция`) — поле `ТекстСогласуемогоОбъекта`
  (`HTMLDocumentField`) с HTML-документом всей инструкции. Документ формируется **один раз
  при старте процесса** в `СтартПередСтартом` объектного модуля бизнес-процесса
  (`ГКСИ_СогласованиеИнструкцийСервер.HTMLИнструкции` → `ГКСИ_АльбомПроцессов.
  СобратьДокументАльбомаПоГруппам` по корневой группе) и сохраняется в реквизите процесса
  `ГКСИ_HTMLИнструкции` — **строка неограниченной длины** (ограничение длины обрезало
  документ, и поле задачи оставалось пустым). Задача показывает зафиксированный
  текст, даже если инструкцию изменят во время согласования; HTML из процесса считается
  валидным только при наличии тега `<html`, иначе документ собирается заново по
  `КорневаяИнструкция`;
- **элемент или группа** (`ВидСогласования = ЭлементИнструкции`) — поле
  `ТекстСогласуемогоОбъекта` с HTML-описанием самого узла
  (`ГКСИ_СогласованиеИнструкцийСервер.HTMLУзла` — HTML из присоединённого файла описания
  на текущем языке), а также два поля сравнения:
  - `ТекстПодписаннойВерсии` — текст **последней подписанной** версии узла
    (`НомерПоследнейПодписаннойВерсии` — максимум `НомерВерсии` среди согласовавших
    участников процесса по этому предмету; текст берётся из снимка версии БСП
    `ВерсионированиеОбъектов.РазборВерсии` → реквизит `ГКСИ_ТекстMarkdown`).
    Текст сегмента нужного языка выделяет `ТекстMarkdownПоКодуЯзыка` (поиск маркеров
    `<!--md:lang:XX-->` без учёта регистра, остатки маркеров вычищаются регуляркой)
    и рендерит в HTML собственный конвертер `ГКСИ_СогласованиеИнструкцийСервер.MarkdownВHTMLПоказа`
    (заголовки H1..H3, маркированные списки, параграфы, жирный/курсив/моноширинный,
    картинки — коды заменяются на data URI). Конвертер построен на строковых операциях,
    без регулярных выражений, поэтому не зависит от сбоев `ГКСИ_ЗагрузкаСценариевИзMarkdown.MarkdownВHTML`;
  - `ТекстИзменений` — построчные различия между подписанной и текущей версией
    (`HTMLРазличийТекстов`: удалённые строки выделены красным с зачёркиванием,
    добавленные — зелёным). Сравнивается Markdown, а не HTML: HTML-описание хранится
    в отдельном присоединённом файле и в снимок версии объекта не входит;
- базой для сравнения служит версия, **зафиксированная при старте процесса** в реквизите
  `НомерБазовойВерсии` (максимум из номера, зафиксированного при подписании, —
  `НомерПоследнейПодписаннойВерсии`, — и номера последней версии, в которой статус узла
  был «Проверено», — `НомерПоследнейПровереннойВерсии`); сравниваемая версия узла тоже
  фиксируется при старте в реквизите `НомерВерсииСогласования`. Оба реквизита заполняет
  `СтартПередСтартом` объектного модуля бизнес-процесса. Это нужно потому, что смена
  статуса узла (`УстановитьСтатусСогласования`) создаёт новую версию объекта: без
  фиксации на этапе подчинённых «текущая» версия оказывалась уже после служебной записи
  и сравнение показывало «изменений нет». Для процессов, запущенных до доработки
  (номера не заполнены), значения считаются на лету, текущей версией считается
  актуальный текст узла;
  если проверенных версий нет — выводится пометка «Ранее не проверялся — сравнивать не с чем».
- в табличную часть участников пишется `НомерВерсии`, зафиксированный процессом
  (`НомерВерсииСогласования`), а не текущий номер версии узла на момент ответа.

Все HTML-фрагменты перед показом проходят серверную обработку алертов
(`ГКСИ_MarkdownСерверВызовСервера.ОбработатьАлертыВHTML`), так как JS в
`HTMLDocumentField` выполняется нестабильно.
