# Багфикс: Несоответствие типов при построении дерева формы списка

Версия: 1.63. Маленькая фича (багфикс одной серверной процедуры).

## Симптом

При открытии формы списка `Справочник.ДемонстрационныеСценарии.Форма.ФормаСпискаДеревоГрупп`
падало исключение с текстом:

```
Ошибка при установке значения атрибута контекста (ТекущийЭлемент)
{ГКС_Инструкции Справочник.ДемонстрационныеСценарии.Форма.ФормаСпискаДеревоГрупп.Форма(586)}:
    ТекущийЭлемент = МассивСсылок[Индекс];
{ГКС_Инструкции Справочник.ДемонстрационныеСценарии.Форма.ФормаСпискаДеревоГрупп.Форма(389)}:
    ГКСИ_ОтсортироватьМассивСсылокПоПолномуКоду(МассивКорневыхГрупп, КэшПоСсылке);
{ГКС_Инструкции Справочник.ДемонстрационныеСценарии.Форма.ФормаСпискаДеревоГрупп.Форма(11)}:
    ГКСИ_ПостроитьДерево();
{Справочник.ДемонстрационныеСценарии.Команда.ДемонстрационныеСценарии.МодульКоманды(9)}:
    ОткрытьФорму("Справочник.ДемонстрационныеСценарии.ФормаСписка",
```

## Причина

В модуле управляемой формы серверная процедура
`ГКСИ_ОтсортироватьМассивСсылокПоПолномуКоду` пыталась
отсортировать переданный по ссылке массив (`МассивСсылок`) методом
вставками с прямым присваиванием элементов по индексу:

```1c
Для Индекс = 1 По КоличествоЭлементов - 1 Цикл
    ТекущийЭлемент = МассивСсылок[Индекс];
    ...
    МассивСсылок[Позиция] = МассивСсылок[Позиция - 1];
    ...
    МассивСсылок[Позиция] = ТекущийЭлемент;
КонецЦикла;
```

В управляемых формах 1С массив, переданный параметром в
`&НаСервере`-процедуру модуля формы, ведёт себя как
`ФиксированныйМассив`: попытка присваивания элемента по индексу
либо попытка прочитать элемент через `[]` в сочетании с локальной
переменной `ТекущийЭлемент` приводит к ошибке «Несоответствие типов»
(сообщение «Ошибка при установке значения атрибута контекста
(ТекущийЭлемент)» — конфликт с одноимённым свойством контекста
управляемой формы).

В самом файле уже был аналогичный паттерн с `СписокЗначений` для
массива структур (см. `ГКСИ_ДобавитьВеткуГруппы`, комментарий
«Прямая сортировка массива структур через параметр процедуры не
работает в управляемой форме …»), но для сортировки корневых
групп этот приём применён не был — отсюда и падение.

## Что сделано

Файл: `src/Catalogs/ДемонстрационныеСценарии/Forms/ФормаСпискаДеревоГрупп/Module.bsl`

1. `ГКСИ_ОтсортироватьМассивСсылокПоПолномуКоду` переписана из
   `Процедуры` в `Функцию`:
   - на вход принимает массив ссылок без модификации;
   - собирает пары `(Ссылка, ПолныйКод)` в `СписокЗначений`;
   - сортирует через `СписокЗначений.СортироватьПоПредставлению()`
     (тот же приём, что уже применён в `ГКСИ_ДобавитьВеткуГруппы`);
   - возвращает **новый** отсортированный массив.
2. В `ГКСИ_ПостроитьДерево()` вызов заменён на присваивание
   результата локальной переменной:
   ```1c
   МассивКорневыхГрупп = ГКСИ_ОтсортироватьМассивСсылокПоПолномуКоду(
       МассивКорневыхГрупп, КэшПоСсылке);
   ```

## Как проверять

1. Открыть форму списка `ДемонстрационныеСценарии`
   (`ФормаСпискаДеревоГрупп`) — ошибки быть не должно, дерево
   строится.
2. Корневые группы отображаются в порядке возрастания `ПолныйКод`
   (сначала меньший код, потом больший).
3. Члены каждой группы по-прежнему сортируются в
   `ГКСИ_ДобавитьВеткуГруппы` — их поведение не менялось.

## Технические замечания

- Локальные переменные серверных процедур модуля управляемой формы
  остаются доступными для записи; присваивание
  `МассивКорневыхГрупп = ...` корректно.
- В отчёте `ОТЧЁТ_СортировкаАльбомаИСпискаПоПолномуКоду.md` была
  фраза «Типизированный массив ссылок поддерживается без проблем» —
  наблюдаемая ошибка её опровергает. Для надёжности сортировка
  составных коллекций через параметр серверной процедуры модуля
  формы теперь всегда идёт через `СписокЗначений`.
