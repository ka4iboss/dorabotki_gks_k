# Отчёт: команда «Добавить доп реквизит» в форме вида номенклатуры

**Дата:** 2026-11-19
**Версия расширения:** `1.0.22.12` → `1.0.23.0`
**Версия подсистемы ШаблоныНаименований:** `1.0.0` → `1.1.0`
**Тип:** фича

## Задача

В форме элемента справочника «Виды номенклатуры» подбор дополнительных реквизитов шёл
неудобно: существующий реквизит можно было взять только через «Из другого набора...»
(созданием копии). Требовалось: в меню «Добавить» таблицы «Реквизиты номенклатуры»
добавить команду **«Добавить доп реквизит»**, открывающую
`ПланВидовХарактеристик.ДополнительныеРеквизитыИСведения.Форма.ФормаСписка`
**только с дополнительными реквизитами** (без доп. сведений), с выбором реквизита;
выбранный реквизит добавляется в набор вида номенклатуры.

## Что сделано

1. **Заимствована форма** `Справочник.ВидыНоменклатуры.Форма.ФормаЭлемента` в расширение
   `Доработки_ГКС_К` (`Form.form`, `Module.bsl`, `BaseForm/Form.form`). Заимствование выполнено
   вручную в EDT: `adoptObject` формы не поддерживает (возвращает «объект не найден в базовой
   конфигурации»).
2. Добавлена **команда формы** `ГКСК_ДобавитьДопРеквизитИзСписка` («Добавить доп реквизит»)
   и **кнопка** `НоменклатураДобавитьДопРеквизитИзСписка` в popup-группу
   `НоменклатураГруппаСоздатьРеквизиты` (меню «Добавить» у таблицы «Реквизиты номенклатуры»).
3. Написан **модуль формы** (только код расширения):
   - `ГКСК_ДобавитьДопРеквизитИзСписка` (&НаКлиенте) - проверки и открытие списка
     с `ОписаниеОповещения`;
   - `ГКСК_ДобавитьДопРеквизитИзСпискаЗавершение` (&НаКлиенте, `Экспорт`) - приём результата;
   - `ГКСК_МассивСвойствИзВыбора` (&НаКлиентеНаСервереБезКонтекста) - нормализация результата;
   - `ГКСК_ДобавитьСвойстваВНабор` (&НаСервере) - добавление строки в таблицу формы.
4. Поднята версия подсистемы (`ГКСК_Версии.ВерсияШаблоновНаименований`) и версия расширения
   (`Configuration.mdo` через инструмент правки метаданных).
5. Обновлена документация: `описание/ДобавлениеДопРеквизитовВВидНоменклатуры.md`,
   `описание/ИсторияВерсий.md`, `состояние/СПИСОК_MD_ФАЙЛОВ.md`, этот отчёт.

## Технические решения

| Решение | Причина |
|---|---|
| Выбор **одиночный**: `ЗакрыватьПриВыборе = Истина` | При множественном выборе (`ЗакрыватьПриВыборе = Ложь`) двойной клик по строке открывает элемент, а выбор требует кнопки «Выбрать». По решению пользователя нужен двойной клик = выбор |
| Результат - через `ОписаниеОповещения` (обработчик `Экспорт`), владелец `ЭтотОбъект` | Форма открывается вкладкой, а не отдельным окном (открытие с владельцем-элементом формы даёт отдельное окно); приём проверен в этом же расширении (`ГКСК_ЗаменаДополнительныхРеквизитов`, 2026-11-18) |
| Параметр `Отбор = Структура("ЭтоДополнительноеСведение", Ложь)` | Стандартный параметр формы динамического списка; отсекает доп. сведения. Дополнительно серверный код пропускает сведения, если они всё же попали в выбор |
| Строка пишется в **таблицу формы** `ТаблицаДопРеквизитовНоменклатуры`, а не в ТЧ набора | В ТЧ набора строку переносит штатный `ПриЗаписиНаСервере` → `ЗаписатьДопРеквизитыСведенияНабора`; не теряются несохранённые правки таблицы |
| `ИндексКартинки = 4` для помеченного на удаление, иначе `1` | Как в штатном заполнении таблицы |
| Заголовок и пометка удаления - **одним запросом** по массиву ссылок | Нет обращений к БД в цикле |

## Проверка

- `GetMarkers` по `Module.bsl`, `Form.form`, `ВидыНоменклатуры.mdo` - **0 маркеров**.
- `mcp__syntax-checker__validate` для нового кода: ошибок 0. Замечания устранены
  (`Знач` у параметра серверной функции, ветка `Иначе`, вложенные вызовы в параметрах,
  длина строк, документирующий комментарий у экспортного обработчика, нестандартная
  область модуля).
- Ручная проверка (в 1С):
  1. открыть записанный вид номенклатуры → страница «Дополнительные реквизиты» →
     «Добавить» у таблицы «Реквизиты номенклатуры» → «Добавить доп реквизит»;
  2. список открывается вкладкой, в нём **нет** доп. сведений;
  3. двойной клик по реквизиту - форма закрывается, строка появляется в таблице;
  4. записать вид, переоткрыть - реквизит в наборе;
  5. повторный выбор того же реквизита - не дублируется, выводится сообщение;
  6. у незаписанного вида - предупреждение вместо открытия списка.

## История правки

Первая версия открывала форму отдельным окном (владелец - скрытая таблица формы) и работала
в режиме множественного выбора с галочками: двойной клик открывал реквизит, а не выбирал.
По замечанию пользователя переделано на одиночный выбор с двойным кликом и открытие вкладкой;
скрытая таблица подбора, её реквизит и колонка удалены.

## Замечания

- Форма вида номенклатуры заимствована целиком, поэтому при обновлении типовой конфигурации
  её нужно сверять с новой базовой версией (`BaseForm/Form.form`).
- Версия поднята по подсистеме **ШаблоныНаименований** по решению пользователя, хотя
  функционально доработка относится к работе с дополнительными реквизитами номенклатуры.
