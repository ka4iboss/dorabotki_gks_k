# Отчёт: команда «Добавить доп реквизит» в форме вида номенклатуры

**Дата:** 2026-11-19
**Версия расширения:** `1.0.22.12` → `1.0.23.0`
**Версия подсистемы ШаблоныНаименований:** `1.0.0` → `1.1.0`
**Тип:** фича

## Задача

В форме элемента справочника «Виды номенклатуры» подбор дополнительных реквизитов шёл
неудобно: существующий реквизит можно было взять только через «Из другого набора...»
(созданием копии). Требовалось: в меню «Добавить» таблицы «Реквизиты номенклатуры»
добавить команду **«Добавить доп реквизит»**, открывающую
`ПланВидовХарактеристик.ДополнительныеРеквизитыИСведения.Форма.ФормаСписка`
**только с дополнительными реквизитами** (без доп. сведений) в режиме множественного выбора;
выбранные реквизиты добавляются в набор вида номенклатуры.

## Что сделано

1. **Заимствована форма** `Справочник.ВидыНоменклатуры.Форма.ФормаЭлемента` в расширение
   `Доработки_ГКС_К` (`Form.form`, `Module.bsl`, `BaseForm/Form.form`). Заимствование выполнено
   вручную в EDT: `adoptObject` формы не поддерживает (возвращает «объект не найден в базовой
   конфигурации»).
2. Добавлена **команда формы** `ГКСК_ДобавитьДопРеквизитИзСписка` («Добавить доп реквизит»)
   и **кнопка** `НоменклатураДобавитьДопРеквизитИзСписка` в popup-группу
   `НоменклатураГруппаСоздатьРеквизиты` (меню «Добавить» у таблицы «Реквизиты номенклатуры»).
3. Добавлены **реквизит формы** `ТаблицаПодбораДопРеквизитов` (`ТаблицаЗначений`, колонка
   `Свойство`) и **скрытая таблица** `ТаблицаПодбораДопРеквизитов` (`visible = false`,
   `enabled = true`) с обработчиком события `ОбработкаВыбора`.
4. Написан **модуль формы** (только код расширения):
   - `ГКСК_ДобавитьДопРеквизитИзСписка` (&НаКлиенте) - проверки и открытие списка;
   - `ГКСК_ТаблицаПодбораДопРеквизитовОбработкаВыбора` (&НаКлиенте, 3 параметра) -
     приём результата, `СтандартнаяОбработка = Ложь`;
   - `ГКСК_МассивСвойствИзВыбора` (&НаКлиентеНаСервереБезКонтекста) - нормализация результата;
   - `ГКСК_ДобавитьСвойстваВНабор` (&НаСервере) - добавление строк в таблицу формы.
5. Поднята версия подсистемы (`ГКСК_Версии.ВерсияШаблоновНаименований`) и версия расширения
   (`Configuration.mdo` через инструмент правки метаданных).
6. Обновлена документация: `описание/ДобавлениеДопРеквизитовВВидНоменклатуры.md`,
   `описание/ИсторияВерсий.md`, `состояние/СПИСОК_MD_ФАЙЛОВ.md`, этот отчёт.

## Технические решения

| Решение | Причина |
|---|---|
| Владелец открываемой формы - **отдельная скрытая таблица** `ТаблицаПодбораДопРеквизитов` | Штатный `ТаблицаДопРеквизитовНоменклатурыОбработкаВыбора` ожидает `Структура`/значение со свойством `ОбщееСвойство`, а не массив ссылок; подменять его нельзя |
| Результат - через событие элемента `ОбработкаВыбора` (3 параметра) | Асинхронные оповещения (`ОписаниеОповещения`, `ПоказатьВыборЭлемента`) в этой базе не срабатывают - зафиксировано в памяти проекта |
| Параметр `Отбор = Структура("ЭтоДополнительноеСведение", Ложь)` | Стандартный параметр формы динамического списка; отсекает доп. сведения. Дополнительно серверный код пропускает сведения, если они всё же попали в выбор |
| Строки пишутся в **таблицу формы** `ТаблицаДопРеквизитовНоменклатуры`, а не в ТЧ набора | В ТЧ набора строки переносит штатный `ПриЗаписиНаСервере` → `ЗаписатьДопРеквизитыСведенияНабора`; не теряются несохранённые правки таблицы |
| `ИндексКартинки = 4` для помеченных на удаление, иначе `1` | Как в штатном заполнении таблицы |
| Заголовки и пометка удаления - **одним запросом** по массиву ссылок | Нет обращений к БД в цикле |

## Проверка

- `GetMarkers` по `Module.bsl`, `Form.form`, `ВидыНоменклатуры.mdo` - **0 маркеров**.
- `mcp__syntax-checker__validate` для нового кода: ошибок 0. Замечания устранены:
  модификатор `Знач` у параметра серверной функции, ветка `Иначе` в `Если...ИначеЕсли`,
  вынос вложенных вызовов из параметров, длина строк.
- Ручная проверка (в 1С):
  1. открыть записанный вид номенклатуры → страница «Дополнительные реквизиты» →
     «Добавить» у таблицы «Реквизиты номенклатуры» → «Добавить доп реквизит»;
  2. в открывшемся списке **нет** доп. сведений; отметить один и несколько реквизитов → «Выбрать»;
  3. строки появились в таблице; записать вид, переоткрыть - реквизиты в наборе;
  4. повторный выбор тех же реквизитов - не дублируются, выводится сообщение;
  5. у незаписанного вида - предупреждение вместо открытия списка.

## Замечания

- Форма вида номенклатуры заимствована целиком, поэтому при обновлении типовой конфигурации
  её нужно сверять с новой базовой версией (`BaseForm/Form.form`).
- Версия поднята по подсистеме **ШаблоныНаименований** по решению пользователя, хотя
  функционально доработка относится к работе с дополнительными реквизитами номенклатуры.
