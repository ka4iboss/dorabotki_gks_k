# ОТЧЁТ: обход кеша изображений из фонового задания

## Суть

При загрузке сценариев из Markdown через `ДлительныеОперации.ВыполнитьВФоне`
узлы дерева падали с ошибкой:

```
Ошибка при вызове метода контекста (СоответствиеКодДанные)
{... ГКСИ_MarkdownПереопределяемый.Модуль(...)}:Возврат
  ГКСИ_ДанныеИзображенийMarkdownПовтИсп.СоответствиеКодДанные(МассивКодов, …);
[…]
по причине:
Несоответствие типов (параметр номер '1')
(Неверный тип параметра. Допустимы только примитивные типы, ссылки, Структура)
```

`ГКСИ_ДанныеИзображенийMarkdownПовтИсп` — общий модуль с признаком
`ReturnValuesReuse = DuringSession`. Платформа в этом режиме ограничивает
допустимые типы параметров экспортной функции: только примитивы, ссылки
и `Структура`. В параметре `МассивКодов` приходит `Массив` из `Строка`,
поэтому вызов через платформенный кеш завершается исключением
«Несоответствие типов». Ограничение действует во всех сеансах, не
только в фоновых заданиях.

Проблема решалась в три итерации, и каждая из них оказалась неполной.

## Итерация 1: условный обход из фонового задания

Разделили реализацию и кеш:

- `ГКСИ_ДанныеИзображенийMarkdown` (новый общий модуль, без признака
  повторного использования) — реальное чтение: пакетный запрос к
  `Справочник.ГКСИ_ФайлыИнструкций`, опциональный пропорциональный
  ресайз через `ОбрабатываемаяКартинка`, сборка соответствия
  `Код → {Base64, Mime}`.
- `ГКСИ_ДанныеИзображенийMarkdownПовтИсп` (существующий) — теперь тонкая
  кеш-обёртка, делегирующая в `ГКСИ_ДанныеИзображенийMarkdown`.

В `ГКСИ_MarkdownПереопределяемый.СоответствиеКодДанныеИзображений` добавлен
условный обход кеша через
`ПолучитьТекущийСеансИнформационнойБазы().ПолучитьФоновоеЗадание()`.

**Результат**: фон пошёл, основной сеанс (альбом процессов) продолжил
падать. Платформа одинаково режет типы везде.

## Итерация 2: ручной кеш в переменной модуля

Сняли `ReturnValuesReuse` с `ГКСИ_ДанныеИзображенийMarkdownПовтИсп` и
реализовали кеш вручную в переменной модуля `ГКСИ_Кеш`:

```bsl
Функция СоответствиеКодДанные(МассивКодов, МаксимальнаяШиринаПикселей = 0) Экспорт
    КлючКеша = XMLСтрока(МаксимальнаяШиринаПикселей);
    РезультатИзКеша = ГКСИ_Кеш.Получить(КлючКеша);
    Если РезультатИзКеша <> Неопределено Тогда
        Возврат РезультатИзКеша;
    КонецЕсли;
    Результат = ГКСИ_ДанныеИзображенийMarkdown.СоответствиеКодДанные(
        МассивКодов, МаксимальнаяШиринаПикселей);
    ГКСИ_Кеш.Вставить(КлючКеша, Результат);
    Возврат Результат;
КонецФункции

ГКСИ_Кеш = Новый Соответствие;
```

**Результат**: ошибка инициализации модуля. В 1С **общие модули не
поддерживают переменные на уровне модуля** — это особенность платформы,
парсер не пропустил декларацию `ГКСИ_Кеш = Новый Соответствие;` на
уровне модуля.

## Итерация 3 (финальная): строка-ключ + ReturnValuesReuse

Вернули `ReturnValuesReuse = DuringSession` на `ГКСИ_ДанныеИзображенийMarkdownПовтИсп`,
но в качестве параметра экспортной функции — **строка-ключ** (допустимый
примитивный тип). Ключ формируется в
`ГКСИ_MarkdownПереопределяемый.СоответствиеКодДанныеИзображений`:

```bsl
КлючКеша = СтрСоединить(МассивКодов, "|") + "#" + XMLСтрока(МаксимальнаяШиринаПикселей);
```

Реализация парсит ключ и зовёт основную функцию:

```bsl
// ГКСИ_ДанныеИзображенийMarkdown / Module.bsl
Функция СоответствиеКодДанныеПоКлючу(КлючКеша) Экспорт
    МассивКодов = Новый Массив;
    Ширина = 0;
    Если НЕ ПустаяСтрока(КлючКеша) Тогда
        ПозицияРазделителя = СтрНайти(КлючКеша, "#");
        Если ПозицияРазделителя > 0 Тогда
            СтрокаКодов = Лев(КлючКеша, ПозицияРазделителя - 1);
            СтрокаШирины = Сред(КлючКеша, ПозицияРазделителя + 1);
            Если НЕ ПустаяСтрока(СтрокаШирины) Тогда
                Попытка
                    Ширина = Число(СтрокаШирины);
                Исключение
                    Ширина = 0;
                КонецПопытки;
            КонецЕсли;
        Иначе
            СтрокаКодов = КлючКеша;
        КонецЕсли;
        Если НЕ ПустаяСтрока(СтрокаКодов) Тогда
            МассивКодов = СтрРазделить(СтрокаКодов, "|", Ложь);
        КонецЕсли;
    КонецЕсли;
    Возврат СоответствиеКодДанные(МассивКодов, Ширина);
КонецФункции
```

**Результат**: ошибок нет, кеш работает через платформу, и в фоне, и в
основном сеансе.

`#` как разделитель безопасен: GUID-ы его не содержат, `XMLСтрока` от
числа его тоже не выдаёт.

## Параллельная правка: чистка удалённых реквизитов

После первой правки проявилась ещё одна ошибка —
`Поле не найдено "ФайлыИнструкций.Ширина"` в
`НормализоватьСоответствиеКодДанные` (`ГКСИ_MarkdownПереопределяемый`).
Запрос к справочнику и сборка `СтруктураДанных` ссылались на реквизиты
`Ширина` и `Высота`, которых в справочнике уже нет. Из запроса и из
`СтруктураДанных` обращения убраны. Поиск по проекту подтвердил, что
`ДанныеФайла.Ширина`/`Высота` нигде не читаются дальше по цепочке —
потребители не пострадали.

## Обнаруженная побочная проблема: картинки не показываются до пересохранения

После возврата `ReturnValuesReuse` через строку-ключ выяснилось, что на
форме элемента/группы картинки в HTML-описании не показываются, пока
пользователь не зайдёт и не запишет элемент заново.

Проблема **не** в кеше изображений (он работает корректно после записи).
Это отдельная проблема того, как HTML-описание сценария попадает на форму:
при первом открытии HTML содержит коды картинок в формате, который
`ЗаменитьКодыИзображенийНаDataURI` не распознаёт, а после записи
формат меняется.

### Корневая причина

В `ГКСИ_ЗагрузкаСценариевИзMarkdown` подмена картинок в исходном тексте
перед конвертацией в HTML обрабатывала только Obsidian-синтаксис
`![[path]]` по регулярке `!\[\[([^\]]+)\]\]`. Остальные варианты ссылок
на картинки оставались «сырыми»:

- `![[path|size|caption]]` — Obsidian с дополнительными полями;
- `![alt](path)` — стандартный markdown.

В результате `MarkdownВHTML` формировал `<img src="path">` с сырым путём
вместо GUID-а файла инструкции. `ЗаменитьКодыИзображенийНаDataURI` в
`ГКСИ_MarkdownПереопределяемый` ищет в `src` только GUID-ы по регулярке
`[0-9a-fA-F]{8}-...`, поэтому сырой путь не матчится — картинка
остаётся битой.

После ручной записи через форму элемента HTML прогоняется по другой
ветке (через `ДемонстрационныеСценарии.РезультатОбновленияПрисоединенногоФайла`
→ `ДемонстрационныеСценарии.ЗаписатьНовыеОписанияСценариевИзФормыОбъекта`),
которая дополнительно обрабатывает картинки — отсюда эффект «появляются
после пересохранения».

### Решение (версия 1.49)

Расширены три функции в
`src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`:

- **`УникальныеПутиКартинокИзТекста`** — два regex: Obsidian
  `!\[\[([^\]|]+)(?:\|[^\]]*)?\]\]` (чистый путь без `|...`) и
  стандартный markdown `!\[[^\]]*\]\(([^)]+)\)`.
- **`СобратьПутиКартинокИзУзла`** — те же два regex в рекурсивном обходе.
- **`ПодменитьСсылкиНаКартинкиВТексте`** — переписана на единый подход:
  один проход двумя regex, сбор массива замен `{Позиция, Длина, Текст}`,
  применение с конца строки. Вынесена общая процедура
  `ДобавитьЗаменыПоРегулярномуВыражению`. Если путь не нашёлся в карте —
  подменяется на `❌ <путь>` (визуальный маркер).

### Что получили

- Картинки показываются в HTML-описании сценария сразу после загрузки
  из Markdown, без ручной перезаписи.
- Поддерживаются три варианта ссылок: `![[path]]`, `![[path|extra]]`,
  `![alt](path)`.
- Если файл картинки не найден — пользователь видит `❌ <путь>` вместо
  молчаливого broken image.

Подробности — в `AGENTS/план/ЗАДАЧА_КартинкиНеПоказываютсяБезПересохранения.md`.

## Что получили

- Альбом процессов: кеш через `ReturnValuesReuse` работает без
  обращения к БД при повторных построениях.
- Загрузка сценариев из Markdown в фоне: ошибка устранена.
- Альбом процессов в основном сеансе: перестал падать.
- Фоновое задание и основной сеанс идут через одну и ту же кеш-функцию
  с одним и тем же контрактом.
- Публичный контракт `СоответствиеКодДанныеИзображений(МассивКодов,
  Ширина)` не изменился, потребители не трогали.
- Параллельно почищены зависшие ссылки на удалённые реквизиты
  `Ширина`/`Высота`.
- **1.49:** картинки в HTML-описании сценария показываются сразу после
  загрузки из Markdown, без пересохранения элемента; поддержаны три
  варианта ссылок (`![[path]]`, `![[path|extra]]`, `![alt](path)`).
  Не найденный файл подменяется на `❌ <путь>` — пользователь сразу
  видит, что картинка не подгрузилась.

## Альтернативы, которые не пошли

- **Условный обход только из фонового задания** (итерация 1) — не
  лечит основной сеанс, платформа ограничивает типы одинаково везде.
- **Ручной кеш через переменную модуля** (итерация 2) — общие модули
  в 1С не поддерживают переменные на уровне модуля, ошибка
  инициализации модуля.
- **Убрать кеш совсем** — лишаем альбом процессов бесплатных повторных
  построений, на больших альбомах деградация заметная.
- **Сменить параметр на `Структура`** через
  `Новый Структура("Коды", МассивКодов)` — работает, но требует менять
  публичный контракт `СоответствиеКодДанныеИзображений` во всех
  потребителях (а их минимум два: альбом процессов и загрузка сценариев).
  Текущее решение локально и не задевает существующий API.
