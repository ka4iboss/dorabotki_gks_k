# Отчёт: подсистема «ВерсииОбъектов» (просмотр версий объектов)

**Дата:** 2026-10-14
**Подсистема:** ВерсииОбъектов (новая)
**Версия подсистемы:** `1.1.0` (выпуск; старт — `1.0.0`)
**Версия расширения:** `1.0.1.0` (minor подсистемы)
**Тип:** фича

## 1. Задача

Обработка для просмотра изменений версий номенклатур (и других версионируемых справочников):
слева — список объектов, справа — три версии (текущая, прошлая, первая) с кнопками перехода
на версию и открытия печатной формы; пакетный переход отмеченных объектов на выбранную версию
(у каждого объекта — на его собственную версию этого вида). Доработка в расширении `Доработки_ГКС_К`.

Уточнения, согласованные с пользователем:

| Вопрос | Решение |
|---|---|
| Что выводить справа | И сводная таблица различий реквизитов, и кнопки открытия штатной печатной формы по каждой версии. |
| Область объектов | Любой версионируемый справочник (на форме — выбор типа объекта). |
| Размещение | Новая подсистема расширения `ГКСК_ВерсииОбъектов`. |
| Пакетный переход | Поле выбора вида версии + кнопка «Перейти для отмеченных». |

## 2. Что сделано

### Созданные объекты

- Подсистема `ГКСК_ВерсииОбъектов`.
- Обработка `ГКСК_ПросмотрВерсийОбъектов` с формой `Форма` (тип `GENERIC`, собранной
  программно из групп/полей/кнопок через инструмент правки метаданных).
- Общий серверный модуль `ГКСК_ВерсииОбъектовСервер` (контекст: Сервер).

Все объекты включены в `Configuration.mdo` (разделы подсистем, обработок, общих модулей).

### Форма

- Группа пакетного перехода (скрывается без права перехода): кнопка «Перейти для отмеченных»
  и поле `ЦелеваяВерсия` со списком выбора `Текущая / Прошлая / Первая`.
- Левая панель: выбор типа объекта, строка поиска, кнопка «Найти», таблица объектов
  (`Отметка`, `Объект`, `Наименование`, `КоличествоВерсий`).
- Правая панель: три группы версий (подпись версии + кнопки «Перейти на …» и «Открыть отчёт»)
  и таблица различий (`Реквизит`, `Текущая`, `Прошлая`, `Первая`, `ЕстьРазличие`).
- Группы «левая/правая» размещены горизонтально (`HorizontalIfPossible`).

### Логика

- Типы объектов — из `РегистрСведений.НастройкиВерсионированияОбъектов` (отбор `Использовать`),
  только справочники; представление — синоним объекта метаданных; по умолчанию выбирается
  `Справочник.Номенклатура`.
- Версии — только с `ТипВерсииОбъекта = ИзмененоПользователем`; текущая — максимальный номер,
  прошлая — предыдущий, первая — минимальный.
- Различия — через `ВерсионированиеОбъектов.РазборВерсии` по трём версиям.
- Переход — через `ВерсионированиеОбъектов.ПерейтиНаВерсиюСервер`.
- Пакетный переход — через `ДлительныеОперации.ВыполнитьВФоне` с фоновой процедурой
  `ГКСК_ВерсииОбъектовСервер.ВыполнитьПереходНаВерсииДляОтмеченных`, ожидание —
  `ДлительныеОперацииКлиент.ОжидатьЗавершение`.

## 3. Принятые решения и находки

1. **Переиспользование штатного механизма версионирования** ERP вместо собственного движка:
   источник — `РегистрСведений.ВерсииОбъектов` и общий модуль `ВерсионированиеОбъектов`.
2. **`Найти` — зарезервированное слово.** Команда формы и процедура-обработчик `Найти`
   вызывают ошибку разбора модуля («Недопустимая лексема "Найти"»). Команда переименована
   в `НайтиОбъекты` (заголовок «Найти» сохранён), кнопка пересоздана.
3. **Запросы вне циклов.** Номера версий для списка объектов считаются одним запросом
   (`НомераВерсийПользователя`) с разбором в коде — иначе срабатывает проверка SU95
   («цикл содержит вызов метода с запросом»).
4. **Загрузка таблиц формы.** Присваивание `ТаблицаЗначений` реквизиту формы типа
   `ТаблицаЗначений` недопустимо (SU254/SU220) — используется
   `ТаблицаОбъектов.Загрузить(ТаблицаЗначений)`.
5. **Обработчики `ОписаниеОповещения` должны быть экспортными** (SU34) — процедуры завершения
   диалогов/длительной операции объявлены с `Экспорт`.
6. **Области модуля формы.** Обработчики элементов размещены в стандартных областях
   (`ОбработчикиСобытийЭлементовШапкиФормы`,
   `ОбработчикиСобытийЭлементовТаблицыФормыТаблицаОбъектов`) — иначе SU93/SU66.
7. **Права.** Переход на версию доступен только полноправному пользователю и при наличии
   права чтения информации о версиях; при отсутствии — кнопки скрываются.
8. **Длительная операция.** Пакетный переход (потенциально блокирующая операция) вынесен
   в фон, как требует правило workspace.
9. **У коллекции `СтандартныеРеквизиты` нет метода `Найти`.** Первая версия
   `ВыражениеНаименованиеОбъекта` падала в рантайме с «Метод объекта не обнаружен (Найти)».
   Имя стандартного реквизита определяется обходом коллекции:
   `Для Каждого ОписаниеРеквизита Из МетаданныеОбъекта.СтандартныеРеквизиты Цикл` →
   `ОписаниеРеквизита.Имя` (поддерживаются как русские имена `Наименование`/`Код`,
   так и английские `Description`/`Code`). Условие поиска по наименованию строится только
   при найденном выражении — `ПОДОБНО` по ссылке (`Объекты.Ссылка`) некорректно.
10. **Проверено по исходникам ERP:** стандартные реквизиты заимствованных справочников
   доступны по русским именам (`СпрНоменклатура.ПометкаУдаления` и т.п.), поэтому
   `НЕ Объекты.ПометкаУдаления` в запросе корректно; структура `РазборВерсии` содержит
   ключ `Реквизиты` (колонки `НаименованиеРеквизита`, `ЗначениеРеквизита`), а регистр
   `НастройкиВерсионированияОбъектов` — ресурсы `Использовать`, `Вариант`,
   `СрокХраненияВерсий` и измерение `ТипОбъекта`.
11. **`ПЕРВЫЕ` не принимает параметр.** Запрос `ВЫБРАТЬ ПЕРВЫЕ &Максимум` падает с
   «{Ожидается константа}». Количество строк подставляется в текст запроса:
   `"ВЫБРАТЬ ПЕРВЫЕ " + Формат(Максимум, "ЧГ=0")`.
12. **Имена стандартных реквизитов зависят от объекта.** У части справочников ERP они
   англоязычные (`DeletionMark`, `Description`) — поэтому и пометка удаления, и наименование
   определяются по фактическому составу коллекции `СтандартныеРеквизиты`, а не хардкодятся.
13. **Фильтр «только изменённые реквизиты».** В командную панель таблицы различий **нельзя**
   положить поле-флажок (`addFormField` в `ТаблицаРазличийКоманднаяПанель` отвечает
   `IllegalStateException: could not bind a field to data path ...` — командная панель
   принимает только кнопки). Реализовано кнопкой-переключателем: команда формы
   `ПоказатьТолькоРазличия` + кнопка `КнопкаТолькоРазличия` в панели; состояние хранится
   в реквизите формы `ТолькоРазличия`, индикация — свойством кнопки `Пометка`
   («нажатая» кнопка). Таблица различий перезаполняется из `ТаблицаРазличийВерсий`
   с отбором по `ЕстьРазличие`.
14. **Регрессия: пустая таблица различий.** После введения фильтра таблица перестала
   заполняться. Причина: `ОбновитьСведенияОВерсиях` сначала присваивала `ВыбранныйОбъект`,
   а затем вызывала `ОчиститьСведенияОВерсиях()`, которая **сбрасывала** этот реквизит
   в `Неопределено`; новый код фильтрации читает именно `ВыбранныйОбъект`, и срабатывал
   ранний выход. Исправлено: сначала очистка, затем присваивание; сброс `ВыбранныйОбъект`
   перенесён в `ОбновитьСписокОбъектов` (смена типа объекта / повторный поиск).
15. **Лимит списка объектов.** В списке объектов показывались только первые 300 строк
   (`ВЫБРАТЬ ПЕРВЫЕ 300`), из-за чего «не вся номенклатура» попадала в список. Ограничение
   снято: `Максимум = 0` означает запрос без `ПЕРВЫЕ`; при необходимости лимит задаётся
   параметром `Максимум` в `СписокОбъектовТипа`.
16. **Кнопки массовой отметки.** Добавлены кнопки «Отметить выделенные» / «Снять отметку
   с выделенных» (команды `ОтметитьВыделенные`, `СнятьОтметкуВыделенных`, служебная процедура
   `УстановитьОтметкуВыделенным`). Таблица переведена в режим множественного выделения
   (`selectionMode = MultiRow`); отметка ставится и снимается сразу у всех выделенных строк.
   **Расположение:** кнопки сначала были помещены в командную панель таблицы объектов
   (`AutoCommandBar`), но на форме не отображались — вынесены в левую группу рядом
   с кнопкой «Найти».
17. **Отбор по виду номенклатуры.** Для фильтрации списка по реквизиту `ВидНоменклатуры`
   справочник `ВидыНоменклатуры` заимствован в расширение (`adoptObject`), в форму добавлено
   поле `ВидНоменклатуры` (позиция 3 в `ГруппаЛевая`, перед таблицей объектов). Общий модуль
   получил `ЕстьРеквизитВидНоменклатуры(ТипОбъекта)` (поле видно только для типов с этим
   реквизитом) и новый параметр `СписокОбъектовТипа(..., ВидНоменклатуры, ...)` — условие
   `Объекты.ВидНоменклатуры = &ВидНоменклатуры`.
18. **Обработчик `ПриИзменении` для поля вида номенклатуры не используется.** Попытка привязать
   к полю `ВидНоменклатуры` обработчик `ВидНоменклатурыПриИзменении` даёт устойчивые
   предупреждения EDT SU44 («неиспользуемый метод») и SU93 («не следует размещать в области
   "ОбработчикиСобытийЭлементовШапкиФормы"»), хотя привязка в `Form.form` записана корректно
   (подтверждено `inspectForm`), а у соседнего поля `ТипОбъекта` такой же обработчик замечаний
   не вызывает. Индекс EDT не связывает позже добавленный обработчик с полем. Обработчик удалён;
   отбор по виду номенклатуры применяется по кнопке «Найти».
19. **Типы реквизитов формы ограничивали состав объектов.** Колонка `Объект` реквизита формы
   `ТаблицаОбъектов` и реквизит `ВыбранныйОбъект` были объявлены типом `СправочникСсылка`,
   поэтому при выборе документа ссылка в колонку не помещалась (значение молча отбрасывалось):
   «Объект» оставался пустым, а «Наименование» (строка) заполнялось. Оба реквизита пересозданы
   с составным типом — справочники, документы, бизнес-процессы, задачи, планы видов характеристик,
   счетов и видов расчёта (как у измерения `Объект` регистра `ВерсииОбъектов`). Заодно
   `ВерсионируемыеСправочники` переименована в `ВерсионируемыеОбъекты` и включает все
   версионируемые типы (фильтр `ЭтоВерсионируемыйТипОбъекта` по префиксу полного имени).
   Таблица объектов пересоздана через `addFormTable` (create_columns), восстановлены
   `selectionMode = MultiRow`, заголовок колонки «Кол-во версий» и обработчик `OnActivateRow`.

## 5. Ограничения и возможные доработки

- Сравниваются только плоские реквизиты; табличные части не сравниваются.
- Отбор по виду номенклатуры доступен только для справочников с реквизитом `ВидНоменклатуры`
  (в частности, `Справочник.Номенклатура`); для остальных типов поле скрыто.
- Отбор по виду номенклатуры применяется по кнопке «Найти» (автообновление по `ПриИзменении`
  не используется — см. п. 18 раздела 3).
- Нет перехода с отменой проведения при статусе `"ОшибкаПроведения"` (для справочников
  не актуально; при распространении на документы — потребуется).

## 7. Доработка: левый список переведён на динамический список (2026-10-14)

Левый список объектов переведён с таблицы значений на **динамический список** — ради штатных
поиска и сортировки.

- Реквизит формы `СписокОбъектов` — тип `ДинамическийСписок`, произвольный запрос с полями
  `Ссылка` и `Наименование`; таблица формы `ТаблицаОбъектов` привязана к нему.
- **Каркас** динамического списка (основная таблица `Справочник.Номенклатура`, признак
  «Произвольный запрос») задан в редакторе форм EDT: инструменты агента (`setDynamicListQuery`)
  умеют менять только запрос уже настроенного динамического списка и не создают его с нуля.
- Текст запроса, основная таблица и значения параметров переустанавливаются на сервере по
  выбранному типу объекта (`НастроитьДинамическийСписок` + `НастройкиДинамическогоСпискаОбъектов`).
- Ограничение платформы: в запросе динамического списка нельзя соединять с подзапросом, поэтому
  количество версий в списке не выводится (поле убрано из формы).
- Штатных отметок динамический список не поддерживает, поэтому отметки **сымитированы**:
  в запрос добавлено вычисляемое поле `Отметка`
  (`ВЫБОР КОГДА Объекты.Ссылка В (&Отмеченные) ТОГДА ИСТИНА ИНАЧЕ ЛОЖЬ КОНЕЦ`), выводимое
  колонкой-флажком; массив отметок хранится в реквизите формы `ОтмеченныеОбъекты`. Кнопки
  «Отметить выделенные» / «Снять отметку с выделенных» меняют массив и перечитывают список;
  пакетный переход (`ПерейтиДляОтмеченных`) — по отмеченным объектам.
- Маркеры EDT после доработки — 0 по `Form.form` и `Module.bsl` формы.

Итог: рабочая версия подсистемы остаётся `1.0.0` (тестовый релиз, версия расширения не
поднимается — см. `ИсторияВерсий.md`, раздел 3).
