# ОТЧЁТ: единая точка конвертации Markdown → HTML

**Версия:** подсистема ГКСИ `2.50.5 → 2.51.0`, расширение `1.0.25.6 → 1.0.26.0`
**Тип:** рефакторинг
**Дата:** 2026-11-20

## Проблема

В подсистеме ГКСИ было четыре независимых преобразования Markdown в HTML,
и результат зависел от того, каким путём текст попал в систему:

| № | Точка | Реализация | Состояние |
|---|---|---|---|
| 1 | Запись элемента `ДемонстрационныеСценарии` | showdown.js в поле предпросмотра формы + серверные постобработки | эталон (по решению пользователя) |
| 2 | Запись группы `ДемонстрационныеСценарии` | тот же showdown, но со своей вставкой `<style>img{vertical-align:middle}</style>` | расхождение с №1 |
| 3 | Импорт из `.md` | `ГКСИ_ЗагрузкаСценариевИзMarkdown.MarkdownВHTML` — регулярки | падала на регулярке картинок (`U_REGEX_MISMATCHED_PAREN`), не знала таблиц, списков и блоков кода |
| 4 | Форма задачи согласования | `ГКСИ_СогласованиеИнструкцийСервер.MarkdownВHTMLПоказа` — строковые операции | только заголовки, абзацы, маркированные списки и инлайн |

Обратное направление (HTML → Markdown) уже шло одной функцией
`ГКСИ_MarkdownКлиент.ТекстMarkdownПоТекстуHTML` (showdown `makeMarkdown`) и не менялось.

## Решение

Единственная серверная точка — новый общий модуль **`ГКСК_MarkdownКонвертер`**
(префикс `ГКСК` — по правилу именования новых объектов расширения).

```
ТекстHTMLПоМаркдауну(ТекстMarkdown, РазбиратьСсылки, ДобавлятьТегиТела, КартаСсылок)
```

Конвейер:

1. `ГКСИ_Видео.РазметкуВидеоВHTML` — `!video(<путь>)` → HTML5-плеер. Многострочный
   HTML-блок выводится как есть (в разборе отслеживается баланс контейнеров `div`,
   `table`, `pre`, `blockquote`, `ul`, `ol`, `video`), поэтому не попадает внутрь `<p>`.
2. `ГКСИ_СсылкиСценариев.ПодставитьСсылкиВТекст` — вики-ссылки `[[Имя]]` → `<a>`.
3. Разбор Markdown (строковый автомат, без регулярных выражений):
   блоки кода ```` ``` ````, заголовки `#`…`######`, горизонтальные линии, таблицы,
   цитаты и GitHub Alerts, списки `-`/`*`/`+`/`1.` с вложенностью и чекбоксами,
   абзацы, инлайн (картинки, ссылки, `**жирный**`, `~~зачёркнутый~~`, `*курсив*`, `` `код` ``).
   Содержимое `` `кода` `` защищается от дальнейших инлайн-замен.
4. `ГКСИ_MarkdownПереопределяемый.ЗаменитьКодыИзображенийНаDataURI` — коды картинок → `data:URI`.
5. `ГКСИ_MarkdownСерверВызовСервера.ОбработатьАлертыВHTML` — классы и inline-стили
   `markdown-alert-*`.
6. При `ДобавлятьТегиТела = Истина` — `ДемонстрационныеСценарииКлиентСервер.ДобавитьТегиТелаЕслиНеобходимо`.

| `CommonModule.ГКСИ_СогласованиеИнструкцийСервер` | `MarkdownВHTMLПоказа` — делегат + обёртка `<div style="font-size:10pt;">`; удалены `УровеньЗаголовкаMarkdown`, `ВстроеннаяРазметкаHTML`, `ЗаменитьКартинкиMarkdown`, `ЗаменитьПарнуюРазметку` (`ЭкранироватьHTMLТекст` оставлена — используется в почтовых уведомлениях и диффе) |
| `CommonModule.ГКСИ_АльбомПроцессов` | без изменений: он читает уже сохранённый HTML присоединённого файла |

## Поведение

- HTML теперь одинаковый для записи элемента, записи группы, импорта `.md` и показа
  в задаче согласования.
- Запись больше не зависит от того, открыт ли предпросмотр Markdown в форме
  (раньше при отсутствии поля `РМ_ПолеПросмотра_ТекстMarkdownСтрока` HTML не
  перегенерировался вовсе).
- Уже сохранённые присоединённые HTML-файлы не меняются до следующей перезаписи
  соответствующего узла.

## Ограничения

- Предпросмотр в форме по-прежнему рисует showdown.js: он и должен показывать текст
  «как в редакторе», а сохранённый HTML формируется серверным конвертером.
- Сырой HTML пользователя проходит без экранирования (как и в showdown); экранируется
  только содержимое блоков кода.
- Вложенность списков поддерживается одним уровнем на каждый отступ.
