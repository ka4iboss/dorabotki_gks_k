# Отчёт «Прикрепить к нашей группе» + диалог выбора текста

**Версия расширения:** 2.0 → 2.1 (большая фича, развитие пакета D).

## Что сделано

В версии 1.9 уже был реализован вариант разрешения конфликтов «Прикрепить к нашей группе» (см. `ОТЧЁТ_ПрикрепитьИАльбомПоПоддереву.md`), но без диалога выбора текста: при разных текстах между файлом и существующим узлом текст узла в БД оставался прежним без вопроса пользователю. Эта версия закрывает оставшийся пробел.

### 1. Удаление «Дублировать»

В `ФормаРазрешенияКонфликтов/Module.bsl` (`НастроитьКолонкуРешения`) убран пункт `«Дублировать»` из списка выбора. Итоговый набор вариантов: **«Пропустить»**, **«Обновить»**, **«Прикрепить к нашей группе»**.

В `ОбработатьУзелРекурсивно` (`ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`) удалена соответствующая ветка `ИначеЕсли РешениеПоУзлу.Действие = "Дублировать"`. Статус `Дублирован` убран из таблицы результата загрузки (теперь возможные значения: `Создан`, `Обновлён`, `Пропущен`, `Прикреплён`, `Ошибка`).

«Дублировать» в новой архитектуре избыточен: при наличии измерения `КореньИнструкции` в РС `ГКСИ_ГруппыСценариев` один и тот же узел справочника переиспользуется в нескольких инструкциях через записи РС, а не через дубли справочника.

### 2. Поле `ТекстИзФайла` в результатах конфликтов

`ПроверитьКонфликтыНаСервере` (форма `Форма` основной обработки загрузки) дополнена: для каждого конфликта в массив структур `МассивКонфликтов` добавляются поля:

- `ТекстИзФайла` — текст узла из MD-файла;
- `СуществующийТекст` — текущее содержимое `ГКСИ_ТекстMarkdown` существующего узла в БД.

Оба поля передаются в `ФормаРазрешенияКонфликтов` через `ПараметрыФормы.МассивКонфликтов` (массив структур, сериализуемый платформой между клиентом и сервером).

В форме разрешения `ПриСозданииНаСервере` `ЗаполнитьЗначенияСвойств` копирует эти поля в строки таблицы `Конфликты` — для этого в `Form.form` уже заведены колонки `ТекстИзФайла` и `СуществующийТекст`. Обе колонки закрыты от редактирования.

### 3. Диалог «чей текст оставить» в форме разрешения

Когда пользователь нажимает «Применить» в форме разрешения:

1. `Применить` (клиент) собирает массив «Прикрепить»-узлов с различающимися текстами через `СобратьМассивКонфликтовПрикрепитьСРазнымиТекстами`. Сравнение — через `ТекстыСовпадает`, который после `СокрЛП` обоих текстов сравнивает их как строки; пустые/Null значения считаются равными.
2. Если массив пуст — форма сразу закрывается с результатом через `ОповеститьОВыборе(СобратьРешения(Новый Соответствие))`.
3. Иначе открывается цепочка диалогов `ПоказатьВыборИзМеню` (по одному на конфликт):

   - **«Оставить из файла»** — в результат пробрасывается текст из файла для этого узла;
   - **«Оставить наш»** — в результат пробрасывается пустая строка (сигнал «не перезаписывать»);
   - **«Пропустить узел»** — для этого узла `Решение` в строке таблицы сбрасывается на «Пропустить», в результат ничего не пишется.
   - **Крестик / Esc** — эквивалент «Пропустить узел» (для этого узла запись в РС не пишется).

   Контекст цепочки (`МассивКонфликтовТекста`, `ИндексТекущего`, `ВыборТекстаПоУзлам`) передаётся через `ДополнительныеПараметры` `ОписаниеОповещения`, что позволяет запускать следующий диалог после ответа пользователя без глобальных переменных модуля.

4. После всех диалогов `СобратьРешения(ВыборТекстаПоУзлам)` формирует `Соответствие` результата:

   ```text
   ИмяИзФайла → {Действие, Ссылка, ТекстИзФайла}
   ```

   - `Действие` — `"Пропустить"` / `"Обновить"` / `"Прикрепить"` (как выбрано в таблице);
   - `Ссылка` — `CatalogRef` существующего узла;
   - `ТекстИзФайла` — непустое **только** для `«Прикрепить + Оставить из файла»`, иначе пустая строка.

### 4. Серверная обработка «Прикрепить» в `ОбработатьУзелРекурсивно`

Ветка `ИначеЕсли РешениеПоУзлу.Действие = "Прикрепить"`:

1. Берётся существующий узел: `СсылкаНаУзел = РешениеПоУзлу.Ссылка`. Создание нового элемента/группы не выполняется.
2. Если `ЗначениеЗаполнено(РешениеПоУзлу.ТекстИзФайла)`:
   - `ОбъектУзла = СсылкаНаУзел.ПолучитьОбъект()`;
   - `ОбъектУзла.ГКСИ_ТекстMarkdown = ОбернутьВМаркерыЯзыка(РешениеПоУзлу.ТекстИзФайла, КодЯзыка)`;
   - `ОбъектУзла.ГКСИ_MarkdownСформирован = Истина`;
   - `ОбъектУзла.Записать()`.
   - Накопление HTML в `МассивHTMLПоУзлам` (для пакетного создания присоединённых файлов в конце загрузки).
3. Дальше стандартная логика: при наличии `РодительскаяСсылка` — `ГКСИ_ГруппыСценариевСервер.ДобавитьСценарийВГруппу(СсылкаНаУзел, РодительскаяСсылка, ИнструкцияИсточникДляУзла)`.
4. Строка результата: `Действие = "Прикреплён"`.

Если `ТекстИзФайла` пустой (пользователь выбрал «Оставить наш» или у узла и так совпадали тексты) — текст узла в БД не перезаписывается, ссылка добавляется в РС как обычно.

### 5. Что осталось прежним

- Поведение «Пропустить» и «Обновить» не изменилось.
- Авто-резолв в `ОбработатьУзелРекурсивно` по-прежнему срабатывает для узлов, у которых нет явного решения в `РешенияПоКонфликтам` (см. `Описание.md` §15.11).
- Связь `КореньИнструкции` (см. `ОТЧЁТ_ИзоляцияУзловПоИнструкции_v85.md`) заполняется по тем же правилам, что и для других вариантов.

### 6. Известное ограничение

**Каскадное прикрепление детей** по-прежнему отложено. Если у прикреплённой группы есть дети в MD, для них действует стандартная логика загрузки:

- новые — создаются;
- существующие — снова попадают в форму разрешения конфликтов и могут быть прикреплены отдельно через повторное нажатие «Прикрепить» (теперь уже с диалогом, если тексты разные).

Так задумано: пользователь решает по каждому узлу явно, особенно когда тексты отличаются между инструкциями.

## Bugfix 2.1: `НайтиТекстУзлаПоИмениВДереве` принимает `ДеревоЗначений`

**Проблема (выявлена пользователем сразу после сдачи версии 2.1):** при проверке конфликтов через `ПроверитьКонфликтыНаСервере` (`Forms/Форма/Module.bsl`, строка 1295) функция `НайтиТекстУзлаПоИмениВДереве` вызывалась с `ДеревоУзлов` (объект `ДеревоЗначений`, полученный из `ПолучитьИзВременногоХранилища(АдресДереваУзлов)`). Внутри функции первой же строкой шло обращение `УзелДерева.Наименование`, а у `ДеревоЗначений` такого свойства нет — у него есть только коллекция `Строки`. Падало с ошибкой:

```text
Поле объекта не обнаружено (Наименование)
{ГКС_Инструкции Обработка.ГКСИ_ЗагрузкаСценариевИзMarkdown.Форма.Форма.Форма(1379)}:Если УзелДерева.Наименование = Имя Тогда
```

Из-за этого блок `Проверить конфликты` падал до того, как форма разрешения успевала открыться. Не работало и само появление диалога «чей текст оставить» — пользователь не мог им воспользоваться.

**Причина:** функция была написана в расчёте на передачу строки дерева, а вызов шел с самим деревом. Соседняя функция `СобратьИменаИзДерева` корректно работает в обоих режимах, потому что опирается на `.Строки` (есть и у дерева, и у строки).

**Исправление** в `Forms/Форма/Module.bsl` (`НайтиТекстУзлаПоИмениВДереве`):

```bsl
Если ТипЗнч(УзелДерева) = Тип("ДеревоЗначений") Тогда
    Для Каждого СтрокаВерхнегоУровня Из УзелДерева.Строки Цикл
        Результат = НайтиТекстУзлаПоИмениВДереве(СтрокаВерхнегоУровня, Имя);
        Если Результат <> "" Тогда
            Возврат Результат;
        КонецЕсли;
    КонецЦикла;
    Возврат "";
КонецЕсли;
```

То есть при передаче самого `ДеревоЗначений` функция сначала обходит строки верхнего уровня и для каждой делегирует рекурсивно в себя же — на следующей итерации `ТипЗнч` уже `СтрокаДереваЗначений`, идём в основную ветку с проверкой `.Наименование`. Сигнатура и существующий контракт не изменились — функция теперь принимает оба типа, как и `СобратьИменаИзДерева` (это упрощает и будущие вызовы из других мест).

В документирующий комментарий добавлено явное упоминание: «Допустимо передавать как само дерево (тогда обход начинается со строк верхнего уровня), так и конкретную строку».

**Проверка:**

- В EDT: Конфигурация → Обновить конфигурацию БД (F7), перезапустить клиент Предприятия, обновить форму (`Ctrl+F5`).
- Открыть обработку `ГКСИ_ЗагрузкаСценариевИзMarkdown`, выбрать ГИП.md, нажать «Проверить конфликты» — должно появиться окно «Найдено совпадений с существующими элементами: N» без ошибки.
- Если такие узлы есть и их тексты отличаются от существующих — нажать «Разрешить конфликты», поставить «Прикрепить к нашей группе», нажать «Применить» — откроется цепочка диалогов «чей текст оставить».

**Файлы изменены:**

- `src/DataProcessors/ГКСИ_ЗагрузкаСценариевИзMarkdown/Forms/Форма/Module.bsl` — `НайтиТекстУзлаПоИмениВДереве` принимает `ДеревоЗначений` или `СтрокаДереваЗначений`.
