# Отчёт: правка бага НСтр + список конфликтов + прогресс загрузки

**Дата:** 2026-09-09
**Проект:** пустая_для_гкс.ГКС_Инструкции
**Объект:** DataProcessor.ГКСИ_ЗагрузкаСценариевИзMarkdown

## Симптомы (сообщение пользователя)

> В ВыполнитьЗагрузкуКнопка текст появился, но в загрузке конфликтов нет текста снова.
> Плюс после загрузки прогресс не идет и не создаётся ничего.

## Причины и фиксы

### 1. Форма разрешения конфликтов — пустой список «Решение»

**Причина:** имена колонок в `Form.form` отличаются от ожидаемых в коде:
- В `Form.form` колонки: `КонфликтыКонфликты`, `КонфликтыКонфликты1`, `КонфликтыКонфликты2`, `КонфликтыКонфликты3`.
- В коде искали: `КонфликтыРешение`, `КонфликтыИмяИзФайла`, `КонфликтыСуществующаяСсылка`, `КонфликтыСуществующееЭтоГруппа`.

`Элементы.Найти("КонфликтыРешение")` возвращал `Неопределено`, список выбора не заполнялся, пользователь не мог выбрать решение.

**Фикс:** `Forms/ФормаРазрешенияКонфликтов/Module.bsl` — `НастроитьКолонкуРешения()`: использованы реальные имена колонок (`КонфликтыКонфликты3` для решения, `КонфликтыКонфликты`/`...1`/`...2` для остальных). Также починен отступ (`Если ... Тогда` теперь обнимает три `СписокВыбора.Добавить(...)`).

### 2. Ничего не создаётся — пустой результат загрузки

**Причина:** форма вызывала `ЗаписатьДеревоСинхронноНаСервере` — синхронную обёртку над `ЗаписатьДеревоВСправочник`. UI блокировался целиком, прогресс был фиктивным (50→100). При этом любой сбой (например, исключение в `НачатьТранзакцию()` или в подписках) оборачивался в `ЗаписьЖурналаРегистрации` и возвращался пустой `АдресРезультатаЗагрузки`, форма показывала «не удалось выполнить загрузку».

В проекте уже существовал заготовленный модуль `ГКСИ_ЗагрузкаСценариевИзMarkdownДлительныеОперации` с процедурой `ЗаписатьДеревоФоново`, но он не использовался.

**Фикс:** форма переключена на `ДлительныеОперации.ВыполнитьВФоне`:
- В серверной функции `ЗапуститьЗаписьДереваВФоне` инициализируется прогресс (`ИнициализироватьПрогресс(3)`), создаётся адрес результата, собирается структура параметров и запускается фоновое задание.
- Клиентская часть использует `ДлительныеОперацииКлиент.ОжидатьЗавершение` с оповещением `ЗавершениеФоновойЗагрузки`.

### 3. Прогресс не двигается

**Причина:** синхронный вызов блокировал UI, `ПроцентГотовности` прыгал с 50 на 100 мгновенно.

**Фикс:** добавлен клиентский обработчик ожидания `ОбработчикОжиданияПрогресса` (период 0.5 с), читающий структуру прогресса через серверную `ПолучитьПрогрессНаСервере` → `ГКСИ_ЗагрузкаСценариевИзMarkdown.ПолучитьПрогресс`. Обновляются `ПроцентГотовности` и `ТекстПрогресса` (текущий узел/картинка). Отключается автоматически при статусах «Готово»/«Ошибка» или по завершению задания.

### 4. Дополнительно: кривые `НСтр` в модуле длительных операций

В `ГКСИ_ЗагрузкаСценариевИзMarkdownДлительныеОперации/Module.bsl`:
- `НСтр("Не удалось получить параметры задания'")` → `НСтр("ru = 'Не удалось получить параметры задания'")`.
- `НСтр("Запуск записи дерева сценариев'")` → `НСтр("ru = 'Запуск записи дерева сценариев'")`.

Без кода языка платформа возвращала пустую строку, исключения теряли текст.

## Дополнение: «Слишком много фактических параметров»

После первой итерации фикса у пользователя упало фоновое задание с диагностикой:

```

{ГКСИ_ЗагрузкаСценариевИзMarkdown Модуль(786)}:
```

**Причина:** в `CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl` три вызова `НСтр` без закрывающей одинарной кавычки:

| Строка | Было | Стало |
| --- | --- | --- |
| 644 | `НСтр("ru = 'Запись элемента: %1")` | `НСтр("ru = 'Запись элемента: %1'")` |
| 786 | `НСтр("ru = 'Поиск картинки: %1")` | `НСтр("ru = 'Поиск картинки: %1'")` |
| 814 | `НСтр("ru = 'Загружено картинок: %1 (новых: %2)")` | `НСтр("ru = 'Загружено картинок: %1 (новых: %2)'")` |

Платформа воспринимала отсутствующую закрывающую `'` как начало параметра `НСтр`, и `СтрШаблон` получал «лишние» аргументы (отсюда «Слишком много фактических параметров»).

**Дополнительно:** интервал `ОбработчикОжиданияПрогресса` уменьшен с `0.5` до `1` секунды — платформа запрещает интервал меньше 1 для периодических обработчиков (только для однократных).

## Дополнение: «Проверить конфликты» открывает пустую форму

После первой итерации у пользователя форма разрешения конфликтов открывалась без строк.

**Гипотезы:**
1. Массив конфликтов на стороне основной формы возвращается пустым.
2. Массив возвращается непустым, но теряется при передаче через `ПараметрыФормы` на сервер открываемой формы.

**Фикс:**
1. В `ПроверитьКонфликты` основной формы массив теперь упаковывается во временное хранилище и передаётся через `ПараметрыФормы.АдресМассиваКонфликтов` — это надёжнее, чем массив структур «по ссылке», особенно когда состав структур менялся между версиями расширения.
2. В форме разрешения конфликтов сначала читается `АдресМассиваКонфликтов` (новый контракт), при пустом адресе — фолбэк на старый `МассивКонфликтов` (на случай параллельной работы с другой версией формы).
3. Добавлено диагностическое логирование в ЖР (`ГКСИ.ЗагрузкаСценариевИзMarkdown.ПроверкаКонфликтов`) на каждом этапе:
   - Количество имён, собранных из дерева (с дампом имён).
   - Количество совпадений, найденных в БД.
   - Размер массива, переданного в форму конфликтов (тип + количество).
   - Количество строк, добавленных в таблицу `Конфликты`.

**Версионирование:** 1.33 → **1.34** (+0.01, багфикс).

## Дополнение: «Старт записи дерева» есть, «Завершение» нет

После фикса окна подтверждения пользователь запустил загрузку. В ЖР появилась запись **«Старт записи дерева. Всего узлов: 6»**, но **«Завершение записи дерева» не появилась**, как и запись об ошибке на конкретном узле. То есть код падает где-то между стартом и первой удачной итерацией цикла, а исключение теряется на пути `ЗаписатьДеревоВСправочник → ЗаписатьДеревоФоново`.

**Фикс — детальное логирование в `ЗаписатьДеревоВСправочник`:**

**Фикс — логирование в `ЗаписатьДеревоФоново` (`ГКСИ_ЗагрузкаСценариевИзMarkdownДлительныеОперации`):**

## Дополнение: «Неправильный путь к файлу 'Структура'» в фоновом задании

После перевыпуска конфигурации БД в ЖР появилась запись о фоновом задании, но с ошибкой:

```
Ошибка при вызове метода контекста (ПолучитьИзВременногоХранилища)
{ГКС_Инструкции ОбщийМодуль.ГКСИ_ЗагрузкаСценариевИзMarkdownДлительныеОперации.Модуль(25)}:Параметры = ПолучитьИзВременногоХранилища(АдресПараметров);
{(1)}:ГКСИ_ЗагрузкаСценариевИзMarkdownДлительныеОперации.ЗаписатьДеревоФоново(Параметры[0],Параметры[1])
```

**Причина:** в `ЗапуститьЗаписьДереваВФоне` параметры для `ДлительныеОперации.ВыполнитьВФоне` передавались не как адрес ВХ, а как массив элементов. Платформа БСП разбирает массив параметров и подставляет элементы как фактические аргументы через `ОбщегоНазначения.ВыполнитьМетодКонфигурации("…", ПараметрыВызова)`. Поэтому `ЗаписатьДеревоФоново` получала на месте `АдресПараметров` сам объект `Структура`, а `ПолучитьИзВременногоХранилища(Структура)` падало с `Неправильный путь к файлу 'Структура'`. То же самое происходило и с `АдресПрогресса`.

**Фикс:** в `ЗапуститьЗаписьДереваВФоне` (`Форма/Module.bsl`) перед `ДлительныеОперации.ВыполнитьВФоне` собранная `СтруктураПараметров` помещается во временное хранилище:

```1c
АдресПараметров = ПоместитьВоВременноеХранилище(СтруктураПараметров, УникальныйИдентификатор);
…
ДанныеФоновогоЗадания = ДлительныеОперации.ВыполнитьВФоне(
    ИмяПроцедуры,
    Новый Структура("АдресПараметров, АдресПрогресса",
        АдресПараметров, АдресПрогресса),
    ПараметрыВыполнения);
```

Теперь `ВыполнитьВФоне` получает массив из двух строк-адресов ВХ, которые платформа корректно передаёт как фактические параметры `ЗаписатьДеревоФоново(АдресПараметров, АдресПрогресса)`.

Дополнительно в `ПараметрыВыполнения` добавлено `НаименованиеФоновогоЗадания = НСтр("ru = 'ГКСИ. Загрузка сценариев из Markdown'")`, чтобы задание было опознаваемо в консоли фоновых заданий.

**Версионирование:** 1.36 → **1.37** (+0.01, багфикс).

## Дополнение: ошибка осталась — `Структура` всё ещё приходит в `ЗаписатьДеревоФоново`

После повторного прогона с `Новый Структура("АдресПараметров, АдресПрогресса", …)` ошибка воспроизвелась точно в том же виде:

```
Ошибка при вызове метода контекста (ПолучитьИзВременногоХранилища)
{… ЗаписатьДеревоФоново(Параметры[0],Параметры[1])
```

**Что показал стек:** платформа вызывает процедуру через `Выполнить ИмяМетода + "(" + ПараметрыСтрока + ")"`. Если передать `Новый Структура(...)`, то `ПараметрыСтрока` рендерится в виде `"Структура"`, и `ЗаписатьДеревоФоново("Структура", "Структура")` → `ПолучитьИзВременногоХранилища("Структура")` → «Неправильный путь к файлу 'Структура'». То есть в этой конфигурации `ВыполнитьВФоне` принимает **только массив**, а `Параметры[0]`/`Параметры[1]` в стеке — это уже распакованные аргументы.

**Фикс:** в `ЗапуститьЗаписьДереваВФоне` (`Форма/Module.bsl`) параметры передаются **массивом** строк-адресов ВХ:

```1c
ПараметрыПроцедуры = Новый Массив;
ПараметрыПроцедуры.Добавить(АдресПараметров);
ПараметрыПроцедуры.Добавить(АдресПрогресса);
```

## Дополнение: ошибка осталась — `Неправильный путь к файлу 'Массив'`

После замены `Новый Структура(...)` на `Новый Массив(...)` ошибка сохранилась, только текст сменился: вместо `"Структура"` теперь `"Массив"`. Стек указывал ровно на ту же точку:

```

{… ЗаписатьДеревоФоново(Параметры[0],Параметры[1])
```

**Корневая причина:** я неправильно прочитал контракт БСП. В `ДлительныеОперации.Модуль(500)` строки 538–543 происходит следующее:

```1c

Если ПустаяСтрока(ПараметрыВыполнения.ЭтоФункция) Тогда
    ПараметрыЭкспортнойПроцедуры = Новый Массив;
    ПараметрыЭкспортнойПроцедуры.Добавить(ПараметрыПроцедуры);                        // ← наше значение целиком
    ПараметрыЭкспортнойПроцедуры.Добавить(ПараметрыВыполнения.АдресРезультата);      // ← дорисованный БСП
КонецЕсли;
```

То есть БСП **всегда** оборачивает переданное `ПараметрыПроцедуры` в массив первым элементом и добавляет `АдресРезультата` вторым. Дальше `ОбщегоНазначения.ВыполнитьМетодКонфигурации` рендерит массив в строку `«Параметры[0], Параметры[1]»` и вызывает `ЗаписатьДеревоФоново(НашеЗначение, АдресРезультата)`. Поэтому:

- если передать `Новый Структура(...)` — фон получает `Структура` как первый аргумент, `ПолучитьИзВременногоХранилища(Структура)` падает с `"Структура"`;

То есть переданное значение **и должно быть первым фактическим аргументом** нашего метода — никакого промежуточного массива из БСП не нужно.

**Фикс:** переделан контракт и с обеих сторон.

1. `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdownДлительныеОперации/Module.bsl` — сигнатура теперь:
   ```1c
   Процедура ЗаписатьДеревоФоново(ПараметрыЗадания, АдресРезультата) Экспорт
   ```
   `ПараметрыЗадания` — это `Структура`, которую мы передадим вторым аргументом `ВыполнитьВФоне`. Все поля читаются через `Свойство(...)` — устойчиво к отсутствующим полям. `АдресРезультата` — служебный адрес от БСП, в нашей схеме не используется, но обязателен по контракту.

2. `src/DataProcessors/ГКСИ_ЗагрузкаСценариевИзMarkdown/Forms/Форма/Module.bsl` (`ЗапуститьЗаписьДереваВФоне`):
   - убрана промежуточная обёртка `ПоместитьВоВременноеХранилище(СтруктураПараметров, …)` и `АдресПараметров`;
   - `АдресПрогресса` теперь лежит внутри той же `СтруктураПараметров`;
   - `ДлительныеОперации.ВыполнитьВФоне(ИмяПроцедуры, СтруктураПараметров, ПараметрыВыполнения)` — структура передаётся напрямую, БСП сам обернёт её в массив первым элементом.

После этого фоновое задание должно стартовать нормально: `ЗаписатьДеревоФоново(СтруктураПараметров, АдресРезультата)`, и в ЖР появятся «Старт фонового задания», «этап 2 — подготовка картинок», «этап 3 — запись в справочник», «Фоновое задание завершилось штатно».

## Дополнение: «Поле объекта не обнаружено (ПолноеИмя)»
