## 1. `SU61` ×6 — префикс в именах обработчиков команд

Обработчики команд переименованы под `ППГД_`:

| команда | обработчик |
|---|---|
| `текстДобавитьРоли` | `ППГД_текстДобавитьРолиПосле` |
| `текстИсключитьРоли` | `ППГД_текстИсключитьРолиПосле` |
| `ЗаполнитьВыбранными` | `ППГД_ЗаполнитьВыбраннымиПосле` |
| `СкопироватьРоли` | `ППГД_СкопироватьРолиПосле` |
| `ОбоработатьОтложенныеРоли` | `ППГД_ОбоработатьОтложенныеРолиПосле` |
| `ОбновитьИзРодителей` | `ППГД_ОбновитьИзРодителейПосле` |

**Способ (проверен на пилоте):** `removeFormCommand` → `addFormCommand` (то же имя команды, новый `handler`) → `addFormButton` (имя кнопки, `command_name`, родитель, позиция) → переименование процедуры в модуле.

**Почему безопасно:** этих команд нет в базовой форме (проверено поиском по `пустая_для_гкс/.../ФормаЭлемента/Form.form`), поэтому `callType=After` висел без базового обработчика и замена контейнера на обычный функционально эквивалентна.

**Не воспроизведено** (нет параметров у операций): подсказки команд и флаг «изменяет сохраняемые данные».

## 2. `SU93` ×7 — размещение обработчиков в области

Модуль был одной областью `СлужебныеПроцедурыИФункции`. Создана `#Область ОбработчикиКомандФормы`, в неё перенесены все 7 обработчиков команд; остальное осталось в служебной области.

## 3. `SU5` ×4 — устаревший метод

`ДанныеФормыВЗначение(X, Тип)` → `РеквизитФормыВЗначение("<имя реквизита>", Тип)` в 4 местах. Первый параметр нового метода — **имя реквизита строкой**, доступен только на сервере; все вызовы серверные.

## 4. Замена динамической команды на статическую

Расширяющий обработчик `OnCreateAtServer` (`пд_ПриСозданииНаСервереПосле`) динамически создавал команду `ППГД_ПодборРолей` и кнопку. Он был снят (см. «Ловушка» ниже), а команда и кнопка объявлены в модели формы статически: `addFormCommand` + `addFormButton` в `РолиКоманднаяПанель`. Динамический код удалён (иначе был бы дубль команды).

## 5. Осталось: `SU123`

Форма привязывает событие `ПередЗаписью` к `ППГД_ПередЗаписьюПеред`, которого в модуле нет. Привязка лежит в `<extInfo xsi:type="form:CatalogFormExtInfo">`, а не в списке обработчиков формы, поэтому `removeFormEventHandler` её не видит («Event BeforeWrite on the form has no handler»), а `.form` файловыми инструментами не редактируется.

**Варианты (нужно решение):** реализовать `&НаКлиенте Процедура ППГД_ПередЗаписьюПеред(Отказ, ПараметрыЗаписи)` с нужной логикой, либо удалить привязку в IDE.

## Ловушка: перепривязка обработчиков формы в расширении

- Обработчик события расширения — это `<handlers xsi:type="form:EventHandlerExtension">` + `<callType>After</callType>`. Плоский `<handlers>` — «свой» обработчик, то есть «вместо»: он **замещает** базовый обработчик конфигурации.
- `addFormEventHandler` не имеет параметра типа вызова — при перепривязке «после» молча понижается до «вместо». На `OnCreateAtServer` это отключило бы базовую инициализацию формы (в базовой форме свой `ПриСозданииНаСервере` есть).
- `.form` не редактируется файловыми инструментами: «Editing is not supported for this file type or the file is locked».
- `SearchText` по проекту расширения после правок врёт (отдаёт 0 по строкам, которые точно есть) — проверять через `Read`/`inspectForm`. Кэш маркеров тоже отстаёт: `GetMarkers` в одном сообщении с правкой возвращает устаревший список.
