# SU95: запрос в цикле — `ППГД_ОбменДаннымиXDTOСервер`

**Дата:** 2026-09-25
**Файл:** `src/CommonModules/ППГД_ОбменДаннымиXDTOСервер/Module.bsl`
**Было:** 1 ошибка (SU95) + 114 маркеров. **Стало:** 0 ошибок.

## Проблема

`Функция СсылкаОбъектаПоСвойствамОбъектаXDTO()` (стр. 2243) перебирает варианты идентификации объекта (`ПравилоКонвертации.ПоляПоиска`) и для каждого варианта, который не решается платформенными методами (`НайтиПоНомеру`/`НайтиПоНаименованию`/`НайтиПоКоду`), строила и выполняла свой запрос — внутри цикла. Варианты описывают **разные** типы метаданных, поэтому один запрос на все варианты не подходил.

## Почему не сработал простой вынос

Проверка `SU95` **отслеживает вызовы**: после выноса запроса в отдельную функцию маркер переформулировался в
«Цикл содержит вызов метода с запросом `НайтиСсылкуОбъектаЗапросом() -> Запрос.Выполнить()`».
Закрыть его можно только так, чтобы из цикла вообще не вызывался метод, выполняющий запрос.

## Решение (вариант 2)

- `ПодготовитьВариантПоискаЗапросом(ПравилоКонвертации, ПоляПоиска, НомерВарианта)` — новая функция: готовит описание варианта (полное имя объекта, условие отбора, значения параметров). Запрос **не** выполняется.
- В цикле: платформенные поиски как были; для SQL-вариантов — только накопление в `ВариантыЗапросов`.
- После цикла: `НайтиСсылкуОбъектаЗапросами(ВариантыЗапросов, АнализироватьПубличныеИдентификаторы, УзелОбмена)` — новая функция: собирает один **пакет** запросов и выполняет его одним вызовом `Запрос.ВыполнитьПакет()` (подтверждено документацией: результат — массив в порядке запросов пакета).
- Приоритет «первый подходящий по порядку вариантов» сохранён: берётся первый непустой результат пакета.

### Тонкости, которые пришлось учесть

- **Уникальные имена параметров.** В пакете параметры задаются на одном объекте `Запрос`, поэтому имя параметра варианта = `<ИмяПоля>_<НомерВарианта>` (иначе значения разных вариантов перекрылись бы).
- **Порядок замен в шаблоне условия.** Сначала `&[Ключ]` → `&<ИмяПараметра>`, только потом `[Ключ]` → имя поля. Иначе суффикс попал бы и в левую часть условия (`Таблица.Наименование_1`) и запрос стал бы нерабочим.
- **Приоритет над платформенным поиском.** Цикл по-прежнему прерывается на первом заполненном платформенном результате, поэтому все накопленные SQL-варианты гарантированно имеют **меньший** номер и потому приоритетнее — их результат перекрывает найденное значение.
- **`АнализироватьПубличныеИдентификаторы`** вынесен из цикла: он зависит только от правила конвертации и аргументов, то есть одинаков для всех вариантов.

## Влияние на риск

Функция `СсылкаОбъектаПоСвойствамОбъектаXDTO` помечена анализатором как **неиспользуемая** (SU44, стр. 2243) — маркер был и до правки. Если это не ложное срабатывание, правка вообще не затрагивает исполняемый путь. Тем не менее прогон тестового обмена обязателен.
