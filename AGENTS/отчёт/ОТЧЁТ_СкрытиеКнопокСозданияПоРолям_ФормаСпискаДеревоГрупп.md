# ОТЧЁТ_СкрытиеКнопокСозданияПоРолям_ФормаСпискаДеревоГрупп

Версия расширения: 2.34.1 → 2.35.0.

## Задача

На форме `ФормаСпискаДеревоГрупп` справочника `ДемонстрационныеСценарии`
есть кнопки «Создать» и «Создать группу». Пользователю с ролью
`ГКСИ_ЧтениеИнструкций` эти кнопки не должны быть видны.

## Что сделано

Файл: `src/Catalogs/ДемонстрационныеСценарии/Forms/ФормаСпискаДеревоГрупп/Module.bsl`.

1. В `ПриСозданииНаСервере` добавлен вызов новой служебной процедуры
   `ГКСИ_НастроитьВидимостьКомандСоздания()`.
2. Сама процедура скрывает кнопки, если у пользователя нет права
   на добавление элементов справочника:

```1c
&НаСервере
Процедура ГКСИ_НастроитьВидимостьКомандСоздания()

	Если ПравоДоступа("Добавление",
		Метаданные.Справочники.ДемонстрационныеСценарии) Тогда
		Возврат;
	КонецЕсли;

	Элементы.ФормаСоздать.Видимость = Ложь;
	Элементы.ФормаСоздатьГруппу.Видимость = Ложь;

КонецПроцедуры
```

## Почему так (а не ролевой настройкой в `Form.form`)

- Роль `ГКСИ_ЧтениеИнструкций` (`src/Roles/ГКСИ_ЧтениеИнструкций/Rights.rights`)
  даёт на `Catalog.ДемонстрационныеСценарии` только права `Read` и `View`,
  без `Insert`. Поэтому проверка `ПравоДоступа("Добавление", …)` для этой роли
  возвращает `Ложь`, а для роли `ГКСИ_РедактированиеИнструкций` (и любых
  полноправных ролей) — `Истина`.
- Проверка **права**, а не имени роли, — рекомендуемый подход: линтер BSL
  помечает `РольДоступна` (правило `IsInRoleMethod`) как антипаттерн и советует
  `ПравоДоступа`. Плюс это не завязывает код на конкретные роли.
- Стандарт 1С #std737 при большом числе ролей (а в ERP их много) рекомендует
  именно проверку прав в коде (`ПриСозданииНаСервере`), а не ролевые настройки
  видимости в форме. Аналогичная рекомендация есть в БСП («Ролевая видимость»).

### Про существующие ролевые настройки в `Form.form`

В текущем `Form.form` уже есть ролевые настройки: у команд `Создать` /
`СоздатьГруппу` заполнено `Использование` (`<use><common>true</common>…`),
а у пустой группы `ФормаГруппа1` — `Видимость` для роли `ГКСИ_ЧтениеИнструкций`.
Эти настройки дают предупреждения EDT **SU109** («Использована ролевая
настройка … для элемента формы»). Править `Form.form` штатными инструментами
нельзя (EDT-инструмент правки метаданных не поддерживает ролевые настройки,
а прямое редактирование `.form` запрещено правилами проекта), поэтому
выбран программный путь, который гарантированно даёт нужный результат и
не зависит от корректности этих настроек.

> Рекомендация на будущее: при очередной правке формы в GUI EDT — убрать
> ролевые настройки у команд и группы `ФормаГруппа1` (они дублируют код),
> чтобы снять SU109.
