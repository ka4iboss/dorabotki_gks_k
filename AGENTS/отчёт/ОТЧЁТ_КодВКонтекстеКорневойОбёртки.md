# Bugfix: КодВКонтексте корневой обёртки и её подчинённых

Версия: 2.32.28. Большая фича (четыре итерации фиксов для одного сквозного бага).

## Симптомы

После загрузки инструкции через `ГКСИ_ЗагрузкаСценариевИзMarkdown` в форме списка `ФормаСпискаДеревоГрупп`:

1. **Пустое дерево** — корневая обёртка инструкции не находится, форма показывает «корней 0, всего 0».
2. **`"001.001."` с хвостовой точкой** в ресурсе `КодВКонтексте` корневой обёртки: `ПолныйПолныйКодКонтекстныйГрафа(Корень, Корень, Граф) = "001."`, потом `КодВКонтексте = "001" + "." + "001." = "001.001."`.
3. **Лишний сегмент** у дочерних узлов: `#`-заголовок верхнего уровня получает `КодВКонтексте = "001.001.001"` вместо правильного `"001.001"`.

## Корневая причина

`ПолныйКод`, возвращаемый `ПолныйПолныйКодКонтекстныйГрафа(Сценарий, Группа, Граф)`, **уже включает** код корневой обёртки как первый сегмент — потому что `ПолныйКодГруппыГрафа(Обёртка)` возвращает её собственный код `"001"`, а самоссылка `Сценарий = Группа = КореньИнструкции` отфильтрована в `ГКСИ_ГрафГрупп`.

При этом `ГКСИ_ЗаписатьПолныйКодКонтекстный` в ресурс `КодВКонтексте` писал `Строка(КодКорня) + "." + ПолныйКод` — то есть добавлял префикс корня **повторно**. Результат:

- Для самоссылки корня: `"001" + "." + "001." = "001.001."` (лишний сегмент и хвостовая точка).
- Для `#`-заголовка верхнего уровня: `"001" + "." + "001.001" = "001.001.001"` (лишний сегмент).

Форма списка искала корневую обёртку по `КодВКонтексте = "001"` — не находила и рисовала пустое дерево.

## Цепочка фиксов (4 итерации)

### v2.32.25 — отдельная нумерация корневых обёрток + защита от сравнения типов

**Что исправлено:**

1. Добавлена функция `ГКСИ_ПолучитьСледующийКодКорневойОбёртки()` в `ГКСИ_ГруппыСценариевСервер`. Возвращает следующий свободный код в формате `"001"`, `"002"`, … среди служебных корневых обёрток (записи РС `ГКСИ_ГруппыСценариев` с самоссылкой `Сценарий = Группа = КореньИнструкции`).

2. В `ОбработатьУзелРекурсивно` (`ГКСИ_ЗагрузкаСценариевИзMarkdown`) для корневой обёртки (`ЭтоГруппа И Узел.Уровень = 1 И ЭтоНовыйЭлемент`) явно задаётся `ОбъектУзла.Код = ГКСИ_ПолучитьСледующийКодКорневойОбёртки()`. Раньше код назначался платформенной автонумерацией как `MAX(Код)+1` от всего справочника, и вторая инструкция получала код `"019"` вместо ожидаемого `"002"`.

3. Защита от Runtime-исключения «Операции сравнения на больше-меньше допустимы только для значений совпадающих примитивных типов»: парсинг кода через `Число(Строка(Выборка.Код))` с `Попытка-Исключение` (тип поля `Код` заимствован из ERP как `Число` по мнению EDT, но в runtime — `Строка`). EDT выдаёт предупреждение SU220 на строке присваивания — это ложное срабатывание, в runtime работает корректно.

**Что осталось:** код корневой обёртки `"001"`/`"002"` правильный, но `КодВКонтексте` всё ещё строится неправильно (см. следующие фиксы).

### v2.32.26 — убран ошибочный «defensive programming» в `ПолныйКодГруппыГрафа` + пропуск самоссылки в `ПересчитатьПолныйКодКонтекстныйДляСценария`

**Что исправлено:**

1. В `ПолныйКодГруппыГрафа` (строка 553) убран блок `Если РодителиРодителя = Неопределено ИЛИ РодителиРодителя.Количество() = 0 Тогда Возврат Формат(Граф.КодыПоСсылкам.Получить(Группа), ...)`. Логика самоссылки уже была выше через `Если Родитель = Группа Тогда Возврат ...`, а дополнительный блок ломал правильное поведение для `#`-заголовка верхнего уровня (возвращал его собственный код вместо `КодОбёртки + "." + ПозицияСиблинга`).

2. В `ПересчитатьПолныйКодКонтекстныйДляСценария` (строка 688) добавлен `Если Выборка.Группа = Сценарий Тогда Продолжить; КонецЕсли;`. Без этого самоссылка корневой обёртки пересчитывалась и её `КодВКонтексте` перетирался на `"001.001."`.

**Что осталось:** пересчёт уже существующих данных защищён, но **изначальная** запись `КодВКонтексте` через `ГКСИ_ЗаписатьПолныйКодКонтекстный` всё ещё пишет `"001" + "." + ПолныйКод` (лишний префикс).

### v2.32.27 — правильная запись для самоссылки корневой обёртки в `ГКСИ_ЗаписатьПолныйКодКонтекстный`

**Что исправлено:**

В `ГКСИ_ЗаписатьПолныйКодКонтекстный` (строка 1433) добавлена ветка для самоссылки: `Если Сценарий = Группа Тогда Запись.КодВКонтексте = Строка(КодКорня); Иначе ...; КонецЕсли;`.

**Эффект:** для самоссылки корневой обёртки `КодВКонтексте = "001"` (без префикса и без хвостовой точки). Форма списка находит корневую обёртку и начинает рисовать дерево.

**Что осталось:** для обычных записей (не самоссылок) код всё ещё пишется как `Строка(КодКорня) + "." + ПолныйКод`, что даёт лишний сегмент (`"001" + "." + "001.001" = "001.001.001"` для `#`-заголовка).

### v2.32.28 — убран дубль префикса для обычных записей в `ГКСИ_ЗаписатьПолныйКодКонтекстный`

**Корневая причина (наконец-то):** `ПолныйКод` от `ПолныйПолныйКодКонтекстныйГрафа` уже включает код корня как первый сегмент (потому что `ПолныйКодГруппыГрафа(Обёртка)` возвращает её собственный код `"001"`, а самоссылка отфильтрована в графе). Поэтому добавлять `Строка(КодКорня)` спереди — дубль.

**Что исправлено:**

```1c
Если Сценарий = Группа Тогда
    Запись.КодВКонтексте = Строка(КодКорня);   // "001" для самоссылки обёртки
Иначе
    Запись.КодВКонтексте = ПолныйКод;          // "001.001" — уже содержит код корня
КонецЕсли;
```

**Эффект:** правильные коды во всех случаях:

- Самоссылка корневой обёртки: `"001"`.
- `#`-заголовок верхнего уровня: `"001.001"`.
- `##`-подзаголовок: `"001.001.001"`.
- Элемент, входящий в обёртку напрямую: `"001.002"`.

### v2.33.1 — гарантированный пересчёт кодов всей инструкции в конце загрузки

**Задача:** при окончании загрузки инструкции всегда пересчитывать `ПолныйКодКонтекстный` у корневой группы и всех подчинённых — независимо от порядка появления связей в регистре.

**Что изменено:**

1. В `ОбработатьУзелРекурсивно` (`ГКСИ_ЗагрузкаСценариевИзMarkdown`) вызов `ПересчитатьПолныйКодДляПоддерева(СсылкаНаУзел)` теперь выполняется **только для корневой обёртки** (`Если Узел.Уровень = 1 И ЗначениеЗаполнено(СсылкаНаУзел)`), а не для каждой группы (`Если ЭтоГруппа`). Пересчёт поддерева корня покрывает всю инструкцию (`ГКСИ_СобратьПотомковРекурсивно` включает и саму группу, и всех вложенных), поэтому промежуточные группы пересчитывать не нужно — это N полных построений графа базы на одном дереве при том же результате. Вызов идёт после рекурсии в детей, когда все связи уже в регистре.
2. В `ПересчитатьПолныйКодДляПоддерева` (`ГКСИ_ГруппыСценариевСервер`) добавлен явный пропуск самоссылок (`Если Выборка.Сценарий = Выборка.Группа Тогда Продолжить`) — массив групп поддерева включает саму корневую обёртку, и её самоссылка попадает в выборку; без пропуска `ПолныйКодКонтекстный` обёртки перетирался на `"001."` (с хвостовой точкой).

**Эффект:** после загрузки любой инструкции все её узлы (корневая обёртка, `#`-заголовки, подгруппы, элементы) гарантированно имеют корректный `КодВКонтексте` — `"001"`, `"001.001"`, `"001.001.001"`, `"001.002"`, … — независимо от того, в каком порядке были записаны связи.

## Как проверять

1. Обновить конфигурацию БД (F7 в EDT), перезапустить клиент Предприятия.
2. Очистить справочник `ДемонстрационныеСценарии` и регистр `ГКСИ_ГруппыСценариев` (старые «сломанные» записи с `"001.001."` сами не исправятся).
3. Загрузить инструкцию через `ГКСИ_ЗагрузкаСценариевИзMarkdown`.
4. Открыть форму списка `ФормаСпискаДеревоГрупп`.
5. Проверить:

   - Корневая обёртка имеет `КодВКонтексте = "001"` (для первой инструкции) — без хвостовой точки и без лишних сегментов.
   - `#`-заголовки верхнего уровня имеют `КодВКонтексте = "001.001"`, `"001.002"`, … — без лишнего префикса.
   - `##`-подзаголовки имеют `КодВКонтексте = "001.001.001"`, `"001.001.002"`, …
   - Форма списка корректно строит дерево, без пустого корня.

6. Загрузить вторую инструкцию — обёртка должна получить код `"002"`, не `"MAX(Код)+1"` от всего справочника.

## Уроки

1. **`ПолныйКод` уже содержит код корня как первый сегмент.** Если добавлять `КодКорня` ещё раз в `КодВКонтексте` — дубль. Это противоречит интуитивному «префикс = код корня», но вытекает из архитектуры: `ПолныйКодГруппыГрафа(Обёртка)` возвращает собственный код корня (самоссылка отфильтрована в графе), и `ПолныйКод` строится через `ПолныйКодГруппы(Группа) + "." + ПозицияСиблинга`. Архитектура — в `Описание.md` §13.4.

2. **Самоссылка корневой обёртки — особый случай в пяти местах кода:**

   - `ДобавитьСценарийВГруппу` — `Сценарий = Группа → Возврат`.
   - `ГКСИ_ГрафГрупп` — `Сценарий = Группа → Продолжить`.
   - Все функции пересчёта (`ПересчитатьПолныйКодДляПоддереваГрафа`, `ПересчитатьПолныйКодКонтекстныйДляСценария`, `ГКСИ_ПересчитатьВсеКодыВРегистре`) — `Если Сценарий = Группа Тогда Продолжить; КонецЕсли;`.
   - `ГКСИ_ЗаписатьПолныйКодКонтекстный` — особое формирование `КодВКонтексте` (см. v2.32.27/2.32.28).
   - `ПолныйПолныйКодКонтекстныйГрафа(Корень, Корень, Граф)` — возвращает `"001."` (с хвостовой точкой), потому что `ПозицияСиблинга` для самоссылки пустая. Это **намеренное** поведение — формат ресурса `ПолныйКодКонтекстный` отличается от `КодВКонтексте`.

3. **Защитное программирование в `ПолныйКодГруппыГрафа` опасно.** В v2.32.25 я добавил блок «на всякий случай, если у родителя нет своего родителя» — он сломал правильное поведение для `#`-заголовков верхнего уровня. Защита от циклов уже есть в `ГКСИ_ГрафГрупп` (самоссылка отфильтрована) и `ПолныйКодГруппыГрафа` (`Если Родитель = Группа Тогда`). Дополнительная защита только мешает.

4. **«Слоёный» баг: каждый фикс закрывает один слой, но не закрывает все.** В этой серии 2.32.25 закрыл «нумерация обёрток», 2.32.26 — «пересчёт самоссылки», 2.32.27 — «изначальная запись для самоссылки», 2.32.28 — «изначальная запись для обычных записей». При разборе подобных багов проверять **каждый** путь записи/чтения кода, не останавливаться на первом найденном.

## Технические замечания

- EDT-предупреждение SU220 на строке присваивания `ОбъектУзла.Код = ГКСИ_ПолучитьСледующийКодКорневойОбёртки()` в `ОбработатьУзелРекурсивно` — ложное срабатывание (EDT не может разрешить тип заимствованного реквизита `Код`, считает Числом, в runtime — Строка). Не блокирует компиляцию, в runtime работает корректно.
- Все маркеры EDT по изменённым функциям (`SU59`, `SU72`, `SU78`, `SU83`, `SU29`) — старые, существовали до правок. Новых маркеров после серии фиксов не появилось.
- Правило в `memory/feedback_skip_self_references_on_recalc.md` уже покрывает часть этой истории (пропуск самоссылки при пересчёте). Этот отчёт дополняет правило для **изначальной** записи (через `ГКСИ_ЗаписатьПолныйКодКонтекстный`).
