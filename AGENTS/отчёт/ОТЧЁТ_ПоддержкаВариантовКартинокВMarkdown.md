# ОТЧЁТ: Поддержка вариантов ссылок на картинки в Markdown-загрузке

## Дата: 2026-09-10

## Версия расширения: 1.48 → 1.49

## Суть проблемы

После загрузки сценария из Markdown в форме элемента / формы группы
справочника `ДемонстрационныеСценарии` картинки в HTML-описании
отображались как «битые» (broken image). После ручной перезаписи
элемента картинки появлялись.

## Диагностика

### Что было причиной

Функция `ПодменитьСсылкиНаКартинкиВТексте` в
`src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl` обрабатывала
только синтаксис `![[path]]` (Obsidian). Все остальные варианты
ссылок на картинки оставались «сырыми» в исходном тексте:

| Синтаксис | Обрабатывался | Результат |
| --- | --- | --- |
| `![[image.png]]` | да | нормальная подмена |
| `![[image.png\|200\|caption]]` | частично | захватывался только путь с `\|200\|caption`, ключ карты не совпадал с тем, что был в HTML |
| `![alt](image.png)` | нет | сырой путь в HTML → битая картинка |

В результате `MarkdownВHTML` формировал `<img src="image.png">` или
`<img src="image.png\|200\|caption">` вместо `<img src="<GUID_файла_инструкции>">`.

`ГКСИ_MarkdownПереопределяемый.ЗаменитьКодыИзображенийНаDataURI` ищет в `src`
только GUID-ы по регулярке `[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-...`. Сырые
пути и пути с `|...` не матчатся — картинка остаётся битой.

После ручной записи через форму элемента HTML прогоняется по другой
ветке (через `ДемонстрационныеСценарии.РезультатОбновленияПрисоединенногоФайла`
→ `ДемонстрационныеСценарии.ЗаписатьНовыеОписанияСценариевИзФормыОбъекта`),
которая дополнительно обрабатывает картинки. Отсюда эффект
«появляются после пересохранения».

### Что подтвердило диагноз

- Кеш изображений `ГКСИ_ДанныеИзображенийMarkdownПовтИсп` — работает
  корректно и в фоне, и в основном сеансе. После ручной записи элемента
  HTML рендерится с теми же вызовами `СоответствиеКодДанныеИзображений`
  и картинки появляются — значит, кеш отдаёт данные нормально.
- `ГКСИ_MarkdownПереопределяемый.ЗаменитьКодыИзображенийНаDataURI` и
  `ГКСИ_АльбомПроцессов.ТелоГипертекста` работают как раньше.
- Воспроизведение стабильное: на скриншоте альбома процессов после
  загрузки сценария видны битые иконки.

## Решение

Изменены три функции в
`src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`.

### 1. `УникальныеПутиКартинокИзТекста` (строка 350)

Собирает уникальные пути картинок из текста Markdown. Теперь использует
два regex:

- Obsidian: `!\[\[([^\]|]+)(?:\|[^\]]*)?\]\]` — захватывает чистый путь
  без `|...`.
- Markdown: `!\[[^\]]*\]\(([^)]+)\)` — захватывает URL.

Ключи в возвращаемом соответствии — нормализованные пути без `|size`
и `|caption`.

### 2. `СобратьПутиКартинокИзУзла` (строка 901)

Рекурсивный обход дерева узлов и сбор путей картинок. Использует те же
два regex, что и `УникальныеПутиКартинокИзТекста`. Сохраняет пути в
переданное соответствие `УникальныеПути`.

### 3. `ПодменитьСсылкиНаКартинкиВТексте` (строка 961)

Полностью переписана:

- Вместо `СтрЗаменить` по каждому ключу карты — один проход двумя regex
  (теми же, что выше).
- Собирается массив замен `{Позиция, Длина, Текст}`.
- Применение замен выполняется с конца строки (от большего индекса к
  меньшему), чтобы не сбивать позиции остальных замен.
- Если путь не нашёлся в карте подмен — подменяется на `❌ <путь>`.
  Это визуальный маркер, по которому пользователь видит, что файл не
  найден на диске или не сопоставлен с уже существующим файлом в
  справочнике.
- Выделена общая процедура `ДобавитьЗаменыПоРегулярномуВыражению`,
  чтобы не дублировать код обхода совпадений.

## Фрагменты кода

### Два regex для сбора путей

```1c
// Obsidian
Совпадения = СтрНайтиВсеПоРегулярномуВыражению(Текст, "!\[\[([^\]|]+)(?:\|[^\]]*)?\]\]");
// Markdown
Совпадения = СтрНайтиВсеПоРегулярномуВыражению(Текст, "!\[[^\]]*\]\(([^)]+)\)");
```

### Применение замен с конца строки

```1c
Для ИндексЗамены = Замены.ВГраница() По 0 Цикл
    Замена = Замены[ИндексЗамены];
    Текст = Лев(Текст, Замена.Позиция - 1)
        + Замена.Текст
        + Сред(Текст, Замена.Позиция + Замена.Длина);
КонецЦикла;
```

## Результат

- Картинки показываются в HTML-описании сценария сразу после загрузки
  из Markdown, без необходимости заходить в элемент и перезаписывать.
- Поддерживаются три варианта ссылок: `![[path]]`, `![[path|extra]]`,
  `![alt](path)`.
- Если файл картинки не найден на диске или его хеш не совпадает с
  существующим в справочнике `ГКСИ_ФайлыИнструкций`, пользователь
  видит `❌ <путь>` вместо молчаливого broken image — это облегчает
  диагностику при подготовке сценариев.

## Файлы

- `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl` —
  изменены три функции, добавлена вспомогательная процедура
  `ДобавитьЗаменыПоРегулярномуВыражению`.
- `src/Configuration/Configuration.mdo` — версия 1.48 → 1.49.

## Горячая правка 1.50

После публикации 1.49 фоновая загрузка сценариев упала с ошибкой
`Метод объекта не обнаружен (НачальнаяПозиция)` в строке
`ГКСИ_ЗагрузкаСценариевИзMarkdown.Модуль(1014)`.

**Причина.** В `ДобавитьЗаменыПоРегулярномуВыражению` я по ошибке
обратился к свойствам элемента результата `СтрНайтиВсеПоРегулярномуВыражению`
как к методам — `Совпадение.НачальнаяПозиция()` и `Совпадение.Длина()`.
Согласно документации (`РезультатПоискаПоРегулярномуВыражению`,
доступно с 8.3.23) это **свойства**, не методы.

**Исправление** в `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`:

```1c
// Было (падает с «Метод объекта не обнаружен»):
Замены.Добавить(Новый Структура("Позиция, Длина, Текст",
    Совпадение.НачальнаяПозиция(), Совпадение.Длина(), НовыйТекст));

// Стало:
Замены.Добавить(Новый Структура("Позиция, Длина, Текст",
    Совпадение.НачальнаяПозиция, Совпадение.Длина, НовыйТекст));
```

Версия расширения поднята 1.49 → 1.50. Маркеры EDT по изменённому `.mdo` — 0.
Синтаксис (`bsl-language-server`): 0 ошибок, 0 предупреждений.

## Багфикс 1.51: `data:URI` не подставлялся при первой загрузке

После 1.49/1.50 пользователь сообщил, что картинки всё ещё видны как
«битые» (`<img src="GUID" alt="">` с вопросиком) при первой загрузке
сценария, и появляются только после ручной перезаписи элемента.

### Диагностика

Расставлены временные `ЗаписьЖурналаРегистрации` в 6 точках цепочки
(событие `ГКСИ.Диагностика.КартинкиMarkdown`):

1. `ЗаменитьКодыИзображенийНаDataURI` — сколько GUID найдено в HTML.
2. `…: СоответствиеКодДанныеИзображений вернуло=N` — есть ли данные в кеше.
3. `…: после НормализоватьСоответствиеКодДанные размер=N` — главная точка.
4. `…: после ГКСИ_СобратьВхожденияКодов размер=N`.
5. `…: ФИНАЛ содержит data:=ДА/НЕТ`.
6. `MarkdownВHTML (после Заменить…)` и
   `ГКСИ_СоздатьПрисоединенныйФайлСценария (вход)` — содержит ли HTML `data:`.

Прогон показал:

```text
ЗаменитьКодыИзображенийНаDataURI: найдено кодов=1
ЗаменитьКодыИзображенийНаDataURI: СоответствиеКодДанныеИзображений вернуло=1
ЗаменитьКодыИзображенийНаDataURI: после НормализоватьСоответствиеКодДанные размер=0
MarkdownВHTML (после ЗаменитьКодыИзображенийНаDataURI): содержит data:=НЕТ
```

То есть кеш данные возвращает, но после нормализации соответствие
всегда пустое — `data:URI` не подставляется.

### Корневая причина

Функция `НормализоватьСоответствиеКодДанные` искала элемент
справочника через
`Справочники.ГКСИ_ФайлыИнструкций.ПолучитьСсылку(Новый УникальныйИдентификатор(КодСтрокой))`.
Это **неправильно**: у справочника `Код` — строковый, мы туда пишем
`Строка(Новый УникальныйИдентификатор())` в `СоздатьЭлементФайлаИнструкции`,
и этот строковый GUID не совпадает с внутренним УИД объекта в БД.
Поэтому `ПолучитьСсылку` возвращал пустую ссылку, `МассивСсылок` оказывался
пустым, запрос `Ссылка В (&МассивСсылок)` возвращал ноль строк, и
`СоответствиеКодДанные` оставалось пустым.

### Решение

Переписана `НормализоватьСоответствиеКодДанные` в
`src/CommonModules/ГКСИ_MarkdownПереопределяемый/Module.bsl` —
убран `ПолучитьСсылку`, теперь читаем напрямую запросом по
`ФайлыИнструкций.Код В (&МассивКодов)` (с фильтром
`И НЕ ФайлыИнструкций.ПометкаУдаления`, как в основной реализации
`ГКСИ_ДанныеИзображенийMarkdown.СоответствиеКодДанные`).

```1c
Запрос.Текст =
"ВЫБРАТЬ
|   ФайлыИнструкций.Код КАК Код,
|   ФайлыИнструкций.Файл КАК Файл,
|   ФайлыИнструкций.Расширение КАК Расширение
|ИЗ
|   Справочник.ГКСИ_ФайлыИнструкций КАК ФайлыИнструкций
|ГДЕ
|   ФайлыИнструкций.Код В (&МассивКодов)
|   И НЕ ФайлыИнструкций.ПометкаУдаления";
```

Строить промежуточное `СоответствиеКодСсылка` больше не нужно —
сразу кладём результат выборки в `Результат` с ключом `Выборка.Код`.

Все диагностические `ЗаписьЖурналаРегистрации` удалены после подтверждения
гипотезы. Версия расширения поднята 1.50 → 1.51.

### Что проверено

- Синтаксис (`bsl-language-server`): 0 ошибок, 0 предупреждений.
- Маркеры EDT по `ДемонстрационныеСценарии.mdo` (изменён `ObjectModule.bsl`):

- Маркеры EDT по `ГКСИ_ЗагрузкаСценариевИзMarkdown.mdo` и
  `ГКСИ_MarkdownПереопределяемый.mdo`: 0.

### Урок

`СправочникМенеджер.ПолучитьСсылку(УИД)` создаёт ссылку по **внутреннему
УИД объекта в БД**, а не по реквизиту `Код`. Если у справочника `Код`
строковый и в него кладут что-то отличное от внутреннего УИД — искать
надо по `Код` через запрос, как в обычном коде, а не через `ПолучитьСсылку`.
