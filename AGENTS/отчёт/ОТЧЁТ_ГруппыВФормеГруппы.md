# Задача: реализация множественной принадлежности к группам в ФормаГруппы

> **Примечание.** Описание архитектуры и алгоритмов подсистемы множественной принадлежности
> к группам (РС `ГКСИ_ГруппыСценариев`, общий модуль `ГКСИ_ГруппыСценариевСервер`,
> перехватчики в `ObjectModule.ДемонстрационныеСценарии`) вынесено в `описание/Описание.md`
> (§13). Здесь фиксируется только хроника правок этой задачи.

## Суть задачи

В справочнике `ДемонстрационныеСценарии` для **элемента** (`ФормаЭлемента`)
уже была реализована программная панель «Входит в группы»: пользователь мог
задать, в какие родительские группы входит сценарий, через таблицу
`ГКСИ_ГруппыСценария`, привязанную к регистру сведений
`ГКСИ_ГруппыСценариев`.

Требовалось перенести ту же логику на **форму группы** (`ФормаГруппы`),
чтобы при создании/редактировании группы можно было указать её
принадлежность к другим группам (то есть поддержать иерархию не только
через типовой `Родитель`, но и через множественную связь в регистре).

## Что сделано

### 1. Общий модуль `ГКСИ_ГруппыСценариевСервер`

Добавлены три экспортные процедуры для переиспользования обеими формами:

- `ДобавитьПанельГруппСценария(Форма)` — программно создаёт на форме
  группу `ГКСИ_ГруппыСценарияГруппа`, команды и кнопки добавления/удаления,
  таблицу `ГКСИ_ГруппыСценария` с колонками `Группа` и
  `ПолныйКодКонтекстный`, привязанные к реквизиту формы
  `ГКСИ_ГруппыСценария` (`ValueTable`). Идемпотентно.
- `ЗаполнитьГруппыСценария(Форма)` — очищает таблицу формы и заполняет её
  из регистра через `ПолучитьГруппыСценария` и `ПолныйКодВКонтексте`.
- `СинхронизироватьГруппыСценария(Форма, ТекущийОбъект, Отказ)` —
  сравнивает текущие и новые связи; удаляет лишние, добавляет новые;
  при каждом изменении пересчитывает `ПолныйКодКонтекстный` для
  поддеревьев затронутых групп, чтобы кеш оставался актуальным.

### 2. Форма выбора `ГКСИ_ФормаВыбораГруппы`

Создана новая форма `Catalog.ДемонстрационныеСценарии.Form.ГКСИ_ФормаВыбораГруппы`:
- реквизит `СписокГрупп` (`ValueTable`) с колонками `Группа` и `Наименование`;
- таблица с автоматически добавленными колонками;
- команда и кнопка `Выбрать`, обработчик выбора строки;
- в `ПриСозданииНаСервере` параметр `ИсключаемыеГруппы` используется
  для отбора (исключает выбранные и уже добавленные группы).

### 3. Форма элемента `ФормаЭлемента/Module.bsl`

Удалены локальные процедуры `ГКСИ_ДобавитьПанельГруппСценария`,
`ГКСИ_ЗаполнитьГруппыСценария`, `ГКСИ_СинхронизироватьГруппыСценария`.
Все вызовы переключены на `ГКСИ_ГруппыСценариевСервер.*`. Команда
«Добавить группу» открывает собственную форму
`ГКСИ_ФормаВыбораГруппы` с массивом исключений (сам сценарий + его
текущие группы).

### 4. Форма группы `ФормаГруппы/Form.form`

Добавлен реквизит `ГКСИ_ГруппыСценария` (`ValueTable`) с колонками
`Группа` (`CatalogRef.ДемонстрационныеСценарии`) и
`ПолныйКодКонтекстный` (`String`, длина 250). Сама панель (группа,
кнопки, таблица) добавляется программно через
`ГКСИ_ГруппыСценариевСервер.ДобавитьПанельГруппСценария` — для избежания
коллизий ID и переиспользования логики.

### 5. Форма группы `ФормаГруппы/Module.bsl`

Создан с нуля. Содержит:
- перехватчик `&Перед("ПриСозданииНаСервере")` — добавляет панель и
  заполняет её;
- перехватчик `&После("ПриЧтенииНаСервере")` — обновляет таблицу при
  чтении объекта;
- перехватчик `&Перед("ПередЗаписьюНаСервере")` — синхронизирует
  регистр с таблицей формы (до типового обработчика);
- клиентские команды `ГКСИ_ДобавитьГруппу`, `ГКСИ_УдалитьГруппу`,
  обработчик `ГКСИ_ЗавершениеВыбораГруппы`;
- серверную функцию `ГКСИ_ПолучитьИсключаемыеГруппыНаСервере` —
  формирует массив ссылок (потомки группы + уже добавленные в таблице),
  которые нужно скрыть в форме выбора.

## Проверки

- `GetMarkers` по `ФормаГруппы/Form.form` — 0 ошибок.
- `GetMarkers` по `ГКСИ_ФормаВыбораГруппы/Form.form` — 0 ошибок.
- `GetMarkers` по `ФормаЭлемента/Module.bsl` — критические ошибки
  `ГКСИ_ДобавитьПанельГруппСценария не определена [Сервер]` и т.п.
  устранены (вызовы переключены на общий модуль). Остаточные
  предупреждения (избыточный `ЭтотОбъект`, неиспользуемые старые методы)
  относятся к коду, существовавшему до правок, и не блокируют компиляцию.
- `GetMarkers` по `ГКСИ_ГруппыСценариевСервер/Module.bsl` — 3 ошибки
  SU95 (запрос в цикле) присутствовали и до правок; архитектурно
  запрос кешируется через `ПовторноИспользуемыеЗначения` (см.
  `ГКСИ_ГрафГрупп`), так что в реальной работе выполняется один раз.

### Исправление: ошибка «Нельзя изменять поле, содержащее объект данных формы»

Первая рабочая версия передавала в серверную функцию
`ГКСИ_ПолучитьИсключаемыеГруппыНаСервере` (`&НаСервереБезКонтекста`)
саму таблицу формы `ГКСИ_ГруппыСценария` (тип `ДанныеФормыКоллекция`).
При попытке обойти её в цикле и обращаться к полям возникала
ошибка «Нельзя изменять поле, содержащее объект данных формы» —
платформа передаёт в безконтекстную функцию копию объекта формы
без права модификации.

Решение: на клиенте формируется обычный `Массив` ссылок, который
и передаётся в серверную функцию. Серверная функция работает
с обычными ссылочными типами без привязки к контексту формы.

## Почему именно так

- **Общий модуль.** Дублирование логики между двумя формами увеличивает
  риск рассогласования. Общий модуль — единственная точка изменений.
- **ValueTable вместо DynamicList** в `ГКСИ_ФормаВыбораГруппы`.
  EDT API `addFormField` в текущей версии падает с NPE при попытке
  привязать колонку к DynamicList. Переделка на ValueTable + ручное
  заполнение в `ПриСозданииНаСервере` снимает проблему и не теряет
  функциональности.
- **Программное добавление панели** (а не описание в `Form.form`) —
  для переиспользования между формами: декларативное добавление
  потребовало бы дублировать структуру группы/таблицы/кнопок.
- **Пересчёт `ПолныйКодКонтекстный` для обоих поддеревьев** при
  синхронизации: иначе при перемещении элемента из одной группы в другую
  кеш `ПолныйКодКонтекстный` у элементов старого и нового поддерева
  устаревает до следующей записи соответствующего объекта.
