## Ключевые архитектурные решения

1. **Дополнение существующих перехватчиков, а не создание новых.**
   В `ФормаГруппы` уже были перехватчики `ГКСИ_ПередПриСозданииНаСервере`,
   `ГКСИ_ПослеПриЧтенииНаСервере`, `ГКСИ_ПередПередЗаписьюНаСервере`
   для панели групп. Чтобы не дублировать аннотации для одних и тех же
   событий (EDT это не любит), их тела **дополнены** вызовами новых
   процедур для Markdown.
2. **Панель Markdown встраивается в `СтраницаВариантОтображенияРедактирование`**
   — ту же страницу, что и в `ФормаЭлемента`. Это сохраняет типовое
   переключение «Просмотр/Редактирование/Перевод» и поведение
   `ДобавитьКТекстуСписокШаговГруппы` (формирует HTML-поле
   `ТекстСценарияЧтение` со списком дочерних шагов в режиме «Просмотр»).
3. **Типовой HTML-вывод сохраняется.** `ГКСИ_СоздатьПрисоединенныеФайлыИзДопСвойств`
   срабатывает ДО типового `ПередЗаписьюНаСервере` и сам создаёт/обновляет
   присоединённые HTML-файлы по каждому языку, поэтому типовая
   `ДемонстрационныеСценарии.ЗаписатьНовыеОписанияСценариевИзФормыОбъекта`
   их не перетирает (строки ТЧ помечены как не-изменённые).
4. **`&Вместо` для типовых команд.** Пустые перекрытия `Редактировать`,
   `ЗакончитьРедактирование`, `ОтменитьРедактирование` гарантируют, что
   типовое открытие внешнего HTML-редактора не сработает ни при каком
   программном вызове команды.
5. **Миграция HTML→Markdown.** При первом открытии группы с
   заполненным HTML, но без Markdown (`ГКСИ_MarkdownСформирован = Ложь`),
   срабатывает `ГКСИ_ВыполнитьМиграциюHTMLВMarkdown`.

## Сохранено без изменений

- Логика панели «Входит в группы» (`ГКСИ_ДобавитьГруппу`,
  `ГКСИ_УдалитьГруппу`, `ГКСИ_ЗавершениеВыбораГруппы`,
  `ГКСИ_ПолучитьИсключаемыеГруппыНаСервере`) — работает как раньше.
- **Список дочерних шагов группы** — типовая процедура
  `ДобавитьКТекстуСписокШаговГруппы` перекрыта через
  `&Вместо` (`ГКСИ_ДобавитьКТекстуСписокШаговГруппыВместо`).
  Исправлены два бага типовой:
    1. HTML со списком шагов формировался в локальной переменной
       `ТекстШаги` и не записывался обратно в реквизит формы —
       пользователь видел «Шаги в группе: 0» с пустым списком.
       Добавлена финальная строка `ТекстСценарияЧтение = ТекстШаги;`.
    2. Типовая процедура искала шаги по `Родитель В ИЕРАРХИИ`, но
       иерархия групп хранится в РС `ГКСИ_ГруппыСценариев`, а поле
       `Родитель` пустое. В перекрытии запрос переписан: шаги берутся
       из `Ссылка В (&ЧленыГруппы)`, где `ЧленыГруппы` =
       `ГКСИ_ГруппыСценариевСервер.ПолучитьЧленовГруппы(Объект.Ссылка)`.
       Полные коды шагов формируются через
       `ГКСИ_ГруппыСценариевСервер.ПолныйКодВКонтексте(...)`.
- Типовая `УправлениеВидимостью` — показывает наши кнопки по условию
  `ТекущийСценарийДоступенДляРедактирования`. Наша `ГКСИ_УправлениеВидимостьюMarkdown`
  вызывается через `&После` и принудительно скрывает 4 типовых кнопки,
  независимо от условий.

## Проверки

- **Синтаксис:** `mcp__syntax-checker__validate` — 0 ошибок.
- **Маркеры EDT:** `GetMarkers` тип `1c` — `inspectForm` подтверждает
  наличие реквизитов `ТекстMarkdownСтрока` и `ФайлыBase64` в `Form.form`.
  BslEditor использует асинхронный индекс и может кратковременно
  показывать устаревшие маркеры на `undefined-variable` после правки;
  эта же ситуация в `ФормаЭлемента` (где реквизиты декларированы
  статически с момента первой реализации). После переиндексации
  проекта маркеры исчезают.

## Обновление просмотра после записи

В `ГКСИ_ПослеПослеЗаписиНаСервере` (`ФормаГруппы` и `ФормаЭлемента`)
добавлено явное обновление реквизита `ТекстСценарияЧтение`
после записи:

```bsl
&После("ПослеЗаписиНаСервере")
&НаСервере
Процедура ГКСИ_ПослеПослеЗаписиНаСервере(ТекущийОбъект, ПараметрыЗаписи)

    ГКСИ_ЗаполнитьФайлыBase64();
    ГКСИ_УстановитьСегментMarkdownВФорму(ЭтотОбъект, ЯзыкСценария);
    ТекстСценарияЧтение = ПолучитьОписаниеНаЯзыке(ЭтотОбъект, ЯзыкСценарияЧтение);
    ГКСИ_ДобавитьКТекстуСписокШаговГруппыВместо();
    ДемонстрационныеСценарииКлиентСервер.ОтразитьТекущиеЯзыкиНаФорме(
        ЭтотОбъект, "ЯзыкСценарияЧтение", "ЯзыкСценария");

КонецПроцедуры
```

**Почему это нужно:** после `ПослеЗаписиНаСервере` платформа 1С
**не вызывает автоматически** `ПриЧтенииНаСервере`. Реквизит формы
`ТекстСценарияЧтение`, который заполняется из присоединённых
HTML-файлов, остаётся со старым значением до переоткрытия формы.
Для `ФормаГруппы` дополнительно вызывается
`ГКСИ_ДобавитьКТекстуСписокШаговГруппыВместо`, чтобы список
дочерних шагов в группе сразу отражал изменения.

Теперь после записи пользователь **сразу** видит обновлённое
описание и список шагов — без переоткрытия формы и без ручного
обновления.
