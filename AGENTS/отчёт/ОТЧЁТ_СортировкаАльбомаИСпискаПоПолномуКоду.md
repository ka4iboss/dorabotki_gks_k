# Сортировка альбома процессов и формы списка по `ПолныйКод`

Версия: 1.62. Маленькая фича (правка двух модулей + уточнение документации).

## Что сделано

Приведена к единому правилу сортировка в двух местах расширения:

1. **Альбом процессов** (`ГКСИ_АльбомПроцессов`):
   - корневые группы сортируются по `ПолныйКод` (было — по `Наименование`);
   - **внутри каждой группы** сценарии и подгруппы идут вперемешку в порядке возрастания `ПолныйКод` через `СписокЗначений.СортироватьПоПредставлению()`. При встрече подгруппы текущая таблица закрывается, выполняется рекурсивный вывод подгруппы, затем при необходимости открывается новая таблица для следующих сценариев. Итог: для группы с прямыми потомками `001.006` (сценарий), `001.007` (подгруппа с `001.007.001`), `001.008` (сценарий) выводится `001.006` → содержимое `001.007` (включая `001.007.001`) → `001.008`. Раньше же сначала выводились все прямые сценарии, и лишь потом — подгруппы.
2. **Форма списка** `ФормаСпискаДеревоГрупп`:
   - в дереве сортируются по `ПолныйКод` корневые группы (`ГКСИ_ОтсортироватьМассивСсылокПоПолномуКоду`) и члены каждой группы — обход через `СписокЗначений.СортироватьПоПредставлению()` прямо в `ГКСИ_ДобавитьВеткуГруппы`. Сортировка — по умолчанию, пользователь не нажимает никаких кнопок;
   - в колонке `ПолныйКодКонтекстный` теперь отображается код не только у элементов, но и у групп. Это стало возможным после того, как в запрос пакета 0 добавили `Спр.Код КАК Код` и прокинули его в кеш `КэшПоСсылке[Ссылка].Код`; процедура `ГКСИ_СоздатьУзелГруппы` уже читала это поле, но раньше ключа в кеше не было, и для групп колонка всегда была пустой.

Правило итоговое: **сначала группа с меньшим кодом, потом её элементы от меньшего к большему, потом группа с большим кодом**. Сценарии и подгруппы внутри группы чередуются по возрастанию кода. Иерархия (`h1`/`h2`/`h3` в альбоме и вложенность в форме списка) сохраняется.

## Изменённые файлы

### `src/CommonModules/ГКСИ_АльбомПроцессов/Module.bsl`

1. `ГКСИ_КорневыеГруппы()` — `УПОРЯДОЧИТЬ ПО ДемонстрационныеСценарии.ПолныйКод` вместо `Наименование`.
2. `ГКСИ_ВывестиГруппуВМассивСтрок()` — переписан блок вывода прямых потомков. Сценарии и подгруппы собираются в один `СписокЗначений`, сортируются по `ПолныйКод`, и обходятся в общем порядке: сценарий — добавить строку в текущую таблицу; подгруппа — закрыть таблицу и рекурсивно вывести подгруппу. Несколько таблиц подряд в HTML валидны.
3. Удалена ставшая ненужной процедура `ГКСИ_ОтсортироватьСценарииПоПолномуКоду` (SU44 «неиспользуемый метод»).

### `src/Catalogs/ДемонстрационныеСценарии/Forms/ФормаСпискаДеревоГрупп/Module.bsl`

1. В `ГКСИ_ПостроитьДерево()`:
   - в `ПоляЗапроса` добавлено `Спр.Код КАК Код`;
   - в `КэшЗаписи.Вставить(...)` добавлен ключ `Код`;
   - после заполнения `МассивКорневыхГрупп` — вызов `ГКСИ_ОтсортироватьМассивСсылокПоПолномуКоду(МассивКорневыхГрупп, КэшПоСсылке)`.
2. В `ГКСИ_ДобавитьВеткуГруппы()` — после получения `МассивЧленов` вместо отдельной процедуры выполняется обход через `СписокЗначений` с `СортироватьПоПредставлению()` и затем обход членов группы сразу через `СписокЧленов`. Массив структур через параметр процедуры в управляемой форме не поддерживает присваивание элементов (SU15 не снимает проблему рантайма), поэтому промежуточная сортировка через `СписокЗначений` сделана прямо в `ГКСИ_ДобавитьВеткуГруппы`.

## Как проверять

1. Открыть форму списка `ДемонстрационныеСценарии` (`ФормаСпискаДеревоГрупп`).
2. В колонке «`ПолныйКодКонтекстный`» убедиться, что код виден и у групп, и у элементов.
3. Порядок строк по умолчанию: сначала корневая группа с меньшим кодом, потом её элементы (от меньшего к большему), потом следующая корневая группа.
4. Открыть «Альбом процессов» — заголовки `h2`/`h3` идут по возрастанию кода; внутри каждой группы сценарии и подгруппы вперемешку по возрастанию кода (например, для группы с прямыми потомками `001.006`, `001.007` (подгруппа с `001.007.001`), `001.008` — порядок вывода: `001.006`, затем `h3` подгруппы `001.007` и её таблица с `001.007.001`, затем `001.008`).

## Технические замечания

- **Сортировка строкой** — приемлемо, т.к. коды в проекте имеют вид `XXX.YY` с числовыми префиксами и ведущими нулями (`002`, `003`), лексикографический порядок совпадает с числовым.
- **Защита от зацикливания** в альбоме — через кеш `Обработанные` (соответствие). Сортировка на этом не отражается.
- **Кеш `КэшПоСсылке`** в форме списка собирается пакетным запросом. Добавление поля `Код` не влияет на количество обращений к БД — поле читается из уже существующего пакета 0.
- **Совместимость с управляемой формой**: типизированный массив формы с элементами `Структура` (`Массив из Структура`) в `&НаСервере`-процедуре не поддерживает присваивание элементов, поэтому сортировка массива структур делается через `СписокЗначений` в месте использования. Типизированный массив ссылок (`Массив из CatalogRef.ДемонстрационныеСценарии`) поддерживается без проблем.
