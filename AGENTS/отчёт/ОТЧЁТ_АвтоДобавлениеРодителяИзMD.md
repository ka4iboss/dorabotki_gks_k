# ОТЧЁТ_АвтоДобавлениеРодителяИзMD

## Суть

При загрузке сценариев через обработку `ГКСИ_ЗагрузкаСценариевИзMarkdown` для любого узла дерева, который уже существует в справочнике `ДемонстрационныеСценарии` с подходящим типом (группа/элемент), автоматически добавляется связь с родителем из текущего MD-файла в `ГКСИ_ГруппыСценариев` — даже если форма разрешения конфликтов не открывалась или узел не попал в `РешенияПоКонфликтам`.

Ранее в этом случае создавался новый элемент/группа с тем же именем — дубль, у которого не было связи с родителем из MD. Теперь дубль не создаётся: существующий узел используется как кандидат на обновление, а связь с родителем добавляется через идемпотентный `ГКСИ_ГруппыСценариевСервер.ДобавитьСценарийВГруппу`. Старые связи узла с другими группами не трогаются; если связь `(Сценарий, Группа)` уже была — запись перезаписывается без дубля.

## Файлы

- `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl` — основная правка.
- `AGENTS/описание/Описание.md` §15.11 — новый раздел с архитектурой.

## Сценарий-пример

1. В базе: `Согласование с поставщиком` — шаг с одной записью в `ГКСИ_ГруппыСценариев` (`Группа = Закупки`).
2. Импортируем `ПроцессПродажи.md`:
   ```markdown
   # Продажи
   ## Согласование с поставщиком
   ```
3. После фичи у `Согласование с поставщиком` — две записи в `ГКСИ_ГруппыСценариев`: `(Закупки)` (старая) и `(Продажи)` (новая, добавлена из MD). Дубль не создан.

## Что изменилось в коде

### Новые локальные функции

- `ГКСИ_СобратьУникальныеИменаИзДерева(ДеревоУзлов)` — итеративный обход дерева в глубину через стек (без рекурсии), собирает плоский массив уникальных наименований узлов. Используется для подготовки одного пакетного запроса к БД по всем именам дерева сразу.
- `ГКСИ_АвтоРезолвУзлаПоКешу(КешСуществующих, Узел, ЭтоГруппа)` — достаёт из кеша массив существующих ссылок с тем же именем, фильтрует по признаку `ЭтоГруппа` (группа/элемент должны совпадать с типом узла из MD), при наличии ровно одного подходящего возвращает решение `{Действие: "Обновить", Ссылка: <...>}`. При нескольких подходящих — берёт первый попавшийся и пишет предупреждение в ЖР.

### Изменения в существующих функциях

- `ЗаписатьДеревоВСправочник` — перед циклом обхода по корням дерева собирает кеш (`ГКСИ_СобратьУникальныеИменаИзДерева` + `НайтиСуществующихПоИмени`) и пробрасывает его в каждый вызов `ОбработатьУзелРекурсивно` (включая рекурсивные). Один запрос к БД на всю загрузку.
- `ОбработатьУзелРекурсивно` — добавлен необязательный параметр `КешСуществующих = Неопределено`. После `РешениеПоУзлу = РешенияПоКонфликтам.Получить(...)` добавлен блок: если `РешениеПоУзлу = Неопределено`, вызывается `ГКСИ_АвтоРезолвУзлаПоКешу(...)`; результат используется в дальнейшей ветке кода как обычное решение «Обновить».

Сигнатура `ОбработатьУзелРекурсивно` теперь содержит 11 параметров (10 со значениями по умолчанию). Это превышает лимит SU16 «7 параметров», но это **pre-existing** архитектурное решение модуля — параметр с дефолтом `МассивHTMLПоУзлам = Неопределено` (10-й) уже был до фичи, новый параметр лишь добавляет единицу.

## Архитектура

Подробное описание — в `AGENTS/описание/Описание.md` §15.11. Кратко:

1. Один запрос `НайтиСуществующихПоИмени` собирает кеш `Имя → Массив {Ссылка, ЭтоГруппа}` для всех уникальных имён дерева.
2. В `ОбработатьУзелРекурсивно` для каждого узла без явного решения ищется кандидат на обновление в кеше (с фильтром по типу).
3. Если кандидат найден — используется существующий узел, перезаписываются реквизиты, добавляется связь с родителем из MD через уже идемпотентный `ДобавитьСценарийВГруппу`.

## Краевые случаи

- **Явный выбор «Создать новый»/«Дублировать»** через форму разрешения конфликтов имеет приоритет: пока в `РешенияПоКонфликтам` есть решение, авто-резолв не вызывается.
- **Циклы в графе групп** — `ДобавитьСценарийВГруппу` бросает исключение через `ЕстьЦиклВГруппах`. Ловится внешним `Исключение` в `ОбработатьУзелРекурсивно`, в ЖР пишется диагностика, обход продолжается.
- **Несколько существующих узлов с тем же именем и типом** (теоретический случай) — берётся первый попавшийся, в ЖР — `УровеньЖурналаРегистрации.Предупреждение` с количеством и выбранной ссылкой.
- **Пустой `КешСуществующих`** (например, при вызове `ОбработатьУзелРекурсивно` из тестов или вне `ЗаписатьДеревоВСправочник`) — авто-резолв возвращает `Неопределено`, узел создаётся новым. Старое поведение сохранено.

## Способ проверки

1. **Юнит-кейс (ручной, в копии базы).** Создать элемент `Шаг 1` в группе `Группа А` (UI или прямой записью в `ГКСИ_ГруппыСценариев`). Подготовить MD со структурой `## Группа Б` → `### Шаг 1`. Загрузить через обработку.
   - **Ожидаемо:** `Шаг 1` без дубля, в `ГКСИ_ГруппыСценариев` — две записи: `(Группа А)` и `(Группа Б)`.

2. **Кейс «форма конфликтов не открылась».** Загрузить MD, в котором ВСЕ имена узлов совпадают с базой, но иерархия другая (без нажатия «Проверить конфликты»).
   - **Ожидаемо:** авто-резолв сработал, ни одного дубля по наименованию, у каждого узла — корректный набор родителей из РС.

3. **Кейс «явный выбор Создать/Дублировать».** Загрузить MD, в форме конфликтов выбрать «Создать новый» для одного узла.
   - **Ожидаемо:** явное решение пользователя сохраняется — создаётся новый элемент, существующий не трогается. Авто-резолв не перекрывает явные решения.

4. **Кейс «цикл».** Вручную создать в базе цикл через прямой SQL/обработку, затем загрузить MD, который через авто-резолв пытается замкнуть этот цикл.
   - **Ожидаемо:** `ДобавитьСценарийВГруппу` бросает исключение, оно обрабатывается в `Исключение` блоке `ОбработатьУзелРекурсивно`, в ЖР — запись с диагностикой.

5. **Проверка EDT:** `GetMarkers` по изменённому модулю — нет `severity=error`. Warnings могут быть (SU16 про 11 параметров, SU18/SU29/SU78/SU83 — pre-existing архитектурный долг модуля).
6. **Валидатор BSL:** `mcp__syntax-checker__validate` для новых функций — 0 ошибок.

## Спорные моменты (на будущее)

- **Несколько существующих с тем же именем.** В текущей реализации берётся первый попавшийся. Альтернатива — выбирать самый свежий по `ДатаИзменения`. Не реализовано: дополнительный запрос в горячем пути авто-резолва не оправдан для редкого случая. Если в базе реально появятся дубли по имени — добавим выборку позже.
- **Форма конфликтов может не открываться вовсе.** Раньше, если имена узлов пересекались с базой, форма конфликтов показывалась пользователю. После фичи авто-резолв сработает ДО открытия формы — она может не появиться, даже если имена совпали (т.к. конфликты будут «разрешены» автоматически). Это **упрощение UX** в духе запроса пользователя, но меняет привычку. Подтверждено пользователем как желаемое поведение.
- **Группы vs элементы.** Главный фокус фичи — группы (множественная принадлежность к группам — основной сценарий). Элементы тоже получают авто-добавление родителя, но там эффект менее заметен (у конечного шага обычно один родитель).
