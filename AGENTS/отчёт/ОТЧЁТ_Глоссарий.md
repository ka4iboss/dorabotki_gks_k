# Отчёт о внедрении глоссария в расширение «ГКС_Инструкции»

## Суть задачи

Использовать типовой справочник `Catalog.Глоссарий` основной конфигурации
(`1С:ERP`) внутри расширения `пустая_для_гкс.ГКС_Инструкции` в трёх точках:

- **(A)** Панель терминов на формах сценариев (`ФормаЭлемента`, `ФормаГруппы`
  справочника `ДемонстрационныеСценарии`), отфильтрованная по объекту
  метаданных текущего элемента.
- **(B)** Кнопка «Глоссарий» в командной панели редактора Markdown
  (`ГКСИ_MarkdownСерверВызовСервера`/`ГКСИ_MarkdownКлиент`). Открывает общую форму выбора
  термина; после выбора термин вставляется как Markdown-ссылка
  `[Наименование](Глоссарий.<GUID>)`.
- **(C)** Автоподстановка терминов в HTML: в `ГКСИ_АльбомПроцессов`
  (после сборки документа) и в `ГКСИ_ФормированиеИнструкции`
  (в скачиваемый HTML-файл).

## Что сделано

### Новые объекты

| Тип | Имя | Назначение |
|-----|-----|------------|
| `CommonModule` | `ГКСИ_Глоссарий` | Серверный модуль. Экспортные: `ТерминыПоОбъектамМетаданных`, `ТерминыДляАвтоподстановки`, `ОбогатитьHTMLТерминами`, `ТекущийКодЯзыка`, `ИзвлечьОписаниеИзХранилища`, `ИдентификаторОбъектаМетаданных`. Сервер, вызов сервера |
| `CommonModule` | `ГКСИ_ТерминыГлоссарияПовтИсп` | Кеш терминов с `ReturnValuesReuse = DuringSession`. Сервер, вызов сервера |
| `CommonForm` | `ГКСИ_ВыборТерминаГлоссария` | Таблица терминов + поле поиска. Возврат через `ОповеститьОВыборе`. Управляемая, клиент-сервер |

### Изменённые объекты

- `Catalog.ДемонстрационныеСценарии.Form.ФормаЭлемента` — в `Form.form`
  декларативно добавлен реквизит `ГКСИ_ТерминыГлоссария` (`ValueTable`) с
  колонками `Ссылка` (String(36)), `Наименование` (String(150)),
  `Описание` (String, неогр.). В `Module.bsl` программно создаётся страница
  «Глоссарий» с таблицей формы и обработчиком `ГКСИ_ОбновитьТаблицуГлоссария`,
  вызываемым из `ПриЧтенииНаСервере` через `ГКСИ_ПриЧтенииНаСервереОбновитьГлоссарий`.
- `Catalog.ДемонстрационныеСценарии.Form.ФормаГруппы` — то же, что и для
  `ФормаЭлемента`.
- `CommonModule.ГКСИ_MarkdownСерверВызовСервера` — добавлена команда `КомандаMDГлоссарий` и
  обработчик `ГКСИ_Глоссарий_ОбработкаКоманды` (открывает общую форму выбора
  термина).
- `CommonModule.ГКСИ_MarkdownКлиент` — добавлены клиентские обработчики
  `ГКСИ_Глоссарий_ОбработкаКоманды` и `ГКСИ_Глоссарий_ПослеВыбораТермина`
  (вставляет Markdown-ссылку на термин в текст).
- `CommonModule.ГКСИ_АльбомПроцессов.СобратьДокументАльбомаПоГруппам` — после
  сборки HTML прогоняет результат через `ГКСИ_Глоссарий.ОбогатитьHTMLТерминами`.
  В стилевом блоке добавлены правила для `.gksi-term`.
- `DataProcessor.ГКСИ_ФормированиеИнструкции.Form.Форма.Печать` — перед
  формированием HTML-файла прогоняет текст через
  `ГКСИ_Глоссарий.ОбогатитьHTMLТерминами`. В файл добавлен блок `<style>` для
  `.gksi-term`.

## Архитектура обогащения HTML

`ГКСИ_Глоссарий.ОбогатитьHTMLТерминами(HTML, КодЯзыка)`:

1. Получает плоский список терминов через `ГКСИ_ТерминыГлоссарияПовтИсп.Термины()`.
2. Сортирует термины по убыванию длины наименования (чтобы избежать частичных
   пересечений «Склад готовой продукции» → «Склад»).
3. Исключает из обработки содержимое `<code>`, `<pre>`, `<a>` — через
   `СтрНайтиВсеПоРегулярномуВыражению` и плейсхолдеры
   (`{ГКСИ_ИСКЛЮЧЕНИЕ_<TAG>_<НачальнаяПозиция>_<Счетчик>}`).
4. Для каждого термина экранирует спецсимволы (`\`, `.`, `+`, `*`, `?`, `(`,
   `)`, `[`, `]`, `{`, `}`, `^`, `$`, `|`, `/`) и заменяет через
   `СтрЗаменитьПоРегулярномуВыражению` с lookbehind/lookahead
   `(?<![а-яёa-z0-9_])…(?![а-яёa-z0-9_])`. Термин оборачивается в
   `<span class="gksi-term" data-term-guid="<GUID>" title="<описание>">…</span>`.
5. Восстанавливает исключённые фрагменты.

CSS-блок в стилях альбома и в скачиваемом файле инструкции:

```css
.gksi-term { border-bottom: 1px dashed #2a4d7a; cursor: help; color: inherit; }
.gksi-term:hover { background-color: #FFF8DC; }
```

## Локализация

- `КодЯзыка = "ru"` → `НаименованиеЯзык1` (фолбэк на `Наименование`).
- Любой другой → `НаименованиеЯзык2` (фолбэк на `Наименование`, затем
  `НаименованиеЯзык1`).
- Описание берётся из ТЧ `ОписанияГлоссария` по `КодЯзыка`.

`ГКСИ_Глоссарий.ТекущийКодЯзыка()` — обёртка над `ТекущийЯзык()` с фолбэком на
`"ru"`.

## Запросы к БД

- `ТерминыПоОбъектамМетаданных` — пакетный (ВТ + основной запрос с
  ЛЕВОЕ СОЕДИНЕНИЕ на ТЧ `ОписанияГлоссария`).
- `ТерминыДляАвтоподстановки` — соединение справочника с ТЧ описаний
  с фильтром по `КодЯзыка`.
- `ИдентификаторОбъектаМетаданных` — одиночный запрос по `ПолноеИмя` метаданных
  ссылки.

Запросов в цикле нет. Используется кеш на сеанс через
`ГКСИ_ТерминыГлоссарияПовтИсп` (`DuringSession`).

## Ограничения и риски

1. **Платформенный `СтрЗаменитьПоРегулярномуВыражению`** — впервые появился
   в 8.3.23. Режим совместимости расширения — 8.3.27, поэтому метод доступен.
2. **Экранирование описания для атрибута `title`** — минимальное
   (`&` → `&amp;`, `"` → `&quot;`, `<` → `&lt;`, `>` → `&gt;`). При длинных
   описаниях обрезается до 500 символов.
3. **Панель глоссария** показывается всем, у кого есть право чтения формы
   сценария. Ограничения по ролям не наложены (по согласованию с
   пользователем).
4. **Декларативный реквизит формы** `ГКСИ_ТерминыГлоссария` объявлен через
   `addFormAttribute` + `addValueTableColumn`, а не через
   `ИзменитьРеквизиты` — чтобы BSL-линтер EDT видел типы колонок и не
   ругался на SU239/undefined-variable.
