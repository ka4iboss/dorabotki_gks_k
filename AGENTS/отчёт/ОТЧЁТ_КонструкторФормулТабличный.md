# Отчёт: табличный конструктор формулы

**Проект:** `Доработки_ГКС_К` (расширение, ветка `workmate`)
**Подсистема:** ШаблоныНаименований
**Версия подсистемы:** `1.1.0` → `1.2.0`
**Версия расширения:** `1.0.23.0` → `1.0.24.0`
**Дата:** 2026-11-19
**Тип:** фича

## Задача

В типовом конструкторе формул (`ОбщаяФорма.КонструкторФормул`) формула шаблона
наименования набирается вручную в одном большом поле: нужно помнить синтаксис
`+?(ЗначениеЗаполнено(...), " " + ..., "")` и вручную вставлять операнды.

Нужно для строковых формул заменить поле на табличный конструктор: «Начало
формулы» + таблица строк `Условие / ЕслиЗаполнено / ЕслиПусто` + предпросмотр
итоговой формулы. Числовые формулы (расчёт цен, планы, финансовые отчёты) не
должны пострадать.

## Что сделано

### Модель формы (заимствованная `CommonForm.КонструкторФормул`)

Реквизиты: `ГКСК_НачалоФормулы` (Строка, неограниченная), `ГКСК_СтрокиФормулы`
(ТаблицаЗначений; колонки `Условие`, `ЕслиЗаполнено`, `ЕслиПусто` — Строка,
неограниченные), `ГКСК_КолонкаВставки` (Строка 20), `ГКСК_Предпросмотр` (Строка,
неограниченная), `ГКСК_КонструкторИзменён` (Булево).

Элементы добавлены в существующую вертикальную группу `ГруппаФормула` (перед
типовым полем `Формула`): поле начала формулы, поле-переключатель колонки вставки,
таблица `ГКСК_ТаблицаФормулы` с колонками `ГКСК_КолонкаУсловие`,
`ГКСК_КолонкаЕслиЗаполнено`, `ГКСК_КолонкаЕслиПусто`, поле предпросмотра
(`readOnly = true`). Все элементы и форма — `enabled = true`.

Отдельная группа-контейнер не использовалась: инструмент не умеет задавать
ориентацию группы (`HorizontalIfPossible` по умолчанию), поэтому элементы
размещены прямо в вертикальной `ГруппаФормула`. Автогенерированные имена колонок
(`ГКСК_ТаблицаФормулыГКСК_ТаблицаФормулы1/2`) заменены осмысленными: поле нельзя
переименовать на месте, колонки пересозданы с заголовками.

Привязки `ПриИзменении`: `ГКСК_НачалоФормулыПриИзменении`,
`ГКСК_КолонкаУсловиеПриИзменении`, `ГКСК_КолонкаЕслиЗаполненоПриИзменении`,
`ГКСК_КолонкаЕслиПустоПриИзменении`.

### Код модуля формы

- `ГКСК_ЭтоСтроковаяФормула()` — общий признак (`ТипРезультата` содержит `Строка`);
  используется и табличным конструктором, и условными разделителями.
- `ГКСК_НастроитьТабличныйКонструктор()` (`&После("ПриСозданииНаСервере")`) —
  видимость элементов конструктора и типового поля `Формула`, заполнение
  `СписокВыбора` переключателя (`Условие` / `ЕслиЗаполнено` / `ЕслиПусто`),
  начальный предпросмотр = текущая формула.
- `ГКСК_СобратьФормулу(НачалоФормулы, СтрокиФормулы)` — сборка текста:
  `"<Начало>"` + для каждой строки с заполненным `Условие`
  `+?(ЗначениеЗаполнено(<Условие>), <ЕслиЗаполнено|"">, <ЕслиПусто|"">)`,
  части через `Символы.ПС`. Пустые строки пропускаются.
- `ГКСК_ПересобратьФормулу()` (по `ПриИзменении` и после вставки) и
  `ГКСК_ПересобратьФормулуПередПроверкой()` (`&Перед("ОК")`, `&Перед("Проверить")`,
  `&Перед("ПередЗакрытием")`; не затирает открытую формулу, если конструктор не
  менялся и пуст).
- `&Вместо("ДеревоОперандовВыбор")` — выбор операнда пишется в целевую ячейку
  таблицы; в остальных случаях `ПродолжитьВызов`.
- `&Вместо("ОператорыВыбор")` — выбранный оператор (`КонструкцияДляВставки`)
  вставляется в целевую ячейку таблицы; группы и нестроковые формулы —
  `ПродолжитьВызов`.
- `ГКСК_КолонкаДляВставки()` — активная ячейка таблицы, если
  `ТекущийЭлемент` — поле колонки; иначе колонка из переключателя.
- Кнопка «Вставить условный разделитель» скрыта (вставляла в скрытое поле);
  команда и группа операторов сохранены.

Формула записывается в типовой реквизит `Формула`, поэтому типовые `ОК`,
`Проверить`, `ПередЗакрытием`, `ОперандыФормулы` и проверка формулы работают без
изменений.

## Проверка

- `GetMarkers` по `Module.bsl` и `Form.form` — 0 маркеров.
- `mcp__syntax-checker__validate` для сборки формулы — 0 ошибок (устранено
  замечание о вложенном вызове в параметре).
- Проектные маркеры (488) — существовавшие ранее в других объектах (ГКСИ,
  ГКСК_ОбъединениеЭлементов и др.), к изменённым файлам не относятся.

## Ручная проверка (в 1С)

1. Вид номенклатуры → «Редактировать шаблон наименования»: поле «Формула» не
   видно; есть «Начало формулы», «Вставлять операнд в», таблица и «Итоговая
   формула».
2. Начало = `Двутавр`; строка: `[{ДР.НомерДвутавра}]` / `" " +[{ДР.НомерДвутавра}]` /
   пусто → предпросмотр
   `"Двутавр"` + `+?(ЗначениеЗаполнено([{ДР.НомерДвутавра}]), " " +[{ДР.НомерДвутавра}], "")`.
3. Выбор операнда в дереве попадает в активную ячейку; повторный выбор
   дописывается.
4. «ОК» сохраняет шаблон; «Проверить» не ругается.
5. Форма из расчёта цен: конструктор скрыт, поле «Формула» работает как раньше.

## Доработка 1.0.24.1 (по замечаниям пользователя)

1. **Вставка в активную ячейку.** `Элементы.<Таблица>.ТекущийЭлемент` в этой
   конфигурации возвращает саму таблицу (подтверждено ранее), а при выборе операнда
   фокус вообще уходит из таблицы в дерево. Добавлен реквизит `ГКСК_АктивнаяКолонка`
   и обработчик `ПриАктивизацииПоля` таблицы (`ГКСК_ТаблицаФормулыПриАктивизацииПоля`):
   в момент активизации ячейки имя колонки берётся из `ТекущийЭлемент` формы и
   запоминается. `ГКСК_КолонкаДляВставки` использует его первым, затем — `ТекущийЭлемент`
   таблицы (резерв), затем — переключатель.
2. **Загрузка существующей формулы.** `ГКСК_ЗагрузитьФормулуВКонструктор()` при
   создании формы разбирает `Формула`: первая часть — строковый литерал (снимаются
   кавычки) либо `+?(...)`; остальные — `+?(ЗначениеЗаполнено(<Условие>), <ЕслиЗаполнено>, <ЕслиПусто>)`.
   Разбор аргументов — `ГКСК_АргументыВызова` (запятые вне скобок и литералов,
   удвоенные кавычки). Если формула не в табличном виде — конструктор скрыт, формула
   остаётся в типовом поле «Формула» и редактируется как раньше (ничего не теряется).
   Флаг `ГКСК_КонструкторИзменён` при загрузке не поднимается — сохранение без правок
   не переписывает текст.

Версия подсистемы ШаблоныНаименований: `1.2.0` → `1.2.1`; расширение `1.0.24.0` → `1.0.24.1`.
Маркеры по `Module.bsl` и `Form.form` — 0.

## Ограничения

- Drag&drop операндов в таблицу не поддерживается — только выбор в дереве/палитре.
- Вопрос о пометке удаления операнда в табличном режиме не задаётся.
- При обновлении типовой конфигурации заимствованную форму нужно сверять с
  `BaseForm/Form.form`: `Элементы.Формула` и `ГруппаФормула` базовым модулем
  используются — они сохранены, поле `Формула` только скрыто.
