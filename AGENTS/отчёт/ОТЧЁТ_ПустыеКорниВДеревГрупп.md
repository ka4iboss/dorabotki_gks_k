# Bugfix: Пустые имена корневых обёрток инструкций в форме списка

Версия: 2.20. Маленькая фича (исправление бага: `ГКСИ_НайтиБлижайшегоПредка` сразу пропускала сам код и поднималась выше, теряя иерархию).

## Корневая причина (финальная)

Все шаги этой серии правок — следствия **одной** ошибки, допущенной в bugfix 1.100:

```bsl
// БЫЛО (BUG):
И Узел.Уровень() = 1

// Правильно:
И Узел.Уровень = 1
```

В `РазобратьMarkdownВДерево` для **корневой обёртки** явно задаётся **значение колонки** `Уровень`:
```bsl
Корень = Дерево.Строки.Добавить();
Корень.Уровень = 1;     // ЗНАЧЕНИЕ моей колонки "Уровень"
```

В `ОбработатьУзелРекурсивно` я ошибочно использовал **системный метод** `Узел.Уровень()` (со скобками) вместо **обращения к колонке** `Узел.Уровень` (без скобок). Это **разные вещи** в 1С для `ДеревоЗначений`:
- `Узел.Уровень()` — системный метод, возвращает фактический уровень строки: `0` для корня, `1` для первого дочернего.
- `Узел.Уровень` — обращение к колонке с заданным значением.

Для обёртки: `Узел.Уровень() = 0`, `Узел.Уровень = 1`. Условие `Узел.Уровень() = 1` для обёртки **никогда не срабатывало** — функция `ЗарегистрироватьКорневуюГруппуИнструкции` не вызывалась, самоссылка в РС не создавалась, форма рисовала фиктивный узел.

## v2.15 — разблокировало регистрацию корня

Замена `Узел.Уровень() = 1` на `Узел.Уровень = 1`. После этого `ЗарегистрироватьКорневуюГруппуИнструкции` начала вызываться, корень стал отображаться с настоящим именем, но обнажилась **следующая** проблема: при записи дочерних узлов — переполнение стека.

## v2.16 — разорвать самоссылку в графе групп

Самоссылка `Сценарий = Группа = КореньИнструкции` в регистре порождала **цикл в графе**:
- `Граф.РодителиГрупп[Обёртка][Обёртка] = Истина`.
- `ПолныйКодГруппыГрафа(Обёртка)` → бесконечная рекурсия → переполнение стека.
- `ЕстьЦиклВГруппах` ложно возвращает `Истина`.

Решение — исключить самоссылку из графа в `ГКСИ_ГрафГрупп`. Дополнительно — defensive programming в `ПолныйКодГруппыГрафа`.

## v2.17 — не пересчитывать самоссылку

После v2.16 загрузка проходила без ошибок, **но** в дереве появлялся **лишний узел** с `КодВКонтексте = "001.001."` и именем обёртки. Причина: `ПересчитатьПолныйКодДляПоддереваГрафа` пересчитывал самоссылку как `"001."` и `ГКСИ_ЗаписатьПолныйКодКонтекстный` добавлял префикс корня → `"001.001."`.

Исправление: пропуск самоссылок в `ПересчитатьПолныйКодДляПоддереваГрафа`.

## v2.18 — неудачная попытка: отказ от промежуточных кодов

Я попытался отказаться от автогенерации промежуточных кодов в `ГКСИ_ПостроитьДерево` — добавлять только те, для которых есть запись в РС. Логика была правильной для фиктивных промежуточных кодов, но **поломала** дочерние узлы: для `001.001.001` родительский код `001.001` не добавлялся в `ВсеКоды`, и при попытке найти родителя в `ВеткаПоКоду["001.001"]` возвращался `Неопределено` → узел пропускался. В результате в дереве осталась только обёртка.

## v2.19 — поднимать дочерних к ближайшему предку

Правильное решение: пропускать фиктивные промежуточные коды (как в v2.18), но **поднимать** дочерний узел к ближайшему существующему предку, если прямой родитель отсутствует.

Добавлена функция [`ГКСИ_НайтиБлижайшегоПредка`](src/Catalogs/ДемонстрационныеСценарии/Forms/ФормаСпискаДеревоГрупп/Module.bsl) — поднимается по иерархии префиксов через точку (`"001.001.002"` → `"001.001"` → `"001"`).

## v2.20 — исправление ошибки в `ГКСИ_НайтиБлижайшегоПредка`

В v2.19 я входил в функцию с прямым родителем `КодВКонтексте = "001.001.002"` (Выбор проекта), но **сразу** пропускал его — искал точку с конца и уменьшал строку до `"001.001"`, **минуя** сам `"001.001.002"`. В результате `001.001.002.001` (Проверка остатков) поднимался к `001` (обёртка), а не к `001.001.002` (Выбор проекта). Иерархия `#`- и `##`-заголовков терялась.

### Исправление

Сначала проверить **сам** `КодВКонтексте` в `ВеткаПоКоду`. Если он там есть — это прямой родитель, возвращаем его. Только если его **нет** — поднимаемся выше:

```bsl
// Сначала проверяем сам код — если он уже в ВеткаПоКоду, значит это
// прямой родитель (или сам узел), и подниматься выше не нужно.
Ветка = ВеткаПоКоду[КодВКонтексте];
Если Ветка <> Неопределено Тогда
    Возврат Ветка;
КонецЕсли;

ТекущийКод = КодВКонтексте;
Пока Истина Цикл
    ПозицияТочки = СтрНайти(ТекущийКод, ".", НаправлениеПоиска.СКонца);
    Если ПозицияТочки = 0 Тогда
        Возврат Неопределено;
    КонецЕсли;
    ТекущийКод = Лев(ТекущийКод, ПозицияТочки - 1);
    Ветка = ВеткаПоКоду[ТекущийКод];
    Если Ветка <> Неопределено Тогда
        Возврат Ветка;
    КонецЕсли;
КонецЦикла;
```

Для инструкции ДМТО:
- `001.001.002` (Выбор проекта) → есть в `ВеткаПоКоду` → используется как прямой родитель для `001.001.002.001` (Проверка остатков).
- `001.001.001` (`# Открытие ведомости покупных`) → нет `001.001.001.001` (нет `##`-подзаголовков) → поднимается к `001` (обёртка).

## Как проверять

1. Обновить конфигурацию БД (`F7` в EDT), перезапустить клиент Предприятия.
2. Очистить справочник `ДемонстрационныеСценарии` и регистр `ГКСИ_ГруппыСценариев`.
3. Прогрузить **одну** инструкцию.
4. Открыть форму списка.
5. Проверить:
   - В форме списка **нет** лишнего подкорневого узла.
   - Все `#`-заголовки находятся **непосредственно** под корнем.
   - Все `##`-подзаголовки находятся **под** своими `#`-родителями, а не под корнем.
   - Диагностика `ГКСИ_ПостроитьДерево v2.20: корней 1, всего 17. <имя>(001) 17 строк` — должно быть ровно **17** (1 обёртка + 8 `#`-заголовков + 8 `##`-подзаголовков = 17).

## Технические замечания

- Ошибка была допущена в первой реализации (bugfix 1.100) и порождала **каскад** из шести багов:
  1. **v2.15**: не регистрировалась самоссылка → пустой корень в форме.
  2. **v2.16**: переполнение стека из-за самоссылки в графе.
  3. **v2.17**: лишняя запись `"001.001."` из-за пересчёта самоссылки.
  4. **v2.18**: неудачная попытка — отказ от промежуточных кодов потерял и фиктивные, и дочерние.
  5. **v2.19**: правильное решение, но `ГКСИ_НайтиБлижайшегоПредка` сразу пропускала сам код — иерархия `#`- и `##`-заголовков терялась.
  6. **v2.20**: финальное исправление — сначала проверить сам код.
- Самоссылка (`Сценарий = Группа = КореньИнструкции`) — **намеренная** конструкция для корневой обёртки; защита от циклов рассчитана на иерархические ссылки, не на самоссылки корней. Сейчас **три** места кода учитывают это явно:
  1. `ДобавитьСценарийВГруппу` — `Сценарий = Группа → Возврат`.
  2. `ГКСИ_ГрафГрупп` — `Сценарий = Группа → Продолжить`.
  3. `ПересчитатьПолныйКодДляПоддереваГрафа` — `Сценарий = Группа → Продолжить`.
- Lint-предупреждение SU83 (формат `НСтр`) на строке 28 — **существующее**, не связано с текущими правками.
- Все имена полей в коде (`Сценарий`, `Группа`, `КореньИнструкции`, `КодВКонтексте`) **совпадают** с именами в `.mdo` регистра.
