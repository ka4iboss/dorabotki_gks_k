# Отчёт о реализации фильтрации элементов по инструкции-источнику

**Версия:** 1.72 → 1.73

## Суть

В форме списка `ДемонстрационныеСценарии.ФормаСпискаДеревоГрупп` решена проблема «притяжения» шагов через общие подгруппы: ДМТО-шные шаги («Запрос и прикрепление счета», «Ознакомление с результатами согласования») отображались под ГИП-Инструкцией, потому что авто-резолв при импорте MD связывал их с общей группой «Согласование ТКП». Группа — общий контейнер (может быть частью нескольких инструкций), а элемент — конкретный шаг роли (должен отображаться только в инструкции, в которой был создан).

## Что сделано

### 1. Новый реквизит справочника

`ДемонстрационныеСценарии.ГКСИ_ИнструкцияИсточник`
- Тип: `CatalogRef.ДемонстрационныеСценарии`
- Происхождение: добавлен в расширении
- Заполняется только у элементов, не у групп
- Ссылается на корневую группу-инструкцию, в которой создан элемент

### 2. Заполнение при импорте MD

Файл: `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`

В `ОбработатьУзелРекурсивно` добавлен параметр `ИнструкцияИсточник` (по умолчанию `Неопределено`). Логика:

- Новый `#`-заголовок верхнего уровня (`Узел.Уровень = 2`) сам становится «инструкцией» для своих детей.
- Дочерние `#`- и `##`-заголовки наследуют инструкцию от родителя.
- Корень-обёртка файла (`Узел.Уровень = 1`) **не** становится инструкцией — это служебная группа с именем файла.
- При записи нового элемента (`ЭтоНовыйЭлемент = Истина`) заполняем `ГКСИ_ИнструкцияИсточник = ИнструкцияИсточник`.
- При обновлении существующего элемента **не** трогаем реквизит — оригинальная инструкция-источник сохраняется.
- Для уже существующих элементов с пустым реквизитом (до введения фичи) — **дозаполняем** при следующем импорте.

### 3. Фильтрация в форме списка

Файл: `src/Catalogs/ДемонстрационныеСценарии/Forms/ФормаСпискаДеревоГрупп/Module.bsl`

В `ГКСИ_ПостроитьДерево`:

- Пакет 0 расширен полем `ГКСИ_ИнструкцияИсточник`, кладётся в `КэшЗаписи`.
- В цикле обработки пакета 1 (связи РС) собирается обратное соответствие `РодителиСценариев[Сценарий] = [Группы]`.
- После цикла строится `КешКорневыхИнструкций[Группа] = КорневаяИнструкция` через подъём по РС до самого верхнего предка.
- Вызов `ГКСИ_ДобавитьВеткуГруппы` для корня передаёт `КешКорневыхИнструкций` и `Корень` как `ИнструкцияТекущейВетки`.

В `ГКСИ_ДобавитьВеткуГруппы`:

- Сигнатура расширена двумя параметрами с дефолтом `Неопределено` (обратная совместимость).
- В начале процедуры — если `ИнструкцияТекущейВетки` не передана, определяем через `КешКорневыхИнструкций[Группа]` (или саму группу, если в кеше нет).
- В рекурсивный вызов для подгруппы проброс: `КешКорневыхИнструкций` и `ИнструкцияТекущейВетки` (подгруппа — в той же ветке).
- Для элементов (не групп) добавлена фильтрация:
  - если `ГКСИ_ИнструкцияИсточник` пусто — показать (обратная совместимость);
  - если заполнено и совпадает с `ИнструкцияТекущейВетки` — показать;
  - иначе — `Продолжить` (скрыть).

Добавлена служебная процедура `ГКСИ_ПолучитьКорневуюИнструкциюГруппы` — рекурсивный подъём по `РодителиСценариев` с кешированием в `Кеш[Группа] = КорневаяИнструкция`. Корнем считается группа, которой нет в `ВсеСценарии` (т.е. у неё нет родителя в РС).

## Открытые вопросы / краевые случаи

1. **Шаг осознанно общий для двух ролей** — пользователь очищает `ГКСИ_ИнструкцияИсточник` вручную, и шаг попадает в обе ветки. Импорт не перезатрёт (условие «пустой» уже не выполнится).
2. **Импорт двух MD в одном файле** (несколько `# Инструкция для X` подряд) — стек `ИнструкцияИсточник` корректно переключается по верхнему `#`-заголовку.
3. **Группы-обёртки инструкций** (`# Инструкция для ГИП`) сами становятся корневыми инструкциями благодаря подъёму по РС.
4. **Стиль `severity: warning`** — `NumberOfParams` (≥10 параметров) в `ГКСИ_ДобавитьВеткуГруппы` и `ОбработатьУзелРекурсивно` (≥12). Существующее предупреждение, до рефакторинга в структуру — допустимо.
