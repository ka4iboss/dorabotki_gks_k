# Отчёт: повторная техническая ревизия подсистемы ГКСИ

**Дата:** 2026-11-22
**Версия расширения на момент ревизии:** 1.0.27.7 (ГКСИ 2.52.7)
**Метод:** три параллельных обхода кода (только чтение) по всем модулям подсистемы ГКСИ
с обязательной привязкой каждого замечания к файлу и номеру строки.
**Зачем:** первая ревизия (2026-11-20) исправлялась пачками версий 1.0.26.33 … 1.0.27.7,
но её исходный перечень в файл не сохранялся. Отчёт фиксирует актуальный остаток,
чтобы он не терялся при сжатии контекста диалога.

Все пункты получены чтением реального кода; номера строк соответствуют версии 1.0.27.7.
Ранее исправленное в отчёт не включено (кроме случаев, где нужна повторная проверка).

## 1. Конвертер Markdown → HTML

`src\CommonModules\ГКСК_MarkdownКонвертер\Module.bsl` (1834 строки)

### 1.1. Критично

**К-1. Пустые строки выбрасываются при разбиении на строки** — `Module.bsl:98`
`СтрРазделить(Текст, Символы.ПС, Ложь)`: третий параметр `ВключатьПустые` по умолчанию
`Истина`, поэтому `Ложь` удаляет пустые строки из массива. Весь разбор построен на их
наличии (ветка `Если ПустаяСтрока(Строка)` на стр. 118, завершение абзаца и тела алерта).
Последствия: абзацы склеиваются в один `<p>…<br>…</p>`; теряются пустые строки внутри
блоков ```; алерт без `>` не может завершиться и съедает остаток документа.
Правка: передать `Истина` (или убрать третий аргумент).

**К-2. Значения атрибутов не экранируются** — `Module.bsl:1227-1230`, `1276-1279`, `1445`, `1489-1492`
`Адрес` и `Альт` вставляются в `href`/`src`/`alt` без экранирования `"`, `&`, `<`, `>`.
Кавычка в адресе или alt рвёт тег; `&` в query-строке даёт невалидную сущность;
возможна инъекция атрибута в отображаемую инструкцию.
Правка: функция `ЭкранироватьАтрибут` (`&`→`&amp;` первым, затем `"`, `<`, `>`),
применять во всех четырёх местах.

### 1.2. Существенно

**С-1. Инлайн-код не экранируется** — `Module.bsl:1097` (и `1051-1060`)
Блочный код экранируется (стр. 399-400), инлайн — нет: `` `a<b>` `` даёт сломанную
разметку, браузер съедает `<b>`.
Правка: `ЭкранироватьHTML(Содержимое)` при сборке `<code>`.

**С-2. Пустые ячейки таблицы исчезают** — `Module.bsl:1027` (`ЯчейкиТаблицы`)
`СтрРазделить(Текст, "|", Ложь)` выбрасывает пустые ячейки: `| a || c |` даёт 2 ячейки
вместо 3 → все последующие значения сдвигаются влево (тихая подмена данных в таблице).
Правка: третий параметр `Истина`.

**С-3. Инлайн-замены задевают готовые теги и атрибуты** — `Module.bsl:1771-1812`,
`1161-1195`, вызовы `1054-1060`
`ЗаменитьКурсивПодчеркиванием` и `ЗаменитьПарнуюРазметку` работают по всей строке,
включая уже собранные `<a href>`/`<img src>`. Подчёркивание в URL
(`http://site/a_b_c`) превращается в `<a href="http://site/a<i>b</i>c">`; `<code>_x_</code>`
мутирует при повторном проходе. Идемпотентности нет — повторный вызов конвертера портит HTML.
Правка: прятать все `<...>` и содержимое готовых `<code>`/`<a>` в плейсхолдеры
(приёмом `ЗащититьКодВСтроке`) и восстанавливать после замен.

**С-4. Тело алерта без `>` не ограничено** — `Module.bsl:607-634` (`СобратьАлерт`)
Заголовок, список, таблица, блок кода сразу после маркера попадают в тело и выводятся
сырым текстом. В сочетании с К-1 съедается весь остаток документа.
Правка: в условии прерывания добавить проверки `УровеньЗаголовка`, `ЭтоЭлементСписка`,
`ЭтоТаблица`, `ЭтоНачалоБлокаКода`.

**С-5. Алерты разбираются двумя независимыми парсерами** — `Module.bsl:163-167`, `181-185`, `66`
Разбор внутри `ФрагментHTMLПоМаркдауну` (`СобратьАлерт`) плюс постобработка
`ГКСИ_MarkdownСерверВызовСервера.ОбработатьАлертыВHTML`. Правила расходятся → результат
зависит от точки входа; риск двойной обёртки готового `<div class="markdown-alert">`.
Правка: оставить один парсер, зафиксировать это в шапке модуля.

**С-6. Текст абзацев/заголовков/ячеек не экранируется** — `Module.bsl:187`, `142`, `980`, `991`, `455`, `602`
`ЭкранироватьHTML` вызывается только для блочного кода (стр. 400). `цена < 100` и `a & b`
попадают в HTML как есть: браузер выбрасывает остаток строки, `&` даёт невалидную сущность.
Правка: экранировать `<`, `>`, `&` на входе `ВстроеннаяРазметка`.

### 1.3. Мелко

**М-1. Незакрытый контейнер выключает разбор до конца документа** — `Module.bsl:111-116`, `345-365`
`БалансHTMLКонтейнеров` считает подстроки без учёта атрибутов; при незакрытом `<div>`
режим «сырой HTML» не выключается.
Правка: считать только теги вне атрибутов, ограничить длину «сырого» блока.

**М-2. Ложное определение готового HTML-блока** — `Module.bsl:312-332`
Признак — «начинается с `<` и заканчивается `>`». Строка `5 < 10 > 3` считается блоком
и теряется при отображении.
Правка: белый список тегов.

**М-3. `www.` без границы слова** — `Module.bsl:1528-1531`, `1474`
`awww.ru` → `a<a href="http://www.ru">www.ru</a>`.
Правка: пропускать, если предыдущий символ — буква/цифра.

**М-4. `ЭтоУжеВРазметке` ложно срабатывает на одиночном `<`** — `Module.bsl:1637-1653`, вызов `1482`
`5 < 10, см. http://a.ru` — URL не линкуется; плюс квадратичная сложность на длинных абзацах.
Правка: требовать после `<` символ имени тега `[a-zA-Z/]`.

**М-5. Хвостовая пунктуация режет допустимые символы URL** — `Module.bsl:1557`
`_` и `)` вырезаются из адреса, хотя допустимы (`http://site/path_` → `path`).
Правка: `_` исключить из набора; `)` убирать только без парной `(` в адресе.

**М-6. Нумерованные списки: ложные срабатывания и потеря номера** — `Module.bsl:780-797`, `844-880`
`2024. Итоги года` становится пунктом списка; `<ol>` без `start` — `3.` отображается как `1.`.
Правка: ограничить номер, передавать `<ol start="N">`.

**М-7. Закрытие блока кода по любой строке с ```** — `Module.bsl:298-302`, `386`
`` ```python `` внутри блока обрывает его; четырёх-бэктиковые ограждения не поддерживаются.
Правка: закрывать только строкой из одних ``` и пробелов.

**М-8. Цитаты и списки внутри цитат не разбираются** — `Module.bsl:844-880`, `480-484`
`> - пункт` → `<p>- пункт</p>`; `>>` даёт текст с `>`; loose-список распадается на несколько `<ul>`.
Правка: рекурсивно прогонять содержимое цитаты тем же построчным разбором.

**М-9. Квадратичные проходы по тексту** — `Module.bsl:1513-1535`, `1664-1683`
`НРег(Текст)` пересчитывается на каждый найденный адрес; поиск с конца реализован повторным
поиском с начала. На длинном абзаце (после К-1 это норма) — заметные задержки.
Правка: считать `НРег` один раз; поиск с конца одним проходом.

**М-10. Лишние аллокации и повторный разбор маркера** — `Module.bsl:347-354`, `163`/`181`, `613-614`
Новый `Массив` тегов на каждую строку; `ЭтоНачалоАлерта` вызывается дважды для одной строки,
каждый раз строя `Структура` в `РазобратьМаркерАлерта`.
Правка: вынести список тегов, кэшировать разбор маркера.

**М-11. Экранирование Markdown (`\*`, `\_`, `` \` ``) не поддерживается** — `Module.bsl:1161-1195`, `1771-1813`
`\*не курсив\*` выводится как `\<i>не курсив\</i>`.
Правка: прятать `\<символ>` в плейсхолдер, восстанавливать без слэша.

**М-12. `ЗначениеЗаполнено` не отсекает строку из пробелов** — `Module.bsl:46-48`, `89-91`
Лишний полный проход конвейера (включая карту ссылок и data-URI) для пустого ввода.
Правка: `ПустаяСтрока(ТекстMarkdown)`.

### Проверено, дефектом не является
- Регулярные выражения в конвертере не используются вообще — рисков бэктрекинга нет.
- CRLF: `Символы.ВК` вырезается на стр. 96 — корректно.
- `ЭтоУжеГиперссылка` (`1700`, `Начало > 7`) — граница `mailto:` проверена верно.
- Бесконечных циклов нет: все сборщики увеличивают `Индекс`; рекурсия списка — только на реальном элементе.
- Ранее исправленное (угловые автоссылки, порядок URL/email, 6 решёток) — регресса нет.

Правка: включать в резолв контекст (родитель/`КореньИнструкции` из РС `ГКСИ_ГруппыСценариев`); сортировать выборку.

### 2.2. Существенно

**С-7. 3–4 полные выборки на каждый узел импорта** — `ГКСИ_ЗагрузкаСценариевИзMarkdown:1078-1079` → `ГКСИ_ГруппыСценариевСервер:30`, `1631`, `1662`

`ГКСИ_ГрафГруппПоКорню` (полный граф) и `ЗначениеРеквизитаОбъекта` (1631).
Импорт 500 узлов — тысячи тяжёлых запросов внутри транзакции узла (892).

**С-8. `ЗаписатьПолныйКодКонтекстный` без корня стирает все записи по паре** — `ГКСИ_ГруппыСценариевСервер:1594-1639`

`НаборЗаписей.Записать()` уничтожает принадлежность общего узла к другим инструкциям.
Правка: запретить/явно помечать служебный вызов; кешировать код корня; писать одним набором.

**С-9. Массовые пересчёты кодов — запись набора на запись** — `ГКСИ_ГруппыСценариевСервер:1145-1155`, `1006-1039`, `907-920`
`ПересчитатьВсеКодыВРегистре` / `ПересчитатьПолныйКодДляПоддерева` вызывают
`ЗаписатьПолныйКодКонтекстный` на каждую запись (запись + запрос на запись).
Тысячи транзакций и блокировок; при сбое — разнобой.

**С-10. Несколько родителей — берётся произвольный** — `ГКСИ_ГруппыСценариевСервер:678-681`, `665-695`
Первый из `Соответствие` с `Прервать`; порядок обхода не определён.
`ПолныйКодКонтекстный` нестабилен между пересчётами, коды ссылок «плавают».

**С-11. Заголовки с отступом/в цитате не распознаются** — `ГКСИ_ЗагрузкаСценариевИзMarkdown:109-121`

Правка: снимать ведущие пробелы перед разбором.

**С-12. Одинаковые заголовки на одном уровне склеиваются** — `ГКСИ_ЗагрузкаСценариевИзMarkdown:134-141`, `159-164`

**С-13. Кодировка файла всегда UTF-8** — `ГКСИ_ЗагрузкаСценариевИзMarkdown:68`
UTF-16/CP1251 читается мусором, импорт «успешен», картинки не находятся.

**С-14. Просроченный адрес ВХ → пустое дерево без ошибки** — `ГКСИ_ЗагрузкаСценариевИзMarkdown:63-66`

## 3. Альбом, согласование, почта, глоссарий, формы

`ГКСИ_АльбомПроцессов`, `ГКСИ_СогласованиеИнструкцийСервер`, `ГКСИ_ПочтовыеУведомленияСервер`,

### 3.1. Критично

**К-6. Запись версии объекта внутри `ПередЗаписью` справочника** — `ДемонстрационныеСценарии\ObjectModule.bsl:74-79` → `ГКСИ_СогласованиеИнструкцийСервер:200-208`
`ВерсионированиеОбъектов.ЗаписатьВерсиюОбъекта` (полная сериализация с HTML и сжатием)
выполняется внутри транзакции записи. Комментарий 70-73 сам признаёт «вешало базу».
Длинная транзакция и блокировки при каждом содержательном сохранении узла.
Правка: перенести в `ПриЗаписи`/пост-обработку или фоновое задание; в `ПередЗаписью` — только флаг.

**К-7. Корневая инструкция узла определяется по `Родители[0]`** — `ГКСИ_СогласованиеИнструкцийСервер:21-33` (строка 28)

корень произволен.
Статус (в т.ч. «Проверено») выставляется узлам чужой инструкции; письма и HTML-снимок
привязываются не к той инструкции.
Правка: определять корень по измерению `КореньИнструкции` в РС `ГКСИ_ГруппыСценариев`
или передавать явно из контекста согласования.

### 3.2. Существенно

**С-28. `<body>` извлекается поиском `>` в обратном направлении** — `ГКСИ_АльбомПроцессов:1226`
`СтрНайти(..., ">", НаправлениеПоиска.СКонца, ПозицияОткрытия)` находит `>` предыдущего тега
(`</head>`), а не закрывающую `>` самого `<body ...>`.
В тело попадает тег `<body ...>` и «хвост» `<head>`; при вставке в `<div>`/ячейку — невалидная
разметка (вложенный `<body>`), искажения вёрстки раздела.
Правка: `НаправлениеПоиска.СНачала`.

**С-29. Полная сборка альбома синхронно при открытии формы** — `Forms\АльбомПроцессов\Module.bsl:67` → `:511-547`

без длительной операции и индикатора.
Долгое открытие и блокировка сеанса на больших альбомах.
Правка: `ДлительныеОперации.ВыполнитьВФоне` + индикатор; в `ПриСозданииНаСервере` — только запуск.

**С-30. Пересборка альбома из формы задачи согласования** — `Forms\ГКСИ_ФормаЗадачиСогласования\Module.bsl:9`, `199`, `207-228`
При отсутствии сохранённого HTML вызывается `HTMLИнструкции → СобратьДокументАльбомаПоГруппам`
синхронно на открытии формы (актуально для процессов, запущенных до доработки).
Правка: ленивая/фоновая сборка; убрать синхронный fallback.

**С-31. Установка статуса по инструкции — объект на узел без транзакции** — `ГКСИ_СогласованиеИнструкцийСервер:417-445` (цикл 441-443) → `:453-467`
N `ПолучитьОбъект()` + `Записать()` вне транзакции.
Медленно на большом дереве; при ошибке на середине статус выставлен частично.
Правка: одна транзакция вокруг цикла и/или пакетная запись.

**С-32. До 100 `РазборВерсии` на открытии задачи** — `ГКСИ_СогласованиеИнструкцийСервер:659-667`, вызов `Forms\ГКСИ_ФормаЗадачиСогласования\Module.bsl:290`

Заметное время открытия задачи при длинной истории узла.

**С-33. Фиксация результата и завершение задачи в разных транзакциях** — `Forms\ГКСИ_ФормаЗадачиСогласования\Module.bsl:148-161`
`ЗафиксироватьТранзакцию()` (149), затем `ВыполнитьЗадачу` (161) вне транзакции.
Сбой второго вызова — результат подписи записан, задача не выполнена: рассинхрон состояния

Правка: обе операции в одной транзакции либо компенсация с проверкой состояния перед повтором.
