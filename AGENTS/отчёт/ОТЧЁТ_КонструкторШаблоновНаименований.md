# Отчёт: юзер-френдли конструктор шаблонов наименований

**Подсистема:** ШаблоныНаименований (новая, версия `1.0.0`)
**Версия расширения:** `1.0.2.0` (было `1.0.1.3`, minor)
**Дата:** 2026-10-15
**Тип:** фича

## 1. Задача

Сделать человеческий конструктор шаблонов наименований номенклатуры (шаблоны
наименования для печати/рабочего наименования номенклатуры, характеристик, серий)
на базе типового редактора формул ERP:

1. Добавить в палитру операторов две «условные» конструкции-разделителя, чтобы
   не писать вручную вложенные `?(...)`:
   - `+ ?(ЗначениеЗаполнено(<Реквизит>), " " + <Значение>, "")`;
   - `+ ?(ЗначениеЗаполнено(<Реквизит>), ?(ЗначениеЗаполнено(<Реквизит>), "" + <Значение>, ""), "")`.
2. Добавить в редактор формулы тумблер «Только дополнительные реквизиты»,
   оставляющий в дереве операндов только дополнительные реквизиты и сведения
   (вместе с их свойствами).
3. Запоминать состояние тумблера между открытиями.
4. Дать кнопку вставки условного разделителя «в один клик».

## 2. Изученный типовой механизм (конфигурация `пустая_для_гкс`, ERP 2.5.26.118)

| Объект | Роль |
|---|---|
| `ОбщаяФорма.КонструкторФормул` | Типовой редактор формул («Редактирование формулы»). Открывается в т.ч. из формы элемента `Справочник.ВидыНоменклатуры` |
| `РаботаСФормулами` | Ядро: дерево операндов, дерево операторов, разворачивание, загрузка в дерево формы |
| `КонструкторФормулСлужебный` | Реализация, в т.ч. `СписокОператоров` |
| `Справочник.ВидыНоменклатуры.МодульМенеджера` | `ПодготовитьДеревоОперандов(НаборыСвойств, ИмяШаблона)` — строит дерево доступных полей |
| `Справочник.ВидыНоменклатуры.ФормаЭлемента` | `ИзменениеВРедактореШаблона`, `ПостроитьДеревоОператоров`, `ПодготовитьДеревоОперандов` — точка открытия конструктора |

Ключевые факты, определившие реализацию:

- **Палитра операторов** — это `ДеревоЗначений` с колонками `Представление`,
  `Идентификатор`, `КонструкцияДляВставки`, `Сдвиг`, `Пояснение`, `ЭтоГруппа`.
  Наполняется методами `РаботаСФормулами.ДобавитьГруппуОператоров(...)` и
  `РаботаСФормулами.ДобавитьОператор(...)`. Для шаблонов наименований палитра
  строится **своим** кодом в форме `ВидыНоменклатуры` (не общим
  `КонструкторФормулСлужебный.СписокОператоров`), и передаётся в конструктор
  параметром `Операторы` (адрес во временном хранилище).
- **Дерево операндов** передаётся параметром `ДеревоОперандов` (адрес во
  временном хранилище). Загрузка в форму — `РаботаСФормулами.ЗагрузитьДеревоОперандовВДеревоФормы(...)`.
- **Тип элемента дерева** лежит в колонке `ТипЭлементаДерева`; дополнительные
  реквизиты и сведения приходят из секции `ХАРАКТЕРИСТИКИ` СКД и помечаются
  значениями `ДополнительныйРеквизит` / `ДополнительноеСведение`.
- **Ленивое разворачивание.** `РаботаСФормулами.РазвернутьСтрокуОперандаДереваФормы`
  при клике на «+» строит детей заново из СКД со стандартными ограничениями
  (`ВыводитьРеквизиты = Истина`) — то есть предварительная фильтрация узлов
  при раскрытии была бы проигнорирована. Это исключило вариант «фильтровать
  дерево формы на месте» в пользу пересборки дерева из исходного адреса.

## 3. Принятая архитектура

### 3.1. Точка расширения — заимствованная общая форма

Заимствована `ОбщаяФорма.КонструкторФормул` в расширение
(`src/CommonForms/КонструкторФормул/`). Модуль формы расширения — **аддитивный**:
он не переопределяет типовую логику целиком, а добавляет свои процедуры и
точечно вмешивается аннотациями.

| Место | Что делает расширение |
|---|---|
| `&После("ПриСозданииНаСервере")` `ГКСК_ПриСозданииНаСервере` | настраивает палитру разделителей и фильтр доп. реквизитов |
| `&Вместо("ВставитьОператорВФормулу")` `ГКСК_ВставитьОператорВФормулу` | для операторов с идентификатором `ГКСК_*` вставляет конструкцию и ставит курсор на первый плейсхолдер; для остальных — `ПродолжитьВызов()` (типовое поведение) |
| Команда формы `ГКСК_ВставитьУсловныйРазделитель` | кнопка «вставить разделитель одним кликом» |
| Реквизит формы `ГКСК_ТолькоДополнительныеРеквизиты` (Булево) + флажок | тумблер фильтра |

### 3.2. Условные разделители

`ГКСК_НастроитьУсловныеРазделители()` добавляет в дерево операторов группы
`ГКСК_УсловныеРазделители` («Условные разделители») два оператора:

| Идентификатор | Представление | Конструкция для вставки |
|---|---|---|
| `ГКСК_РазделительПробел` | Условный разделитель (пробел) | `+ ?(ЗначениеЗаполнено(<Реквизит>), " " + <Значение>, "")` |
| `ГКСК_РазделительВложенный` | Условный разделитель (вложенный) | `+ ?(ЗначениеЗаполнено(<Реквизит>), ?(ЗначениеЗаполнено(<Реквизит>), "" + <Значение>, ""), "")` |

Плейсхолдеры `<Реквизит>` и `<Значение>` — видимые тексты в угловых скобках
(в стиле типовой палитры: `<Значение>`, `<Форматная строка>`), в пояснении
оператора написано, что их надо заменить операндами из дерева.

Дополнительно:

- `Сдвиг` оператора = позиция первого `<Реквизит>` от конца строки — платформа
  ставит курсор сразу в этот плейсхолдер.
- `ГКСК_ВыделитьПлейсхолдерРеквизит(Конструкция)` после вставки **выделяет**
  первый `<Реквизит>`, чтобы его можно было сразу заменить перетаскиванием
  операнда или выбором из дерева.
- Палитра разделителей показывается только для строковых формул
  (`ТипРезультата.СодержитТип(Тип("Строка"))`): для шаблонов наименований это
  всегда так, а в чужих сценариях (числовые формулы) лишние кнопки не мешают.

### 3.3. Фильтр «Только дополнительные реквизиты»

Тумблер **не фильтрует дерево на месте**, а пересобирает его из исходного
адреса `АдресДереваОперандов`:

- `ГКСК_ДеревоТолькоДопРеквизиты(ДеревоИсточник)` — обход исходного дерева,
  переносятся только узлы с `ТипЭлементаДерева ∈ {ДополнительныйРеквизит,
  ДополнительноеСведение}` вместе со всеми их потомками-свойствами
  (`ГКСК_ПеренестиВсеПодчиненныеСтроки`). Узлы-группы сохраняются, если внутри
  есть доп. реквизиты (`ГКСК_СтрокиСодержатДопРеквизиты`) — иначе ломается сборка
  полных идентификаторов строк.
- Переключение — `ГКСК_ПереключитьДеревоОперандов()`: берёт исходное дерево из
  временного хранилища, при необходимости фильтрует и грузит в дерево формы.
  Так выключение тумблера всегда возвращает полное дерево, без накопления ошибок.
- **Разрешённые операнды не пересчитываются.** `РаботаСФормулами.ЗагрузитьДеревоОперандовВДеревоФормы`
  вызывается без массива разрешённых операндов, чтобы проверка формулы
  (`Проверить`) продолжала работать по полному списку: включение фильтра не
  должно объявлять ранее корректную формулу ошибочной.
- Флажок **скрывается**, если в дереве вообще нет дополнительных реквизитов
  (`Элементы.ГКСК_ТолькоДополнительныеРеквизиты.Видимость`), — чтобы не
  предлагать бессмысленный режим.
- Состояние запоминается в хранилище общих настроек БСП под ключом
  `ГКСК.КонструкторФормул` / `ТолькоДополнительныеРеквизиты`
  (`ОбщегоНазначения.ХранилищеОбщихНастроекЗагрузить/Сохранить`) и применяется
  при следующем открытии формы.

## 6. Ограничения и что осталось

- **Палитра разделителей видна во всех строковых формулах**, а не только в
  шаблонах наименований: форма `КонструкторФормул` общая. Практического вреда
  нет (конструкции универсальны), но при желании можно сузить показ по признаку
  вызова.
- **Свойства доп. реквизитов появляются при разворачивании узла** — так устроен
  типовой механизм; в отфильтрованном дереве разворачивание работает штатно,
  так как дерево пересобирается из исходного адреса.
- **Предпросмотр итогового наименования** по текущему объекту не делался —
  вынесен в отдельную задачу.
