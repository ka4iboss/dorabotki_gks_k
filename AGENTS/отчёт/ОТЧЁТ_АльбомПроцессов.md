# ОТЧЁТ — АльбомПроцессов через регистр сведений

Этап 8 плана `ПЛАН_МаркдаунДляОписанийПроцессов.md`. Реализован сводный документ
«Альбом процессов» на собственной иерархии регистра `ГКСИ_ГруппыСценариев`.

## Что сделано

1. **Создан общий модуль `ГКСИ_АльбомПроцессов`** (`Server`, `ExternalConnection`).
   Файл: `src/CommonModules/ГКСИ_АльбомПроцессов/ГКСИ_АльбомПроцессов.mdo` +
   `Module.bsl`.
2. **Модуль `Module.bsl` формы `АльбомПроцессов`** перехватывает типовой
   `ПриСозданииНаСервере` через `&Перед("ПриСозданииНаСервере")` и записывает
   результат построителя в реквизит формы `ТекстHTML`. Файл:
   `src/Catalogs/ДемонстрационныеСценарии/Forms/АльбомПроцессов/Module.bsl`.
3. **Сборка HTML перенесена** из типовой формы (которая опиралась на пустой
   `Родитель`) в собственный построитель. Типовая логика формы фактически
   отключена — она не имеет доступа к иерархии через регистр.

## Алгоритм построителя

```
СобратьДокументАльбомаПоГруппам(ГруппыДляАльбома):
  1. ГКСИ_НормализоватьГруппы — пустой вход → все корневые группы
  2. КодыЯзыковКонфигурации — Метаданные.Языки
  3. ГКСИ_СобратьВсеСценарииДерева — обход предзагруженного графа
     (Соответствия из ПовторноИспользуемыеЗначения, O(1)), без запросов в БД
  4. ГКСИ_ЗагрузитьОписанияВсехЯзыков:
       - один запрос к ДемонстрационныеСценарииПрисоединенныеФайлы
         по всем (Владелец, ИмяФайла) за один проход
       - один пакетный вызов РаботаСФайлами.ДвоичныеДанныеФайлов
       - для каждого языка формируется своё Соответствие
         {Сценарий → ТелоГипертекста}
  5. ГКСИ_СобратьПоддеревоВМассивСтрок — рекурсивный обход дерева,
     только работа с памятью (запросов к БД нет)
  6. ГКСИ_СобратьДокумент — финальный HTML со стилями
```

Структура итогового документа:

```html
<!DOCTYPE html>
<html>
  <head>
    <style>...альбомные стили...</style>
  </head>
  <body>
    <h1 class="album-lang">ru</h1>
      <h2 class="album-group">Группа 1</h2>
        <h3 class="album-scenario">Сценарий 1.1</h3>
        ...тело описания из присоединённого файла...
        <h3 class="album-group">Подгруппа 1.1</h3>
          ...
    <h1 class="album-lang">en</h1>
      ...
  </body>
</html>
```

## Публичный API

| Функция | Описание |
|---------|----------|
| `СобратьДокументАльбома()` | Полный альбом по всем корневым группам. Экспорт. |
| `СобратьДокументАльбомаПоГруппам(ГруппыДляАльбома)` | Альбом по выбранным группам (как в типовой форме: выделенные строки). Экспорт. |
| `КодыЯзыковКонфигурации()` | Коды языков конфигурации (Метаданные.Языки). Экспорт. |

Все остальные процедуры/функции — служебные, префикс `ГКСИ_`.

## Извлечение `<body>`

Типовой HTML-файл описания сценария — это полноценный документ (`<!DOCTYPE html>`,
`<html>`, `<body>...</body>`). Чтобы при склеивании не получать вложенный
HTML-документ, `ГКСИ_ТелоГипертекста` извлекает только содержимое тега
`<body>…</body>` (учитывает атрибуты открывающего тега). Если тегов нет —
возвращается исходная строка. Если закрывающий `</body>` отсутствует -
возвращается всё, что после `>` открывающего.

## Модуль формы

```bsl
&Перед("ПриСозданииНаСервере")
Процедура ГКСИ_ПередПриСозданииНаСервере(Отказ, СтандартнаяОбработка)

    Если Отказ Тогда
        Возврат;
    КонецЕсли;

    ТекстHTML = ГКСИ_АльбомПроцессов.СобратьДокументАльбома();

КонецПроцедуры
```

Шаблон `&Перед` с уникальным именем метода — тот же, что используется в
`ФормаЭлемента` и `ФормаГруппы` (`ГКСИ_ПередПриСозданииНаСервере`). Это
позволяет типовому обработчику `ПриСозданииНаСервере` всё равно отработать
после нашего — форма не падает.

## Маркеры EDT

### Устранено в процессе

- **SU193** (Общий модуль имеет некорректные настройки `ClientOrdinaryApplication` для серверного типа). Зафиксировано явное `<clientOrdinaryApplication>false</clientOrdinaryApplication>` в `.mdo` (значение по умолчанию для атрибута в `1C:EDT` — `true`, поэтому недостаточно опустить тег).
- **SU95 × 2** («Запрос в цикле» в `ГКСИ_СобратьПоддеревоВМассивСтрок → ГКСИ_ЗагрузитьОписанияПоддерева → Запрос.Выполнить`). Устранено переходом на двухуровневую схему: сначала рекурсивно собирается плоский список листьев дерева через граф в памяти, затем описания для всех языков загружаются одним запросом. В рекурсивном обходе обращений к БД нет.
- **LatinAndCyrillicSymbolInWord × N** (линтер BSL: смешение латиницы и кириллицы в идентификаторах). Устранено переименованием: `СформироватьHTMLАльбома → СобратьДокументАльбома`, `СформироватьHTMLАльбомаПоГруппам → СобратьДокументАльбомаПоГруппам`, `ГКСИ_ЗаголовокHTML → ГКСИ_ЗаголовокГипертекста`, `ГКСИ_ЭкранироватьHTML → ГКСИ_ЭкранироватьГипертекст`, `ГКСИ_ТелоHTML → ГКСИ_ТелоГипертекста`, переменная `HTML → Гипертекст`.
- **NestedFunctionInParameters** (Уберите инициализацию параметров метода `Добавить` вложенными методами). Устранено: `ОписанияПоСценариям.Получить(…)` вынесено в локальную переменную перед `.Добавить()`.

## Связь с другими частями расширения

- Использует предзагруженный граф `ГКСИ_ГруппыСценариевСервер.ГКСИ_ГрафГрупп()` — тот же кеш, что и формы элемента/группы/списка. Никаких дополнительных запросов на построение графа не происходит.
- Использует имена файлов описаний `ГКСИ_ГруппыСценариевСервер.ИмяФайлаОписанияСценария()` — гарантирует стабильное имя `<GUID>_<КодЯзыка>.html` при перемещении сценария между группами.
- Использует БСП-обёртку `РаботаСФайлами.ДвоичныеДанныеФайлов` для пакетного чтения содержимого присоединённых файлов.
