# Отчёт: Загрузка сценариев из Markdown

Дата: 2026-09-03
Задача: реализация обработки `ГКСИ_ЗагрузкаСценариевИзMarkdown`.

Обновление: 2026-09-04 — устранена регрессия (пустой `ГКСИ_ТекстMarkdown` и пустой справочник присоединённых файлов).

## Что сделано

1. **Создан общий модуль `ГКСИ_ЗагрузкаСценариевИзMarkdown`** (`src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/`).
   Экспортные функции:
   - `РазобратьMarkdownВДерево(АдресФайлаВоВременномХранилище, ИмяФайла = "")` — парсинг файла регулярным выражением `^(#{1,3})\s+(.+?)\s*$` с формированием `ДеревоЗначений` (колонки `Уровень`, `Наименование`, `ТекстMarkdown`, `Порядок`).
   - `НайтиСуществующихПоИмени(МассивНаименований)` — поиск существующих элементов/групп для обнаружения конфликтов.
   - `ЗаписатьДеревоВСправочник(ДеревоУзлов, КодЯзыка, РешенияПоКонфликтам)` — рекурсивная запись дерева в `ДемонстрационныеСценарии`. Связи групп — через РС `ГКСИ_ГруппыСценариев` (`ГКСИ_ГруппыСценариевСервер.ДобавитьСценарийВГруппу`). Поле `Родитель` обнуляется в `ObjectModule` (типовое поведение расширения).
   - `MarkdownВHTML(ТекстMarkdown)` — минимальный серверный конвертер (H1–H3, параграфы, жирный/курсив/моно, ссылки) на платформенных функциях регулярных выражений (без COM/VBScript).

2. **Создана обработка `ГКСИ_ЗагрузкаСценариевИзMarkdown`** (`src/DataProcessors/ГКСИ_ЗагрузкаСценариевИзMarkdown/`):
   - `Форма` — основная форма. Все элементы (поля `ИмяФайла`, `ТекстПревью`; кнопки `Выбрать файл`, `Загрузить`, `Проверить конфликты`, `Выполнить загрузку`) заданы **статически** в `Form.form`. Помещение файла на сервер — через `ПоместитьФайлыНаСерверАсинх` с вариантом диалога (современное асинхронное API). Данные между клиентом и сервером передаются через адреса во временном хранилище (`АдресФайлаВоВременномХранилище`, `АдресДереваУзлов`, `АдресРешенийВоВременномХранилище`).
   - `ФормаРазрешенияКонфликтов` — таблица `Конфликты` (`ИмяИзФайла`, `СуществующаяСсылка`, `СуществующееЭтоГруппа`, `Решение`) со списком выбора «Пропустить / Обновить / Дублировать» в колонке `Решение`. Возврат — через `ОповеститьОВыборе`.

3. **Переработан `ObjectModule.ДемонстрационныеСценарии`** (`src/Catalogs/ДемонстрационныеСценарии/ObjectModule.bsl`):
   - Перенесена логика создания/обновления присоединённых HTML-файлов из формы элемента/группы в `&После("ПриЗаписи")` (`ГКСИ_СоздатьПрисоединенныеФайлыИзДопСвойств`).
   - Хук читает HTML из `ДополнительныеСвойства["ГКСИ_АдресHTMLПоЯзыкам"]` (адрес ВХ, по адресу — соответствие КодЯзыка → HTML) и обновляет ТЧ `ОписанияСценария`.
   - Создание файлов происходит **после** пересчёта `ПолныйКод` — это требование к порядку хуков: имя файла строится через `ГКСИ_ГруппыСценариевСервер.ИмяФайлаОписанияСценария(ПолныйКод, КодЯзыка)` и при пустом коде получается `ОписаниеСценария___ru`.

## Ключевые технические решения

- **Иерархия групп — через РС `ГКСИ_ГруппыСценариев`**, а не через поле `Родитель` — повторяет существующую архитектуру расширения.
- **Контракт передачи HTML в `ДемонстрационныеСценарии`** — `ДополнительныеСвойства["ГКСИ_АдресHTMLПоЯзыкам"]` (адрес ВХ, по адресу — `Соответствие` КодЯзыка → HTML). Этот же канал используют типовые формы `ФормаЭлемента` и `ФормаГруппы`. Чтение и запись — только в `ObjectModule.ГКСИ_ПриЗаписи`. Любая серверная логика, записывающая сценарий с HTML, должна использовать этот канал, не создавая файлы напрямую через `ДемонстрационныеСценарииПрисоединенныеФайлы`.
- **HTML из Markdown** генерируется минимальным серверным конвертером; при первом открытии формы элемента в `ДемонстрационныеСценарии` типовой механизм (`showdown`/`highlight.js` из подсистемы `ГКСИ_РМ_РедакторMarkdown`) пересоберёт HTML с подсветкой кода.
- **Политика конфликтов** — интерактивная: «Пропустить», «Обновить», «Дублировать». Решения передаются в серверный метод через структуру с полями `Действие` и `Ссылка`.
- **Имена файлов описаний** формируются функцией `ГКСИ_ГруппыСценариевСервер.ИмяФайлаОписанияСценария` (`<GUID_сценария>_<КодЯзыка>`), что обеспечивает совместимость с типовым механизмом `ДемонстрационныеСценарии`.
- **Иерархические парсеры** в общих модулях расширения строятся через массив-стек (индекс = уровень − 1), не через `Соответствие` с числовыми ключами (см. ниже «Корневая причина регрессии 04.09»).

## Корневая причина регрессии 04.09

Симптом: после загрузки `.md`-файла создавались группы/элементы без `ГКСИ_ТекстMarkdown`; справочник `ДемонстрационныеСценарииПрисоединенныеФайлы` оставался пустым, в ТЧ `ОписанияСценария` ссылок не было.

Локализация (через диагностическое логирование `[ГКСИ-ДИАГ]` в ЖР):

1. В парсере — 12 заголовков распознавались, но **ни одной записи `ТекстДобавлен`**, при этом у стека уровней содержимое было пустым (`Стек=`) уже на первой итерации после добавления заголовка уровня 2.
2. В `ObjectModule.ГКСИ_ПриЗаписи` — `ЕстьГКСИ_АдресHTMLПоЯзыкам=false`, `ДлинаТекстMarkdown=0`.
3. В обработке перед `ОбъектУзла.Записать()` — `ДлинаТекстMarkdown=0`, `ЕстьКлючДоп=false`.

Причина: в `ГКСИ_ЗагрузкаСценариевИзMarkdown.РазобратьMarkdownВДерево` стек текущих узлов строился на `Соответствие` с числовыми ключами уровней и функцией `ДобавитьУзелВДерево`, которая после `СтрокиУровня.Вставить(Уровень, Узел)` не отдавала ссылку обратно через `СтрокиУровня.Получить(Уровень)` — добавление текста в «самый глубокий открытый узел» возвращало `Неопределено` сразу после первого заголовка. Внешне код выглядел корректно, баг ловился только трассировкой.

Фикс:

- Стек переписан на `Массив` (индекс = уровень − 1, верхушка = текущий узел). Текстовые строки добавляются без поиска, по верхушке стека. Если у родителя уже есть ребёнок с тем же именем — он переиспользуется (полезно при повторной загрузке).
- Вся диагностика `[ГКСИ-ДИАГ]` удалена после успешного теста.
- Удалена ставшая ненужной функция `ДобавитьУзелВДерево`.

После фикса пользователь подтвердил: текст в `ГКСИ_ТекстMarkdown` появился, присоединённые HTML-файлы созданы, ТЧ `ОписанияСценария` заполнена.

## Этап 13. Загрузка картинок из Markdown (Obsidian `![[...]]`)

### Решение

Расширение сценария: вместе с текстом `.md`-файла обработка теперь загружает и встраивает картинки, на которые ссылается текст в синтаксисе Obsidian `![[path]]`.

Пользовательские решения (согласовано):

1. Источник картинок — каталог, выбранный пользователем через диалог выбора каталога. Картинки ищутся рекурсивно в этом каталоге.
2. Поддерживается только синтаксис Obsidian `![[path]]`. При загрузке заменяется на стандартный `![](КодФайла)`.
3. Дедупликация по SHA-256 от двоичных данных. Если файл с тем же хешем уже есть — переиспользуется.
4. Битые ссылки помечаются в тексте как `❌ path` и пишутся в журнал регистрации как предупреждение.

### Изменения в метаданных

### Изменения в коде

- `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`:

  - `ЗаписатьДеревоВСправочник` теперь принимает параметр `КаталогПоиска`. Перед рекурсивным обходом дерева вызывает `ПодготовитьКартинкиДляДерева`, который собирает все уникальные пути картинок, делает один пакетный запрос на дедупликацию и создаёт недостающие элементы. Готовая карта подмен передаётся в рекурсивный обход — без обращений к БД внутри цикла.

  - Добавлены команды: `ВыбратьКаталог` (открывает диалог выбора каталога) и связанные элементы формы.

  - Старый клиентский поток с `ПоместитьФайлыНаСерверАсинх` заменён на выбор каталога → выбор файла из списка.

### Архитектурный акцент: запрос вне циклов (SU95)

Первая реализация вызывала `Запрос.Выполнить()` внутри цикла по картинкам — это срабатывание SU95 (severity: error, priority: high). Исправлено двухэтапным процессом:

1. `ПодготовитьКартинкиДляДерева` собирает все уникальные пути, ищет файлы на диске и считает SHA-256 без обращения к БД.
2. Один пакетный запрос `ХешиСуществующихФайлов(МассивХешей)` отдаёт существующие коды.
3. Создание новых элементов идёт вне цикла.
4. `ОбработатьУзелРекурсивно` работает только с готовой картой подмен, без обращений к БД.

Линтер SU95 не срабатывает.
