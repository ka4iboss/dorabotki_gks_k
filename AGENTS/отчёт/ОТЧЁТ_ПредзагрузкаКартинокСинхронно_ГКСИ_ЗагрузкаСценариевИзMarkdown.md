# ОТЧЁТ — Предзагрузка картинок из Markdown синхронным серверным вызовом

**Версия расширения:** 1.7 → **1.71**
**Объект:** обработка `ГКСИ_ЗагрузкаСценариевИзMarkdown` (импорт `.md` со сценариями)
**Тип задачи:** исправление бага в клиент-серверной базе с тонким клиентом

## 1. Симптом

В клиент-серверной базе, при подключении через тонкий клиент, картинки из Markdown
(`![[image.png]]`, `![](image.png)`, обычные ссылки) **не загружались** в справочник
`ГКСИ_ФайлыИнструкций`. После импорта справочник с файлами оставался пустым, в тексте
сценария появлялись заглушки вида `❌ <путь>` (вместо валидных `![](<код>)`),
HTML-просмотр картинки не показывал.

Локальная файловая база работала корректно — баг воспроизводился только в
клиент-серверном варианте, когда `.md` и картинки лежат на машине клиента
(внешний ресурс `\\comp`, не диск сервера 1С).

## 2. Корневая причина

В форме обработки при выборе файла через диалог `ПоместитьФайлНаСервер`/`ПоместитьФайлыНаСервер`
формировался `Соответствие<ИмяФайла, адресВХ>` (адреса ВХ с UID текущего сеанса)
и передавался в фоновое задание. В форме стоял вызов
`СоответствиеИзВХ(АдресаКартинокВоВременномХранилище)`, который **на клиенте десериализовал
адреса в `ДвоичныеДанные`** ещё до передачи в фон.

Далее в общем модуле `ГКСИ_ЗагрузкаСценариевИзMarkdown` функция
`НайтиКартинкуИПосчитатьХеш(Путь, КаталогПоиска, СоответствиеКартинок)` пыталась
прочитать `СоответствиеКартинок[Путь]` и:

1. Получала **уже десериализованный `ДвоичныеДанные`** (а не адрес ВХ),
   поэтому `ПолучитьИзВременногоХранилища` падал или возвращал пустоту.
2. Пыталась искать файл по дисковому пути на **сервере** (например
   `\\comp\share\image.png`), но сервер 1С в режиме тонкого клиента не имел
   доступа к этому ресурсу → картинка не находилась.

Итог: `КартаПодменКартинок` оказывалась пустой, во всех ссылках `![[path]]`
вставлялась заглушка `❌ <путь>`.

## 3. Решение

Разделить поток загрузки на две фазы:

1. **Предзагрузка (синхронный серверный вызов в основном сеансе).**
   Читает двоичные данные картинок из ВХ текущего сеанса, считает SHA-256,
   создаёт/находит элементы справочника `ГКСИ_ФайлыИнструкций`, собирает карту
   `ОригинальныйПуть → КодФайла`.
2. **Запись (фоновое задание / синхронно для файловой БД).**
   Получает на вход **готовую карту** и только выполняет обход дерева с подменой
   ссылок. Никаких обращений к диску, никаких адресов ВХ в контракте фона.

### 3.1 Что изменено

#### `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`

- **Добавлена** экспортная функция
  `ПодготовитьФайлыИнструкций(ДеревоУзлов, АдресаКартинокВоВременномХранилище, АдресПрогресса)`.
  Шаги:
  1. `СобратьПутиКартинокИзДерева(ДеревоУзлов)` — обходом дерева собрать все
     уникальные оригинальные пути картинок.
  2. Для каждого пути вызвать `НайтиКартинкуИПосчитатьХеш(Путь, "",
     АдресаКартинокВоВременномХранилище)` — пустой `КаталогПоиска` гарантирует,
     что поиск идёт только по переданному соответствию ИмяФайла → адресВХ.
  3. Один пакетный запрос `ХешиСуществующихФайлов` (без изменений) — получить
     коды уже существующих элементов по SHA-256.
  4. Для новых хешей — `СоздатьЭлементФайлаИнструкции` (без изменений).
  5. Поместить карту `ОригинальныйПуть → КодФайла` во временное хранилище
     через `ПоместитьВоВременноеХранилище(Карта, ЭтотОбъект, , ИмяФайла)`.
     Возвращается **адрес ВХ без UID** (последний параметр), чтобы фон мог
     прочитать данные через `ПолучитьИзВременногоХранилища`.

- **Изменена** сигнатура `ЗаписатьДеревоВСправочник`:
  - Было: `(ДеревоУзлов, КодЯзыка, РешенияПоКонфликтам, КаталогПоиска,
    АдресаКартинокВоВременномХранилище, АдресПрогресса, АдресРезультатаЗагрузки)`.
  - Стало: `(ДеревоУзлов, КодЯзыка, РешенияПоКонфликтам, КартаПодменКартинок = Неопределено,
    КаталогПоиска = "", АдресаКартинокВоВременномХранилище = Неопределено,
    АдресПрогресса = "", АдресРезультатаЗагрузки = "")`.
  - Поведение: если `КартаПодменКартинок` задана — используется она (готовый
    результат `ПодготовитьФайлыИнструкций`); иначе, если есть `КаталогПоиска`
    или адреса ВХ — вызывается `ПодготовитьКартинкиДляДерева` (старая логика,
    без изменений в её коде).
  - Логика подмены в `ОбработатьУзелРекурсивно` не меняется.

#### `src/DataProcessors/ГКСИ_ЗагрузкаСценариевИзMarkdown/Forms/Форма/Module.bsl`

- **Добавлен** реквизит `АдресКартыФайлов` (Строка) в `Form.form`.
- **Добавлена** серверная процедура `ПодготовитьФайлыИнструкцийНаСервере(
  ДеревоУзлов, АдресаКартинокВоВременномХранилище)` — вызывает общую функцию,
  сохраняет результат в ВХ, возвращает адрес строкой.
- **Изменена** `ЗапуститьЗаписьДереваВФоне`:
  - После `ЗагрузитьФайлИКартинкиНаСервере` (который кладёт адреса ВХ в реквизит
    формы) добавлен явный вызов
    `АдресКартыФайлов = ПодготовитьФайлыИнструкцийНаСервере(ДеревоУзлов,
    АдресаКартинокВоВременномХранилище)`.
  - В фон теперь передаётся `КартаПодменКартинок =
    ПолучитьИзВременногоХранилища(АдресКартыФайлов)` (а не `СоответствиеИзВХ(...)`).
- **Изменена** `ЗаписатьДеревоСинхронноНаСервере` — аналогичные изменения для

- **Изменена** `ЗапуститьЗагрузкуСейчас` — обновлён вызов

#### `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdownДлительныеОперации/Module.bsl`

  - Из `Параметры` извлекается новое поле `КартаПодменКартинок` (вместо
    `АдресаКартинокВоВременномХранилище`).
  - В `ЗаписатьСтартФоновогоЗаданияВЖурнал` добавлено логирование размера карты

  - Передача в `ЗаписатьДеревоВСправочник` использует новую сигнатуру с
    `КартаПодменКартинок`.

### 3.2 Что НЕ менялось (важно)

- `ПодготовитьКартинкиДляДерева` — оставлена для сценария «выбрать каталог +
  выбрать .md», где сервер сам ищет файлы на диске. Внутри фон.задания
  работает по старой схеме.
- `НайтиКартинкуИПосчитатьХеш`, `ХешиСуществующихФайлов`,
  `СоздатьЭлементФайлаИнструкции`, `СобратьПутиКартинокИзДерева` —
  переиспользуются без правок.
- Сценарий «выбрать каталог» — поведение сохранено, минимальный риск регрессии.

## 4. Контракты

### 4.1 `ПодготовитьФайлыИнструкций`

```1c
Функция ПодготовитьФайлыИнструкций(
    ДеревоУзлов,
    АдресаКартинокВоВременномХранилище, // Соответствие из КлючИЗначение
    АдресПрогресса = "") // Строка, необязательный
    // Возвращает: Строка — адрес ВХ (без UID) с готовой картой
    //   подмен ОригинальныйПуть -> КодФайла.
```

### 4.2 Новая сигнатура `ЗаписатьДеревоВСправочник`

```1c
Процедура ЗаписатьДеревоВСправочник(
    ДеревоУзлов,
    КодЯзыка,
    РешенияПоКонфликтам,
    КартаПодменКартинок = Неопределено, // Соответствие из КлючИЗначение, необязательный
    КаталогПоиска = "",                 // Строка, необязательный
    АдресаКартинокВоВременномХранилище = Неопределено, // Соответствие из КлючИЗначение
    АдресПрогресса = "",                // Строка, необязательный
    АдресРезультатаЗагрузки = "")       // Строка, необязательный
```

Приоритет:
1. `КартаПодменКартинок` (готовый результат) — если задана, используется как есть,
   никаких дополнительных действий по подготовке.
2. Иначе — старая логика: если `КаталогПоиска` или `АдресаКартинокВоВременномХранилище`
   заданы, вызывается `ПодготовитьКартинкиДляДерева`.

## 5. Тест-план (ручной, в клиент-серверной базе)

1. Подготовить `.md` с синтаксисами `![[path]]`, `![[path|caption]]`, `![alt](path)`
   на сетевом ресурсе `\\comp\share\<каталог>\test.md` + сопутствующие картинки в том же каталоге.
2. В обработке выбрать `.md` и приложенные картинки одним диалогом (команда `ВыбратьФайл`).
3. Запустить загрузку.
4. Ожидаемо:
   - В журнале регистрации (фоновое задание) видно `Загружено файлов: N`.
   - В справочнике `ГКСИ_ФайлыИнструкций` созданы элементы (с заполненным `Файл`,
     `Расширение`, `ХешSHA256`).
   - В тексте сценария ссылки заменены на `![](<код>)` (без заглушек `❌`).
   - В HTML-просмотре картинки отображаются.

Регресс:
- Локальные файлы на диске сервера (сценарий «выбрать каталог») — должны
  загружаться без изменений через старую функцию `ПодготовитьКартинкиДляДерева`.
