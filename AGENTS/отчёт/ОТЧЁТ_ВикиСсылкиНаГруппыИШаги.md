# Отчёт: вики-ссылки на группы и шаги демонстрационных сценариев

**Расширение:** `Доработки_ГКС_К`, подсистема ГКСИ.
**Дата:** 2026-10-19.
**Версия расширения:** `1.0.2.0 → 1.0.3.0` (ГКСИ `2.35.4 → 2.36.0`).
**Тип:** фича.

---

## 1. Задача

Добавить в Markdown-тексты описаний демонстрационных сценариев ссылки на другие
группы/шаги — по аналогии со ссылками на документы в Obsidian. Ссылки должны быть
кликабельными:

- на форме элемента и форме группы — переход к объекту `CatalogRef.ДемонстрационныеСценарии`;
- в альбоме процессов — прокрутка к разделу внутри уже открытого документа.

Синтаксис:

```text
[[Имя группы или шага]]
[[Имя группы или шага|Отображаемый текст]]
[[КодВКонтексте|Отображаемый текст]]
```

`![[…]]` (картинки) ссылками не считаются и обрабатываются прежним механизмом
загрузки картинок.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Разрешение цели | Сначала по `КодВКонтексте` (однозначен), затем по наименованию — и только если оно **уникально** в пределах карты. |
| Неоднозначное имя | Ссылка не разрешается: в HTML попадает `<span class="gksi-link-broken" title="Ссылка не найдена: …">`. Автору нужно указать код. |
| Область разрешения | Карта строится по корню инструкции текущего узла (`КореньИнструкции` в РС `ГКСИ_ГруппыСценариев`), а для альбома — по всем корням, представленным в альбоме. |
| Производительность | Карта строится двумя пакетными запросами, обращений к БД в цикле нет. |
| Предпросмотр Markdown | `[[…]]` разбираются JS-предобработчиком **до** конвертации showdown, карта ссылок передаётся в HTML как `window.__gksiLinks`. |
| Клик на форме | `href` = навигационная ссылка 1С (`e1cib/data/…`), обработка — штатным `ПерейтиПоНавигационнойСсылке`. |
| Клик в альбоме | `href` переписывается на внутренний якорь `#gksi-node-<uuid>`; прокрутка — своим клиентским обработчиком. |
| Хранение | Ничего нового не хранится: в `ГКСИ_ТекстMarkdown` остаётся исходный `[[…]]`, преобразование — на отображении. Загрузка/выгрузка Markdown не меняются (round-trip тождественный). |

## 3. Что сделано

### 3.1 Новый общий модуль `ГКСИ_СсылкиСценариев` (сервер)

Единая точка работы со ссылками. Экспортный интерфейс:

| Метод | Назначение |
|---|---|
| `КартаСсылокСценариев(КорниИнструкций = Неопределено)` | Строит карту узлов: `ПоИменам` (уникальные имена → ссылка), `ПоКодам` (`КодВКонтексте` → ссылка), `ПоСсылкам` (ссылка → `{Наименование, Код, ЭтоГруппа}`), `Пустая`. |
| `РазрешитьЦель(Цель, Карта)` | Цель → `CatalogRef.ДемонстрационныеСценарии` или `Неопределено`. |
| `НавигационнаяСсылкаУзла(Ссылка)` | `ПолучитьНавигационнуюСсылку` с защитой от исключения. |
| `ИмяЯкоряУзла(Ссылка)` | `"gksi-node-" + УникальныйИдентификатор`. |
| `ЭкранироватьHTMLСтроку(Значение)` | Экранирование `& < > "`. |
| `ЕстьВикиСсылки(Текст)` | Быстрая проверка наличия `[[…]]` (с учётом `![[…]]`). |
| `ПодставитьСсылкиВТекст(Текст, Карта, РежимПодстановки)` | Разбор `[[…]]` в HTML. Режимы: `"Навигация"` (href = навигационная ссылка) и `"Якорь"` (href = `#якорь`). |
| `СсылкиJSONДляКлиента(Карта)` | Карта в JSON (`name`, `code`, `href`, `anchor`) для JS предпросмотра; сортировка по убыванию длины наименования. |
| `ПереписатьСсылкиНаЯкоряВHTML(HTML, МножествоЯкорей)` | Заменяет `href` на `#якорь` для узлов, попавших в альбом. |
| `КорниИнструкцийУзлов(Узлы)` | Корни инструкций для набора узлов (пакетный запрос). |
| `КореньИнструкцииУзла(Ссылка)` | Корень инструкции одного узла. |
| `КартаСсылокДляУзла(Ссылка)` | Карта по инструкции узла. |
| `УзлыИнструкцииДляВыбора(КореньИнструкции)` | Таблица узлов инструкции (`Ссылка`, `Наименование`, `Код`, `ЭтоГруппа`) для формы вставки ссылки. |

Формат разметки, на который опирается `ПереписатьСсылкиНаЯкоряВHTML` (порядок атрибутов
обязателен, он же повторён в JS-предобработчике):

```html
<a class="gksi-link" href="<адрес>" data-gksi-anchor="<якорь>">текст</a>
```

### 3.2 Предпросмотр Markdown (`ГКСИ_MarkdownСерверВызовСервера`)

- В `СформироватьТекстHTMLДляТекстаMarkdown` добавлен параметр `СсылкиJSON`.
- Перед конвертацией showdown выполняется JS-предобработка: разбор `[[…]]`, разрешение
  через `window.__gksiLinks`, генерация `<a class="gksi-link" …>` либо
  `<span class="gksi-link-broken" …>`; `![[…]]` пропускаются.
- Добавлены CSS-классы `.gksi-link`, `.gksi-link:hover`, `.gksi-link-broken`.
- На панель редактирования добавлена команда **«Ссылка на группу или шаг»**
  (`КомандаMDСсылкаНаУзел`, картинка `ГКСИ_Ссылка`).

### 3.3 Формы элемента и группы

- Клик по ссылке обрабатывается в `ГКСИ_MarkdownКлиент.ПриНажатииПоляПросмотраКомментария`:
  адрес, начинающийся с `e1cib`, открывается через `ПерейтиПоНавигационнойСсылке`,
  остальные — прежним способом через `НачатьЗапускПриложения`.
- Кнопка вставки ссылки открывает форму `Catalog.ДемонстрационныеСценарии.Form.ГКСИ_ФормаВыбораГруппы`
  в режиме `РежимВыбора = "УзлыСсылки"`, результат подставляет в текст `[[Имя]]` либо `[[Код|Имя]]`
  в позицию курсора (`ГКСИ_Ссылки_ПослеВыбораУзла`).

### 3.4 Форма выбора `ГКСИ_ФормаВыбораГруппы` (режим выбора узлов)

Таблица узлов (группа/шаг, код в контексте, признак группы), возврат выбора фрагментом `[[…]]`
через метод `Закрыть`.

- **Два режима в одной форме.** Параметр `РежимВыбора`: `"Группы"` (по умолчанию) — прежний выбор
  родительской группы с исключениями; `"УзлыСсылки"` — выбор узла для вики-ссылки.
- **В списке и шаги, и группы.** `ГКСИ_СсылкиСценариев.УзлыИнструкцииДляВыбора` собирает узлы
  в двух ролях: как потомка (измерение `Сценарий` регистра `ГКСИ_ГруппыСценариев` — тогда
  известен код в контексте) и как группу (измерение `Группа`). Вторая роль нужна, чтобы в списке
  была и корневая группа-обёртка инструкции, у которой кода в контексте нет: ссылка на неё
  вставляется по наименованию. В ветке объединения код группы — `NULL`, агрегат `МИНИМУМ` его
  игнорирует, поэтому у подгруппы остаётся её собственный код.
- **Работа без известной инструкции.** Параметр `СсылкаУзла` необязателен: если узел не указан
  или ещё не связан с инструкцией, список заполняется узлами всех инструкций.
- **Контекст.** Корень инструкции определяется по ссылке текущего узла через
  `ГКСИ_СсылкиСценариев.КореньИнструкцииУзла`; кнопка вызова ссылки не требует записанного элемента.
- **Результат.** `ГКСИ_СсылкиСценариев.ФрагментСсылкиДляУзла` строит `[[Код|Наименование]]`
  (цель — код в контексте, у корневой группы — наименование); в режиме выбора группы результатом
  остаётся ссылка на группу. Значение передаётся методом `Закрыть`, его получает обработчик,
  указанный в `ОткрытьФорму`.

### 3.5 Альбом процессов (`ГКСИ_АльбомПроцессов`)

- Описания узлов прогоняются через `ПодставитьСсылкиВТекст(…, "Навигация")` в
  `ГКСИ_ЗаполнитьОписанияПоЯзыкам` (получила параметр `КартаСсылок`).
- Разделы получили якоря: `<details id="gksi-node-<uuid>">` у групп и
  `<tr id="gksi-node-<uuid>">` у шагов.
- После сборки документа ссылки на узлы, присутствующие в альбоме, переписываются
  на `#gksi-node-<uuid>` (`ПереписатьСсылкиНаЯкоряВHTML`); ссылки на узлы вне альбома
  остаются навигационными и открывают объект.

### 3.6 Перехват нажатия в форме альбома

**Важно.** Типовой обработчик `ДемонстрационныеСценарииКлиент.ПриНажатииВПолеHTMLДокумента`
для любой непустой ссылки выставляет `СтандартнаяОбработка = Ложь`, а для адресов без
префикса базы вызывает `ФайловаяСистемаКлиент.ОткрытьНавигационнуюСсылку`. Внутренние
якоря `#gksi-node-…` в этот сценарий не попадали: платформа пыталась открыть навигационную
ссылку из строки `"#gksi-node-…"`, а собственная прокрутка браузера была подавлена.

Поэтому в модуль формы `АльбомПроцессов` добавлен перехватчик:

```1c
&Вместо("ТекстHTMLПриНажатии")
&НаКлиенте
Процедура ГКСИ_ТекстHTMLПриНажатии(Элемент, ДанныеСобытия, СтандартнаяОбработка)
```

Адреса, начинающиеся с `#`, обрабатываются сами (`ГКСИ_ПерейтиКЯкорюАльбома`):
раскрываются все свёрнутые `<details>` по пути к целевому узлу и выполняется
`scrollIntoView(Истина)`. Все прочие адреса передаются типовому обработчику без изменений.

Оба метода размещены в области `СлужебныеПроцедурыИФункции` (в профильной области
`ОбработчикиСобытийЭлементовШапкиФормы` метод с собственным префиксом даёт SU93).

### 3.7 Регистрация объектов

В подсистему `ГКСИ_РМ_РедакторMarkdown` добавлен `CommonModule.ГКСИ_СсылкиСценариев`.
Общая форма `ГКСИ_ВыборУзлаСсылки` удалена из расширения (вместе с записью в подсистеме и в
`Configuration.mdo`) — выбор узла отдана форме `ГКСИ_ФормаВыбораГруппы` справочника.

## 4. Что НЕ менялось

- Загрузка и выгрузка Markdown: `[[…]]` хранятся в тексте как есть, дополнительной
  конвертации при round-trip не требуется.
- Механизм картинок (`![[…]]`, `![](…)`) — без изменений.
- Типовой код основной конфигурации (`ДемонстрационныеСценарииКлиент`) — не менялся,
  перехват сделан на стороне расширения.

## 5. Проверка

- `ГКСИ_СсылкиСценариев` — маркеров EDT нет.
- Форма `АльбомПроцессов`: новых маркеров нет (остались прежние SU61/SU88/SU93/SU44/SU11,
  существовавшие до правки).
- Проектный прогон `GetMarkers` (тип `1c`): ошибок (`severity: error`) нет.

## 6. Ручной сценарий проверки

1. Открыть шаг сценария, нажать **«Ссылка на группу или шаг»**, выбрать узел — в текст
   вставится `[[…]]`.
2. Сохранить, переключиться в режим просмотра — ссылка отображается и кликабельна,
   клик открывает выбранный узел.
3. Ввести заведомо неверное `[[НетТакого]]` — ссылка отображается как битая с подсказкой.
4. Открыть альбом процессов — клик по ссылке прокручивает документ к разделу; если
   раздел был свёрнут, группа раскрывается.

## 7. Найденные в ходе отладки дефекты

### 7.1 Клик по якорю в альбоме не работал

Типовой `ДемонстрационныеСценарииКлиент.ПриНажатииВПолеHTMLДокумента` подавляет
стандартную обработку для любой непустой ссылки и пытается открыть `#gksi-node-…` как
навигационную ссылку. Исправлено перехватчиком `&Вместо("ТекстHTMLПриНажатии")` в модуле
формы `АльбомПроцессов` (см. §3.6).

### 7.2 Ошибка «Поле объекта не обнаружено (РМ_аУзел_ТекстMarkdownСтрока)»

Вставка ссылки через кнопку падала. Причина: в `ГКСИ_MarkdownКлиент.ОбработкаКомандыПоляКомментария`
ветки выбираются через `СтрНайти(Команда.Имя, "<префикс>") = 1`, то есть сравнивается только
**начало** имени. Ветка обычной ссылки `РМ_КомандаMDСсылка` стояла в цепочке раньше ветки
`РМ_КомандаMDСсылкаНаУзел` и перехватывала команду `РМ_КомандаMDСсылкаНаУзел_<ПутьКДанным>`.
Далее `ВыполнитьЗаменуВТекстеКомментарияПоСтруктуреЗамены` отрезала от имени команды длину
строки `"РМ_КомандаMDСсылка_"` (19 символов) — оставалось `аУзел_ТекстMarkdownСтрока`,
и элемент формы искался как `РМ_аУзел_ТекстMarkdownСтрока`.

Исправление: ветка `РМ_КомандаMDСсылкаНаУзел` перенесена **выше** общей ветки
`РМ_КомандаMDСсылка` (в модуле оставлен комментарий о причине порядка).

**Вывод для будущих кнопок редактора:** имя команды не должно начинаться с префикса уже
существующей команды, либо ветка-потомок обязана стоять в цепочке раньше ветки-предка.

### 7.3 «Ссылку можно вставить только в сохранённое описание» на существующем элементе

Даже на записанном элементе кнопка **«Ссылка на группу или шаг»** отказывалась работать.
Причина — в `ГКСИ_MarkdownКлиент.СсылкаТекущегоУзла`: определение ссылки узла шло через
`ТипЗнч(Форма.Объект) = Тип("СправочникОбъект.ДемонстрационныеСценарии")`, и вся проверка
была обёрнута в `Попытка`, которая при любом сбое возвращала `Неопределено`. Ошибка сравнения
типов (в расширении имя типа через `Тип("…")` может не совпасть/не разрешиться) молча
превращалась в «элемент не записан».

Клиентский доступ к `Форма.Объект` при этом рабочий — это доказано записью описания
(`&НаКлиенте РМ_КлиентскийПередЗаписью` → `ГКСИ_MarkdownФормаКлиент.ЗаписатьHTMLИзMarkdown`
читает `Форма.Объект.ГКСИ_ТекстMarkdown`).

Исправление: проверка типа убрана, функция просто читает `Форма.Объект.Ссылка` и возвращает
её только при заполненном значении; недоступность `Объекта`/`Ссылки` по-прежнему гасится
`Попыткой` (это нужно для формы-примера редактора, где основной реквизит — не узел сценария).

**Вывод:** не оборачивать в `Попытку` проверки, результат которых управляет бизнес-ветвлением —
при сбое получается ложное «данные не заполнены» вместо внятной диагностики.

### 7.4 Кнопка вставки ссылки требовала записанного элемента, а в списке не было групп

Правка по замечаниям при ручной проверке (см. §3.4):

1. Требование «сначала запишите элемент» снято — кнопка всегда открывает форму выбора.
   Ссылка текущего узла передаётся как контекст (ограничение инструкцией), но её отсутствие
   больше не блокирует вставку.
2. `УзлыИнструкцииДляВыбора` отдавала только измерение `Сценарий` регистра, поэтому в списке
   не было корневой группы-обёртки инструкции. Теперь узлы собираются и по измерению `Группа`;
   добавлен режим «все инструкции» с колонкой «Инструкция».

Дополнительно при проверке маркеров выяснилось, что `ПриСозданииНаСервере` формы выбора не был
объявлен в форме как обработчик события (в `Form.form` не было секции `events`). Привязка
добавлена; обработчики `ФильтрПоле.ПриИзменении` и `УзлыТаблица.Выбор` переведены с
`УстановитьДействие` на декларативные обработчики.

### 7.5 Ошибки формы `ГКСИ_ВыборУзлаСсылки` и перевод выбора на форму группы

Ручная проверка собственной формы выбора дала две ошибки времени выполнения, после чего форма
была упразднена в пользу уже существующей формы выбора группы.

1. `Значение не является значением объектного типа (Цель)` — в обработчике `Выбор` таблицы
   формы второй параметр события (`ВыбраннаяСтрока`) приходит **числом** (идентификатором
   строки), а не строкой таблицы; код обращался к нему как к строке. Рабочий образец — обработчик
   `СписокГруппВыбор` формы `ГКСИ_ФормаВыбораГруппы`: он ищет строку через
   `СписокГрупп.НайтиПоИдентификатору(ВыбраннаяСтрока)`.
2. `Поле объекта не обнаружено (Форма)` — в `ГКСИ_Ссылки_ПослеВыбораУзла` читалось
   `ПараметрыВыполнения.Форма`, но при открытии формы структура параметров не содержала поля
   `Форма` (в отличие от ветки глоссария). Поле добавлено.

**Решение по архитектуре (по замечанию пользователя).** Собственная форма выбора удалена:
кнопка **«Ссылка на группу или шаг»** открывает существующую форму
`Catalog.ДемонстрационныеСценарии.Form.ГКСИ_ФормаВыбораГруппы` — ту же, что вызывает кнопка
«Добавить группу» на формах элемента и группы. В форме появился режим `РежимВыбора = "УзлыСсылки"`
(колонки «Код в контексте», «Группа», заголовок «Группа / шаг»), а результат выбора зависит
от режима: ссылка на группу либо готовый фрагмент `[[Код|Наименование]]`
(`ГКСИ_СсылкиСценариев.ФрагментСсылкиДляУзла`).

**Найденный попутно дефект.** В обеих кнопках «Добавить группу» (`ФормаЭлемента`, `ФормаГруппы`)
указывалось несуществующее имя формы `Catalog.ДемонстрационныеСценарии.Form.РМ_ФормаВыбораГруппы`
(форма переименована в `ГКСИ_ФормаВыбораГруппы`, вызовы не обновлены) — кнопка была нерабочей.
Имя исправлено.

**Возврат результата.** Форма закрывается методом `Закрыть(Результат)` вместо
`ОповеститьОВыборе`: `ОповеститьОВыборе` (см. документацию платформы) оповещает **владельца
формы** и вызывает его `ОбработкаВыбора`, а значение получает обработчик, переданный в
`ОткрытьФорму` как `ОписаниеОповещения`, — именно так построены вызовы в расширении
(и так же работает форма выбора термина глоссария).
