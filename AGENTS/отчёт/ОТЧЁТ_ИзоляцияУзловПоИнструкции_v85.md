# ОТЧЁТ: Изоляция узлов по корню инструкции через `КореньИнструкции` в РС

**Версия расширения:** 1.85 (архитектура), 1.86 (использование ресурса)
**Дата:** 2026-09-19
**Категория:** архитектурное изменение (большая фича)

---

## Контекст и мотивация

В версии 1.78 была добавлена четырёхэтапная модель защиты от «притяжения»
чужих шагов в Альбом процессов:

1. Переиспользование без перезаписи источника в `ОбработатьУзелРекурсивно`.
2. Защита авто-резолва от переиспользования чужих узлов.
3. Процедура исправления существующих данных `ГКСИ_ИсправитьИнструкцииИсточников`.
4. Фильтр в Альбоме процессов по реквизиту `ГКСИ_ИнструкцияИсточник` (на справочнике).

На реальных данных ГИП+ДМТО обнаружилось, что модель **недостаточна**:
- Общая группа (например, «Согласование ТКП») при «обновить всё» ДМТО притягивает
  в себя детей ГИП (001.005.001 — 001.005.003).
- ГИП-уникальные дети этой общей группы оказываются в ДМТО-альбоме.
- ДМТО-уникальные дети этой общей группы (Запрос счёта 012.003.004,
  Ознакомление 012.003.005) оказываются в ГИП-альбоме.

Причина: реквизит справочника `ГКСИ_ИнструкцияИсточник` хранится **на узле
один раз**, и для общего узла, живущего в нескольких корнях, нельзя хранить
информацию о всех его корнях.

---

## Архитектурное решение

В РС `ГКСИ_ГруппыСценариев` добавлено новое **измерение** `КореньИнструкции`
(тип `CatalogRef.ДемонстрационныеСценарии`) и новый **ресурс** `КодВКонтексте`
(тип `String`).

Составной ключ регистра теперь: `(Сценарий, Группа, КореньИнструкции)`.
Это позволяет хранить **несколько связей** «Сценарий — Группа» для одного узла
— по одной на каждый корень, в котором узел живёт.

Пример для общего шага «Задачи и процессы согласований» (Группа =
«Согласование ТКП»):

| Сценарий           | Группа              | КореньИнструкции        | КодВКонтексте |
|--------------------|---------------------|-------------------------|---------------|
| Задачи и процессы… | Согласование ТКП    | Инструкция ГИП          | 001.005.001   |
| Задачи и процессы… | Согласование ТКП    | Инструкция ДМТО         | 012.003.001   |

ГИП-уникальные дети имеют только одну запись с `КореньИнструкции = ГИП`,
ДМТО-уникальные — только одну с `КореньИнструкции = ДМТО`.

## Изменённые объекты

### Метаданные

`src/InformationRegisters/ГКСИ_ГруппыСценариев/ГКСИ_ГруппыСценариев.mdo`:
- добавлено измерение `КореньИнструкции` (тип `CatalogRef.Демонкларатура…`,
  правильнее — `CatalogRef.ДемонстрационныеСценарии`).
- добавлен ресурс `КодВКонтексте` (тип `String`).

### Бизнес-логика

`src/CommonModules/ГКСИ_ГруппыСценариевСервер/Module.bsl`:
- `ДобавитьСценарийВГруппу(Сценарий, Группа, КореньИнструкции = Неопределено)` —
  добавлен третий параметр `КореньИнструкции`.
- Внутренняя `ГКСИ_ЗаписатьПолныйКодКонтекстный(Сценарий, Группа, КореньИнструкции, Код)` —
  добавлены параметры `КореньИнструкции`, `Код`. Записывает/обновляет запись
  РС с указанным корнем и кодом в контексте этого корня.
- Внутренняя `ЗаписатьПолныйКодКонтекстный(Сценарий, Группа, КореньИнструкции)`
  — добавлен параметр `КореньИнструкции`; **обязательно** передаёт его в
  `ГКСИ_ЗаписатьПолныйКодКонтекстный`, иначе вторая половина
  `ДобавитьСценарийВГруппу` (пересчёт позиции сиблинга) затирала бы корень,
  записанный первой половиной.

`src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`:
- `ОбработатьУзелРекурсивно` — третий параметр вызова `ДобавитьСценарийВГруппу`
  теперь передаётся как `ИнструкцияИсточник`.

`src/CommonModules/ГКСИ_АльбомПроцессов/Module.bsl`:
- `ГКСИ_ОтфильтроватьУзлыПоИнструкции(Узлы, КорневыеГруппы, ДанныеУзлов)` —
  переписана логика фильтрации. Вместо подъёма по графу для определения
  принадлежности узла корню используется прямой запрос к РС по измерению
  `КореньИнструкции`.

### Пересчёты кодов в контексте корня

После фикса архитектуры РС добавлены правки, чтобы пересчёты не затирали
связи `(Сценарий, Группа, КореньИнструкции)` других корней:

| Процедура | Что изменено |
|-----------|--------------|
| `ПересчитатьПолныйКодДляПоддереваГрафа` | Вместо обхода графа `ЧленыГруппы` (только пара С-Г) делает запрос по всем записям поддерева с учётом `КореньИнструкции`; для каждой записи перезаписывает `КодВКонтексте` через `ГКСИ_ЗаписатьПолныйКодКонтекстный` с сохранением корня. |
| `ПересчитатьПолныйКодКонтекстныйДляСценария` | Вместо `Граф.ЧленыГруппы.Получить(Сценарий)` делает прямой запрос `ВЫБРАТЬ Группа, КореньИнструкции ГДЕ Сценарий = &Сценарий`; для каждой записи пересчитывает код и записывает с её корнем. |
| `ГКСИ_ПересчитатьВсеКодыВРегистре` | Запрос теперь возвращает три поля `(Сценарий, Группа, КореньИнструкции)`; для каждой записи считает `ПолныйКодВКонтекстеГрафа` и пишет через `ГКСИ_ЗаписатьПолныйКодКонтекстный` с этим корнем. |

Это нужно потому, что без пересчётов с учётом корня записи с другими
корнями для той же пары (Сценарий, Группа) стирались бы.

## Алгоритм фильтрации в Альбоме

Шаги алгоритма в `ГКСИ_ОтфильтроватьУзлыПоИнструкции`:

1. По корневым группам альбома строится множество корневых инструкций альбома
   (`МассивКорневыхИнструкцийАльбома`).
2. Делается один запрос к РС `ГКСИ_ГруппыСценариев` с условием
   `КореньИнструкции В (&МассивКорневыхИнструкцийАльбома)`. Результат запроса
   собирается во множество `СценарииВключенныеВКорни`.
3. Узел из `Узлы` показывается в Альбоме, если он содержится во множестве
   `СценарииВключенныеВКорни`.

Граф корней (`ГКСИ_ГрафГрупп`) используется для определения того, **какие
корневые инструкции** входят в Альбом (через подъём от корневых групп до корня).
Это решает задачу «Альбом содержит корневые группы нескольких инструкций — какие
корневые инструкции покрывает этот Альбом?» без N+1 запросов.

## Миграция данных с 1.84 на 1.85

Версия 1.85 **не содержит** автоматической миграции данных. После обновления
конфигурации необходимо:

1. Перезагрузить MD-файлы всех инструкций через обработку
   `ГКСИ_ЗагрузкаСценариевИзMarkdown` с действием «обновить всё».
   Это создаст корректные записи в РС с заполненным `КореньИнструкции`.
2. Старые записи РС (без `КореньИнструкции` — пустое измерение) фильтруются
   как «без корня» и не показываются ни в одном альбоме, пока не будут
   пересозданы.

`ГКСИ_ГруппыСценариевСервер.ГКСИ_ИсправитьИнструкцииИсточников()` (Шаг 3 из 1.78)
**больше не используется** в 1.85. Рекомендуется удалить в одной из следующих
версий.

Реквизит справочника `ГКСИ_ИнструкцияИсточник` помечен как устаревший (`Deprecate`).
Его планируется удалить в версии 1.9 или 2.0 (после того как пользователи
перейдут на фильтр по `КореньИнструкции`).

## Тестирование

Перед сдачей необходимо проверить:

1. Загрузка ГИП с нуля — в РС появляются записи с `КореньИнструкции = ГИП`.
2. Загрузка ДМТО с нуля — в РС появляются записи с `КореньИнструкции = ДМТО`.
3. Загрузка ДМТО с «обновить всё» поверх уже загруженной ГИП:
   - Общая группа «Согласование ТКП» — запись РС дополняется связью с ДМТО-корнем
     (или создаётся новая запись с корнем ДМТО).
   - ГИП-уникальные дети этой общей группы — НЕ появляются в РС с `КореньИнструкции = ДМТО`.
   - ДМТО-уникальные дети этой общей группы — появляются в РС с `КореньИнструкции = ДМТО`.
4. Формирование Альбома для ГИП:
   - В Альбоме показываются только ГИП-уникальные дети + общие дети.
   - ДМТО-уникальные дети НЕ показываются.
5. Формирование Альбома для ДМТО:
   - В Альбоме показываются только ДМТО-уникальные дети + общие дети.
   - ГИП-уникальные дети НЕ показываются.

## Использование ресурса `КодВКонтексте` (v1.86)

В v1.85 ресурс `КодВКонтексте` был добавлен в РС, но не заполнялся — вся
бизнес-логика продолжала писать и читать старый `ПолныйКодКонтекстный`. В
результате ресурс `КодВКонтексте` оставался пустым во всех записях.

В v1.86 ресурс `КодВКонтексте` **начинает заполняться**. Назначение — дать
возможность по значению ресурса однозначно понять, к какой инструкции
(корню) относится узел.

### Формат значения

`<КодКорня>.<ПолныйКод>`, где:

- `<КодКорня>` — системный `Код` корневой группы-инструкции в справочнике
  `ДемонстрационныеСценарии`. Получается через
  `ОбщегоНазначения.ЗначениеРеквизитаОбъекта(КореньИнструкции, "Код")`.
  Для ГИП с системным кодом `001` это будет `001`, для ДМТО с кодом `012`
  это будет `012`.
- `<ПолныйКод>` — значение ресурса `ПолныйКодКонтекстный` этой же записи
  (путь узла в графе, например `005.001` или `001.005.001`).

Пример:

| Сценарий | Группа | КореньИнструкции | ПолныйКодКонтекстный | КодВКонтексте |
|----------|--------|-------------------|----------------------|---------------|
| Задачи и процессы… | Согласование ТКП | ГИП (код `001`) | 005.001 | 001.005.001 |
| Задачи и процессы… | Согласование ТКП | ДМТО (код `012`) | 003.001 | 012.003.001 |

По первой части значения `КодВКонтексте` (до первой точки) сразу видно,
к какому корню-инструкции относится запись. Это и было целью введения
ресурса — дать явный идентификатор инструкции в значении, без необходимости
делать дополнительный запрос к справочнику за `КоранИнструкции`.

### Где пишется

В `ГКСИ_ГруппыСценариевСервер.ГКСИ_ЗаписатьПолныйКодКонтекстный`:

```bsl
Запись.ПолныйКодКонтекстный = ПолныйКод;
Если КореньИнструкции <> Неопределено Тогда
    Запись.КореньИнструкции = КореньИнструкции;
    КодКорня = ОбщегоНазначения.ЗначениеРеквизитаОбъекта(КореньИнструкции, "Код");
    Если ЗначениеЗаполнено(КодКорня) Тогда
        Запись.КодВКонтексте = Строка(КодКорня) + "." + ПолныйКод;
    Иначе
        Запись.КодВКонтексте = ПолныйКод;
    КонецЕсли;
КонецЕсли;
```

`ГКСИ_ЗаписатьПолныйКодКонтекстный` — единая точка записи для всех
публичных пересчётов (`ДобавитьСценарийВГруппу`, `ПересчитатьПолныйКодДляПоддереваГрафа`,
`ПересчитатьПолныйКодКонтекстныйДляСценария`, `ГКСИ_ПересчитатьВсеКодыВРегистре`),
поэтому ресурс заполняется автоматически во всех сценариях записи.

### Миграция

Старые записи РС (без `КореньИнструкции` — из v1.84 и ранее) по-прежнему
не заполняют `КодВКонтексте`, потому что у них нет корня. Чтобы заполнить
ресурс для них, нужно перезагрузить MD-файлы через
`ГКСИ_ЗагрузкаСценариевИзMarkdown` с действием «обновить всё» — каждая
новая запись будет содержать и `КореньИнструкции`, и `КодВКонтексте`.

## Явная передача корня-инструкции через форму (v1.87)

### Контекст и мотивация

В v1.85-v1.86 логика определения корня-инструкции при загрузке MD-файлов
работала по принципу: **первый `#-заголовок` файла = корень-инструкция**:

```bsl
Если ЗначениеЗаполнено(СсылкаНаУзел)
    И НЕ ЗначениеЗаполнено(ИнструкцияИсточник)
    И Узел.Уровень = 2 Тогда
    ИнструкцияИсточникДляДетей = СсылкаНаУзел;  // первый #-заголовок
```

Это работало только когда структура MD-файла была «плоской»:
```
# Инструкция ГИП            ← первый #-заголовок = настоящий корень
## Согласование ТКП
### Шаг 1
```

Но **на практике** структура MD-файлов ДМТО была другой:
```
# Согласование ТКП           ← первый #-заголовок = ПРОМЕЖУТОЧНАЯ группа
## Инструкция ДМТО           ← настоящий корень лежит в #2
### Запрос счёта
```

В этом случае первый `#-заголовок` «Согласование ТКП» записывался как
`ИнструкцияИсточникДляДетей`, и затем наследовался всеми дочерними узлами.
ДМТО-уникальные шаги, находящиеся на корневом уровне ДМТО-инструкции
(но **не** в «Согласование ТКП»), записывались в РС с
`КореньИнструкции = "Согласование ТКП"` (промежуточная группа), а **не**
с настоящим корнем ДМТО. При формировании Альбома ГИП через общую группу
«Согласование ТКП» эти шаги оказывались в Альбоме ГИП.

### Архитектурное решение

Добавлен **явный параметр** `ИнструкцияИсточник`, который передаётся через
всю цепочку загрузки: `ЗапуститьЗаписьДереваВФоне` (форма) →
`ЗаписатьДеревоФоново` (фон) → `ЗаписатьДеревоВСправочник` →
`ОбработатьУзелРекурсивно`.

Приоритет в `ОбработатьУзелРекурсивно`:

```bsl
Если ЗначениеЗаполнено(ИнструкцияИсточник) Тогда
    ИнструкцияИсточникДляДетей = ИнструкцияИсточник;     // приоритет: явно переданный
ИначеЕсли ЗначениеЗаполнено(СсылкаНаУзел) И Узел.Уровень = 2 Тогда
    ИнструкцияИсточникДляДетей = СсылкаНаУзел;            // fallback: первый #-заголовок
Иначе
    ИнструкцияИсточникДляДетей = ИнструкцияИсточник;     // наследование от родителя
КонецЕсли;
```

### Изменения в форме

В форме обработки `DataProcessors.ГКСИ_ЗагрузкаСценариевИзMarkdown.Form.Форма`:

- Добавлен реквизит `ГКСИ_ИнструкцияИсточник` (тип
  `CatalogRef.ДемонстрационныеСценарии`).
- Добавлен элемент формы `ГКСИ_ИнструкцияИсточникПоле` — поле выбора из
  справочника (оператор выбирает корневую группу-инструкцию, в которую
  загружается сценарий).
- Значение реквизита передаётся в `СтруктураПараметров` фонового задания
  под ключом `ИнструкцияИсточник`.

### Сценарий использования

1. Оператор открывает обработку `ГКСИ_ЗагрузкаСценариевИзMarkdown`.
2. Выбирает MD-файл.
3. **В поле «Инструкция-источник (корень)» выбирает корневую группу** —
   например, `Инструкция по «Планирование...» для ДМТО`.
4. Запускает загрузку.
5. В РС `ГКСИ_ГруппыСценариев` все дочерние узлы (включая ДМТО-уникальные
   шаги на корневом уровне) записываются с `КореньИнструкции = ДМТО`.

Если поле «Инструкция-источник» **не заполнено**, используется fallback —
первый `#-заголовок` MD-файла (старое поведение для обратной совместимости).
