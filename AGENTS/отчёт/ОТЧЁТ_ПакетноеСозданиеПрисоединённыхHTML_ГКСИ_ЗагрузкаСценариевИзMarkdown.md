# ОТЧЁТ: Пакетное создание присоединённых HTML-файлов при загрузке сценариев (версия 1.7 → 1.71)

**Версия расширения:** 1.64 → **1.7** (большая фича) → **1.71** (горячий багфикс).
**Дата:** 2026-09-18.
**Тип правки:** большая фича + горячий багфикс в той же итерации.

## 0. Сводка для читателя

- **1.7** — основная фича: перенос создания HTML-файлов из `ObjectModule.ГКСИ_ПриЗаписи` в `СоздатьПрисоединенныеHTMLФайлыПакетно` с новым каналом `МассивHTMLПоУзлам`. Подробности — §1–§11.
- **1.71** — горячий багфикс: в `ОбработатьУзелРекурсивно` рекурсивный вызов дочерних узлов **не передавал** накопитель `МассивHTMLПоУзлам`. В итоге у всех дочерних узлов HTML-файлы не создавались. Подробности — §12.

## 1. Контекст

Загрузка сценариев из Markdown через обработку `ГКСИ_ЗагрузкаСценариевИзMarkdown`
на больших деревьях (200+ узлов) была медленной из-за архитектурного
узкого места, выявленного в `AGENTS/план/ПЛАН_ДоработкаУсловнойЗащитыЖР_ГКСИ_ЗагрузкаСценариевИзMarkdown.md`
(п.5 анализа производительности).

На каждый записанный сценарий `ObjectModule.ГКСИ_ПриЗаписи` вызывал
`ГКСИ_СоздатьПрисоединенныеФайлыИзДопСвойств`, который:

1. Создавал/обновлял присоединённый HTML-файл через `РаботаСФайлами.ДобавитьФайл`.
2. **Делал повторную** `ОбъектСценария.Записать()` ради сохранения ТЧ `ОписанияСценария`.

Каждая такая запись снова триггерила `&Перед("ПередЗаписью")` /
`&После("ПриЗаписи")` и пересчёт `ПолныйКод` — на дереве из 200 узлов это
сотни лишних записей и многократное замедление.

## 2. Решение

Перенос создания присоединённых HTML-файлов из синхронного хука
`ObjectModule.ГКСИ_ПриЗаписи` в отдельную серверную функцию
`СоздатьПрисоединенныеHTMLФайлыПакетно`, вызываемую **один раз** после
записи всего дерева.

План — `AGENTS/план/ПЛАН_ПакетноеСозданиеПрисоединённыхHTMLПриЗагрузке.md`.

## 3. Что сделано в этой итерации

### 3.1 Новый канал передачи данных

В `ОбработатьУзелРекурсивно` **перестали** заполнять
`ДополнительныеСвойства["ГКСИ_АдресHTMLПоЯзыкам"]`. Вместо этого — внешний
массив структур `{Сценарий, КодЯзыка, ТекстHTML}`, который передаётся
параметром и накапливается по всему дереву.

Добавлен параметр `МассивHTMLПоУзлам = Неопределено` в сигнатуру
`ОбработатьУзелРекурсивно`. Старый канал сохранён в `ObjectModule` для пути
из типовых форм (`ФормаЭлемента`/`ФормаГруппы`) — он не трогается.

### 3.2 Новая функция `СоздатьПрисоединенныеHTMLФайлыПакетно`

Файл: `src/CommonModules/ГКСИ_ЗагрузкаСценариевИзMarkdown/Module.bsl`.

Сигнатура:

```bsl
Функция СоздатьПрисоединенныеHTMLФайлыПакетно(
    МассивСценариевИHTML, РазмерЧанка = 1) Экспорт
```

Возвращает `Структура`:

| Ключ | Тип | Смысл |
|------|-----|-------|
| `ОбработаноСценариев` | Число | Успешно обработано сценариев |
| `СозданоФайлов` | Число | Новых присоединённых файлов создано |
| `ОбновленоФайлов` | Число | Существующих файлов обновлено |
| `Ошибок` | Число | Сценариев с ошибкой |
| `ТекстОшибки` | Строка | Текст последней ошибки (для протокола) |

Алгоритм:

1. Сгруппировать элементы массива по `Сценарий` (Соответствие: ссылка → массив `{КодЯзыка, ТекстHTML}`).
2. Разбить на чанки по `РазмерЧанка`. Для каждого чанка:
   - `НачатьТранзакцию()` / `Попытка`.
   - Для каждого сценария в чанке: **внутренний** `Попытка`/`Исключение` — ошибка на одном сценарии не валит весь чанк.
   - `ОбъектСценария = Сценарий.ПолучитьОбъект()`. Если `Неопределено` — запись в ЖР + `Продолжить`.
   - Для каждой пары `{КодЯзыка, ТекстHTML}`: найти/создать строку ТЧ `ОписанияСценария`; если `ПрисоединенныйФайл` уже есть — `ДемонстрационныеСценарии.РезультатОбновленияПрисоединенногоФайла(...)`, иначе — создать через `РаботаСФайлами.ДобавитьФайл` с именем `ГКСИ_ГруппыСценариевСервер.ИмяФайлаОписанияСценария(ПолныйКод, КодЯзыка)`.
   - Если ТЧ изменилась (`ОбъектСценария.Модифицированность()`) — `ОбъектСценария.Записать()`. Если нет — пропустить (микрооптимизация).
   - `ЗафиксироватьТранзакцию()`. Если исключение во внешнем блоке — `ОтменитьТранзакцию()` и запись в ЖР с указанием чанка.
3. Итог в ЖР (с условной защитой `ПолучитьИспользованиеЖурналаРегистрации()`): сколько сценариев, сколько файлов создано/обновлено, сколько ошибок.

`РазмерЧанка = 1` по умолчанию — атомарность на уровне одного сценария.
Основной выигрыш по производительности — от устранения повторной
`ОбъектСценария.Записать()` после файла, а не от уплотнения БСП-транзакций.

Внутренняя вспомогательная процедура `ОбработатьОдинСценарийВПакете`
инкапсулирует логику создания/обновления файлов для одного сценария.

### 3.3 Этап 4 в `ЗаписатьДеревоВСправочник`

После цикла по корням дерева, **до** финального кадра прогресса «Загрузка
завершена», **внутри** блока `Попытка` добавлен этап 4:

```bsl
Если МассивHTMLПоУзлам.Количество() > 0 Тогда
    ЗаписатьПрогресс(АдресПрогресса, 3, ВсегоУзлов, ВсегоУзлов,
        НСтр("ru = 'Создание присоединённых файлов'"));
    Сводка = СоздатьПрисоединенныеHTMLФайлыПакетно(МассивHTMLПоУзлам);
    Если Сводка.Ошибок > 0 Тогда
        ЗаписатьПрогресс(АдресПрогресса, 3, ВсегоУзлов, ВсегоУзлов,
            СтрШаблон(НСтр("ru = 'Создание файлов: %1 ошибок'"), Сводка.Ошибок));
    КонецЕсли;
КонецЕсли;
```

Прогресс теперь показывает этап «Создание присоединённых файлов» в
диапазоне 95–100%, а не прыгает сразу в «Готово».

### 3.4 Совместимость с типовыми формами

- `ObjectModule.ГКСИ_СоздатьПрисоединенныеФайлыИзДопСвойств` **сохранён** (физически не удалён) — он по-прежнему нужен для пути из `ФормаЭлемента`/`ФормаГруппы`, которые кладут HTML в `ПараметрыЗаписи["ГКСИ_АдресHTMLПоЯзыкам"]` и оттуда попадают в `ДополнительныеСвойства` того же ключа.
- В `ЗаписатьДеревоВСправочник` больше не заполняется `ДополнительныеСвойства["ГКСИ_АдресHTMLПоЯзыкам"]` → `ObjectModule` на ранней проверке `Свойство(...)` (строка 82) выходит из обработки файлов, повторная `Записать()` не вызывается.
- Повторная `ОбъектСценария.Записать()` в `ObjectModule` остаётся — она нужна для пути из форм.

## 7. Что осталось на пользователя (замер производительности)

Шаги 6 и 7 плана **не могут быть выполнены ИИ** — требуют запуска
`ЗаписатьДеревоВСправочник` на типовом стенде:

### 7.1 Baseline (до правок — нужно замерить сейчас, **до** развёртывания)

Дерево из 100+ узлов, реальные картинки в `![[...]]`. Замерить время
выполнения `ЗаписатьДеревоВСправочник` (или соответствующей обработки)
в секундах. Зафиксировать цифру в этом разделе как
**`baseline_сек = __`**.

### 7.2 Тест «после» (после развёртывания 1.7)

На том же стенде, той же нагрузке. Замерить время **после** правок.
Зафиксировать как **`после_сек = __`**. Критерий готовности — ускорение
**≥ 30%** от baseline (т.е. `после_сек ≤ baseline_сек × 0.7`).

### 7.3 Если цель не достигнута

Если ускорение `< 30%` — увеличить `РазмерЧанка` в вызове
`СоздатьПрисоединенныеHTMLФайлыПакетно` до 25–50 (см. открытый вопрос 2
плана). Это уплотнит БСП-транзакции `РаботаСФайлами.ДобавитьФайл`.

См. `AGENTS/план/ПЛАН_ПакетноеСозданиеПрисоединённыхHTMLПриЗагрузке.md` §«Открытые вопросы»:

3. **Группы тоже получают HTML** — осознанное решение, поведение сохранено.
4. **Параллельное изменение иерархии** — унаследованный риск.

## 9. Что НЕ входит в эту итерацию

См. `AGENTS/план/ПЛАН_ПакетноеСозданиеПрисоединённыхHTMLПриЗагрузке.md` §«Что НЕ входит»:

- Изменение канала для типовых форм (`ПараметрыЗаписи["ГКСИ_АдресHTMLПоЯзыкам"]` остаётся как есть).
- Изменение `ДемонстрационныеСценарииПрисоединенныеФайлы` или формы присоединённых файлов.
- Кеширование HTML в ВХ между вызовами.
- Оптимизация `ЗаменитьКодыИзображенийНаDataURI` на каждом узле (out of scope).
- Оптимизация размера HTML с data URI (out of scope).
